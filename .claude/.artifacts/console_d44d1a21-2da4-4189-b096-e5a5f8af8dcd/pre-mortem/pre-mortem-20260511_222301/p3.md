## Intent Summary

Multi-terminal subagent enforcement system for Claude Code. Detects delegation opportunities (skill invocations + regex patterns), writes terminal-scoped blocking state, and enforces Task/Agent usage before other tools. Three hooks coordinate: UserPromptSubmit prospector writes state, PreToolUse gate blocks non-delegation tools, PostToolUse tracker clears state after Task invocation.

## Logical Gaps & Inconsistencies

1.1. [HIGH] **Terminal ID source mismatch defeats enforcement** (source: adversarial-compliance, adversarial-security)
   - Prospector extracts `terminal_id` from `HookContext.data` (delegation_prospector.py:146)
   - Gate re-detects from `WT_SESSION` directly (PreToolUse_delegation_gate.py:39)
   - When these diverge, prospector writes to path A, gate reads from path B → enforcement silent-fails
   - **FIX REQUIRED**: Gate must accept terminal_id from input data, not re-detect independently

1.2. [HIGH] **matched_pattern not redacted before persisting to state file** (source: adversarial-security)
   - `_write_delegation_state()` passes `prompt_snippet` through `_redact_sensitive()` but writes `matched_pattern` raw (delegation_prospector.py:178)
   - Detection pattern strings may contain fragments of user prompts or inferred intent
   - **FIX REQUIRED**: Apply `_redact_sensitive()` to `matched_pattern` before writing

1.3. [HIGH] **_log_gate_event() is dead code** (source: adversarial-compliance)
   - Function defined at PreToolUse_delegation_gate.py:81-97 but never called from `main()`
   - All gate telemetry silently dropped — no observable evidence of blocked/bypassed events
   - **FIX REQUIRED**: Add calls at each gate decision point (bypass_used, cleared, blocked)

1.4. [HIGH] **No end-to-end integration test** (source: adversarial-testing)
   - `_run_gate()` uses synthetic stdin instead of actual hook execution (test_delegation_gate.py:375)
   - State path mismatch (COMP-001) would NOT be caught by current test suite
   - **FIX REQUIRED**: Add integration test exercising real hook entry points

1.5. [MEDIUM] **Block message routed to wrong channel** (source: adversarial-logic)
   - `_build_block_message()` prints to stderr only (PreToolUse_delegation_gate.py:151)
   - Modern Claude Code may expect stdout JSON contract for hard blocks
   - **NOTE**: This finding is unverified against PROTOCOL.md. Claude Code docs show exit 2 + stderr is valid for blocking hooks. Downgraded from Phase 1 HIGH to MEDIUM pending PROTOCOL.md verification. Currently functional but may break on future Claude Code versions.

1.6. [MEDIUM] **Truncation applied before redaction** (source: adversarial-security)
   - `prompt_snippet[:200]` cuts credential patterns mid-match before `_redact_sensitive()` runs (delegation_prospector.py:179)
   - **FIX REQUIRED**: Apply `_redact_sensitive(prompt_snippet)[:200]` — redact before truncate

## Hidden Assumptions & Fragile Dependencies

2.1. [MEDIUM] **No terminal_id validation on state file read** (source: adversarial-io-validation)
   - State file stores `terminal_id` from time of write; no validation it matches current detection on read
   - Cross-terminal state bleed possible if env var appears mid-session
   - **FIX**: On read, verify loaded `terminal_id` matches current `_detect_terminal_id()`. Mismatch = treat as stale, clear state.

2.2. [MEDIUM] **PostToolUse hook registration not verified** (source: Phase 2 meta-critique)
   - `task_tracker_hook.py` clears state after Task/Agent invocation (task_tracker_hook.py:702)
   - **No specialist verified whether PostToolUse hook is actually registered and firing**
   - If PostToolUse hook doesn't run, state never clears until TTL expires (300s window)
   - **FIX**: Verify hook registration and add runtime telemetry for state clearing

2.3. [MEDIUM] **task_tracker_hook.py uses different terminal_id source than gate** (source: Phase 2 meta-critique)
   - `task_tracker_hook.py:67` reads `WT_SESSION` directly for `_get_delegation_state_dir()`
   - Gate also reads `WT_SESSION` directly (PreToolUse_delegation_gate.py:39)
   - But prospector reads from `context.data`
   - **Three different terminal_id sources**: prospector (context.data) vs gate/tracker (WT_SESSION) — consistent WITHIN gate+tracker but MISMATCHED with prospector

2.4. [LOW] **Fail-open on empty/malformed stdin** (source: adversarial-io-validation)
   - Empty stdin → `json.loads("")` raises `JSONDecodeError` → caught → returns None → gate exits 0 (allow)
   - Violates fail-secure principle
   - **NOTE**: This may be intentional — hooks should not block on malformed input. Keep as LOW.

2.5. [LOW] **Bypass flag semantics unclear** (source: adversarial-logic)
   - `--allow-inline` name does not convey "bypass delegation enforcement" semantics
   - **NOTE**: No evidence of actual user confusion. Design opinion, not verified failure mode.

## Missing Obvious Actions / Best Practices

3.1. [HIGH] **Incomplete sensitive data redaction patterns** (source: adversarial-security)
   - Only 3 patterns defined: labeled credentials, `sk-*` keys, PEM headers
   - Missing: GitHub tokens (`ghp_*`, `gho_*`), AWS keys (`AKIA*`), JWT tokens
   - **FIX**: Expand patterns to cover `gh[pousr]_[A-Za-z0-9_]{36,}`, `AKIA[0-9A-Z]{16}`, `eyJ[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+`

3.2. [MEDIUM] **No explicit file permissions on state files** (source: adversarial-security)
   - State files use default permissions; readable by other users on multi-user systems
   - **FIX**: `os.chmod(state_file, stat.S_IRUSR | stat.S_IWUSR)` after write

3.3. [MEDIUM] **Atomic write pattern not verified for race conditions** (source: Phase 2 meta-critique)
   - `_write_delegation_state` uses `tempfile + os.replace()` for atomicity (delegation_prospector.py:182-187)
   - No verification of what happens if two terminals race on same state file path
   - Atomic write protects against corruption but not against one terminal's state being overwritten by another
   - **NOTE**: Low probability in practice (requires same terminal_id in different sessions)

3.4. [LOW] **TTL constant duplicated in two files** (source: adversarial-compliance)
   - `DELEGATION_TTL_SECONDS=300` in both delegation_prospector.py:38 and PreToolUse_delegation_gate.py:23
   - Desync risk on future edits
   - **FIX**: Extract to `__lib/shared_constants.py` and import from both

## Risks and Edge Cases

4.1. [MEDIUM] **unknown terminal_id causes cross-terminal state pollution** (source: adversarial-io-validation)
   - When `WT_SESSION` absent, all hooks fall back to `unknown` as isolation key
   - All sessions without `WT_SESSION` share one state directory
   - **FIX**: Fallback chain should be `WT_SESSION` → `CLAUDE_TERMINAL_ID` → `hash(PID + cwd)`. Never bare `unknown`.

4.2. [LOW] **_log_gate_event silently swallows OSError** (source: adversarial-logic)
   - Telemetry lost on read-only filesystem or disk full with no warning
   - **FIX**: Fallback to stderr warning when primary logging fails

4.3. [LOW] **Test state isolation not mocked in prospector tests** (source: adversarial-compliance)
   - `TestDelegationProspectorState` writes actual state files to real `.artifacts/` directory
   - **FIX**: Mock `_get_state_dir` to return `temp_dir`

4.4. [LOW] **Duplicated state clearing across modules** (source: adversarial-testing)
   - Three modules have separate `_clear_delegation_state()` functions
   - **NOTE**: Functions are small and simple. Extraction beneficial but not critical.
