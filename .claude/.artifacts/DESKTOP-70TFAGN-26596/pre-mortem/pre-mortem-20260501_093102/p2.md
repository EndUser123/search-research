## Severity Calibration Issues
1. **Three specialists, three severity labels, one root cause**: The budget-scoping bug (budget defined inside `if _mod_name not in SAFETY_MODULES:` block, used outside it) appears as:
   - [HIGH] in COMP-001/002/003 (adversarial-compliance)
   - [HIGH] in QUAL-001/002 (adversarial-quality)
   - [HIGH] in LOGIC-001/002/003 (adversarial-logic, framed as "inconsistent skip-cost behavior")

   All three agree it's HIGH but describe it differently. This is good calibration — severity is consistent even if framing differs. No calibration issue here.

2. **cognitive_enhancers structure — inconsistency unacknowledged**: adversarial-logic says "decrement placement is correct" [LOW], adversarial-quality says "same structure is inconsistent" [MEDIUM]. The Phase 1 findings don't acknowledge this contradiction. Should be reconciled: either the structure IS correct (and QUAL-003 should be downgraded) or it IS inconsistent (and LOGIC-005 should be upgraded).

3. **TEST-007 (tokenization ratio) rated [LOW]**: The same 4x assumption underlies all budget calculations. If it's wrong, all conditional modules miscount. This is more systemic than [LOW].

## Missed Blind Spots
1. **Hypothesis: The 20000 hard cap is never validated against actual total injection sizes.** If the sum of all possible injections exceeds 20000 chars (the hard cap), the system will never trigger budget exhaustion. Specialists tested individual module guards but not whether the hard cap is reachable. With 10+ cognitive enhancers potentially each injecting 50-100 chars, and reasoning modes injecting similar amounts, total injection could approach 2000+ chars per turn. This is not necessarily a bug (20k is generous) but no specialist verified the cap is never reached.

2. **Hypothesis: The `context.data.get("skipped_budget", [])` pattern — if two modules skip at the same budget level, they both append to the same list.** No specialist flagged that `setdefault("skipped_budget", [])` could accumulate duplicates across multiple runs if the dict is reused. But in the current architecture, context.data is per-turn, so this is not a bug — just an untested assumption.

3. **Hypothesis: No specialist examined the `reasoning_contract_already_applied` path in reasoning_mode_selector.** At line 102, if `contract_active` is True, the system_context is shortened. This means the actual injection length varies depending on whether upstream hooks applied the reasoning contract. The budget decrement uses `len(system_context + user_message)` but the actual injection could be shorter if contract was already active. This could cause budget drift.

4. **Hypothesis: `_build_injection` in cognitive_enhancers returns a string that is appended to other injections.** The combined context is joined with `"\n\n"`. But the budget decrement uses raw `len(injection)`, not the joined length. If multiple enhancers produce overlapping content, the budget appears larger than the actual combined injection.

## Precision Failures
1. **LOGIC-005 "no issue found" — premature closure**: adversarial-logic says "decrement placement is correct" and rates it [LOW], but then also says "No change needed." This is precision failure: the specialist correctly identified that the placement is structurally inconsistent with the other modules but then dismissed it without explaining why inconsistency at [LOW] severity is acceptable when similar inconsistencies (LOGIC-004) are rated [MEDIUM].

2. **TEST-006 _is_actionable_prompt edge cases — vague**: "No test verifies /search or /commit are actually skipped" is a valid gap, but the finding doesn't specify what the correct behavior should be. Is /search supposed to be skipped? The finding implies it should be but doesn't verify the configuration is intentional.

3. **QUAL-004 exception handling — mislabeled**: Rated [MEDIUM] but says "the exception handling itself is adequate." If the exception handling is adequate, why is it a [MEDIUM] finding at all? The actual issue is QUAL-001 (undefined budget), not the exception handling. This finding should be merged into QUAL-001.

4. **TEST-008 unreachable code — severity mismatch**: The finding itself says "May produce suboptimal test guidance" but rates it [MEDIUM]. If the behavior is suboptimal but not broken, [LOW] would be more calibrated. [MEDIUM] implies it causes incorrect behavior.
