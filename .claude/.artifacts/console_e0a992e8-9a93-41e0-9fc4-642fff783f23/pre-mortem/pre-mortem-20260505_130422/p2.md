## Severity Calibration Issues
1. **PTY noise filter "Warning:" edge case rated LOW by adversarial-logic** — A real stderr containing only "Warning:" would be treated as PTY noise (not an error). adversarial-testing rated this HIGH (TEST-PCLI-002) because the downstream consequence is a false error classification that could trigger quota-fallback cascades. adversarial-logic rated it LOW because real warnings always have context text. The disagreement is about likelihood (adversarial-logic) vs consequence if wrong (adversarial-testing). The HIGH rating from adversarial-testing is more appropriate given the impact chain — this should be HIGH, not LOW.
2. **Config path migration rated MEDIUM by adversarial-logic but no other specialist commented** — This is the only MEDIUM finding and only one specialist weighed in. adversarial-io-validation's "no issues found" is misleading — the migration concern is real but not an I/O bug. Should have been surfaced by adversarial-quality as a design gap.

## Missed Blind Spots
1. **"_save_cli_output TypeError already fixed" claim is unverified** — The work summary states `_save_cli_output` TypeError (line 70) was "already fixed in session" and `_save_cli_output` is not in the fix list. The "Warning:" fix was only applied to the PTY noise filter upstream — but the downstream `_process_llm_results` filter was NOT changed. This is a gap: the plan's Fix 1 mentioned "verify that warnings go through the `if` branch (treat as success) not the `elif error` branch" but this was never verified or fixed.
3. **The plan's item about `_process_llm_results` was marked as "Fix 1" but only one of its two sub-fixes was applied** — Adding "Warning:" to the PTY filter was done. But the `_process_llm_results` error filter was NOT modified. The error filter still checks `error.lower()` for `"warn"`, which would match "Warning: No models match pattern..." and clear output. This means the root cause of the empty output bug is only half-fixed.

The recommendation should pick one or note which is preferred. As-is, it gives the implementer no guidance.

This is appropriate for trivial changes but misses the systemic issue: zero test coverage across all fixes means sound logic has no regression protection. adversarial-quality should have flagged the test gap as a quality concern.
