## Intent Summary
bf_v3_service.py is a FastAPI/LangGraph service that routes LLM requests through Bifrost with multi-model fan-out for compare operations and a multi-turn code agent loop with sandboxed file tools. The accompanying SKILL.md (v4.0.0) is a thin dispatcher that parses `/bf <model> <mode> <prompt>` and calls the service endpoints.

## Health Score: 30%

BLOCKER issues make the compare endpoint inaccessible (VALID_RUN_MODES gap) and the service port binding mismatch means the PowerShell startup must be verified. Multiple HIGH issues in path traversal guards and model output injection attack surface compound the risk. The service is not production-safe without fixes.

## Logical Gaps & Inconsistencies

1.1. [BLOCKER] compare mode returns HTTP 400 — bf_v3_service.py:43 VALID_RUN_MODES excludes compare, so /bf/compare is unreachable. Skill docs list it as valid; service rejects it.

1.2. [HIGH] Port binding unverified — The service defaults to FastAPI port 8000. The PowerShell `start-bf-stage2` passes `--port 8091` to uvicorn. If the service is started differently, all dispatches fail connection-refused.

1.3. [HIGH] CodeRequest.mode is dead weight — mode field accepted but never read or validated. Aesthetic inconsistency with RunRequest.

1.4. [MEDIUM] Error fallback unreachable — bf_v3_service.py:504 `"unknown error" or 'empty response'` — first truthy string always wins; 'empty response' never reached.

1.5. [LOW] CompareRequest.mode accepted but unused — silently ignored; misleading API contract.

## Hidden Assumptions & Fragile Dependencies

2.1. [HIGH] Model output trusted as JSON schema — run_code_agent passes raw LLM text to json.loads then dispatches as tool actions with no schema validation. Prompt injection or a compromised model can trigger arbitrary file reads/writes.

2.2. [HIGH] TOCTOU path guard window — _resolve_allowed_path resolves once, check and file operation use the same resolved path. A symlink swap between check and use escapes containment. No re-validation before actual I/O.

2.3. [MEDIUM] Bifrost response content not validated — malformed JSON or non-text blocks silently treated as empty string, masking injection or manipulation.

2.4. [MEDIUM] BF_ALLOWED_ROOT validated once at module load — if the env var changes or the path is deleted/moved, the stale resolved value persists silently.

2.5. [LOW] Timeout=0 silently accepted — REQUEST_TIMEOUT_MS=0 from env causes indefinite hangs on all model calls.

## Missing Obvious Actions / Best Practices

3.1. [HIGH] Startup validation absent — BF_ALLOWED_ROOT never checked to exist, be a directory, or be non-empty at import. Misconfiguration passes silently until first file operation.

3.2. [HIGH] Pydantic model for tool actions absent — raw dict from json.loads executed directly as file system operations. No Literal action whitelist, no field validation.

3.3. [MEDIUM] API key sanitization missing — error=str(e) in exception handlers can leak Bearer tokens into logs if exception messages include request context.

3.4. [MEDIUM] Sensitive fields in /health — BF_ALLOWED_ROOT, model names, base URL disclosed to unauthenticated clients.

## Risks and Edge Cases

4.1. [HIGH] Prompt injection via code agent — Model returns crafted JSON; execute_tool_action runs read/write/glob with no schema enforcement. Combined with TOCTOU, arbitrary files accessible.

4.2. [MEDIUM] mkdir parents=True outside containment check — tool_write_file creates directory trees before writing; parent path not re-validated after mkdir.

4.3. [MEDIUM] /health discloses security boundary — exact allowed root path and routing config to any network caller.

4.4. [LOW] Glob builds full result list before filtering — large directories cause memory pressure before limit kicks in.

4.5. [LOW] LangGraph graph rebuilt every request — no caching of compiled graph; wasteful for repeated calls.

## Concrete Recommendations

5.1. [HIGH] Add compare to VALID_RUN_MODES or clarify in SKILL.md that compare has a dedicated endpoint and is not validated at /bf/run. bf_v3_service.py:43
5.2. [HIGH] Add startup validation: assert BF_ALLOWED_ROOT.exists(), BF_ALLOWED_ROOT.is_dir(), BF_ALLOWED_ROOT.resolve() matches expected. bf_v3_service.py startup block
5.3. [HIGH] Add Pydantic model for tool actions with Literal action whitelist. bf_v3_service.py:execute_tool_action / run_code_agent
5.4. [MEDIUM] Sanitize error messages: strip Bearer tokens from str(e) before logging. bf_v3_service.py exception handlers
5.5. [MEDIUM] Remove sensitive fields from /health or add auth. bf_v3_service.py:health endpoint
5.6. [MEDIUM] Validate parent directory in tool_write_file before mkdir, or reject if parent would escape containment. bf_v3_service.py:tool_write_file
5.7. [LOW] Filter empty/whitespace model names from CompareRequest.models before building graph.
5.8. [LOW] Add Literal constraint to CodeRequest.mode or remove it if unused.
5.9. [LOW] Enforce REQUEST_TIMEOUT_MS > 0 at startup.
5.10. [LOW] Pre-compile and cache LangGraph per model list to avoid rebuilding on every /bf/compare call.
