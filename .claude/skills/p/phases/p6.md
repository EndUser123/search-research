# Phase 6: Security Gate

> **Core Question: Is this code secure for production?**

Comprehensive security scanning and vulnerability detection before production deployment.

## Purpose

P6 is the **security certification gate** that runs after P5 (Certify) and before production deployment. It validates:

- **Code security** via Bandit static analysis (SQL injection, hardcoded secrets, etc.)
- **Dependency security** via pip-audit CVE scanning

This phase **HALTS** on High/Critical severity findings, preventing vulnerable code from reaching production.

## AID Integration (Application-Layer Security)

P6 runs `aid_analyze_security` on every `/p6` invocation as additive app-layer security evidence.

Ownership boundary:
- Bandit + pip-audit remain core gate checks.
- AID security pass augments findings; it does not replace or move ownership from `/p2`.

## Prerequisite

**Phase 5 exit criteria must be met before invoking `/p6`:**

- [ ] P5 certification complete
- [ ] All tests passing
- [ ] Code ready for production deployment

## Your Workflow

When `/p --phase=6 <target>` is invoked:

### Step 0: AID Security Pass (Always)

Run AID security analysis on target first:

```bash
aid_analyze_security(target_path=<target>)
```

Merge policy:
- keep actionable findings with file references
- include results in final security summary
- High/Critical AID findings are blocking for P6 verdict

Conflict/failure handling:
- If AID security pass fails/conflicts (timeout/unavailable), continue P6 and emit explicit degraded-security-analysis warning.

### Step 1: Bandit Static Analysis

Run Bandit security scanner on target:

```bash
python P:/.claude/skills/p/scripts/security.py <target>
```

| Result | Action |
|--------|--------|
| Exit 0 | `✅ PASS` → No security issues |
| Exit 1 | `⚠️ WARN` → Medium/Low severity (non-blocking) |
| Exit 2 | `❌ FAIL` → High/Critical severity - HALT |
| Exit 3 | `❌ ERROR` → Tool not installed - HALT |

**Bandit detects:**
- SQL injection vulnerabilities
- Hardcoded passwords/API keys
- Use of insecure functions
- YAML loading issues
- Shell injection risks

### Step 2: CVE Scan (pip-audit)

Scan dependencies for known vulnerabilities:

```bash
python P:/.claude/skills/p/scripts/cve_scan.py
```

| Result | Action |
|--------|--------|
| Exit 0 | `✅ PASS` → No known CVEs |
| Exit 1 | `⚠️ WARN` → Low/Medium CVEs (non-blocking) |
| Exit 2 | `❌ FAIL` → High/Critical CVEs - HALT |
| Exit 3 | `❌ ERROR` → Tool not installed - HALT |

### Step 3: Report Verdict

After AID + Bandit + CVE scans complete, report overall verdict:

```
## P6 Security Summary

### Bandit Static Analysis
✅ PASS / ⚠️ WARN / ❌ FAIL

### CVE Scan (pip-audit)
✅ PASS / ⚠️ WARN / ❌ FAIL

### AID Security Analysis
✅ PASS / ⚠️ WARN / ❌ FAIL

## Overall Verdict
✅ PASS - Security checks passed
⚠️ WARN - Security issues found, review recommended
❌ FAIL - Blocking security issues found, must fix before deployment
```

## HALT Conditions

P6 **HALTS** on:

| Condition | Action |
|-----------|--------|
| High/Critical AID security findings | Fix security issues before deployment |
| High/Critical Bandit findings | Fix code security issues before deployment |
| High/Critical CVEs found | Update dependencies before deployment |
| Tools not installed | Install required tools: `pip install bandit pip-audit` |

## Installation

```bash
# Install required security tools
pip install bandit pip-audit
```


## Integration

- **`/p5` (Certify)** — P6 runs after P5 completes
- **`/adversarial-security`** — Use for deeper security analysis if P6 finds issues
- **Deployment** — P6 is the final gate before production deployment

## Exit Criteria

**P6 Phase Complete when:**

1. Both security scans executed
2. Verdict reported (PASS/WARN/FAIL)
3. No High/Critical issues remaining (for PASS)
4. Next steps presented to user

## Next Steps

```
**Next Steps** (pick one):

1. [Passed] Proceed to deployment
2. [Passed] /adversarial-security for deeper analysis
```

## Guardrails

- **Zero Tolerance:** Any High/Critical security finding stops deployment
- **Evidence:** Must show actual Bandit/pip-audit output
- **Context:** Running in `context: fork` to prevent main session bloat
