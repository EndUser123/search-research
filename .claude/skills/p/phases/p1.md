# Phase 1: Build

## Purpose

Make rough code **work correctly** with test-first discipline. This is the first phase of the 4-phase Code Maturation Pipeline (`/p1` → `/p2` → `/p3` → `/p4`).

**Core question this phase answers:** "Does it work?"

## What This Phase Does

1. Discover what exists (read code, run existing tests)
2. Identify test gaps (what's untested)
3. Write tests for existing behavior (TDD RED phase)
4. Fix all known bugs (TDD GREEN phase)
5. Simplify and modernize Python code (code-simplifier subagent)
6. Clean up while tests pass (TDD REFACTOR phase)
7. Verify integration (functions are actually wired in)

## Delegated Skills

| Step | Skill | Purpose |
|------|-------|---------|
| Gap analysis | `/test` | Discover what tests exist, what's missing, generate `.test_gaps.json` |
| Test writing + implementation | `/tdd` | RED → GREEN → REFACTOR cycle with parallel subagents |
| Bug fixes | `/fix` | TDD-driven bug fixing (delegates to `/tdd`) |
| Code simplification | `code-simplifier` | Python 3.12+ modernization, clarity, consistency (subagent) |

## Decomposition Ownership

`/p1` owns execution-side recovery that was previously implied by `/oops`:
- apply verified fixes for edit/loop failures using TDD (`/fix`/`/tdd`)
- re-run tests and integration checks after each failure-driven fix

`/p1` does not perform exploratory diagnosis (owned by `/s`) and does not perform deterministic triage synthesis (owned by `/r`).

## Your Workflow

When `/p --phase=1` is invoked with a target:

### Step 1: Discover

Run `/test` on the target to get coverage analysis and gap identification.

```
/test <target>
```

This produces:
- Coverage report (pytest-cov)
- Test classification (unit, integration, edge case, error path)
- `.test_gaps.json` with prioritized missing tests
- Solo-dev pattern violations (if any)

### Step 1.5: Analyze Test Quality

After discovering what tests exist, check their quality using the `TestQualityDetector` from `commands.duplicates`:

```python
from commands.duplicates import TestQualityDetector
from pathlib import Path

# Initialize detector
detector = TestQualityDetector()

# Scan for test quality issues
issues = detector.scan(Path("<target>"))

# Issues are categorized by severity:
# - critical: Requires immediate attention
# - high: Empty tests, tests without assertions
# - medium: Over-mocked tests (brittle)
# - low: Missing test files
```

**Issue Types Detected:**

| Issue Type | Severity | Description | Action |
|------------|----------|-------------|--------|
| `no_test` | low | Source file has no corresponding test | Add to gap backlog |
| `empty_test` | high | Test function appears empty (≤2 lines) | Add assertions or remove |
| `no_assertions` | high | Test has no assert/raise statements | Add assertions |
| `over_mocked` | medium | Test has >5 mocks (may be brittle) | Refactor to reduce mocks |

**Integration with TDD:** Prioritize high-severity issues (empty_test, no_assertions) before writing new tests. These quality issues undermine the test foundation.

### Step 2: Build Test Coverage

For each gap identified in Step 1, invoke `/tdd` to write tests and implement fixes:

```
/tdd <target>
```

The TDD skill enforces:
- **RED**: Write failing tests (parallel `tdd-test-writer` subagents)
- **GREEN**: Implement minimal code to pass (parallel `tdd-implementer` subagents)
- **REFACTOR**: Clean up while tests pass (parallel `tdd-refactorer` subagents)
- **VERIFY**: Confirm integration (grep for call sites)
- **REGRESSION**: Run related tests to catch cascading breaks

### Step 3: Fix Known Bugs

If bugs are identified during Step 1 or Step 2, invoke `/fix` for each:

```
/fix <bug description>
```

### Step 4: Simplify and Modernize (Python-only)

**Skip this step for non-Python code.**

After tests pass and bugs are fixed, run the `code-simplifier` subagent to simplify and modernize the Python code:

```
Task: code-simplifier

Simplify and refine the target code for clarity, consistency, and maintainability.

Focus on recently modified code. Preserve all functionality.

Target: <the files modified in this P1 cycle>
```

**What this does:**
- Applies Python 3.12+ modern standards (type hints, modern syntax)
- Improves clarity and consistency
- Removes unnecessary complexity
- Preserves all verified functionality

**Rationale:** Code simplification after tests pass ensures changes are verified by the existing test suite.

### Step 5: Re-assess

Run `/test` again to confirm:
- All tests pass
- Coverage has improved
- No new gaps introduced

### Loop Condition

**Repeat Steps 2-5 until:**
- All tests pass
- Core logic has test coverage
- No known bugs remain
- Code is simplified and modernized (Python-only)
- Integration verified (functions are called, not just defined)
- TestQualityDetector shows no high-severity issues (empty_test, no_assertions)

## Exit Criteria

Phase 1 is complete when:
- [ ] All existing tests pass
- [ ] New tests cover core logic paths
- [ ] Known bugs are fixed with regression tests
- [ ] `/test` shows no critical gaps
- [ ] TestQualityDetector shows no high-severity issues (empty_test, no_assertions)

## Phase Progression

When exit criteria are met:
```
Ready for /p2 (Review) - find problems via adversarial analysis
```

## Usage

```
/p --phase=1 <target>           # Promote a file or directory
/p --phase=1 src/module.py      # Single file
/p --phase=1 src/               # Directory
/p --phase=1                    # Infer from context
```

## What This Does NOT Do

- Does not run adversarial review (that's `/p2`)
- Does not run validation pipeline (that's `/p3`)
- Does not generate portfolio artifacts (that's `/p4`)
- Does not add features — only makes existing code work correctly

## Return Contract

When running as a phase subagent dispatched by `/p` orchestrator, end your response with this block:

**On pass (all tests passing, no bugs found):**
```
PHASE_RESULT: PASS
PHASE: 1
SUMMARY: {e.g., "Tests passing (42/42), coverage 87%"}
```

**On pass with blocking bugs fixed (tests now passing because bugs were fixed):**
```
PHASE_RESULT: PASS
PHASE: 1
BUGS_FIXED: true
BLOCKING_FOUND: {description of the bug that was found and fixed}
FIX_APPLIED: {brief description of the fix}
SUMMARY: {e.g., "Tests passing (42/42) after 1 bug fixed — coverage 87%"}
```

**On halt (tests still failing after TDD loop):**
```
PHASE_RESULT: HALT
PHASE: 1
REASON: {e.g., "2 tests failing after TDD loop — fix before review"}
BLOCKING_COUNT: {number of failing tests}
SUMMARY: {brief description}
```
