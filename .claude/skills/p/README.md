# /p - Code Maturation Pipeline

Intelligent code quality orchestrator that automatically detects codebase state and runs appropriate quality gates.

## Purpose

`/p` is a heavy AI-assisted development ecosystem where technical direction guides LLM implementation. It automates the code maturation pipeline with 6 phases:

- **P0**: Scaffold - Create project structure
- **P1**: Build - Make code work correctly (test-first)
- **P2**: Review - Find all problems (adversarial analysis)
- **P3**: Validate - Prove it works (gated pipeline)
- **P4**: Publish - Make presentable (documentation)
- **P5**: Certify - Final QA certification
- **P6**: Security - Security scan before deployment

## Core Features

- **Auto-detection**: Automatically determines which phase to run based on codebase state
- **No flags required**: Normal usage is just `/p` - the system figures out what to do
- **Quality-first**: Thoroughness > speed - "Does it work correctly?" > "How fast can we ship?"
- **HALT on blocking errors**: Fixes problems before proceeding to next phase

## Quick Start

```bash
# Auto-detect and run appropriate phase
/p

# Target specific file or directory
/p src/module.py

# Run specific phase
/p --phase=2  # Review only
/p --phase=3  # Validate only

# Quick mode (changed files only)
/p --quick

# Publish mode (halt on warnings)
/p --publish
```

## Pipeline Phases

### P1: Build
Make code work correctly with test-first discipline.
- Runs existing tests
- Identifies test gaps
- Fixes bugs
- Ensures all tests pass

### P2: Review
Find all problems via adversarial analysis.
- 7 parallel specialist agents (security, performance, compliance, quality, testing, code-critic, qa)
- 3 PR-review-toolkit agents (code-reviewer, pr-test-analyzer, silent-failure-hunter)
- Synergy detection (cross-file refactoring opportunities)
- Duplicate detection
- Git history analysis
- 7-layer filtering (context, deduplication, architectural, test quality, quality gate, constitutional, practicality)

### P3: Validate
Prove it works with gated pipeline.
- 15+ validation stages
- Syntax, naming, type checking, integration tests
- Coverage, layer validation, security scans
- All blocking stages must pass

### P4: Publish
Generate portfolio artifacts.
- README.md generation
- LICENSE creation
- CHANGELOG.md
- API documentation (optional)

### P5: Certify
Final QA certification.
- Test quality verification
- Documentation completeness
- Release readiness checks
- Portfolio registration

### P6: Security
Security gate before deployment.
- Vulnerability scanning
- Dependency security checks
- Deployment readiness verification
