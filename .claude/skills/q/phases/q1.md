# Q1 - ScopeResolver

## Purpose

Resolve analysis scope deterministically for `/q`.

## Workflow

1. Read WT_SESSION-scoped activity (primary).
2. Read conversation context (secondary).
3. Cross-check with fresh git state (tertiary verification only).
4. **[From /triage]** Calculate complexity score for scope classification:
   - High Impact (+3-4): integrate, new system, migration, multi-system
   - Medium Impact (+2): refactor, backward compat, performance, security
   - Lower Impact (+1): testing, validation, logging
   - Classify scope: TRIVIAL (0-5), STANDARD (6-12), CAREFUL (13-18), DESIGN_REVIEW (19-25)
5. Build `scope` with:
   - target files/topics
   - scope type (`code|topic|project`)
   - complexity_class (`trivial|standard|careful|design_review`)
   - confidence (`high|medium|low`)
   - degraded flags

## Rules

- Do not use git-only scope in multi-terminal workflows.
- If session and conversation scope are both unavailable, HALT with remediation.
- Output `scope` object for Q2.

## Decomposed from /triage

Complexity scoring now integrated into Q1 scope resolution:
- Used to classify analysis depth required
- Informs downstream phases about appropriate validation level
- Maps to path selection: TRIVIAL→quick scan, DESIGN_REVIEW→deep analysis
