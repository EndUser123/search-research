# Decomposition Ownership

`/r` owns deterministic parts of removed skills:

## Consolidated From

| Source Skill | Deterministic Checks Owned by /r |
|-------------|----------------------------------|
| `/opt` | Low-risk simplification proposals, constitutional filtering, predictable tradeoffs |
| `/oops` | Failure triage checklist (evidence, assumption audit, counterfactual) for non-exploratory diagnosis |
| `/opts` | Deterministic opportunity refinement from current-session signals |
| `/value` | Deterministic value-opportunity ranking (leverage, optionality, asymmetric upside, flywheel) |
| `/value-maximization` | Completeness gate and exclusion disclosure policy |
| `/val` | Deterministic command/skill standards audit when metadata files are in scope |
| `/verify` | Deterministic verification-completeness audit (tier evidence present/missing) |
| `/analysis-audit` | Deterministic audit-coverage gap checks |
| `/analysis-profile` | Deterministic bottleneck follow-up checklist |
| `/analysis-logs` | Deterministic error-pattern corroboration |

## Integrated Skills (Detailed Checks)

### From `/slc` (Pragmatic Solo Dev Guidelines)
- Complexity justification check: value > costs?
- Complete solutions check: no dead code
- Evidence verification: proofs shown?
- Local/portable validation: no infra/lock-in

### From `/read-before-write` (SRPI Protocol)
- Search codebase check: Glob/Grep used?
- Read working code check: existing patterns understood?
- Plan minimal change check: avoiding over-engineering
- Implementation tool check: Edit/Write not bash one-liners?

### From `/library-first`
- Existing solution registry check before generating code
- Standard library function check
- Codebase pattern reuse check
- "Why new instead of reuse?" justification

### From `/investigate`
- Absence claims verified before stating (see verification_tiers.md Absence Claim Protocol)
- Git history verification before claiming "was never implemented"
- Evidence-gathering methodology (TSK folders, alt locations)

## Boundaries

`/r` does NOT own:
- Exploratory multi-option strategy (`/s`)
- Promotion gates (`/p*`)
