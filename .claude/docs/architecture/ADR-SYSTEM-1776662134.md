# ADR-20260420: Batch Query + Citation Granularity for QMD Wiki Backend

## Status
Proposed

## Context
The QMD Wiki backend (search-research/core/backends/local/qmd_wiki_backend.py) supports single-query search only. The transcript comparison showed NotebookLM handling 10 parallel questions in ~1 minute vs single-query-then-wait for LLM Wiki. Additionally, SearchResult has no positional citation — the fallback grep discards line/byte offsets entirely, making it impossible to trace a result back to the exact source segment.

## Decision
Add batch query support and citation granularity to QMDWikiBackend.

### Change 1: search_batch_async

Add a new public method to QMDWikiBackend:

```python
async def search_batch_async(
    self, queries: list[str], limit: int = 10
) -> list[SearchResult]:
```

**Behavior:**
- Runs each query via `asyncio.gather` with the existing `search_async` path
- Aggregates results, deduplicates by file_path (first-seen score wins)
- Returns flat list sorted by descending score
- Timeout per-query: same TIMEOUT (0.5s) with individual timeout tracking
- Circuit breaker cooldown applies per-query independently (shared `_rebuild_cooldown_until`)
- **Degrade path:** If `asyncio.gather` would exceed 5s total, fall back to sequential loop with reduced timeout per query

**Rationale:** Low effort (shares existing subprocess infrastructure), high return (closes main friction from transcript). Parallel via gather is the minimal pattern for this.

### Change 2: cite_ref field on SearchResult

Add `cite_ref: str | None` to the `SearchResult` dataclass (or document it as an optional annotation if the model is external).

**For fallback grep path:**
- `_fallback_grep` tracks match line numbers per file using a simple enumerate loop
- `cite_ref` = `f"{md_file}:{line_number}"` (e.g. `ray-dalio-decisions.md:142`)
- Snippet extracted as `content[byte_offset:byte_offset+200]` with byte capture, not just first 200 chars

**For qmd direct path:**
- `_parse_qmd_json` currently discards positional info from qmd JSON output
- qmd search returns `file`, `snippet`, `score`, `title` — no line offset
- **Verification needed:** Check if qmd search output includes line numbers or byte offsets; if not, `cite_ref` stays `None` for the direct path and line-number capture is fallback-only

### Change 3: Refactor _fallback_grep for byte+line capture

Replace the simple `query_lower in content.lower()` scan with:

```python
query_lower = query.lower()
with open(md_file, "rb") as f:
    content_bytes = f.read(MAX_FILE_READ)
content = content_bytes.decode("utf-8", errors="replace")
lines = content.split("\n")
for line_num, line in enumerate(lines, start=1):
    if query_lower in line.lower():
        byte_off = sum(len(l) + 1 for l in lines[:line_num - 1])
        snippet = content[byte_off:byte_off + 200]
        cite_ref = f"{md_file.name}:{line_num}"
```

**Performance note:** Splitting all lines per file is O(n) where n = file length. Acceptable since MAX_FILE_READ = 1MB and fallback only triggers when qmd is unavailable.

## Consequences
- **Positive:** Batch query enables parallel question submission; cite_ref enables precise source tracing in fallback path
- **Negative:** Line-split loop adds ~10-15% latency to fallback grep (acceptable — fallback is already the slow path)
- **Risk:** SearchResult model may live in search-research/models.py (external to this package) — cite_ref must be added as optional field to avoid breaking existing consumers. Verified via code inspection before implementation.
- **Rollback:** Batch feature behind a flag or new method name (not modifying search_async signature) — safe to revert without affecting existing callers.

   - `test_fallback_grep_cite_ref`: known file + known query → cite_ref matches line number of match

## Alternatives Considered
- **Parallel queries via ThreadPoolExecutor in sync context** — rejected; asyncio.gather is cleaner and already used in the codebase
- **Pre-compute concept index at query time (on-demand extraction)** — deferred; architectural change to index/query boundary, not needed to close the batch gap
- **Add cite_ref to qmd path by patching qmd CLI output** — not feasible; qmd is an external tool, we parse its output
