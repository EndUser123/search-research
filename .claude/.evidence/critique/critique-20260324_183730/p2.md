## Cross-Agent Contradictions
1. **Severity calibration for the same underlying issue is inconsistent.** IO-001 (AttributeError on non-string message) and IO-002 (TypeError on unhashable message) are rated BLOCKER by io-validation, but TEST-001 (severity case mismatch causing ALL batches to report LOW severity) is only HIGH — despite being far more impactful in practice. Every single batched finding in RSN output is wrong when it could be triggered. IO-001/IO-002 require malformed input (None message); TEST-001 triggers on normal GTO output with properly-formed Gap dicts.

2. **IO-003 (arbitrary effort multipliers) is BLOCKER but TEST-002 (no test coverage) is only HIGH.** The lack of tests is what allows IO-003's arbitrary constants to go unquestioned. If tests existed, the multiplier values could be validated against real effort data.

3. **adversarial-logic identified LOGIC-001 (double-truncation collision) but adversarial-quality found the same root cause as QUAL-002 (reason split on dot losing attr name) without flagging the collision consequence.** They analyzed the same code differently.

## Severity Calibration Issues
1. **BLOCKER vs HIGH inconsistency:** IO-001/IO-002 (malformed-input crashes) rated BLOCKER; TEST-001 (systematic wrong output on valid input) rated HIGH. The more impactful bug (TEST-001) affects every run, not just edge-case input.

2. **IO-004 (sys.path mutation) rated LOW despite being a multi-terminal correctness hazard.** The fix is well-known (importlib.util.spec_from_file_location) and the risk is real — but it's correctly low because the try/except import works in practice.

3. **TEST-004 (partial overlap silently drops gaps) is MEDIUM.** This is silent data loss — no crash, but gaps disappear. Given that TEST-001 is HIGH for a visible wrong-output bug, TEST-004's silent nature should arguably be HIGH too.

## Missed Blind Spots
1. **No specialist checked whether RSN-formatted output from _detect_batch_groups is validated before passing to RSNFormatter.** The function produces a specific schema (id, severity, message, file_ref, action_type, effort_minutes, domain, is_batch, batch_count, gap_ids) but there's no schema validation. Malformed output silently passes through.

2. **severity_order dict is defined twice in two loops (lines 388 and 445) but no specialist flagged this as a quality/maintenance issue.** Duplicate definitions make future changes easy to miss in one location. This is both a quality issue and a minor performance issue (dict recreated on every batch group).

3. **The three strategies interact through used_indices but no specialist verified the strategy priority is correct.** A gap matching both Strategy 1 and Strategy 2 criteria is claimed entirely by Strategy 1. No specialist asked: is location-based batching actually higher priority than reason-based batching? The open question from LOGIC is unresolved.

4. **format_rsn_from_gaps() has no error handling.** If _detect_batch_groups() throws for any reason, the entire RSN generation crashes with no graceful degradation. IO-001 and IO-002 could both cause this. No specialist flagged the absence of try/except around the call chain.

5. **The GTO batch detection was verified working in the session that implemented it, but the verification was manual (stdout inspection).** No specialist noted this as evidence that the happy path works — but also no specialist noted the verification was insufficient (no automated test).

## Precision Failures
1. **IO-004 (sys.path mutation) overstates the risk.** The actual risk is theoretical — the try/except import path is a one-time mutation at import time, and the fallback is well-established. In practice, all GTO sessions import this module once and the path resolves correctly. Rated LOW correctly.

2. **QUAL-004 (Windows path colon ambiguity) is MEDIUM but the practical impact is low.** The batch ID is primarily for display and traceability. No downstream code parses these IDs. The real impact is cosmetic in RSN output, not a functional breakage.

3. **IO-003 (arbitrary multipliers) is BLOCKER but the actual consequence is misleading effort estimates, not crashes.** Blocking is appropriate for "arbitrary without upper bound" but the framing overstates runtime risk.

## Improvements to the Phase 1 Findings
1. TEST-001 severity should be elevated to BLOCKER or at minimum acknowledged as more impactful than IO-001/IO-002 given trigger probability.
2. Add finding: format_rsn_from_gaps() lacks try/except error containment — unhandled exceptions propagate to RSN rendering.
3. Add finding: severity_order dict defined twice (lines 388, 445) — maintenance hazard, should be module-level constant.
4. The open questions about Strategy 1/2 priority and multiplier empirical basis should be promoted from open questions to recommendations (add named constants with justification, document strategy priority).
