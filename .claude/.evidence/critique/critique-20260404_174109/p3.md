# Critique: /rns Skill (v1.1.0)

## Intent Summary

The /rns skill converts unstructured LLM output into structured Recommended Next Steps with selectable actions, using a dynamic-domain flat-numbered format with recover/prevent/realize action tags, priority, effort, reversibility, and file:line citations. The skill was created via /skill-ship and linted by the user to v1.1.0 which added the action/reversibility tags. The skill is scoped as a procedure skill with session persistence and strict enforcement.

## Logical Gaps & Inconsistencies

1.1. [HIGH] Reversibility field `[R:1.5]` appears in the self-reference example but has no definition in the Step 2 classification table. The table defines domain, action, priority, and effort — reversibility is absent. This is a specification gap that makes the format unresolvable from documentation alone. (source: adversarial-compliance, SKILL.md:98-104 vs self-rns-example.md:21)

1.2. [MEDIUM] Item format specification mismatch. The Format Rules table (SKILL.md:63) specifies `[action/priority] ID Description @ file:line` — a single bracketed `[action/priority]` segment. The self-reference example shows effort and reversibility as separate bracketed fields that precede the ID: `QUAL-001 [~10min] [R:1.5] Description (file)`. These are structurally incompatible formats. (source: adversarial-compliance, adversarial-critic, SKILL.md:63 vs self-rns-example.md:21)

1.3. [MEDIUM] Self-reference example uses parentheses for file references `(test_critique_io_concurrent.py)`, but the Format Rules table specifies `@ file:line` suffix notation. Two different file reference formats are used across the same document. (source: adversarial-compliance, SKILL.md:64 vs self-rns-example.md:21)

1.4. [LOW] Effort value `[~10min]` in the self-example is not in the defined scale. Step 2 defines the effort scale as ~2min, ~5min, ~15min, ~30min, ~1hr. ~10min is absent from both the scale and the effort notation (the scale uses bare `~2min` without brackets). (source: adversarial-compliance, SKILL.md:104 vs self-rns-example.md:21)

1.5. [LOW] "0 — Do ALL" directive uses N in some locations and an exact number in others. SKILL.md:65 shows the rendered example with `(3 items)` while the format rules section at :130 uses `(N items)`. No functional impact but the inconsistency undermines format precision. (source: adversarial-critic, SKILL.md:65 vs :130)

1.6. [LOW] Dependency notation inconsistency. SKILL.md:108 defines `[caused-by: ID]` (singular) but :109 shows `[causes: ID]` (plural) in the example. The exact notation format is ambiguous. (source: adversarial-critic, SKILL.md:108-109)

## Hidden Assumptions & Fragile Dependencies

2.1. [MEDIUM] `enforcement: strict` is factually incorrect. The skill declares strict enforcement but the lib/ directory is empty — no programmatic validation exists. The skill relies entirely on LLM self-enforcement of documented format rules. This is not strict enforcement; it is social enforcement with mislabeled frontmatter. The correct frontmatter value is either `enforcement: advisory` (if format is enforced by convention) or `enforcement: social` (if format relies on LLM compliance). (source: adversarial-quality, Phase 2 meta-critique, SKILL.md:13, lib/)

2.2. [MEDIUM] No error handling specification. The skill defines no behavior for: empty input, no extractable findings, missing file references, or unresolved dependency IDs. Users receive undefined behavior — empty output, silent skips, or crashes depending on LLM interpretation. (source: adversarial-critic, SKILL.md:144-149)

2.3. [LOW] "Last LLM output" undefined after context compaction. Step 1 instructs reading "the last assistant message in the conversation transcript" but provides no definition of message boundaries after context compaction or conversation splicing. (source: adversarial-critic, SKILL.md:82)

2.4. [LOW] `supports_multiple: true` semantics undefined. The frontmatter flag declares support for multiple findings but specifies neither what "multiple" refers to (per-turn, per-session, per-domain) nor how simultaneous invocations should be merged or deduplicated. (source: adversarial-critic, adversarial-quality, SKILL.md:12)

## Missing Obvious Actions / Best Practices

3.1. [MEDIUM] Self-reference example is the skill's primary teaching artifact and it fails its own specification in 6 distinct ways. It uses effort/reversibility fields not in the spec, parentheses instead of @ suffix, ~10min not in the defined scale, and skips an input item from its own "before" section. A reference implementation that doesn't match its own spec undermines format credibility. (source: adversarial-critic, Phase 2 meta-critique, self-rns-example.md)

3.2. [MEDIUM] No test coverage exists for the RNS format. No lib/ implementation means no programmatic validation of compliance. Format violations will only be caught manually, not by CI. (source: adversarial-quality, SKILL.md, lib/)

3.3. [LOW] The self-example cites `test_critique_io_concurrent.py` without file existence verification. SKILL.md:146 explicitly forbids fabricating file paths, yet the example does exactly that. (source: adversarial-critic, SKILL.md:146 vs self-rns-example.md)

## Risks and Edge Cases

4.1. [MEDIUM] Format drift risk. The self-example uses fields and notations that are not in the specification. Without programmatic validation, future changes to either the spec or the example will propagate inconsistencies silently.

4.2. [LOW] Edge case: empty input produces undefined output. No specification of what RNS should return when no findings can be extracted.

4.3. [LOW] Concurrent invocation: no merge strategy specified when multiple RNS calls reference overlapping content. Duplicate findings or conflicting priorities could result.

## Concrete Recommendations

5.1. [MEDIUM] Add reversibility to the Step 2 classification table, or remove `[R:1.5]` from the self-example. This is the most actionable single fix — the v1.1.0 user lint added reversibility as a field but didn't update the Step 2 table to define it. (SKILL.md:98-104, self-rns-example.md:21)

5.2. [MEDIUM] Align the Format Rules table with actual output format. The table claims `[action/priority] ID @ file:line` but the actual output uses `[effort] [R:reversibility] ID Description (file)`. Either update the table or update the example. (SKILL.md:63, self-rns-example.md:21)

5.3. [MEDIUM] Fix `enforcement: strict` — either implement lib/rns_formatter.py for programmatic enforcement, or change frontmatter to `enforcement: advisory`. A skill cannot claim strict enforcement of a format through documentation alone. (SKILL.md:13, lib/)

5.4. [MEDIUM] Add error handling section to SKILL.md. Define: empty input returns empty RNS with a message, missing file references are logged as warnings, unresolved dependencies reported as orphaned items. (SKILL.md)

5.5. [LOW] Fix effort value in example: change `[~10min]` to `[~15min]` or add `~10min` to the Step 2 effort scale. (self-rns-example.md:21, SKILL.md:104)

5.6. [LOW] Standardize self-rns-example.md file references: use `@ filename:line` suffix instead of parentheses throughout. (self-rns-example.md, SKILL.md:64)

5.7. [LOW] Standardize "0 — Do ALL" to always use N: `0 — Do ALL Recommended Next Steps (N items)`. (SKILL.md:65, :130)

5.8. [LOW] Clarify dependency notation: pick singular `[caused-by: ID]` or plural `[causes: ID]` and use consistently in both definition and example. (SKILL.md:108-109)

5.9. [LOW] Define "last LLM output" as the most recent complete assistant message, or explicitly request user confirmation after context compaction. (SKILL.md:82)

5.10. [LOW] Specify merge strategy for simultaneous multiple invocations: deduplicate by (description_hash, domain, action), use highest priority on conflicts. (SKILL.md:12, Phase 2 meta-critique)

## Open Questions / Unknowns

6.2. [LOW] Should self-rns-example.md serve as a test corpus once a lib/ implementation exists? The example was designed as a reference but currently fails its own specification. (source: adversarial-quality)
