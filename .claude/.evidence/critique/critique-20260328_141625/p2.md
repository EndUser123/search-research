## Missed Blind Spots

### 1. No specialist addressed the "publishedAfter cursor ceiling" edge case at the implementation level
META-005 (adversarial-critic) describes the algorithm ceiling problem — if newest downloaded video is actually the most recent, the cursor fetches from that point and finds no overlap, then sets cursor to oldest fetched (which may be older than gap boundary). The specialist recommends a max-iterations cap. But no specialist asked: **what happens if the channel has fewer videos than the gap implies?** If channel has 20 total videos and newest is 3 months old, API with `publishedAfter=cursor` returns all 20, no overlap, cursor moves to oldest... and the loop terminates because we've fetched everything. The max-iterations cap is correct but no specialist analyzed what happens when the gap is *larger* than the channel.

### 2. No specialist addressed API key validity / malformed response handling
All quota discussion assumes the API key is valid. What if:
- API key is revoked or malformed? (403 error)
- API returns 503 Service Unavailable?
- API returns a response with 0 items but valid nextPageToken?

The algorithm at lines 129-148 has no error handling — it assumes API calls always return either results or a terminal condition. No specialist evaluated this.

### 3. No specialist addressed Phase 1 rollback / backward compatibility
If Phase 1 is implemented and breaks the existing ingest pipeline (e.g., `analyze_videos_parallel()` has different error semantics than the sequential subprocess loop), there is no rollback plan. The ADR treats Phase 1 as purely additive. No specialist asked "what if this makes things worse?"

### 4. No specialist addressed the transcript cache staleness question
META-018 (adversarial-critic) notes that cached transcripts are "always valid" assumption is unstated. But the deeper question is: **if a transcript was cached 6 months ago, is it still accurate for a video that may have been updated?** YouTube videos can have transcripts edited. No specialist raised this as a validity concern.

### 5. No specialist evaluated the test matrix adequacy
The ADR test matrix (lines 219-226) has tests for source attribution, ingest batch integration, API enumeration, yt-dlp fallback, RSS, and transcript cache. But there is:
- No test for concurrent `csf-source check` on the same channel (TOCTOU)
- No test for quota exhaustion behavior
- No test for gap detection with a channel that has zero new videos
- No test for `channel_metadata` CRUD operations

The test matrix was reviewed but not evaluated for completeness by either specialist.

### 6. Recall failure — `_get_batch_status_storage()` process boundary misunderstanding risk
Both specialists confirmed WAL mode is correct for multi-process safety. But neither specialist identified the risk that `batch_status.py`'s module-level singleton means **each terminal's Python process has its own connection pool**. If one terminal updates `batch_status` and another reads it within the same second, they see each other's writes because SQLite WAL propagates between processes. But if `csf-ingest` and `csf-batch` are launched as separate subprocesses from the same parent, they may not share the WAL lock timing. This is subtle but not caught.

## Precision Failures (Over-Criticism)

### 1. META-004 "infinite loop" framing is overstated
The adversarial-critic describes "infinite loop potential" for gap resolution when channels have irregular upload patterns. This is technically imprecise:
- YouTube has a hard ceiling of ~5 million videos per channel
- At 50 videos per API call, worst case is 100,000 API calls — not infinite
- The real risk is *excessive* API calls (quota exhaustion), not infinite looping

**Verdict:** The concern is valid (excessive API usage) but "infinite loop" is precision failure. Should be "unbounded quota consumption."

### 2. META-018 "always-valid transcript" framing may be a non-issue
The adversarial-critic raises "what if cached transcript is stale?" — but YouTube transcripts are generally immutable once published. Very few videos have their transcripts edited post-upload. This may be theoretical risk, not practical concern. A transcript freshness timestamp (`cached_at`) is nice-to-have, not critical.

### 3. META-010 "10x faster" without measurement — reasonable design estimate
The ~10x API performance claim has no measurement, but for **initial import** (not gap detection), this is architecturally sound:
- yt-dlp must download and parse `.info.json` for every video
- API returns structured data directly
- The magnitude estimate is defensible without a benchmark

**Verdict:** Should be reworded from "~10x faster" to "expected ~10x for initial import based on architecture" — still a concern, but not the confidence overreach the finding implies.

### 4. META-016 ISO 25010 applied inconsistently — vague finding
The finding that "ISO 25010 attributes applied inconsistently" is true but not very actionable. The ADR uses ISO 25010 as a qualitative framing aid, not a rigorous scoring system. Calling this a "LOW quality" calibration issue (35/100) seems disproportionate to the actual impact.

## Improvements to the Phase 1 Findings

1. **Separate idempotency contradiction (META-015) from source column migration (adversarial-compliance §4):** These are two distinct issues. META-015 belongs in the HIGH bucket for logical contradiction; the migration concern belongs in MEDIUM for Phase 1 completeness.

2. **Reframe META-004 from "infinite loop" to "unbounded quota consumption":** More precise description of the actual risk.

3. **Add a "what both specialists agreed on" section:** Both flagged the transcript cache API problem. Both flagged the 7-day threshold. A consensus section would clarify what is undeniable vs what is interpretive.

4. **Distinguish recall failures by specialist focus area:** The adversarial-compliance specialist reviewed for spec/code alignment (narrow, deep). The adversarial-critic reviewed for reasoning quality (broad, architectural). The recall failures from each are in different domains — this should be explicit rather than merged.

5. **The "CRITICAL" rating for META-004 vs no mention in compliance is a scope issue, not a calibration failure:** The Phase 1 findings should note that META-004 is outside the compliance specialist's review scope, not a missed finding.
