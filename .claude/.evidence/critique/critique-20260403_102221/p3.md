# /critique Self-Review — Final Critique

## Intent Summary

/critique is an adaptive adversarial review skill that dispatches specialist subagents in three phases: initial triage and parallel specialist analysis, cross-agent meta-critique, and final synthesis. The multi-terminal isolation fix redirected specialist outputs from a global directory to a session-scoped `specialists/` subdirectory. This review evaluates whether that fix is complete and surfaces residual risks in session recovery and Phase 2 orchestration.

## Logical Gaps & Inconsistencies

1.1. [HIGH] Session recovery does not refresh `last_used` — recovered sessions keep their original registry timestamp. When `cleanup_old_sessions` runs, it may remove an actively-used session if its `last_used` has aged past the cutoff. `lib/critique_io.py:224` — recovery returns without calling `_save_registry()`.

1.2. [HIGH] Phase 2 has no guard for zero specialist files — `p2_meta_critique.md` line 17 instructs reading `specialists/*.json` with no prior existence check. If Phase 1 dispatched zero specialists, Phase 2 silently operates on empty input. This is the unaddressed kill criterion from the pre-mortem. `phases/p2_meta_critique.md:17`

1.3. [HIGH] Phase 1 completion is never validated before Phase 2 — SKILL.md Step 4 says "wait for specialist agents to complete" but never defines what completion means. No check verifies that at least one specialist JSON exists before the orchestrator proceeds to Phase 2. The gap between "Phase 1 ran" and "Phase 1 produced valid output" is unguarded.

1.4. [HIGH] Session recovery only checks work.md and p1_findings.md existence, not p2.md or p3.md. If a session was interrupted after Phase 1 but before Phase 2 started, the orchestrator would receive a session with `p1_findings.md` present but `p2.md` absent, and Phase 2 would try to read a file that doesn't exist. `lib/critique_io.py:200-207`

## Hidden Assumptions & Fragile Dependencies

2.1. [MEDIUM] Stale-entry vs incompatible-session distinction — `find_or_create_session` conflates two scenarios: (a) registry entry points to a deleted/moved session dir (stale, should clean up and create new), and (b) registry entry points to a session that exists but lacks `specialists/` (pre-fix, raises RuntimeError). Case (a) is silently handled by the `is_safe and session_dir.exists()` check. Case (b) throws. The distinction matters: a stale entry with a valid session_dir path that somehow lost its `specialists/` dir would trigger the RuntimeError instead of recovery. `lib/critique_io.py:213`

2.2. [MEDIUM] Phase 1 dispatches are fire-and-forget — the orchestrator launches Task agents in parallel and waits, but does not track which specialists were actually dispatched or whether they produced output. If the Task dispatch silently fails (e.g., the agent crashes without output), Phase 1 would report completion with zero specialist files. `SKILL.md:64-78`

2.3. [MEDIUM] GTO skill coverage logging is best-effort but provides no failure signal — the bare `except (ImportError, AttributeError)` at line 317 silently swallows all exceptions, including API changes, import errors, and programming errors. If skill coverage logging fails every time, there is no observable indicator. `lib/critique_io.py:317`

## Missing Obvious Actions / Best Practices

3.1. [HIGH] Add explicit Phase 1 completion criteria to SKILL.md — define what "Phase 1 is complete" means: at least one specialist JSON exists in `specialists/` AND `p1_findings.md` exists. Without this, Phase 2 has no reliable signal to gate on. `SKILL.md:64-78`

3.2. [MEDIUM] Call `_save_registry()` before returning recovered instance — this single line refreshes `last_used` on every recovery, preventing active sessions from being incorrectly cleaned up. `lib/critique_io.py:224` — add `instance._save_registry()` before `return instance`.

3.3. [MEDIUM] Add Phase 2/3 filename round-trip tests — `test_critique_io.py` covers Phase 1 file paths but not Phase 2 (p2.md) or Phase 3 (p3.md) round-trips. A future refactor changing those filenames would not be caught. `tests/test_critique_io.py:1`

3.4. [MEDIUM] Add zero-specialist explicit failure to `p2_meta_critique.md` — before reading specialist JSONs, check that at least one exists. If zero, write `p2.md` with a calibration failure note and exit Phase 2 early. `phases/p2_meta_critique.md:17`

## Risks and Edge Cases

4.1. [MEDIUM] Windows path traversal check uses `startswith` + `Path("/")` — while not exploitable in practice (Path.resolve() normalizes separators on Windows), the pattern is confusing and fragile to maintain. Use `is_relative_to()` (Python 3.9+) for clarity. `lib/critique_io.py:486`

4.2. [MEDIUM] WORK_INPUT with spaces or special characters may fail the SKILL.md Step 2 shell invocation on Windows — the inline python command uses `sys.argv[1]` with shell quoting that varies across shells and platforms. `SKILL.md:87-97`

4.3. [LOW] `get_recent_sessions` lexical sort without explicit key — functionally correct (directory names start with `critique-YYYYMMDD_HHMMSS`, lexical reverse sort equals chronological reverse), but non-obvious. Use explicit `key=lambda d: d.name` to make intent clear. `lib/critique_io.py:404`
