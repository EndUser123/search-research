# Phase 3 Final Synthesis: Cleanup Prevention Enhancement Plan

## Intent Summary

The plan aims to shift filesystem violation detection from reactive (cleanup after accumulation) to preventive (write-time blocking) by adding a PreToolUse type validator hook, session debris patterns to policy, and a cleanup feedback loop. The approach is sound: intercepting violations at write-time is more effective than detecting them post-hoc. However, the plan has critical schema and procedural gaps that block implementation of the two most complex tasks (TASK-002 and TASK-004).

## Hidden Assumptions & Fragile Dependencies

**[HIGH] Assumption 1**: `acquire_cleanup_lock()` exists in cleanup.py and is accessible
- **Evidence**: TASK-004 says "wrap writes in `acquire_cleanup_lock()`" but plan never imports or defines this function
- **Risk**: TASK-004 may fail at runtime if function doesn't exist or has different signature
- **Mitigation**: Verify function exists and has correct signature before implementing TASK-004

**[HIGH] Assumption 2**: Implementer knows PreToolUse hook registration pattern
- **Evidence**: TASK-002 says "Register in PreToolUse.py" but provides no registration steps
- **Risk**: Hook may be created but never invoked (silent failure at write-time)
- **Mitigation**: Add explicit registration steps to plan

**[MEDIUM] Assumption 3**: `directory_policy.json` ai_generated_patterns schema is inferable
- **Evidence**: TASK-003 shows example JSON but schema is not explicitly documented
- **Risk**: Implementation may miss validation rules, causing runtime errors
- **Mitigation**: Add explicit schema definition to plan

**[MEDIUM] Assumption 4**: Windows Path.suffix behavior for double-extension files
- **Evidence**: Plan says "check Path.suffix AND all path components" but Windows Path.suffix returns `.txt` not `.py` for `malware.py.txt`
- **Risk**: Double-extension detection may not work on Windows
- **Mitigation**: Clarify detection algorithm

**[LOW] Assumption 5**: 3 occurrences is the right threshold for feedback loop
- **Evidence**: Threshold is stated as invariant but not justified
- **Risk**: Feedback may be too noisy or too conservative
- **Mitigation**: Make threshold configurable or justify empirically
