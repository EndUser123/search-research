Adding a daemon-independent semantic chain strategy to `session_chain.py` via a SentenceTransformer direct fallback, with a 5-minute TTL cache to manage memory, and tuning the similarity threshold from 0.7 to 0.5 based on empirical validation against real session text.

## Logical Gaps & Inconsistencies

1.1. **[HIGH]** Threshold docstring mismatch: docstring says `0.7`, function signature is `0.5` (`session_chain.py:483` vs `:471`)

1.2. **[HIGH]** `get_embed_client()` uses `auto_start=False, enable_fallback=False` — daemon never auto-starts when semantic chain runs. The SentenceTransformer fallback was added as the workaround, but the intended architecture (daemon) is disabled by misconfiguration (`core/chs/embeddings.py:194`)

1.3. **[HIGH]** `window_days` filter (default 7) silently excludes sessions beyond ±7 days — no test, no warning. A session from 2 weeks ago on the same topic will not appear in semantic chain results

1.4. **[HIGH]** Duplicate functions across modules: `_find_handoff_referencing` and `_get_prior_transcript_path` exist in both `session_chain.py` and `handoff_chain.py`. If a caller imports from the wrong module after future PreCompact fixes, chain traversal silently breaks

1.5. **[MEDIUM]** `newest_first=True` reversal of semantic results (line 653) reverses similarity ordering, giving worst-match-first — semantically wrong for semantic chain. The reversal is mechanically applied but produces misleading output

## Hidden Assumptions & Fragile Dependencies

2.1. **[MEDIUM]** Windows `st_ctime` used as session birth fallback (line 339-341) — `st_ctime` on Windows changes on metadata modification, not file creation. Sessions without `createdAt` may be ordered incorrectly in sessions-index chain on Windows

2.2. **[MEDIUM]** `_st_model` and `_st_model_last_used` are module-level globals without thread-safety. Two threads racing through `_get_st_model()` could delete a model while another thread is encoding with it. Currently safe in single-threaded Claude Code use, but fragile if the module is ever called from hooks/agents

2.3. **[MEDIUM]** `EmbedClient` uses `enable_fallback=False` — if the daemon returns any response (even malformed), it won't fall back. Only explicit exceptions trigger the SentenceTransformer path. A malfunctioning daemon returning garbage would bypass the fallback

## Missing Obvious Actions / Best Practices

3.1. **[HIGH]** Strategy 3 (semantic chain) has zero test coverage — `_session_text`, `walk_semantic_chain`, `_cosine_sim`, `_get_st_model` completely untested. This is the only working chain strategy for all post-March 19 2026 sessions

3.2. **[HIGH]** `_get_st_model` TTL eviction has zero test coverage — no test verifies the 5-minute eviction actually fires, or that a reload after eviction works correctly

3.3. **[HIGH]** No integration test for `walk_session_chain` unified entry point — only a single "unknown session returns empty" test exists. The 3-strategy fallback logic, strategy selection, and `newest_first` reversal are all untested

3.4. **[HIGH]** `EmbedClient→SentenceTransformer` fallback path not tested — near-zero detection (`norm < 0.01`) and the exception catch are exercised by integration but not by unit tests

3.5. **[HIGH]** `_session_text` edge cases untested — all fields empty returns `""`, goal precedence over lastPrompt, active_files truncation at 10 items

## Risks and Edge Cases

4.1. **[MEDIUM]** Bare `except Exception` at lines 548, 556, 558 — catches KeyboardInterrupt, SystemExit, and programming errors silently. If `model.encode()` raises `AttributeError` because `_st_model` was concurrently deleted, the chain returns empty results with no error signal

4.2. **[MEDIUM]** `walk_semantic_chain` has no limit on returned entries — all candidates above threshold are returned. With `threshold=0.5` and 585 rich sessions, a popular topic could return 100+ entries. No pagination or cap

4.3. **[MEDIUM]** `st_birthtime` check at line 338 uses `hasattr(stat_result, 'st_birthtime')` — on Python 3.12+ Windows, `st_birthtime` may exist but return 0 for files copied between filesystems, producing epoch-1970 timestamps

4.4. **[LOW]** `normalize_embeddings=True` in SentenceTransformer call means cosine similarity = dot product. But the cosine similarity formula in `_cosine_sim` still divides by norms — for normalized vectors this is mathematically redundant but not wrong
