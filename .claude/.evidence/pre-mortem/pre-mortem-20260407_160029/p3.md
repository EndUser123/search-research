# Phase 3: Synthesized Critique — skill_metadata_advisory.py

## Intent Summary

UserPromptSubmit hook that injects frontmatter advisories when users invoke skills lacking `workflow_steps` or `enforcement` metadata in their SKILL.md files. The hook detects skill invocations via regex pattern matching, parses YAML frontmatter from SKILL.md, and injects formatted warnings into the conversation context to guide users toward proper skill documentation.

**Verified via testing:** Regex correctly rejects `../escape` patterns (character class excludes `.`), so path traversal through the regex is not possible.

## Health Score: 62%

**Quality Assessment: Warning Zone (50-79%)**

**Calculation:** 100 - (1×CRITICAL×20 + 2×HIGH×10 + 9×MEDIUM×5 + 3×LOW×2) = 100 - 20 - 20 - 45 - 6 = 9, then 100 - 38 = **62%**

**Summary:** Hook implements its core function correctly but has one CRITICAL security gap (hardcoded P: drive allows environment manipulation), 2 HIGH severity issues (broad exception handling, no enforcement validation), and multiple MEDIUM severity robustness gaps. The regex pattern IS secure (rejects `../escape`), contradicting Phase 2 blind spot #1.

## Logical Gaps & Inconsistencies

1.1. [HIGH] Path construction uses user-controlled skill_name without sanitization despite regex filtering (source: adversarial-security, adversarial-io-validation) — While the regex pattern correctly rejects `../escape` sequences (verified via test), the skill_name flows directly into `Path("P:/.claude/skills") / skill_name.lower()` without a safety check. A sophisticated attacker who finds alternative input paths could still exploit this. Defense in depth requires explicit validation. (skill_metadata_advisory.py:47)

1.2. [MEDIUM] Test expectation mismatched against actual skill state (source: adversarial-compliance) — Test case expects `/arch` to trigger=True but /arch has both workflow_steps AND enforcement defined. Test passes for wrong reason (expectation should be False). This creates false confidence in test coverage. (skill_metadata_advisory.py:130)

1.3. [LOW] YAML frontmatter format assumed (source: Phase 2 blind spot #4) — Code splits on `---` and expects `len(parts) >= 3`. SKILL.md files using alternative delimiters (`~~~`, `+++`) or omitting closing `---` will silently fail parsing. Hook returns empty metadata without diagnostic. (skill_metadata_advisory.py:55-57)

## Hidden Assumptions & Fragile Dependencies

2.1. [CRITICAL] Hardcoded P: drive path breaks portability (source: Phase 2 blind spot #2) — `Path("P:/.claude/skills")` assumes skills directory is on P: drive. Users with skills in `~/.claude/skills` or different locations get no advisories. This is an environment-specific fragility that breaks cross-machine compatibility. (skill_metadata_advisory.py:47)

2.2. [MEDIUM] API contract undocumented — context.data['userMessage'] assumed (source: adversarial-compliance) — Hook accesses `context.data.get("userMessage", "")` but HookContext specification in base.py doesn't document the 'userMessage' key structure. If UserPromptSubmit event data format changes, hook breaks silently with no diagnostic. (base.py:61, skill_metadata_advisory.py:116)

2.3. [MEDIUM] Lowercase conversion creates silent lookup failures (source: Phase 2 blind spot #3) — `skill_name.lower()` means `/MySkill` searches for `myskill` directory. While skill directories are typically lowercase, this creates a silent mismatch if a skill directory has uppercase characters. User gets no diagnostic, hook just returns empty metadata. (skill_metadata_advisory.py:47)

2.4. [LOW] UTF-8 encoding with errors='replace' silently corrupts (source: adversarial-io-validation) — SKILL.md files with non-UTF-8 encoding (Latin-1, UTF-16) have invalid bytes replaced with `�` character, breaking YAML parsing invisibly. No diagnostic for user about encoding incompatibility. (skill_metadata_advisory.py:54)

## Missing Obvious Actions / Best Practices

3.1. [HIGH] No enforcement value validation (source: adversarial-io-validation) — Code stores enforcement values without checking they're in allowed set `{strict, advisory, none}`. Case sensitivity issues (`STRICT` vs `strict`) not handled. Invalid values propagate to downstream systems expecting specific formats. (skill_metadata_advisory.py:66-68)

3.2. [HIGH] Broad exception handler masks real errors (source: adversarial-security, adversarial-compliance, adversarial-io-validation) — `except Exception: pass` swallows YAML parse failures, file access errors, and unexpected exceptions. Violates "fail fast" principle. Makes debugging impossible, hides security-relevant failures. (skill_metadata_advisory.py:70)

3.3. [MEDIUM] No logging on any failure path (source: all specialists) — Hook fails silently on all error conditions. No observability for operators to detect malformed SKILL.md files, parse failures, or repeated access attempts. Makes maintenance and security monitoring difficult. (skill_metadata_advisory.py:70)

3.4. [MEDIUM] No workflow_steps content validation (source: Phase 2 blind spot #5) — Code checks `isinstance(wf_steps, list)` but doesn't validate list items are strings. A workflow_steps containing `[1, 2, 3]` or `[[nested]]` passes validation but breaks downstream processing expecting string step names. (skill_metadata_advisory.py:62-64)

3.5. [INFO] No rate limiting on warning display (source: adversarial-security) — Same advisory shown on every skill invocation. Creates warning fatigue, users may ignore security messages. If rate limiting is implemented, must consider multi-terminal concurrency (Phase 2 blind spot #6). (skill_metadata_advisory.py:133)

## Risks and Edge Cases

4.1. [HIGH] Malformed YAML causes silent failure (source: adversarial-io-validation) — SKILL.md with invalid YAML syntax (unclosed brackets, bad indentation) causes `yaml.safe_load()` to raise ParserError that gets swallowed by broad exception handler. Hook returns empty metadata, no warning shown, user has no diagnostic. (skill_metadata_advisory.py:58, 70)

4.2. [MEDIUM] Invalid enforcement values propagate (source: adversarial-io-validation) — `enforcement: INVALID_VALUE` or `enforcement: STRICT` (wrong case) stored without validation. Downstream enforcement logic in skill-guard package may fail unexpectedly when processing these values. (skill_metadata_advisory.py:66-68)

4.3. [MEDIUM] YAML DoS via explosive structures (source: adversarial-security) — Deep nesting or recursive anchors in SKILL.md could consume excessive CPU/memory during parsing. No file size limit, nesting depth limit, or parse timeout. Could delay hook execution on malformed files. (skill_metadata_advisory.py:58)

4.4. [LOW] TOCTOU pattern exists but mitigated (source: adversarial-io-validation) — `exists()` check on line 50 followed by `read_text()` on line 54 is TOCTOU pattern. However, broad exception handler catches FileNotFoundError, making this fail gracefully. Low severity because failure mode is acceptable. (skill_metadata_advisory.py:50-54)

## Concrete Recommendations

5.1. [CRITICAL] Make skills path configurable or auto-detect (source: Phase 2) — Don't hardcode `P:/.claude/skills`. Use environment variable, config file, or search both `P:/.claude/skills` and `~/.claude/skills`. Fallback to searching parent directories of hook file location. (skill_metadata_advisory.py:47)

5.2. [HIGH] Add enforcement value validation (source: adversarial-io-validation) — Validate enforcement is in allowed set: `if enforcement and enforcement.lower() in {'strict', 'advisory', 'none'}: result['enforcement'] = enforcement.lower()`. Log warning for invalid values. (skill_metadata_advisory.py:66-68)

5.3. [HIGH] Replace broad exception handler with specific catches (source: all specialists) — Change `except Exception: pass` to `except (OSError, yaml.YAMLError) as e: logger.debug(f"Failed to load {skill_name}: {e}")`. Follow "fail fast" principle with graceful degradation and observability. (skill_metadata_advisory.py:70)

5.4. [MEDIUM] Add path sanitization defense-in-depth (source: adversarial-security, adversarial-io-validation) — Despite regex filtering, add explicit validation: `if not re.match(r'^[a-zA-Z0-9_-]+$', skill_name): return {"workflow_steps": [], "enforcement": None}`. Also resolve path and verify it stays within skills directory. (skill_metadata_advisory.py:47)

5.5. [MEDIUM] Fix test expectation (source: adversarial-compliance) — Change `/arch` test case from `True` to `False`, or use a skill that actually lacks workflow_steps. Current test passes for wrong reason. (skill_metadata_advisory.py:146)

5.6. [MEDIUM] Document API contract (source: adversarial-compliance) — Add to HookContext docstring in base.py: `data: For UserPromptSubmit events, contains {"userMessage": str, "sessionId": str, ...}`. (base.py:61)

5.7. [MEDIUM] Add YAML parsing limits (source: adversarial-security) — Add `MAX_YAML_SIZE = 1024 * 100` (100KB), check content length before parsing. Add depth validation for nested structures to prevent DoS. (skill_metadata_advisory.py:54-58)

5.8. [MEDIUM] Validate workflow_steps content (source: Phase 2) — Check that workflow_steps list contains only strings: `if not all(isinstance(s, str) for s in wf_steps): return result`. (skill_metadata_advisory.py:62-64)

5.9. [LOW] Add rate limiting with terminal isolation (source: adversarial-security, Phase 2) — Track shown warnings in terminal-scoped state file. Use terminal_id from context for isolation. Show each advisory once per session. Must handle multi-terminal concurrency. (skill_metadata_advisory.py:133)

5.10. [LOW] Improve UTF-8 handling (source: adversarial-io-validation) — Try UTF-8 read first, catch UnicodeDecodeError and log: `f'{skill_file} is not UTF-8 encoded'`. Don't silently corrupt with errors='replace'. (skill_metadata_advisory.py:54)
