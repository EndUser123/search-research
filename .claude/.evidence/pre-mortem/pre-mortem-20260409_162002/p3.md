# Phase 3: Synthesized Refined Critique — CRIT-LOGIC-001 Fix

## Intent Summary

This pre-mortem reviews the CRIT-LOGIC-001 fix to `PreToolUse_skill_pattern_gate.py`: adding `sys.path` setup before `from skill_guard.skill_auto_discovery import get_skill_config` to prevent phantom import failure. The fix addresses why skill-guard enforcement was silently bypassed — the module-level import had no `sys.path` entry for `P:/packages/skill-guard/src`, causing an uncaught `ImportError` that propagated to the top-level fail-open handler at lines 762-770.

## 1. Logical Gaps & Inconsistencies

1.1. [HIGH] Second phantom import at line 516 — `from skill_guard.breadcrumb.tracker import _load_workflow_steps` inside `handle_pre_tool_use` has NO `sys.path` guard. The module-level setup at lines 60-63 only runs at import time; if `handle_pre_tool_use` is invoked in a subprocess (which it is — PreToolUse hooks run via `subprocess.run([sys.executable, hook_path])`), the subprocess gets a fresh Python environment with no `sys.path` modification from the parent. This import will fail with `ImportError` → fail-open → workflow step enforcement silently bypassed.
   - **Source:** adversarial-quality, QUAL-004
   - **File:** `PreToolUse_skill_pattern_gate.py:516`

1.2. [HIGH] Missing `.exists()` check before `sys.path` insertion — `_skill_guard_path` is created at line 61 but never validated with `.exists()`. If `P:/packages/skill-guard/src` does not exist, the guard check at line 62 passes (path not in `sys.path`), `sys.path.insert(0, ...)` adds a non-existent directory, then `import skill_guard` fails with `ImportError` → top-level fail-open at line 762. This is the root cause SEC-001, LOGIC-001, and IO-001 all independently identified from different angles.
   - **Source:** adversarial-security SEC-001, adversarial-logic LOGIC-001, adversarial-io-validation IO-001
   - **File:** `PreToolUse_skill_pattern_gate.py:61-63`

1.3. [MEDIUM] Path inserted without `.resolve()` — `Path("P:/packages/skill-guard/src")` is not canonicalized. On Windows, junctions or symlinks could redirect the path without the visible string changing, allowing path-redirection attacks if an attacker can create a junction at `P:/packages/skill-guard`.
   - **Source:** adversarial-security SEC-002
   - **File:** `PreToolUse_skill_pattern_gate.py:61`

1.4. [MEDIUM] Inconsistent exception handling between breadcrumb and skill_guard imports — breadcrumb failures (line 515-520) use a `try/except` that fails open correctly. But the `skill_guard.skill_auto_discovery` import at line 66 has no local exception handling — `ImportError` propagates to the top-level handler at line 762. If both imports fail, breadcrumb silently fails open while skill_guard error propagates to stderr.
   - **Source:** adversarial-logic LOGIC-002
   - **File:** `PreToolUse_skill_pattern_gate.py:533-538` (breadcrumb) vs `line 66` (skill_guard)

## 2. Hidden Assumptions & Fragile Dependencies

2.1. [HIGH] Assumes module-level `sys.path` setup covers all call paths — the fix at lines 60-63 runs when Python imports the hook file. But `handle_pre_tool_use` contains a second `skill_guard` import (line 516) that assumes the module-level setup persists. On subprocess invocation, this assumption breaks silently.
   - **Source:** adversarial-quality QUAL-004 (primary), adversarial-logic LOGIC-001 (cross-validation)
   - **Why it matters:** The hook passes tests because the test imports the module directly (module-level setup runs), but fails in production because the subprocess path differs.

2.2. [HIGH] Assumes `P:/packages/skill-guard/src` exists and is not attacker-controlled — no validation before inserting into `sys.path`. If the directory is compromised, malicious code executes with PreToolUse hook privileges.
   - **Source:** adversarial-security SEC-001
   - **Why it matters:** For a solo-developer machine this is low-probability, but the assumption is unstated and unverified.

2.3. [MEDIUM] Assumes consistent Windows path string representation — `str(_skill_guard_path) not in sys.path` uses string comparison. On Windows, `sys.path` might contain `'P:\\packages\\skill-guard\\src'` (backslash) while `_skill_guard_path` produces `'P:/packages/skill-guard/src'` (forward slash). The duplicate guard could miss pre-existing entries, causing duplicate `sys.path` insertions.
   - **Source:** adversarial-security SEC-003, adversarial-logic LOGIC-003
   - **Why it matters:** Minor operational issue, but indicates fragile path-handling assumptions.

2.4. [MEDIUM] Assumes hook file will not be relocated — the path `P:/packages/skill-guard/src` is hardcoded at line 61. Line 56 uses `Path(__file__).resolve().parent.parent` to derive the hook_base import path, but line 61 does not follow the same pattern for skill_guard.
   - **Source:** adversarial-quality QUAL-002
   - **Why it matters:** If the hook file is moved, the hardcoded path breaks silently.

## 3. Missing Obvious Actions / Best Practices

3.1. [HIGH] Add `.resolve()` + `.exists()` check before `sys.path.insert` — the one-line fix that addresses SEC-001, SEC-002, LOGIC-001, and IO-001 simultaneously:
   ```python
   _skill_guard_path = Path("P:/packages/skill-guard/src").resolve()
   if _skill_guard_path.exists() and str(_skill_guard_path) not in sys.path:
       sys.path.insert(0, str(_skill_guard_path))
   ```
   - **Source:** adversarial-security, adversarial-logic, adversarial-io-validation (convergent finding)

3.2. [HIGH] Add `sys.path` setup before line 516 import — the module-level setup does NOT cover function-body imports in subprocess execution. Before line 516, add:
   ```python
   _sg_path = Path("P:/packages/skill-guard/src").resolve()
   if _sg_path.exists() and str(_sg_path) not in sys.path:
       sys.path.insert(0, str(_sg_path))
   from skill_guard.breadcrumb.tracker import _load_workflow_steps
   ```
   - **Source:** adversarial-quality QUAL-004

3.3. [MEDIUM] Derive skill_guard path from `__file__` consistently — use the same `Path(__file__).resolve().parent.parent.parent / 'packages' / 'skill-guard' / 'src'` pattern used at line 56 for hook_base. This eliminates the hardcoded-path fragility.
   - **Source:** adversarial-quality QUAL-002

## 4. Risks and Edge Cases

4.1. [HIGH] Subprocess execution model breaks module-level `sys.path` assumption — PreToolUse hooks run as `subprocess.run([sys.executable, hook_path])`, giving each invocation a fresh Python environment. The module-level `sys.path` setup only runs once at import time; subprocess invocations do not re-import the module. Line 516's import in `handle_pre_tool_use` will fail in subprocess context because `sys.path` was never updated.
   - **Source:** Phase 2 cross-specialist synthesis

4.2. [MEDIUM] Junction/symlink attack on Windows path — `Path()` without `.resolve()` allows junction redirection. Attacker with filesystem access creates `P:/packages/skill-guard` as a junction to `C:/attacker-controlled/`, causing malicious code to execute on import.
   - **Source:** adversarial-security SEC-002

4.3. [LOW] Duplicate `sys.path` entries from Windows path separator variance — `'P:/packages/skill-guard/src'` vs `'P:\\packages\\skill-guard\\src'` means the guard check may not detect already-present entries on Windows.
   - **Source:** adversarial-security SEC-003, adversarial-logic LOGIC-003
