## 1. Logical Gaps & Inconsistencies

1.1. [CRITICAL] **cache_only detection is completely non-functional** — The detection iterates only source files (via `key_patterns` glob), never iterates cache files directly. `cache_files_set` is populated exclusively inside the source-file loop (lines 420-422). A file existing only in cache (never present in source) is never discovered. `cache_only = cache_files_set - src_files_set` (line 440) is always empty because both sets are built from the same source-file iteration. The function claims to detect cache-only files but cannot. (source: adversarial-logic, lines 414-449)

1.2. [MEDIUM] **_version_key single-component tuple sort bug** — A directory named `'0'` or `'0.x'` produces `(0,)` or `(0, x)` which compares less than `(0, 0, 0)` in Python tuple comparison. Such directories sort below the fallback `(0, 0, 0)` and get marked stale for deletion. Version dirs named `'1'` or higher are NOT affected (they compare > (0,0,0)). This edge case requires an unlikely `'0'` or `'0.x'` version directory name. The tuple padding fix (`+ (0,)*(3-len(parts))`) is still correct and should be applied, but severity is MEDIUM not HIGH. (source: adversarial-testing, lines 346-350; verification confirmed `(0,) < (0,0,0)` = True)

1.3. [HIGH] **robocopy availability not checked before subprocess call** — `subprocess.run(['robocopy', ...])` raises `FileNotFoundError` on non-Windows systems. The exception propagates unhandled through the outer drift-fix loop (the `except OSError` at line 832 is in the orphan-junction loop, not the drift-fix loop). The script silently exits on non-Windows. (source: adversarial-io-validation, line 857)

1.4. [MEDIUM] **key_patterns limited to 3 extensions** — Only `**/*.py`, `**/*.json`, `**/SKILL.md` are monitored. Changes to README.md, CHANGELOG.md, .sh, .yaml, or other markdown files are silently invisible to drift detection. Auto-fix won't sync them. (source: adversarial-logic, line 410)

## 2. Hidden Assumptions & Fragile Dependencies

2.1. [HIGH] **Auto-fix hardcodes `P:/packages/{pkg}` in source sync** — Audit reads from the correct marketplace path (`plugins_dir`), but auto-fix (line 854) syncs from hardcoded `P:/packages/{pkg}`. On systems where packages live elsewhere, audit and fix target different directories. Also: the same bug was reported independently by three specialists (io-validation, quality, testing) — a clear missed consolidation in Phase 1. (source: adversarial-io-validation, line 854)

2.2. [HIGH] **No post-sync re-audit after robocopy** — `result.returncode < 8` is treated as success; robocopy exit codes 2-7 (partial sync, extra files in dest, mismatches) all print "Synced: pkg" without verification. Drift may persist but user sees green. (source: adversarial-testing, lines 862-866)

2.3. [MEDIUM] **shutil.rmtree has no exception handler for stale version deletion** — If a directory is locked (antivirus, another process), `PermissionError` propagates silently and the loop continues. User sees "Deleted stale: X" but the directory persists. Subsequent runs report the same stale versions. (source: adversarial-io-validation, line 849)

2.4. [MEDIUM] **_version_key pre-release fallback with no diagnostic** — Versions like `'2.0-beta'` or `'1.5-rc1'` all fall back to `(0,0,0)`, making 'current' version selection unstable. No warning is emitted when a non-numeric version is encountered. (source: adversarial-quality, lines 346-349)

2.5. [LOW] **TOCTOU window in cache version detection** — Between `cache_dir.iterdir()` (line 390) and subsequent file reads, another process could delete `current_version_dir`. Re-verification `if not current_version_dir.exists(): continue` would bound this. (source: adversarial-io-validation, line 390-394)

## 4. Risks and Edge Cases

4.1. [MEDIUM] **Files deleted from cache but present in source produce no finding** — `cache_file.exists()` at line 421 silently skips source files absent from cache. Neither `source_modified` nor `cache_only` is triggered. External cache cleanup (disk pressure, user deletion) is invisible to the audit. (source: adversarial-testing, lines 420-427)

4.2. [MEDIUM] **robocopy exit codes 2-7 treated as success** — Exit code 1 = files copied (clean); 2 = extra files in dest; 4 = mismatch; 5 = copied with skips; 6 = extras + skipped; 7 = some files couldn't be copied. All pass `returncode < 8`. Partial syncs print "Synced". (source: adversarial-io-validation, line 862)

4.3. [LOW] **Duplicate version directory names may trigger inconsistent comparison** — `Path !=` comparison on case-insensitive filesystems could treat `'1.0.0'` and `'1.0.0.LOCAL'` as different or same depending on how Path objects are constructed. Using `d.name` (string) for comparison instead of path object identity would be more deterministic. (source: adversarial-testing, line 397)
