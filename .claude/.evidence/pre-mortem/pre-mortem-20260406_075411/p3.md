## Logical Gaps & Inconsistencies

1.1. [HIGH] pytest.ini rootdir points to non-existent directory `debugRCA` instead of `rca`. Tests will fail to run from configured root. (`P:/.claude/skills/rca/pytest.ini:5`)

1.2. [HIGH] SKILL.md:53 uses `$CLAUDE_PROJECT_DIR` for hook paths, but hooks exist at `P:/.claude/skills/rca/hooks/`. The env var may not resolve at runtime, causing silent hook registration failure. (`P:/.claude/skills/rca/SKILL.md:53`)

1.3. [HIGH] Conflicting evidence tier definitions across documentation. SKILL.md defines Tier 1-4 (95%/85%/75%/50%), GENERIC_PROTOCOL.md defines Tier 0-4 (20%/40%/60%/85/95%). RCA findings from different sessions have incomparable confidence levels. (`P:/.claude/skills/rca/SKILL.md:130-138` vs `P:/.claude/skills/rca/GENERIC_PROTOCOL.md:17-27`)

1.4. [MEDIUM] Hook error reporting uses sys.stderr.write(), but Claude Code treats ANY stderr as a hook error. This creates a catch-22 where error reporting itself triggers a hook error cascade, masking the actual root cause. (`P:/.claude/skills/rca/hooks/hook_error_rca.py:104`)

## Hidden Assumptions & Fragile Dependencies

2.1. [CRITICAL] FileLock fallback silently proceeds without lock. All 5 hook files define a local FileLock class as fallback when portalocker is not installed. The fallback __enter__ returns self without acquiring any lock. Concurrent multi-terminal writes are NOT protected, risking rca_workflow.json corruption with no warning to users. (`P:/.claude/skills/rca/hooks/PostToolUse_rca_phase_tracker.py:83-91`)

2.2. [MEDIUM] Silent import fallbacks: `record_delegation_event` and `should_trigger_research` become None when rca package imports fail, with no user warning. Auto-research and delegation metrics silently stop working in non-dev environments. (`P:/.claude/skills/rca/hooks/PostToolUse_rca_phase_tracker.py:33-53`)

2.3. [MEDIUM] No specialist traced how hooks actually register with Claude Code. The path from SKILL.md → Claude Code → hook execution is undocumented and unverified.

2.4. [LOW] conftest.py has hardcoded absolute paths (`P:/packages/rca/src`, `P:/__csf/src`) that assume a specific development environment. Tests fail with cryptic import errors if these paths don't exist. (`P:/.claude/skills/rca/tests/conftest.py:21`)

## Missing Obvious Actions / Best Practices

3.1. [HIGH] Update pytest.ini rootdir from `debugRCA` to `rca` — one-line fix, immediately restores test functionality.

3.2. [HIGH] Audit and fix `$CLAUDE_PROJECT_DIR` references in SKILL.md. Use `CLAUDE_PLUGIN_ROOT` or absolute paths instead.

3.3. [CRITICAL] Replace all sys.stderr.write() error reporting with logger.warning() or collected stdout warnings. This is the single most impactful fix — it resolves the catch-22 that makes all hook debugging circular.

3.4. [HIGH] Unify evidence tier system: adopt GENERIC_PROTOCOL.md's 5-tier (Tier 0-4) as canonical across SKILL.md, output-format.md, and all documentation.

3.5. [HIGH] Add `_acquired` flag to FileLock fallback and assert after __enter__, or make portalocker a hard dependency. Currently concurrent RCA sessions silently corrupt shared state.

3.6. [MEDIUM] Add stderr warning when optional rca package imports fail so users know functionality is degraded rather than silently absent.

3.7. [LOW] Precompile regex patterns in detect_phase_from_output at module load time instead of per-call. Minor performance improvement.

3.8. [LOW] Replace hardcoded absolute paths in conftest.py with relative path discovery using Path(__file__).

## Risks and Edge Cases

4.1. [HIGH] Multi-terminal concurrent RCA sessions risk state file corruption due to no-op FileLock fallback. No warning is given to users about this vulnerability.

4.2. [MEDIUM] When rca is pip-installed (non-dev mode), all metrics tracking and action tracing silently stop working. User receives no feedback that RCA is running in degraded mode.

4.3. [MEDIUM] Hook path resolution via `$CLAUDE_PROJECT_DIR` may fail silently on different Claude Code installations or configurations.

4.4. [LOW] detect_phase_from_output has inefficient nested loop with repeated regex compilation per tool call — minor performance degradation.
