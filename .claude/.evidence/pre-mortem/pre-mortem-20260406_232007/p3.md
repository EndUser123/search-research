## Logical Gaps & Inconsistencies

1.1. [CRITICAL] Package structure violation — skill_forced_eval lives in packages/ but imports hooks/ modules (source: adversarial-compliance, skill_forced_eval.py:35-37)
   - Module at P:/packages/skill-guard/src/skill_guard/ imports from UserPromptSubmit_modules and __lib
   - This violates package isolation — the module is neither a hooks module nor a proper package with its own dependencies
   - Impact: Package cannot be installed via pip, imports fail outside P:/.claude context
   - COMP-006 exacerbates this — duplicate module exists in P:/.claude/hooks/UserPromptSubmit_modules/ (verified during synthesis)

1.2. [CRITICAL] Zero test coverage despite critical hook ordering (source: adversarial-compliance, COMP-004)
   - QA findings from 2026-04-02 identified ZERO test coverage
   - Re-enablement added sys.path fixes but no tests
   - Impact: All four QA failure modes (ordering, state corruption, path traversal, symlink hijacking) remain untested

1.3. [HIGH] Duplicate module creates maintenance burden (source: adversarial-compliance, COMP-006 — VERIFIED TRUE)
   - skill_forced_eval.py exists in TWO locations:
     - P:/.claude/hooks/UserPromptSubmit_modules/skill_forced_eval.py (18553 bytes, Apr 2)
     - P:/packages/skill-guard/src/skill_guard/skill_forced_eval.py (modified during re-enablement)
   - Which is source of truth? Edits to wrong file don't take effect
   - Impact: Debugging confusion, edits may not apply

1.4. [HIGH] Symlink-based module import without target validation (source: adversarial-io-validation, IO-005, registry.py:40-47)
   - skill_execution_state.py symlink points to skill-guard package
   - No runtime verification that loaded code is from expected location
   - Impact: Local attacker with filesystem access could load malicious code

1.5. [MEDIUM] TOCTOU race condition in state file write (source: adversarial-io-validation, IO-001, skill_forced_eval.py:318-326)
   - Directory could be deleted between mkdir() and write()
   - State capture fails silently (pass), compact immunity breaks without indication
   - Impact: Feature fails silently, confusing behavior

1.6. [MEDIUM] sys.path manipulation creates path shadowing (source: adversarial-logic, LOGIC-002, skill_forced_eval.py:26-28)
   - Conditional sys.path.insert(0) checks exact string match, not parent/child path conflicts
   - Could shadow more specific imports already in sys.path
   - Impact: Wrong module imports if duplicate paths exist

1.7. [LOW] State directory fallback is silent (source: adversarial-io-validation, IO-006, skill_forced_eval.py:55-63)
   - _get_state_dir() falls back to _FALLBACK_STATE_DIR without logging
   - Different terminals may use different state directories
   - Impact: Terminal isolation breaks

1.8. [LOW] Non-deterministic import ordering (source: adversarial-logic, LOGIC-003, registry.py:40-47)
   - sys.path manipulation at module import time creates race condition
   - Multi-terminal scenarios may import different versions
   - Impact: Intermittent bugs depending on session load order

   - Hooks execute sys.path.insert(0, ...) during module load
   - Assumption: Single-terminal environment or import order doesn't matter

   - Fragility: NTP adjustment, timezone change, or manual time change breaks TTL logic

## Risks and Edge Cases

4.1. [MEDIUM] Symlink drive letter normalization attack surface (source: adversarial-security, SEC-001)
   - Symlink uses lowercase /p/ path, manipulable on case-sensitive filesystems
   - Windows normalizes to P:/ but Unix systems preserve case
   - Attacker could create malicious /p/packages/skill-guard/ directory chain
   - Impact: Arbitrary code execution if symlink target replaced

4.2. [MEDIUM] sys.path without namespace protection (source: adversarial-security, SEC-002, skill_execution_state.py:280)
   - sys.path.insert(0, ...) without checking if module already exists
   - Could shadow legitimate imports
   - Impact: Import confusion, data leakage

4.3. [LOW] Hook registration uses package path but module structure invalid (source: adversarial-compliance, COMP-003)
   - registry.py loads skill_guard.skill_forced_eval but module imports from hooks/
   - Hook registration succeeds but imports are fragile
   - Impact: Non-portable, breaks if paths change
