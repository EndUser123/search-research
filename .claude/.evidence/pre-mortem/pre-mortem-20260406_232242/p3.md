## Intent Summary

The mtime-gap + semantic verification algorithm in `session_chain.py` extends session chain traversal beyond `/compact` sessions to all sessions by using file modification time proximity as a chain heuristic, verified by semantic similarity between prior session goals and successor opening messages. The implementation adds `_extract_last_goals()`, `_semantic_sim()`, and replaces the non-compact early return in `walk_sessions_index_chain` with a backward-walking chain that checks mtime gaps and semantic thresholds.

### Critical Correctness Issues

1.1. [HIGH] Semantic verification `break` exits entire chain walk — when cosine similarity is below threshold, the code at line 455 executes `break` which exits the outer `while current` loop, not the inner gap-search loop. This means one below-threshold similarity terminates all further chain walking, silently dropping valid older sessions. The chain should instead try the next-best mtime candidate. (source: adversarial-logic, adversarial-quality — session_chain.py:455)

1.2. [HIGH] Semantic verification bypassed when `prior_goals` is None — the condition `if prior_goals and current_first_msg:` at line 452 means missing goal content skips verification entirely. Sessions from different contexts can be chained via mtime proximity alone with zero semantic confirmation. False positive chains result. (source: adversarial-logic — session_chain.py:452)

1.3. [HIGH] TOCTOU race in `walk_handoff_chain` — `_get_prior_transcript_path` checks `p.exists()` at line 132 then returns the Path. Later `_find_handoff_referencing` opens the same file at line 149. A concurrent terminal deletion between these calls produces an uncaught exception that halts chain traversal. (source: adversarial-io-validation — session_chain.py:117-155)

1.4. [HIGH] Off-by-one in `walk_handoff_chain` depth — `depth = chain_depth + 1` at line 230 doesn't equal actual entry count when the loop breaks early. The bug only manifests in error paths but produces incorrect depth reporting. (source: adversarial-logic — session_chain.py:230)

1.5. [HIGH] `_extract_last_goals` has zero test coverage — this is the sole semantic verification mechanism in the mtime-gap strategy. No tests validate it for empty files, missing assistant messages, mixed content, or max_chars truncation. (source: adversarial-testing — session_chain.py:302)

### Logical Gaps & Inconsistencies

1.6. [MEDIUM] `walk_semantic_chain` is not a chain-walker — it returns a flat list of similarity matches, not a predecessor chain. The function finds one best match and returns it alone. When semantic fallback is triggered, users receive a single session, not a chain. This was missed by all specialists. (source: synthesis blind-spot)

1.7. [MEDIUM] Strategies cannot merge or reconcile when they disagree — `walk_session_chain` returns the first non-empty strategy result. If mtime-gap finds session A as predecessor but semantic finds session B, the caller receives no signal that the strategies disagreed or which result is more reliable. (source: synthesis blind-spot)

1.8. [MEDIUM] `_semantic_sim` threshold 0.35 lacks empirical basis — cosine similarity of 0.35 on normalized all-MiniLM-L6-v2 embeddings means nearly orthogonal text pairs are accepted as verified. The threshold appears to be inherited from `walk_semantic_chain`'s 0.5 default without adjustment for the different text types (short goal strings vs first messages) being compared. (source: adversarial-io-validation open question, synthesis)

1.9. [MEDIUM] `MAX_MTIME_GAP_SECS=120.0` is an arbitrary threshold — sessions with legitimate gaps >120 seconds (e.g., user thinks for 10 minutes) are not chained by mtime-gap and fall through to semantic strategy which may also fail. No empirical basis documented. (source: adversarial-logic — session_chain.py:40)

### Hidden Assumptions & Fragile Dependencies

2.1. [MEDIUM] `st_birthtime` used for chronological ordering but unavailable on Python <3.12 and some platforms — fallback to `st_ctime` tracks metadata changes, not file creation. Could cause incorrect session ordering on affected platforms. (source: adversarial-io-validation — session_chain.py:387)

2.2. [LOW] `gap<=0` exclusion prevents same-mtime session chaining — if sessions share exact mtime (possible with multi-terminal startup), valid predecessor links are missed. Theoretical risk; practical risk is near zero given filesystem timestamp resolution. (source: adversarial-logic — session_chain.py:439)

2.3. [LOW] Semantic verification skipped when either `prior_goals` or `current_first_msg` is absent — chains on mtime alone when only one signal exists. Unrelated sessions with similar mtime gaps could be incorrectly linked. (source: adversarial-quality — session_chain.py:452)

2.4. [LOW] `SessionChainEntry` has no confidence or similarity score field — chains from handoff files, mtime-gap, and semantic similarity have fundamentally different reliability but look identical to callers. No way to distinguish high-confidence chains from heuristic guesses. (source: synthesis blind-spot)

### Concrete Recommendations

5.1. [HIGH] Change `break` to try-next-candidate in semantic verification loop — when similarity < threshold, instead of exiting the chain walk, iterate to the next-best mtime gap candidate and re-check. Chain continuity should not depend on a single similarity score. (source: adversarial-quality — session_chain.py:455)

5.2. [HIGH] Require semantic verification or conservative fallback when `prior_goals` is missing — if goals are absent, either require a stronger mtime signal (smaller gap) or don't chain at all. Document the permissive behavior explicitly if intentionally allowing mtime-only chaining. (source: adversarial-logic — session_chain.py:452)

5.3. [HIGH] Add try/except around `_find_handoff_referencing` file opens — wrap line 149 in try/except (OSError, PermissionError) and continue to next handoff file on failure, preventing TOCTOU-induced halts. (source: adversarial-io-validation — session_chain.py:149)

5.4. [HIGH] Change `depth = chain_depth + 1` to `depth = len(entries)` — ensures depth always reflects actual entry count regardless of early break conditions. (source: adversarial-logic — session_chain.py:230)

5.5. [HIGH] Add tests for `_extract_last_goals` — empty file, no assistant entries, mixed content, assistant at various positions within last 50 lines, max_chars truncation boundary. (source: adversarial-testing — session_chain.py:302)

5.6. [MEDIUM] Add `max_depth` parameter to `walk_sessions_index_chain` — matching `walk_handoff_chain`'s depth limit, default 50. (source: adversarial-quality — session_chain.py:420)

5.7. [MEDIUM] Add `logger.warning` when transcript file is missing from disk — provides audit trail for silent data loss scenario. (source: adversarial-io-validation — session_chain.py:374)

5.8. [MEDIUM] Add tests for `walk_semantic_chain` — cover all three branches: embed daemon success, daemon failure → SentenceTransformer, SentenceTransformer unavailable → graceful degradation. (source: adversarial-testing — session_chain.py:535)

5.9. [MEDIUM] Add boundary tests for `_MAX_MTIME_GAP_SECS` — test at 100s, 119s, 120s, 121s gaps. Verify 119s chains, 121s does not, 120s is deterministic. (source: adversarial-testing — session_chain.py:40)

5.10. [LOW] Cap `active_files` joined string in `_session_text` — add `[:500]` to prevent embedding domination by file paths. (source: adversarial-testing — session_chain.py:508)

5.11. [LOW] Add `logger.warning` when `_semantic_sim` fails due to exception — enables debugging of silent chain termination. (source: adversarial-testing — session_chain.py:532)

5.12. [LOW] Restore test globals with `try/finally` in `test_model_reloads_after_ttl` — use monkeypatch or explicit restore. (source: adversarial-quality — test_session_chain.py:630)
