# Pre-Mortem: Stop_negative_existence_guard.py Pattern Extension

## Intent Summary

Extended `Stop_negative_existence_guard.py` with three new regex alternatives in `NEGATIVE_EXISTENCE_PATTERNS` to catch false negative-existence claims about runtime constructs: `subprocess`, `thread`, `process`, `agent`, and code elements (`method`, `function`, `class`, `module`). The trigger was a plan-review agent falsely claiming "There's no subprocess" when `subprocess.Popen` exists at `gto_orchestrator.py:574`. All 42 tests pass.

## Hidden Assumptions & Fragile Dependencies

1.1. [MEDIUM] Runtime-construct denials have no exemption path — `_should_exempt_claim()` (line 402) only exempts code-element patterns (`method|function|class|module`) grounded by `Grep`. Runtime-construct nouns (`subprocess`, `thread`, `process`, `agent`) are NOT code elements and would not be exempt even if a Read-target exemption were added. A developer who `Read`s `gto_orchestrator.py` and states "there's no subprocess available for this call" would be blocked even though the claim is empirically grounded and nuanced — the subprocess exists but may not be the right mechanism for the stated purpose. This is a design question the pre-mortem was needed to surface. (source: adversarial-quality/QUAL-001, p2_meta_critique blind-spot #1)

1.2. [LOW] Quote-stripping at line 456 removes content within quotes before pattern matching (confirmed at correct line, not 354 as initially cited). The comment explains this is for GTO artifact messages. Very low risk of stripping a legitimate quoted claim. (source: adversarial-quality/QUAL-003)

1.3. [LOW] Keyword list for runtime constructs appears in two inline regex alternations with no shared constant. Maintenance risk is low (patterns are stable, 42 tests passing) but adds manual sync burden if a new keyword is needed. (source: adversarial-quality/QUAL-002)

## Missing Obvious Actions / Best Practices

2.1. [LOW] Plural form "no subprocesses" is not covered by `\bno\s+subprocess\b`. Untested. Whether this is intentional or a gap depends on whether plural denials are considered valid negative-existence claims. (source: adversarial-logic open question)

## Risks and Edge Cases

3.1. [MEDIUM] The new patterns could cause false positives on nuanced grounded claims — "there's no subprocess" after reading the code is blocked with no exemption path. The original false claim ("There's no subprocess" about existing code) was correctly caught, but so would be the nuanced case ("there's no subprocess for this specific use case"). This is the expected precision/recall tradeoff of extending the guard, not a bug in the implementation. (source: p2_meta_critique blind-spot #2)

3.2. [LOW] Code-element exemption only applies to `Grep` patterns, not `Read` file targets. The proposed fix (extending `_should_exempt_claim` to check `read_targets["files"]`) would not address runtime-construct denials — it would only help code-element claims. Design decision required: should runtime-construct denials have their own exemption category? (source: p2_meta_critique precision failure #3)

## Concrete Recommendations

4.1. [MEDIUM] Clarify the intended scope of runtime-construct denials. The guard now catches "there's no subprocess" without an exemption path, even when the claim is Read-verified. Document whether this is intentional (the guard blocks ALL such claims regardless of verification) or whether a Read-target exemption should be added for runtime constructs specifically. If intentional: add a comment in the code explaining why runtime constructs have no exemption. If not: extend `_should_exempt_claim()` to exempt runtime-construct claims when the relevant file has been Read this turn. (source: p2_meta_critique improvement #2)

4.2. [LOW] Consider whether plural form "no subprocesses" should be blocked. If yes, change `\bno\s+subprocess\b` to `\bno\s+subprocesses?\b`. If no (plural implies a count rather than existence), confirm via test. (source: adversarial-logic)

4.3. [LOW] Extract runtime-construct keywords into named constants for documentation clarity: `_RUNTIME_CONSTRUCTS = ("subprocess", "thread", "process", "agent")` and `_CODE_ELEMENTS = ("method", "function", "class", "module")`. Cosmetic only — do not change behavior. (source: adversarial-quality/QUAL-002)

## Open Questions / Unknowns

The guard catches false "no subprocess" claims aggressively, including nuanced cases where the subprocess exists but the claim is about availability for a specific context. This appears intentional given the original motivation but was never documented. (source: p2_meta_critique)
