# Pre-Mortem: csf/nlm_exporter.py Profile Bypass (TASK-007)

## Intent Summary

`csf/nlm_exporter.py` implements the TASK-007 composite batching algorithm — grouping YouTube videos by channel, sorting by publish date, splitting into ≤500K-word / ≤300-video chunks, and exporting each composite to NotebookLM via the `nlm` CLI. The module promises atomic write + idempotent export via `nlm_export_state` table with multi-terminal safety via InterProcessLock. The target under review is a profile-pinning bypass in `export_composite()` that causes guaranteed PERMISSION_DENIED failures under noninteractive mode.

## 1. Logical Gaps & Inconsistencies

1.1. **[BLOCKER]** `export_composite()` lines 257-268 bypass nlm_auth_guard entirely — raw `shutil.which("nlm")` + `subprocess.run()` with no `--profile` argument. The nlm_auth_guard profile-pinning layer is bypassed. This is the **same failure class that caused PERMISSION_DENIED in nlm_scraper.py** and was already fixed there. Under noninteractive mode (`YTIS_NLM_AUTH_NONINTERACTIVE=1`), every `export_composite()` call will fail with PERMISSION_DENIED. The module is unusable in automated pipelines. (source: adversarial-security:1, adversarial-logic:1, adversarial-quality:1, adversarial-testing:1, csf/nlm_exporter.py:257-268)

1.2. **[HIGH]** `export_composite()` idempotency check (lines 234-243) validates `nlm_source_id` + `content_hash` but never checks that `doc.notebook_id` matches the stored `notebook_id`. If NotebookLM source IDs are notebook-scoped (not globally unique), returning a stale `nlm_source_id` and proceeding to `upsert_nlm_export_state` corrupts DB state — the composite is claimed to be in notebook B but actually lives in notebook A. (source: adversarial-logic:3, csf/nlm_exporter.py:234-243)

1.3. **[MEDIUM]** `_parse_nlm_output()` returns `None` silently when nlm stdout is malformed (no JSON, no 'Source added:' prefix, no 8+ char alphanumeric token). This `None` propagates to `source_id` on line 280, which is then persisted as `nlm_source_id=NULL` in the DB on line 292. Downstream consumers find an incomplete record with no source ID. Re-running `export_composite()` sees `nlm_source_id=None`, the idempotency check fails, and the upload is retried — causing duplicate NotebookLM sources. (source: adversarial-logic:4, csf/nlm_exporter.py:323-353, 280, 292)

## 2. Hidden Assumptions & Fragile Dependencies

2.1. **[MEDIUM]** `notebook_id` parameter is not validated despite flowing into composite_id hashing (SHA-256 prefix on line 171), markdown content generation (heading on line 175), and CLI argument passing (line 262). Empty `notebook_id` silently produces blank headings and duplicate composite_ids across different empty-notebook exports, causing content collisions. An adversarial `notebook_id` with newlines could inject spurious markdown sections into the composite. (source: adversarial-quality:4, csf/nlm_exporter.py:73-76, 171, 175)

2.2. **[MEDIUM]** Bare `except Exception` at line 308 catches all error categories identically — disk-full, network timeout, db lock, and type errors produce identical log messages (`"Failed to export composite %s: %s"`). Mean time to resolution increases because debugging requires manual exception classification from indistinguishable logs. (source: adversarial-quality:3, csf/nlm_exporter.py:308)

2.3. **[LOW]** `_DEFAULT_EXPORTS_DIR` is hardcoded as `Path("P:\\.data/yt-is/nlm_exports")` with no environment variable override, unlike nlm_auth_guard which reads NOTEBOOKLM_PROFILE, YTIS_NLM_CLI, and other config from env vars. Non-portable across drive letters or machines without P: mapped. (source: adversarial-quality:5, csf/nlm_exporter.py:22)

2.4. **[LOW]** No locking within `export_composite()` itself — concurrent calls for the same `composite_id` from multiple processes could race through the idempotency check simultaneously, both see no existing record, both upload, both upsert. The module docstring references FM-010 (InterProcessLock) at a higher orchestration level, but the function has no per-composite lock. (source: meta-critique, no specialist caught this)

## 3. Missing Obvious Actions / Best Practices

3.1. **[HIGH]** Test suite masks the profile pinning gap. Every test in `test_nlm_exporter.py` that exercises `export_composite()` mocks `subprocess.run` and `shutil.which` directly at lines 235-237, 271, 309-312 — they pass 100% without ever proving that `--profile` appears in the nlm subprocess command. After the primary fix (1.1) is applied, the tests will still pass but will not verify the fix is correct. A future refactor removing `--profile` from the guard call would also pass silently. (source: adversarial-security:2, adversarial-quality:2, adversarial-testing:3, tests/test_nlm_exporter.py:235-237)

3.2. **[HIGH]** `test_export_composite_re_export_on_hash_mismatch` has zero assertions after calling `export_composite()`. The test always passes regardless of whether re-export actually happens. The comment `"# Should not return old nlm_source_id (re-export attempted)"` is documentation, not an assertion. This is the exact test that should verify re-export behavior — it currently verifies nothing. (source: adversarial-testing:2, tests/test_nlm_exporter.py:242)

3.3. **[MEDIUM]** `_parse_nlm_output()` has no dedicated tests despite being a critical path — called on every successful export to extract the source ID. Three parsing strategies (JSON, 'Source added:' prefix, bare ID) with zero coverage. A format change in NotebookLM CLI output would silently fall back to stale source_id or None. (source: adversarial-testing:4, no test for `_parse_nlm_output`)

3.4. **[LOW]** `test_export_composite_no_tmp_file_after_success` asserts `len(rename_called) > 0` but never checks the `dst` argument value. A broken rename targeting `.tmp.2` instead of `.txt` would pass. (source: adversarial-testing:5, tests/test_nlm_exporter.py:317)

## 4. Risks and Edge Cases

4.1. **[MEDIUM]** `nlm_source_id` scoping is unverified. If NotebookLM source IDs are notebook-scoped, finding 1.2 (notebook_id mismatch in idempotency) is a correctness bug causing corrupt DB state. If globally unique, finding 1.2 is a non-issue. This uncertainty means the idempotency fix cannot be implemented safely without verification. (source: adversarial-logic:3)

4.2. **[MEDIUM]** Does `nlm source add` accept `--profile` on the `source add` subcommand? `add_profile_args` injects `--profile` for all non-login commands, but this hasn't been verified against the actual `nlm source add --help` output. If `--profile` is only accepted for login/check-status commands, the primary fix (1.1) would still fail. (source: adversarial-logic)

4.3. **[LOW]** `_cleanup_tmp` swallows all errors silently with bare `except: pass`. If cleanup fails (e.g., permission denied), it is invisible — tmp files may accumulate on disk. (source: meta-critique)

## 5. Concrete Recommendations

5.1. **[BLOCKER → HIGH]** Replace lines 256-268 with nlm_auth_guard wrapper (matching the nlm_scraper.py fix pattern):
   ```python
   from csf import nlm_auth_guard
   cmd_args = nlm_auth_guard.add_profile_args([
       "source", "add", doc.notebook_id, "--text", str(tmp_path)
   ])
   result = nlm_auth_guard.run_nlm(cmd_args, timeout_s=300.0)
   ```
   Note: `nlm_auth_guard.run_nlm()` handles binary resolution internally via `build_nlm_command()` — no need for `shutil.which`. The `nlm_auth_guard` import currently lives inside the try block; it should be moved to module level for the fix.
   (source: all four specialists, csf/nlm_exporter.py:256-268)

5.2. **[HIGH]** Add an integration test that patches `nlm_auth_guard.run_nlm()` and asserts `--profile` appears in the forwarded args:
   ```python
   with mock.patch("csf.nlm_exporter.nlm_auth_guard.run_nlm") as mock_run_nlm:
       mock_run_nlm.return_value = mock.MagicMock(returncode=0, stdout="Source added: sid")
       result = export_composite(doc, nlm_source_id=None)
       args = mock_run_nlm.call_args[0][0]
       assert "--profile" in args, f"expected --profile in {args}"
   ```

   After the primary fix (5.1) is applied, `nlm_auth_guard` will be imported at module level and this patch path will be valid. (source: adversarial-security:2, adversarial-quality:2, adversarial-testing:3)

5.3. **[HIGH]** Add assertions to `test_export_composite_re_export_on_hash_mismatch`:
