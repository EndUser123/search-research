# Phase 3: Synthesized Refined Critique

## Intent Summary

This work implements runtime halt enforcement for the /sqa skill. When any layer produces findings exceeding a configured severity threshold (CRITICAL > HIGH > MEDIUM > LOW), execution stops immediately via HaltExceededThreshold exception. The implementation adds a check_halt() helper function called by all 8 layers (L0-L7 + META), with state tracking via terminal-scoped JSON files.

## Health Score: 55%

**Warning Zone (50-79%)** — The halt mechanism is functionally implemented but has critical design weaknesses (exception bypass, first-run skip) and missing safeguards (state file permissions, concurrent execution handling). Core logic works, but enforcement guarantees are fragile.

## Logical Gaps & Inconsistencies

**1.1. [HIGH] First-run bypass violates user expectations** (source: adversarial-io-validation, verified orchestrator.py:114-117)

check_halt() returns silently when load_state() returns None (first run before state file exists). If user configures `--halt-on HIGH`, they expect enforcement from layer 0, not silent bypass. A user's explicit safety configuration is violated without warning.

**Evidence**: orchestrator.py:114-117 shows `if state is None: return` with no logging or warning.

**Impact**: Contract violation — user's halt threshold setting is ignored on first execution.

**1.2. [MEDIUM] Import path assumes skill execution context** (source: adversarial-io-validation, verified layers/layer*.py)

Layers use `from orchestrator import check_halt` but orchestrator.py uses `from lib.sqa_state_tracker`. This assumes the skill entry point (SKILL.md) manipulates sys.path to make `orchestrator` importable. If this code were extracted to a library, imports would break.

**Evidence**: layer1_syntactic.py uses `from orchestrator import check_halt` (not shown in excerpt but standard skill pattern).

**Impact**: Fragile to refactoring — code is coupled to skill structure, not modular.

## Hidden Assumptions & Fragile Dependencies

**2.1. [CRITICAL] Exception bypass assumption** (source: adversarial-security, verified orchestrator.py:98-127)

check_halt() enforces halts by raising HaltExceededThreshold, assuming the exception will propagate and stop execution. However, if any layer wraps its execution in a broad `try/except` without re-raising, the halt is silently bypassed. The design assumes no caller will catch exceptions, which is not enforced.

**Evidence**: orchestrator.py:127 raises `HaltExceededThreshold`, but no mechanism exists to prevent `try/except: pass` in caller code from swallowing it.

**Impact**: Fundamental design flaw — entire halt mechanism can be defeated by standard exception handling.

**2.2. [HIGH] FileLock timeout causes state loss** (source: adversarial-io-validation, verified lib/sqa_state_tracker.py:169-176)

_write_state() uses FileLock with 1s timeout. If acquisition fails (concurrent terminal executing /sqa), the function logs a warning and skips the state update entirely. This means layer completion data is lost in concurrent scenarios.

**Evidence**: sqa_state_tracker.py:173-176 shows `except Exception: logger.warning(...) ; tmp.unlink(missing_ok=True)` — the update is dropped without retry.

**Impact**: Concurrent /sqa runs (multi-terminal workflows) will have missing or corrupted state.

**2.3. [MEDIUM] Duplicated sanitization logic** (source: adversarial-quality, verified orchestrator.py:171-172, sqa_state_tracker.py:87-89)

Terminal ID sanitization (`re.sub(r"[^a-zA-Z0-9_-]", "", raw_id)`) exists in two files. Changes to sanitization rules require synchronized updates in both locations.

**Evidence**: orchestrator.py:172 and sqa_state_tracker.py:89 both contain identical sanitization logic.

**Impact**: Maintenance burden — future changes risk divergence if only one location is updated.

## Missing Obvious Actions / Best Practices

**3.1. [HIGH] Missing file permissions on state data** (source: adversarial-security, verified lib/sqa_state_tracker.py:160-179)

State files contain project paths and execution history in plaintext. _atomic_write() (orchestrator.py:162) correctly uses chmod(0o600), but _write_state() (sqa_state_tracker.py:164) writes state without restrictive permissions. State files are world-readable by default.

**Evidence**: sqa_state_tracker.py:164 uses `tmp.write_text()` without chmod, unlike orchestrator.py:162 which calls `os.chmod(path, 0o600)`.

**Impact**: Information leakage — state files expose project structure and tool usage to other users.

**3.2. [MEDIUM] Silent failure on missing tools** (source: adversarial-quality, verified layer1_syntactic.py:86-87)

L1 layer catches FileNotFoundError and passes silently when ruff/mypy/aid are not available. No warning or finding is produced, so users don't know why a layer produced fewer results than expected.

**Evidence**: layer1_syntactic.py:86-87 shows `except FileNotFoundError: pass`.

**Impact**: Reduced visibility — users can't distinguish between "no issues found" and "tool not available."

**3.3. [MEDIUM] Insufficient subprocess argument validation** (source: adversarial-security, verified orchestrator.py:216-221)

_check_command() validates only the base command name against ALLOWED_COMMANDS, not the arguments. If user-controlled paths are passed to subprocesses, argument injection is possible.

**Evidence**: orchestrator.py:218-220 checks `cmd_name not in ALLOWED_COMMANDS` but doesn't validate arguments.

**Impact**: Potential subprocess argument injection if target paths contain shell metacharacters.

## Risks and Edge Cases

**4.1. [CRITICAL] Halt bypass via exception suppression** (source: adversarial-security, verified orchestrator.py:46-127)

If any layer wraps check_halt() in `try/except Exception: pass` or similar, HaltExceededThreshold is swallowed and execution continues despite threshold being exceeded. No fail-safe flag exists to prevent this.

**Evidence**: No enforcement mechanism prevents exception suppression — the design relies on caller discipline.

**Impact**: Core safety mechanism can be defeated accidentally or maliciously.

**4.2. [HIGH] Concurrent execution data loss** (source: adversarial-io-validation, verified lib/sqa_state_tracker.py:169-176)

Two terminals running /sqa simultaneously will race for state file lock. One terminal's state updates will be dropped due to FileLock timeout, causing missing layer completion records.

**Evidence**: sqa_state_tracker.py:173-176 shows silent skip on lock timeout.

**Impact**: Multi-terminal workflows will have incomplete or inaccurate state tracking.

**4.3. [MEDIUM] False negative in nested executor detector** (source: adversarial-quality, verified layer6_performance.py:93-96)

L6's nested executor detector resets `in_executor` on `indent <= executor_indent`, which incorrectly triggers when entering a function definition at the same indent level as the `with` statement. This causes false negatives in detecting nested executors.

**Evidence**: layer6_performance.py:93-96 shows dedent logic that doesn't account for nested functions.

**Impact**: Performance anti-patterns (nested thread pools) may go undetected.

## Concrete Recommendations

**5.1. [Add fail-safe halt flag]** (source: adversarial-security) — Write halt flag to disk (`halted.json`) BEFORE raising HaltExceededThreshold. Add `is_halted()` check at start of each layer that reads flag and aborts if present. This prevents exception suppression from bypassing halts.

**5.2. [Set restrictive file permissions]** (source: adversarial-security) — Add `os.chmod(path, 0o600)` to _write_state() in sqa_state_tracker.py:164, matching the pattern in orchestrator.py:162.

**5.3. [Fix FileLock timeout behavior]** (source: adversarial-io-validation) — Implement exponential backoff retry (3 attempts: 1s, 2s, 4s) before giving up. If all retries fail, raise an exception rather than silently dropping state update.

**5.4. [Initialize state before first layer]** (source: adversarial-io-validation) — Call `init_state()` before layer 0 execution so check_halt() works on first run. Add warning message explaining that first-run state was initialized.

**5.5. [Extract terminal ID sanitization]** (source: adversarial-quality) — Create `get_sanitized_terminal_id()` in sqa_state_tracker.py, import from orchestrator.py to eliminate duplication.

**5.6. [Add timeout/tool-missing logging]** (source: adversarial-quality) — Replace bare `pass` with `logger.warning(f"{tool} not available, skipping")` in L1/L2/L3 layers.

**5.7. [Fix L6 nested executor detector]** (source: adversarial-quality) — Track with-block depth using a counter instead of comparing indentation levels. Increment on `with`, decrement on matching dedent.

## Open Questions / Unknowns

**6.1. [LOW] FileLock timeout intention unclear** (source: adversarial-io-validation) — Is the 1s FileLock timeout intended for fast-fail behavior, or should it block longer to prioritize state consistency? The current design prioritizes availability over consistency.

**6.2. [LOW] First-run enforcement design decision** (source: adversarial-io-validation) — Should check_halt() enforce threshold on first run (require pre-initialization), or is the current "skip on None" behavior intentional to avoid blocking before baseline is established?

**6.3. [LOW] Concurrent execution expectation** (source: adversarial-io-validation) — Are concurrent /sqa runs in multiple terminals an expected workflow? If not, the FileLock complexity may be unnecessary overhead for a single-terminal tool.
