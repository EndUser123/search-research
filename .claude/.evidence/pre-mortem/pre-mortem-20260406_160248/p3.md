# Pre-Mortem: Incremental CHS Indexing Fix

## Intent Summary

The work adds schema detection to `_load_chs_messages_incremental()` in `unified_semantic_daemon.py`, enabling the function to query the correct table (`messages` vs `chat_messages`) and column (`raw_json` vs `metadata`) based on whether the database uses the v2 or legacy schema. This fixes a silent failure where incremental indexing never ran because the query targeted a non-existent table.

## Health Score: 72% (Warning)

The fix is correct and well-targeted. The core schema detection logic is sound. However, two secondary issues were identified: a pre-existing architectural gap in state file locking (IO-001), and an inconsistency where the non-incremental loader (`_load_chs_messages()`) lacks schema detection while the incremental loader now has it.

## Logical Gaps & Inconsistencies

1.1. [MEDIUM] **`_load_chs_messages()` hardcoded to v2 schema** (source: adversarial-compliance, line 2532) — This non-incremental loader queries `SELECT ... metadata FROM messages` without schema detection. If a full reindex is ever run on a legacy-schema database, it will fail silently. The incremental loader now correctly detects schema, creating an asymmetry. The function may be dead code (incremental path is preferred), but if used, would fail on legacy schema.

## Hidden Assumptions & Fragile Dependencies

2.1. [MEDIUM] **State file has no cross-process locking** (source: adversarial-io-validation, IO-001, lines 3757-3783) — `_get_last_indexed_id()` and `_save_last_indexed_id()` read/write `chs_index_state.json` without file locking. Multiple terminals can corrupt state, causing duplicate indexing or message gaps. Note: This is a pre-existing architectural issue, not introduced by this fix. The fix merely corrects the table/column query — it did not create the locking gap.

2.2. [LOW] **sqlite3.connect default 5s timeout** (source: adversarial-io-validation, IO-002, line 3805) — Connection uses default timeout rather than explicit fail-fast. Will block instead of raising immediately if database is locked.

2.3. [LOW] **Dual state tracking mechanisms** — `_save_last_indexed_id()` writes to JSON file (`chs_index_state.json`), but the reindex script uses SQLite `indexer_checkpoint` table. These are separate systems with no apparent synchronization, potentially causing state drift.

## Missing Obvious Actions / Best Practices

3.1. [HIGH] **Add state file locking** (source: adversarial-io-validation, IO-001) — Use fail-fast exclusive lock pattern for state file read/write, similar to `FAISS_LOCK_PATH` at lines 2893-2961. Prevents multi-terminal state corruption.

## Risks and Edge Cases

4.1. [MEDIUM] **Blocking under database lock contention** (source: adversarial-io-validation) — With default 5s timeout, each call to `_load_chs_messages_incremental` can block up to 5s if database is locked. Under sustained contention, this degrades indexing responsiveness and can cause request timeouts.

4.2. [LOW] **TOCTOU on database existence check** (source: adversarial-io-validation, lines 3801-3805) — `db_path.exists()` check precedes `connect()` with a narrow race window. Handled gracefully by returning `[]`.

4.3. [LOW] **Partial migration scenario** (source: adversarial-logic open question) — If `messages` table exists but lacks `raw_json` column, query fails at execution time. Unlikely given v2 schema is the current standard.

## Concrete Recommendations

5.1. [MEDIUM] **Add explicit timeout to sqlite3.connect** (source: adversarial-io-validation) — Pass `timeout=1.0` to `sqlite3.connect()`. Wrap in `try/except sqlite3.OperationalError` to return `[]` on lock failure.

5.2. [LOW] **Remove dead code in `_get_chs_db_path()`** (source: adversarial-io-validation, lines 2508-2509) — The `exists()` check result is unused; the function always returns `new_path` regardless. Remove or use consistently.

5.3. [LOW] **Apply schema detection to `_load_chs_messages()`** (source: adversarial-compliance) — For consistency and to prevent silent failure if this code path is ever used. Alternatively, document that full reindex is v2-schema-only.

## Open Questions / Unknowns

6.1. [LOW] **Is multi-terminal CHS indexing supported?** (source: adversarial-io-validation) — If yes, IO-001 (state file locking) is required before production use. If no, the locking concern is moot.

6.2. [LOW] **Is `_load_chs_messages()` used anywhere?** (source: adversarial-compliance) — If this function is dead code (replaced by incremental path), the schema detection gap is academic. Need to verify callers.
