## Recall Failures (Missed Issues)

### 1. Missing: Sentence Position Check for 'Why'
**Issue:** The implementation detects 'why' anywhere in user_prompt, but doesn't check if it's actually a question. User prompt "That's why I think X" would trigger explanatory prose detection even though no question was asked.

**Why this matters:** This is a false positive path not flagged by any specialist. adversarial-testing TEST-004 comes close but focuses on substring matching in words, not sentence position.

**Severity:** MEDIUM - causes false positives in production.

### 2. Missing: Catastrophic Phrases Should Never Be Allowed
**Issue:** _is_explanatory_prose() allows ANY causal assertion if user asked 'why' and response has data. But what about catastrophic phrases like "is broken" or "are broken"? Should those be allowed in explanatory prose?

**Why this matters:** The fix might allow overconfident catastrophic claims (HIGH severity) just because user asked 'why' and response includes a number.

**Severity:** HIGH - could allow dangerous overconfident claims.

### 3. Missing: What About 'Explain', 'Clarify', 'Reason For'?
**Issue:** The implementation only checks for 'why' keyword. User prompts like "Explain why X" or "What's the reason for Y" wouldn't trigger explanatory prose detection even though they're semantically equivalent to 'why' questions.

**Why this matters:** False negatives - explanatory prose blocked because it doesn't use exact 'why' keyword.

**Severity:** MEDIUM - reduces effectiveness of the fix.

### 4. Missing: Interaction with RCA Mode
**Issue:** overconfidence_detector.py has special handling for rca_turn flag (skips some checks). _is_explanatory_prose() doesn't account for RCA mode - should explanatory prose detection behave differently in RCA context?

**Why this matters:** Hook behavior inconsistent between normal and RCA modes.

**Severity:** MEDIUM - potential unexpected behavior in RCA mode.

### 5. Missing: No Logging for Tuning
**Issue:** QUAL-005 asks "What is the false positive/negative rate?" but no specialist points out that there's NO logging to measure this. _is_explanatory_prose() has no debug output to track when it allows/block and why.

**Why this matters:** Can't tune the heuristics without data on how they perform in production.

**Severity:** MEDIUM - makes it impossible to improve the fix based on real usage.
