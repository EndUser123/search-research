# Phase 3: Synthesized Refined Critique

## Intent Summary

This work implements a UserPromptSubmit hook that detects design/implementation intent in user prompts and injects cognitive guardrails to prevent two systemic LLM failures: (1) proposing new implementations without searching for existing ones, and (2) solving symptoms without checking broader problem classes. The hook uses regex-based pattern matching with three detection categories (action verbs + objects, planning framing, slash commands), env var gating, and FRAMEGUARD pattern compliance.

**Assessment: Healthy** — The implementation is functionally correct, well-structured, and achieves its stated purpose. Specialist findings identified minor security/logic/compliance issues, but verification revealed most are either non-issues (verified no impact) or design decisions rather than bugs. The hook is production-ready with optional improvements for hardening.

## Hidden Assumptions & Fragile Dependencies

2.1. [MEDIUM] (source: adversarial-security) — Assumes user input length is reasonable. No truncation before regex matching (cognitive_guardrails.py:69). While not a current issue, extremely large prompts (>10MB) could cause memory exhaustion. The hook does not set a MAX_QUERY_LENGTH limit.

---

## Missing Obvious Actions / Best Practices

3.1. [MEDIUM] (source: adversarial-security) — Regex quantifier `{0,100}` larger than needed. Cognitive guardrails classifier uses same pattern but could be `{0,50}` for same coverage. Larger quantifiers increase ReDoS attack surface (cognitive_guardrails.py:31).

3.2. [LOW] (source: adversarial-security) — Env var parsing only accepts 'true' string. Values like '1', 'yes', 'on' would disable unexpectedly. This may be intentional strict boolean semantics rather than a bug (cognitive_guardrails.py:25).

3.3. [LOW] (source: adversarial-security) — Regex patterns not precompiled. Using `re.compile()` at module load would improve performance, though actual impact depends on call frequency (cognitive_guardrails.py:29-36).

---

## Risks and Edge Cases

4.1. [MEDIUM] (source: adversarial-security) — ReDoS attack via crafted input with alternating word boundaries within 100-char window. The lazy quantifier `.{0,100}?` mitigates but doesn't eliminate risk entirely. Attack scenario: repetitive `\b` patterns interspersed with matching text could trigger catastrophic backtracking (cognitive_guardrails.py:31).

4.2. [INFO] (source: adversarial-security) — Memory exhaustion from extremely large prompts (>10MB) with no length limit. Currently theoretical but could be triggered by paste operations or file reads (cognitive_guardrails.py:69).

---

## Concrete Recommendations

5.1. [Reduce regex quantifier] (source: adversarial-security) — Change `.{0,100}?` to `.{0,50}?` in all DESIGN_INTENT_PATTERNS. This maintains coverage while reducing ReDoS attack surface (cognitive_guardrails.py:29-36).

5.2. [Add input length limit] (source: adversarial-security) — Add `MAX_QUERY_LENGTH = 10000` and truncate with warning log. Prevents memory exhaustion from extreme inputs (cognitive_guardrails.py:69).

5.3. [Precompile regex] (source: adversarial-security) — Use `re.compile()` at module load for performance. Convert DESIGN_INTENT_PATTERNS to compiled patterns at import time (cognitive_guardrails.py:29-36).

5.4. [Verify env var design] (source: Phase 3 synthesis) — Confirm whether strict 'true' parsing is intentional. If permissive parsing desired, accept '1', 'yes', 'on' as truthy values or document exact 'true' requirement (cognitive_guardrails.py:25).

## Open Questions / Unknowns

6.1. [LOW] (source: adversarial-logic) — Is `str(None)='None'` behavior intentional? Works correctly but inelegant. Could use `"" or context.data.get("prompt", "")` to avoid literal 'None' string (cognitive_guardrails.py:69).

6.2. [LOW] (source: Phase 3 synthesis) — What is typical usage frequency? Without knowing how often this hook runs per session, the performance benefit of precompiled regex is unverified. May be unnecessary optimization if called <10 times/session.

6.3. [LOW] (source: Phase 3 synthesis) — Were test files verified? Specialist claimed "42 positive cases all match correctly" but no specialist cited actual test file paths. Claim remains unverified.
