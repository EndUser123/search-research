## Logical Gaps & Inconsistencies

### 1. Critical Correctness Bugs

1.1. **[BLOCKER] Subletter generation overflows at 27+ items per domain** (render.py:107, render.py:222)

`chr(ord('a') + idx - 1)` produces `{` at idx=27 (ASCII 123). Both `render_actions` and `render_machine_format` have the same overflow. A domain with 27+ action items produces malformed output: `27{ [recover/high] ...` instead of `27aa [...]`.

Source: adversarial-logic, verified at render.py:107 and render.py:222

1.2. **[HIGH] file_ref unconditionally overwritten to None in Path B extraction** (chain.py:236, chain.py:239)

`file_ref` is correctly assigned at chain.py:234 within the bug_statement branch, then unconditionally set to `None` at chain.py:236 (else branch), then reset again at chain.py:239. For all non-file_reference signals (bug_statement, missing_thing, recommendation, id_reference, etc.), file_ref is always `None` even when the source line contains `@ file.py:123`. The assignments at lines 234 and 241-243 are made dead by line 239's unconditional reset.

Source: adversarial-logic (LOGIC-002), adversarial-quality (QUAL-001)

1.3. **[HIGH] Duplicate dead file_ref assignment block** (chain.py:231-243)

The file_reference branch at lines 231-234 assigns `file_ref`, then lines 238-243 unconditionally overwrite it with `None` before the re-assignment. This makes the first assignment unreachable dead code. Both the bug_statement extraction and the file_reference extraction are destroyed by the same unconditional reset.

Source: adversarial-quality (QUAL-001)

### 2. Precision Issues in Phase 1 Findings

1.4. **[MEDIUM] LOGIC-004 overstated — priority_part IS stripped** (chain.py:91-92)

Meta-critique correction: priority_part is stripped at line 92 before the replace. The issue is only that `replace('high', 'high')` is a no-op — not that whitespace escapes. Downgraded from standalone MEDIUM to a note alongside LOGIC-003.

1.5. **[MEDIUM] TEST-002 dedupe collision risk is low-probability** (chain.py:279)

Two action descriptions must share 50+ character prefix while differing after. Given the `(domain|action|description[:50])` key structure, genuine collisions require semantically distinct actions with nearly identical prefixes. LOW probability in practice, though the fix (use `set()` not `list`) is still correct and free.

## Hidden Assumptions & Fragile Dependencies

2.1. **[MEDIUM] Carryover section has same subletter overflow as domain groups** (render.py:117)

`enumerate(carryover, start=1)` at line 117 feeds `chr(ord('a') + idx - 1)` — same 26-item overflow applies to carryover items. If a carryover session has 27+ items, the same `{` overflow corrupts the carryover section. Not independently flagged by any specialist.

2.2. **[MEDIUM] No file reference support in carryover section** (render.py:117-122)

Carryover items render `[{action}/{priority}] {description}` then `@ {file_ref}` if present (lines 118-120). The `@ file_ref` suffix is correctly supported. However, the carryover numbering at line 117 uses a bare `for idx, action in enumerate(carryover, start=1)` loop without the domain_num prefix — carryover items render as bare `a`, `b`, `c` without a domain number, unlike domain items. This is inconsistent with the numbered-domain design but not incorrect.

2.3. **[MEDIUM] Domain sort key `-len(actions)` is confusingly named** (render.py:186)

`_domain_sort_key` returns `(explicit_order.get(domain, 99), -len(actions), domain)`. The `-len(actions)` tiebreaker sorts domains with more items first (negative = higher priority in sort). This is counterintuitive — more items should sort lower, not higher. The sort happens in `sorted(groups.items(), key=lambda kv: _domain_sort_key(kv[0], kv[1]))`, so `-len(actions)` means "domains with fewer items appear later." This happens to be correct behavior but the negative sign is backwards from what the variable name implies.

2.4. **[MEDIUM] No end-to-end test for unknown domain through full render pipeline** (render.py)

`_get_domain_def` falls back to `("📌", domain.upper())` for unknown domains, but no test renders an action with an unknown domain through `render_actions()` to verify the full output format is correct.

Source: adversarial-testing (TEST-004)

## Missing Obvious Actions / Best Practices

3.1. **[HIGH] Fix file_ref overwrite — makes Path B extraction silently lose data** (chain.py:239)

Remove the unconditional `file_ref = None` at line 239 and the duplicate `if signal_name == "file_reference":` block at lines 240-243. Let the first assignment at lines 233-234 handle all file_ref extraction.

3.2. **[HIGH] Add subletter overflow guard or use two-letter suffixes** (render.py:107, render.py:222)

Either cap at 26 items per domain (document the limit) or implement two-letter suffixes (aa, ab, ... az, ba, bb...) for overflow. Minimal fix for 26-item cap: `subletter = chr(ord('a') + (idx - 1) % 26)` — but this collides at 27 (1a, 1b...1z, 1a again). Proper fix: two-letter base-26 notation when idx > 26.

3.3. **[MEDIUM] Add carryover rendering to render_machine_format** (render.py:189-233)

`render_machine_format` accepts `carryover` but never uses it. Either implement carryover support (add carryover domain after all regular domains) or explicitly reject carryover in machine format with an error. Current silent drop misleads downstream consumers.

Source: adversarial-testing (TEST-003)

3.4. **[MEDIUM] Remove dead code branch in _resolve_options** (render.py:166)

`return DEFAULT_OPTIONS` at line 166 is unreachable — all code paths above return first. Not a bug but Confuses readers. Remove it or add `assert False` if it's truly unreachable.

3.5. **[MEDIUM] Validate kwargs in format_rns_output** (render.py:260)

`format_rns_output` passes `**kwargs` directly to `RenderOptions(**kwargs)`. A typo like `show_file_reffs=True` raises a raw `TypeError` with no suggestion. Add validation: check kwargs against `RenderOptions.__dataclass_fields__` and raise a helpful error.

Source: adversarial-testing (TEST-005)

## Risks and Edge Cases

4.1. **[MEDIUM] Unicode truncation produces garbled output when max_description_chars is set** (render.py:139-141)

`len()` counts Python code units, not visual columns. Emoji (2-4 code units each) get 2-4× fewer visual characters than intended. `max_description_chars` is an opt-in feature but produces wrong output when triggered with non-ASCII descriptions.

Source: adversarial-testing (TEST-001)

4.2. **[MEDIUM] Dedup hash collision silently drops semantically distinct actions** (chain.py:282)

`description[:50]` truncates and uses the prefix as a dedupe key. Two distinct actions whose descriptions differ only after 50 characters are incorrectly deduplicated. Impact is low in practice but the silent data loss is concerning for completeness-critical use.

Source: adversarial-testing (TEST-002)

4.3. **[LOW] Fragile priority normalization chain** (chain.py:91-99)

Priority goes through: strip → replace(no-op for high) → priority_map.lower() lookup. The replace is dead code; the lower() is applied to the result of priority_map.get(), which already returns lowercase values. Two transformations that partially overlap and partially duplicate each other. Hard to reason about correctness.

Source: adversarial-logic (LOGIC-003, LOGIC-004)

## Concrete Recommendations

5.1. **[HIGH] Replace list-with-set pattern in _dedupe_actions** (chain.py:279)

`seen: set[str] = []` — list used as set. Change to `seen: set[str] = set()` and `seen.append(key)` to `seen.add(key)`. O(n) → O(1). Also resolves the type-annotation mismatch (annotates set but initializes list).

5.2. **[MEDIUM] Use distinct description strings in test_render.py sort test** (test_render.py:188-196)

`assert quality_lines[0].strip().endswith("1a [recover/high] recover/high")` — the action description and expected string are identical. Replace descriptions with unique strings like "primary recover" and assert on those. Ensures the test actually validates sort order.

Source: adversarial-quality (QUAL-003)

5.3. **[MEDIUM] Add test for carryover-only render path** (render.py)

`render_actions([], carryover=[...])` — when actions is empty but carryover has items, verify the carryover section renders with `0 items` in the do-all footer. Not currently tested.

5.4. **[LOW] Add test for equal-count domain tiebreaking** (render.py:186)

Two domains with same explicit_order and same item count should sort alphabetically. No test covers this. Add explicit test for the tiebreak behavior.

Source: adversarial-testing (TEST-006)

## Open Questions / Unknowns

6.1. **[LOW] Is the 26-item-per-domain limit intentional?** (render.py:107)

If two-letter suffixes (aa, ab) are acceptable as overflow, LOGIC-001 severity reduces from BLOCKER to HIGH. The current single-letter scheme explicitly limits output to 26 items per domain. If that's intentional, document it; if not, implement two-letter overflow.

Source: adversarial-logic (LOGIC-001)

6.2. **[LOW] Should render_machine_format support carryover?** (render.py:189)

TEST-003 flagged this as a bug, but it may be intentional exclusion. If machine format is meant for programmatic consumption without carryover semantics, add a comment explicitly stating this or raise an error when carryover is passed. If carryover should be supported, implement it.

6.3. **[LOW] Is Path B file_ref extraction intentional only for file_reference signal?** (chain.py:231-243)

The current design extracts file_ref only when the primary signal is `file_reference`, not when other signals (bug_statement, recommendation) happen to contain `@ file.py:123` patterns. This may be intentional to avoid false positives, but the bug at line 239 destroys even the intentional extraction for file_reference signals.
