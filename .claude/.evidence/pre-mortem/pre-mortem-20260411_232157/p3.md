# Pre-Mortem Critique: Handoff Skill Invocation Goal Drift Fix

## Intent Summary

The goal-drift fix addresses a structural flaw where session compaction mid-Skill invocation causes the captured goal to become the Skill's arguments rather than the user-level task. The three-layer fix adds a META_PATTERNS skip filter for slash-commands, a defensive fallback in the capture hook, and a continuation_rule warning when Skills are interrupted.

## Logical Gaps & Inconsistencies

1.1. [HIGH] Defensive fallback has unhandled None case — if `extract_preceding_message` returns None (exact string match fails due to whitespace normalization), the `and preceding.strip()` check short-circuits correctly, but if it returns an empty string the fallback silently skips and the unfiltered skill args propagate as goal. No logging or flag on failure. (source: adversarial-state-machine, PreCompact_handoff_capture.py:634-638)

1.2. [MEDIUM] No semantic validation on fallback result — `extract_preceding_message` can return a preceding message that is itself a meta-invocation or whitespace-only. The code checks `preceding and preceding.strip()` but doesn't validate that the result is goal-quality content. (source: adversarial-state-machine, PreCompact_handoff_capture.py:635-638)

1.3. [MEDIUM] Three-layer defense is degrading, not deterministic — Layer 1 (skip filter) and Layer 2 (fallback) can both fail silently depending on string normalization edge cases. Layer 3 always fires when `pending_operations` has the interrupted skill, but provides only a warning, not a correction. The snapshot's goal field has no indicator of which layer succeeded, so downstream consumers treat all goals as equally trustworthy. (source: adversarial-state-machine, PreCompact_handoff_capture.py + handoff_v2.py:657-684)

## Hidden Assumptions & Fragile Dependencies

2.1. [MEDIUM] Transcript entry normalization must match between `extract_last_substantive_user_message` and `extract_preceding_message` — if message normalization (whitespace, encoding) differs between storage and retrieval, the exact-match in `extract_preceding_message` fails silently. No explicit dependency contract exists between these two functions. (source: adversarial-state-machine, transcript.py)

2.2. [MEDIUM] Layer 3 warning depends on `extract_pending_operations` correctly capturing `skill:type` with `state=in_progress` — if the pending operation is not recorded or its state is mis-set, Layer 3 warning does not fire even when Layers 1 and 2 both fail. (source: adversarial-state-machine, transcript.py:2353-2356)

## Missing Obvious Actions / Best Practices

3.1. [MEDIUM] No test for the defensive fallback path — 9 tests cover `is_meta_instruction` skip behavior and `build_restore_message_compact` warning output, but there is no test that exercises the `extract_preceding_message` fallback when the goal matches the Skill invocation pattern. The fallback logic has never been exercised by a test.

3.2. [MEDIUM] No logging when defensive fallback is triggered — when `extract_preceding_message` returns None or empty, the code silently skips the fallback. A single log line would make the degraded path observable without adding significant complexity.

## Risks and Edge Cases

4.1. [MEDIUM] If all three layers fail simultaneously — Layer 1 skip misses (normalization), Layer 2 fallback returns None (string not found), AND Layer 3 warning doesn't fire (skill not in pending_operations) — the skill args become the goal with no indication anything went wrong. This is the catastrophic failure path and has no guard.

4.2. [LOW] Unix path literals starting with `/` and containing a space could theoretically match the slash-command regex if they look like `/cmd args`. The `is_meta_instruction` docstring claims Unix paths won't match, but the regex is not anchored to exclude them.

## Concrete Recommendations

5.1. [MEDIUM] Add None guard with logging and is_meta_instruction validation to the defensive fallback. If `preceding` is None or empty, log a warning. If `preceding` is a meta-invocation, do not use it as the goal. (PreCompact_handoff_capture.py:634-638)

5.2. [MEDIUM] Add a `goal_origin` field to the snapshot schema to make degraded states explicit. Values: `user_message | skill_args_filtered | skill_args_unfiltered | preceding_message`. This allows downstream consumers to handle unfiltered skill args appropriately. (PreCompact_handoff_capture.py — snapshot construction)

5.3. [MEDIUM] Write a test for the `extract_preceding_message` fallback path. Create a transcript entry where the last substantive message is a skill invocation with args, and verify the goal is set to the preceding message. (test_skill_invocation_goal_drift.py)

5.4. [LOW] Add a log line when the defensive fallback is skipped due to None/empty `preceding`. Makes the degraded path observable in diagnostics. (PreCompact_handoff_capture.py:636)

## Open Questions / Unknowns

6.1. [LOW] What normalization does `extract_last_substantive_user_message` apply to message content? If it strips trailing whitespace but `extract_preceding_message` does exact-match without the same normalization, the string comparison fails. (uncertainty: transcript.py)

6.2. [LOW] Does `extract_pending_operations` always record a Skill invocation as `state=in_progress` or can it record it as `completed` immediately after the Skill tool returns? If the latter, Layer 3 warning could miss interrupted Skills. (uncertainty: transcript.py:2353-2356)
