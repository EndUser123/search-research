They are NOT failures caused by the goal-drift fix — the specialist ran `git stash` to confirm these tests were failing before changes were applied. Rating them as HIGH findings in THIS review (of the goal-drift fix) overstates their relevance to the reviewed work. Severity calibration: these should be MEDIUM or flagged as pre-existing, not HIGH relative to the goal-drift fix.

2. **STATE-001 (HIGH) vs STATE-004 (MEDIUM) inconsistency** — STATE-001 describes a silent failure where `extract_preceding_message` returns None and the skill args propagate as goal. STATE-004 describes the same failure mode as one of four cases in a degraded cascade. Both affect the same code path. If STATE-001 is HIGH, STATE-004's description of the overall degraded behavior should also be rated HIGH or both should be MEDIUM. Rating them differently without explicit justification is a calibration gap.

3. **STATE-003 (LOW) is over-stated as a finding** — The regex doesn't support `---flag` convention, but this is non-standard Unix behavior. Rating it as a finding at all is precision failure (see below).

## Missed Blind Spots

1. **The TEST-001 and TEST-002 failures are pre-existing, not caused by the fix** — The adversarial-testing specialist confirmed these failures existed before the goal-drift changes (via git stash verification in the original investigation). Flagging them as findings in this pre-mortem of the goal-drift fix creates false urgency about unrelated failures. The pre-mortem should have excluded these as "pre-existing failures not introduced by this fix."

2. **No specialist examined the actual regex implementation in transcript.py vs. the defensive fallback in PreCompact_handoff_capture.py** — adversarial-logic confirmed the patterns are "equivalent" but didn't verify they produce identical behavior on the same input. If the normalization that happens between transcript storage and goal extraction causes the defensive fallback regex not to match, all three layers can fail without any of them detecting it. This is the core risk but no specialist modeled it as a concrete adversarial scenario with specific failure probability.

3. **STATE-004's `goal_origin` recommendation is architectural** — Adding a `goal_origin` field to the snapshot is a schema change with downstream consumer implications. No specialist assessed whether this is within scope of the current fix, whether it requires a version bump in the handoff envelope schema, or whether existing consumers would break. This is labeled a HIGH recommendation but has not been analyzed for blast radius.

## Precision Failures

1. **STATE-003: "---flag not supported" is not a real issue** — Rating this LOW severity implies it is a valid finding. `---flag` is not a standard Unix convention. Flagging it as a finding at all is precision failure. The finding should be removed or marked "informational only."

2. **TEST-004 (LOW): "string-matching assertions are fragile"** — This is a meta-commentary about test quality, not a finding about the goal-drift fix. It does not identify a bug, risk, or action item. It should be excluded from findings.

3. **STATE-002: "extract_preceding_message can return a preceding message that is itself a skill invocation"** — The adversarial scenario chains through multiple steps: user invokes /pre-mortem, session compacts, captured goal is /pre-mortem args, preceding message is /plan (bare skill), goal becomes "/plan". This is a real concern but the scenario is constructed. In practice, if a bare /plan was the actual user goal and preceded /pre-mortem, then /plan would have been the captured goal before compaction, not /pre-mortem args. The scenario requires the bare /plan to appear AFTER the skill invocation in transcript order, which contradicts the premise that bare /plan is the user's goal. The specialist may have assumed reverse chronological ordering in the transcript.

4. **"No significant issues found" by adversarial-logic and adversarial-io-validation** — These are valid and useful null results, but the report structure treats them as uninteresting rather than positive evidence of quality.
