## Logical Gaps & Inconsistencies

1.1. [HIGH] Staleness check uses OLDEST entry (`entries[0]`) instead of MOST RECENT (`entries[-1]`) — skill_coverage_detector.py:631
   - **What happens:** When a skill was recently run, the code checks against the oldest entry's timestamp. If files changed since the oldest entry but not since the most recent skill run, the skill is incorrectly flagged as stale.
   - **Core logic error confirmed** at line 631: `check_timestamp = entries[0].timestamp if entries else now`

1.2. [HIGH] `_import_skill_registry` returns `None` instead of falling through to `_build_fallback_catalog()` — skill_registry_bridge.py:73-79
   - **What happens:** CSF import failure causes early `return None` without reaching the fallback catalog builder. When CSF path fails, the entire skill catalog is empty.
   - **Verified at lines 73-79:** `return None` inside the `except ImportError` block for CSF

1.3. [MEDIUM] Integer division truncates large effort estimates — next_steps_formatter.py
   - 150 minutes formats as "2hr" not "2.5hr"

1.4. [MEDIUM] Missing negation words in `_STOP_WORDS` — skill_registry_bridge.py
   - "dont", "doesnt", "not", "no", "never" absent, degrading keyword extraction quality

1.5. [MEDIUM] `_infer_domain_from_gap_type()` duplicates `GAP_TYPE_TO_CATEGORIES` logic — gap_skill_mapper.py:357-381
   - Creates maintenance risk when gap types are added to one dict but not the other
