# RCA Package Adversarial Review — Final Critique

## Intent Summary

The RCA package is a root-cause analysis tool providing debugging hypothesis generation, temporal API validation, fix registry, and confidence tracking for Claude Code sessions. It exposes a SimpleRCAEngine as its primary entry point and integrates via hooks and skill components.

## Health Score: 0%

Critical — Systemic problems across testing, type safety, state management, and integration. Two blockers prevent any meaningful test coverage; four HIGH issues affect core correctness; six MEDIUM issues affect reliability and developer experience. The package should not be used for production RCA without addressing blockers.

**QA-002 Verification Criteria:** Any blocker = Critical regardless of aggregate score.

## Logical Gaps & Inconsistencies

1.1. [HIGH] Three test modules cannot be imported — pytest cannot collect tests for `hypothesis_generator`, `error_signature`, or `stack_trace_fingerprint` because they are not exported from `rca.__init__.py`. This means 100% of test coverage for these core modules is non-functional. (source: adversarial-qa, tests/test_hypothesis_generator.py — QA-001)

1.2. [HIGH] `FixRegistry.__init__` accepts only `cache_dir` parameter, but `_test()` passes `max_age_hours=24` which is not valid — `_test()` would crash with `TypeError` if executed. Test infrastructure is broken. (source: adversarial-logic, packages/rca/src/rca/fix_registry.py:418 — LOGIC-002)

1.3. [HIGH] `Mapping` type hint used in `hypothesis_generator.py:108` (`weights: Mapping[str, float]`) but `Mapping` is never imported — only `TYPE_CHECKING` block with `pass`. At runtime with non-None weights, this raises `NameError`. (source: adversarial-quality, packages/rca/src/rca/hypothesis_generator.py:108 — QUAL-001)

1.4. [HIGH] `test_integration_e2e.py:15` asserts `rca.__version__ == '0.1.0'` but `pyproject.toml` declares version `2.5.0`. Integration test will always fail on version assertion. (source: adversarial-qa — QA-002)

1.5. [MEDIUM] `_determine_verdict()` logic has multiple branches but no dedicated unit tests — only tested indirectly through integration. Edge cases around empty warning lists and API keyword detection could silently produce wrong verdicts. (source: adversarial-logic — LOGIC-003)

1.6. [MEDIUM] Confidence scoring in `HypothesisScorer` lacks calibration testing — no verification that output scores correlate with actual hypothesis quality across diverse error types. (source: adversarial-quality — QUAL-003)

## Hidden Assumptions & Fragile Dependencies

2.1. [MEDIUM] `action_tracer.py:22` uses `STATE_DIR = Path.home() / '.claude' / 'state' / 'rca'` (home-relative), while `session.py:69` and hooks use `P:/` or `CLAUDE_HOME`-based paths. On Windows where home and P: drive differ, action graphs saved by `action_tracer` are not visible to hooks reading `rca_workflow.json`. (source: adversarial-compliance, packages/rca/src/rca/action_tracer.py:22 — COMP-001)

2.2. [MEDIUM] `FlowVisualizer._get_mermaid_style()` references `action.action_id` (UUID) but `render_mermaid()` creates node IDs as `A0, A1` — style dictionary keys never match node IDs. All action styles silently fail to apply. (source: adversarial-compliance — COMP-004)

2.3. [MEDIUM] `FixRegistry` and `LibraryDocsCache` both use check-then-act TOCTOU patterns — between existence check and read, another process could delete the file, causing `FileNotFoundError`. (source: adversarial-performance — PERF-001, PERF-002)

2.4. [MEDIUM] RCA hooks at `packages/rca/skill/hooks/` execute with RCA package privileges. Any committed hook file will be loaded by `hook_launcher.py`'s `runpy.run_path()`. No signature or validation on hook content before execution. (source: adversarial-security — SEC-003)

2.5. [LOW] `ConfidenceTracker.update()` has `evidence_supports: bool` parameter documented as "ignored" — dead parameter that could mislead callers. (source: adversarial-quality — QUAL-002)

2.6. [LOW] `PhaseStateManager` state directory is not validated to exist or be writable before use. (source: adversarial-quality — QUAL-004)

## Missing Obvious Actions / Best Practices

3.1. [HIGH] `SimpleRCAEngine.analyze_issue()` — the primary entry point for RCA analysis — has zero unit or integration test coverage. No test calls this method. The entire end-to-end RCA pipeline is untested. (source: adversarial-testing — TEST-001)

3.2. [HIGH] `test_integration_e2e.py::test_complete_rca_workflow` instantiates components but never calls `engine.analyze_issue()`. The test passes regardless of whether the RCA engine works. (source: adversarial-testing — TEST-001)

3.3. [HIGH] No test calls `SimpleRCAEngine.analyze_issue()` with a real error scenario and validates output structure. (source: adversarial-testing — TEST-001)

3.4. [MEDIUM] `test_filter_causes_by_relevance` only asserts `len(filtered) <= 5` — passes any list of 5 elements regardless of whether causes match issue keywords. (source: adversarial-testing — TEST-002)

3.5. [MEDIUM] Version assertion in test should use `pyproject.toml` as source of truth, not hardcoded string. (source: adversarial-qa — QA-002)

## Risks and Edge Cases

4.1. [MEDIUM] If `P:/.claude/state/rca/` is cleaned between terminals, `ActionTracer` state persists in `~/.claude/state/rca/` but hook state is in `P:/` — cross-terminal safety guarantees silently fail. (source: adversarial-compliance — COMP-001)

4.2. [MEDIUM] `VersionExtractor.extract_versions()` passes user-provided package names to `subprocess.run()` without allowlist validation. A malicious hypothesis text could inject unexpected package names. (source: adversarial-security — SEC-001)

4.3. [MEDIUM] `FixRegistry` and `PatternRegistry` store fingerprints in plaintext JSON at `P:/__csf/.data/rca/` — error patterns reveal system vulnerability history over time. (source: adversarial-security — SEC-002)

4.4. [MEDIUM] `cli._get_session_id()` uses `STATE_FILE.exists()` then `read_text()` — TOCTOU race where file deletion between check and read causes `FileNotFoundError`. (source: adversarial-performance — PERF-003)

4.5. [LOW] Emoji in `TYPE_LABELS` can break Mermaid rendering, ASCII output, and log aggregation. (source: adversarial-compliance — COMP-002)
