## Missed Blind Spots
1. **QUAL-003 was not caught by adversarial-logic or adversarial-testing** — The LEFT JOIN + project filter silently drops orphaned messages in _like_search (line 244). adversarial-logic confirmed BM25/ranking correctness but did not examine SQL query construction. adversarial-testing focused on _diversify_results edge cases but did not test project-filtered _like_search paths. This is a real correctness bug affecting production queries.

2. **Round-robin exhaustion with small limits** — No specialist examined what happens when `limit < len(session_iters)`. The round-robin yields one result per session per round; if limit is reached mid-round, some sessions may receive zero results. This is a diversification completeness gap that could surprise callers using small limits (e.g., limit=3 with 10 sessions).

3. **No caller-side analysis** — TEST-003 correctly identified that `max_per_session=2` prevents relevance-first searching, but no specialist examined whether max_per_session is configurable at the API level. If callers cannot override this default, the design concern is more serious: users who want relevance-first have no path to get it.

4. **No examination of LIKE pattern escaping** — adversarial-logic confirmed FTS5 MATCH query escaping is structurally correct, but no specialist examined LIKE pattern escaping in _like_search. LIKE patterns with `%` or `_` wildcards could produce unexpected matches if not escaped.

5. **Missing score field handling** — No specialist tested what happens when a result is missing the `score` field. The code uses `x.get('score', 0)` as a safe default, but this was not verified against actual SearchResult structure from the backends.
