## Hidden Assumptions

### HA-1 [MEDIUM] Agent tool dispatch populates shell AGENT_PIDS array
SKILL.md assumes `Agent(...) & AGENT_PIDS=($!)` works the same as manual subprocess backgrounding. This is unverified — Agent tool runs in Claude Code context, not as a direct shell subprocess. `$!` may be empty or capture the wrong PID.

### HA-2 [MEDIUM] merge_agent_results.py filename pattern is robust
merge_agent_results.py:81-84 silently continues on filenames that don't split into 4 parts. This assumes all agent output files strictly follow `gto-correctness-{type}-{terminal_id}.json`. Non-standard terminal IDs (containing hyphens) or alternate naming would cause silent result loss.

### HA-3 [MEDIUM] Agent findings use {HIGH/MEDIUM/LOW} severity vocabulary
merge_agent_results.py:30-32 validates against `VALID_SEVERITIES = {"HIGH", "MEDIUM", "LOW"}`. GTO uses `{critical, high, medium, low}`. Agents using GTO vocabulary would have all critical findings silently dropped.

### HA-4 [LOW] gap_finder_subagent.py MD5 gap IDs are inconsistent with signature-based deduplication
gap_finder_subagent.py:36 generates gap_id via MD5 of concatenated string. If file content order changes across runs, the same gap gets different IDs, breaking signature-based deduplication.
