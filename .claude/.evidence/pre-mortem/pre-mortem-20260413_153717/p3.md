## Logical Gaps & Inconsistencies

1.1. [HIGH] (adversarial-quality, adversarial-performance) — `_content_semaphore = Semaphore(5)` is created **inside** `_fetch_via_notebooklm_batch` at line 1456. Every call to the function creates a NEW independent Semaphore. The Semaphore only limits concurrency WITHIN a single batch call — concurrent calls from different threads each get their own semaphore and bypass the rate limit entirely. ## Hidden Assumptions & Fragile Dependencies

2.1. [MEDIUM] (adversarial-performance) — `CookieFreshnessTracker.is_fresh()` releases its lock BEFORE running the subprocess probe at line 298. A concurrent `invalidate()` call can interleave between lock release and subprocess execution. If `invalidate()` sets `_last_check=0.0` under lock and then the probe runs and succeeds, `is_fresh()` returns True despite the tracker having been invalidated. The probe result is advisory (used for auth re-check), so the practical impact is an unnecessary auth attempt, not a hard failure. `transcript.py:286-298`

2.2. [MEDIUM] (adversarial-quality) — Bare `except Exception:` at line 313 in `CookieFreshnessTracker.is_fresh()` and `except Exception: pass` at line 1326 in `_ensure_nlm_auth` catch `KeyboardInterrupt`, `SystemExit`, and `MemoryError` silently. The cookie probe swallowing `SystemExit` means a Ctrl+C during a probe would incorrectly mark the cookie as stale. `transcript.py:313,1326`

2.3. [MEDIUM] (adversarial-io-validation) — `tempfile.mktemp()` at line 944 creates a path string without creating the file. A TOCTOU window exists between `mktemp()` and subsequent `shutil.copy2()` / `open()` calls. On Windows with concurrent threads accessing the same cache path, the temp file could be claimed by another thread's cleanup. `transcript.py:944`

## Missing Obvious Actions / Best Practices

3.1. [HIGH] (adversarial-performance) — **No aggregate batch timeout.** A 300-video batch call has no overall timeout — only per-subprocess timeouts. Worst-case wall-clock: `create(30s) + add(900s) + list(30s) + parallel_content(300/5×60s=3600s) + delete(15s)` = 4575s (~76 minutes). The caller has no visibility into partial progress and no abort mechanism. A stuck batch can cascade to caller timeouts and retry storms. `transcript.py:1364-1491`

3.2. [HIGH] (adversarial-security) — **Firefox cookies written to world-readable temp files.** `_get_firefox_cookie_file()` extracts SID/SSID auth cookies to plaintext temp files with default ACL (no restrictive permissions). On a shared Windows system, any local user can read these files from `%TEMP%`. The cookies enable YouTube session hijacking. For solo-dev on a personal workstation the risk is low (single-user machine), but the finding is technically valid. `transcript.py:967-984`

3.3. [HIGH] (adversarial-security) — **video_id not validated in batch subprocess URL construction.** `_fetch_via_notebooklm_batch` builds URLs at line 1404 without calling `_validate_video_id()`. The batch regex at line 1387 only checks video_id length ([:8]), not character class. If `nlm` CLI doesn't sanitize its URL argument, a malformed video_id could cause injection. The actual exploitability depends on `nlm` CLI's argument handling. `transcript.py:1404`

3.4. [MEDIUM] (adversarial-quality) — **Local redundant imports inside `_fetch_via_notebooklm_batch`.** Lines 1376-1379 import `subprocess`, `json`, `ThreadPoolExecutor`, `as_completed`, and `Semaphore` inside the function body. All of these are already imported at module level (lines 8, 15, 20, 100). Creates namespace pollution and suggests copy-paste from another module. `transcript.py:1376-1379`

3.5. [MEDIUM] (adversarial-io-validation) — **Notebook cleanup in finally block ignores failures.** The `subprocess.run` at line 1488 has no return code check and no exception wrapping. If `nlm notebook delete` times out (15s may be insufficient under load), `subprocess.TimeoutExpired` propagates from the finally block and can shadow the original exception. Accumulated orphaned notebooks increase NLM quota pressure. `transcript.py:1486-1491`

3.6. [MEDIUM] (adversarial-quality, adversarial-performance) — **ThreadPoolExecutor(max_workers=1) at 3 locations.** Lines 593, 639, and 1118 wrap single-shot API calls in `ThreadPoolExecutor(max_workers=1)`. This provides zero parallelism — the executor is used only to enforce a timeout via `future.result(timeout=X)`. Thread creation/destruction overhead is pure cost with no benefit. `transcript.py:593,639,1118`

## Risks and Edge Cases

4.1. [HIGH] (adversarial-security) — **Unencrypted YouTube session cookies at rest.** Firefox cookies (including auth tokens) are written as plaintext to temp files and stored in the `_cookie_cache` dict. Any process with filesystem access can read them for up to 5 minutes (COOKIE_CACHE_TTL). The cookies are passed to yt-dlp, which writes them to disk again. `transcript.py:969,1027-1031`

4.2. [MEDIUM] (adversarial-io-validation) — **Cookie file descriptor leak on Windows.** If `open(cookie_file, 'w')` succeeds but `f.write()` raises an exception (e.g., DiskFullError), the exception handler at lines 986-992 calls `os.unlink(cookie_file)` on an open file handle. On Windows this raises `PermissionError` because the file is still open. The cookie file leaks. `transcript.py:986-992`

4.3. [MEDIUM] (adversarial-performance) — **Semaphore(5) under-utilizes 15 workers.** `ThreadPoolExecutor(max_workers=15)` creates 15 threads but `Semaphore(5)` limits to 5 concurrent content fetches. Ten threads are permanently idle during the content fetch phase. For 300 videos: `300/5×60s = 3600s` content fetch time vs `300/10×60s = 1800s` with `Semaphore(10)`. The configuration is provably suboptimal. `transcript.py:1456,1474`

4.4. [LOW] (adversarial-io-validation) — **External provider callable has no exception wrapping.** The `_external_provider` callable at line 1788-1806 is called with no try/except. A malformed return (2-tuple instead of 3) causes an unpacking error in the caller. An exception from a buggy provider aborts the entire transcript chain for the batch. `transcript.py:1788-1806`

## Concrete Recommendations

5.1. [HIGH] — Move `_content_semaphore = Semaphore(5)` to module level for cross-batch rate limiting. Add module-level semaphore: `_nlm_content_semaphore = Semaphore(5)`. Inside `_fetch_content_for_vid`, acquire the module-level semaphore instead of a local one. `transcript.py:1456`

5.2. [HIGH] — Add per-batch overall timeout (e.g., 300s) with partial result tracking. Estimate worst case and set a budget. On timeout, return partial results so the caller can retry remaining videos. `transcript.py:1364`

5.3. [HIGH] — Apply `_validate_video_id()` to each video_id before subprocess URL construction in `_fetch_via_notebooklm_batch`. Skip invalid video_ids with an error logged. `transcript.py:1404`

5.4. [MEDIUM] — Add restrictive permissions to cookie files: `os.chmod(cookie_file, stat.S_IRUSR | stat.S_IWUSR)` immediately after `open()`. On Windows, use `os.stat().st_mode` to verify permissions are restrictive. `transcript.py:967`

5.5. [MEDIUM] — Remove local redundant imports from `_fetch_via_notebooklm_batch` body. `transcript.py:1376-1379`

5.6. [MEDIUM] — Wrap notebook cleanup in try/except within the finally block; log a warning on failure. Add `check_output=True` to capture return code and log if non-zero. `transcript.py:1486-1491`

5.7. [MEDIUM] — Replace `ThreadPoolExecutor(max_workers=1)` with direct function calls or `threading.Thread` with timeout. The single-worker executor provides no parallelism benefit. `transcript.py:593,639,1118`

5.8. [MEDIUM] — In `CookieFreshnessTracker.is_fresh()`, capture state before subprocess probe and verify after: `with self._lock: last_check_before = self._last_check`. If `last_check_before == 0.0` after the subprocess call, return False (was invalidated during probe). `transcript.py:286-298`
