## Intent Summary

The `/nlm-to-wiki` skill is a prose workflow that syncs NotebookLM notebook content into an Obsidian wiki vault. It extracts structured concept pages from NLM query responses and writes them with provenance-tracking YAML frontmatter. The skill claims to leverage the wiki skill's auto-linking phase to create cross-references, but this claim is false — the auto-linking never runs.

## Logical Gaps & Inconsistencies

1.1. [HIGH] **CONFIRMED FALSE INTEGRATION: wikilinks are NEVER created** — Step 7 claims "wiki's auto-linking mechanism handles [[wikilinks]] creation." adversarial-compliance verified this is false. The wiki skill's auto-linking (wiki/SKILL.md lines 24-26) only runs when the wiki skill's ingest workflow is explicitly invoked. The nlm-to-wiki skill writes files directly to the vault without invoking the wiki skill, so auto-linking never runs. Users will never get wikilinks. This is not a missing specification — it is a broken promise against documented behavior (SKILL.md:143, confirmed by COMP-001)

1.2. [HIGH] Slug collision silently destroys data — two distinct concept names can normalize to the same slug (e.g., "Machine Learning" and "Machine-learning" both → "machine-learning"), causing the second page to overwrite the first with no warning (SKILL.md:104-106)

1.3. [HIGH] Empty query responses produce zero pages with exit code 0 — the parser splits on `## ` headings unconditionally. If the LLM returns no headings, no pages are written but sync reports success (SKILL.md:99-101)

1.4. [HIGH] No rollback on partial failure — writing 10 concept pages where page 3 fails mid-stream leaves 3 pages written, 7 missing, no manifest, no resume. Re-running sync may overwrite already-written pages with updated provenance (SKILL.md:109-110)

1.5. [HIGH] Re-sync behavior is undefined — the skill does not specify whether syncing the same notebook twice overwrites existing pages or creates duplicates. Running `sync all` twice produces indeterminate results (SKILL.md:59-64, confirmed by COMP-002)

## Hidden Assumptions & Fragile Dependencies

2.1. [HIGH] **CONFIRMED: auto-linking requires explicit wiki skill invocation** — The skill assumes writing files to the vault triggers wiki auto-linking. This is false. Wiki auto-linking requires the wiki skill ingest workflow. The nlm-to-wiki skill must explicitly invoke the wiki skill after writing pages, or wikilinks must be created manually via `/wiki` (SKILL.md:143, confirmed COMP-001)

2.2. [MEDIUM] Vault path misconfiguration silently writes outside vault — `OBSIDIAN_VAULT_PATH` from settings.json is user-controlled. If misconfigured to a relative path or path outside the intended root, the skill writes files to unintended locations. No path traversal guard exists (SKILL.md:55, 151)

2.3. [MEDIUM] NLM auth auto-handler assumes success — `nlm login` is interactive and may fail. No retry, no backoff, no error reporting if login itself fails (SKILL.md:74-78)

2.4. [MEDIUM] `sync all` is sequential with ambiguous rate-limit scope — the 2-second delay applies to "query operations" but scope is ambiguous between notebooks. A large `sync all` could hit NLM API limits with no retry/resume (SKILL.md:149, confirmed by COMP-003)

2.5. [MEDIUM] Both integrations are external services with no fallback — if NLM CLI output format changes, all existing sync frontmatter becomes inconsistent. No schema versioning, no offline cache (SKILL.md:47-50)
