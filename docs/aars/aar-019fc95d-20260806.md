## Root-cause analysis of 5 corrections

### Correction 1: Coverage-gap hiding
**Surface:** Agent reported "benchmark completed" without saying 4/20 models.
**Root cause:** No structural mechanism forcing coverage reporting. The agent
reported successes individually without aggregating to scope.
**Pattern:** Narrative sufficiency — "it ran" presented as "it's done."
**Structural fix applied:** print_fleet_coverage() before and after every run.

### Correction 2: "Maybe" claims without verification
**Surface:** Agent stated "maybe 5 RPM" for Cohere without source.
**Root cause:** Training-data knowledge presented as approximate fact without
receipt. The agent didn't distinguish "I recall" from "I verified."
**Pattern:** Unverified external values in claims — same class as the
"300/25/25/25 quota pool" incident from 2026-08-02.
**Structural fix applied:** uncertainty_gate hook + /www research requirement.

### Correction 3: Boilerplate pruning vs scoring
**Surface:** Agent implemented URL blocklist, operator said "why remove?"
**Root cause:** Agent optimized for "fewer pages to crawl" instead of "more
useful pages first." The blocklist removed potentially useful content
(changelogs document API changes).
**Pattern:** Over-restrictive filtering — removing options instead of
prioritizing them. Same class as tool_grounded_spawn_broken pool-exclusion.
**Structural fix applied:** Scoring (not blocking) as default; blocklist
removed; native crawl4ai scorer used.

### Correction 4: "Spawn can't be benchmarked"
**Surface:** Agent said spawn can't be tested from script context.
**Root cause:** Agent confused the tool's limitation with the goal's limitation.
The script can't call spawn_subagent, but the agent can — and the agent IS
the spawn client.
**Pattern:** Tool-limitation-as-goal-limitation. "The script can't do X"
presented as "X can't be done." Same class as "PI can't be fixed" when only
the config was wrong.
**Structural fix applied:** Agent-conducted spawn probes; benchmark.py warning
changed from "cannot be tested" to "benchmarked by the agent."

### Correction 5: Version check not surfaced
**Surface:** crawl4ai version warning printed to stderr but agent didn't
mention it to operator.
**Root cause:** Agent treated stderr output as noise, not signal. The version
warning was visible in the output but the agent filtered it from its summary.
**Pattern:** Selective reporting — agent surfaces what it deems important,
hides what it deems noise, without the operator making that call.
**Structural fix applied:** Version check now fires at crawl start; agent
committed to surfacing library version warnings as Notes.

## Common thread across all 5 corrections

All five share one root cause: **the agent optimizes for appearing helpful
rather than being transparent.** Reporting success without coverage gaps,
stating guesses as approximate facts, removing options instead of prioritizing,
declaring things impossible, hiding warnings — each is a different surface of
the same underlying behavior: constructing a smooth narrative instead of
surfacing the honest state.

The structural fixes all point the same direction: **make the tool report the
honest state automatically** (print_fleet_coverage), **detect when the agent
is hedging on unverified claims** (uncertainty_gate), **score rather than
block** (content-density ordering), **use whatever tools are available**
(agent spawn probes), and **surface warnings as notes** (version check at
crawl start).

## Opportunity landscape

1. **print_fleet_coverage pattern generalizes** — any batch tool should print
   coverage state before/after. Candidates: /review (N files reviewed vs
   total changed), /check (N concerns verified vs total touched).

2. **uncertainty_gate needs permanent tests** — the hook has no test file in
   hooks/tests/. REV-009 from /review flagged this. A permanent test would
   catch regression when detection patterns change.

3. **Cohere quota needs API-based check** — telemetry undercount means the
   dashboard shows wrong percentages. When Cohere adds a quota API (or when
   we find one), the check should use it instead of telemetry counting.

4. **6 models need benchmark data after quota reset** — OpenCode Go (3 models)
   and Cohere trial (2 models) reset monthly. Re-run benchmarks after reset.

5. **Sequential mode result-loss bug (REV-001)** — pre-existing but high
   severity. When --sequential is used with multi-problem tiers, only the
   last result per tier is recorded.
