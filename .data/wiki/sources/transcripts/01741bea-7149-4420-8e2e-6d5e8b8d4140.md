When I started with claude code I was overwhelmed with all the new terms around it. This article is aimed at demystifying those for absolute beginners.

If you understand that CLAUDE.md sets context, /commands save prompts, skills teach behavior, and hooks automate workflows, you understand most of claude code.

CLAUDE.md

What is it

It is claude code’s default point of reference about the current project. It contains project documentation both semantic (such as application use case, architecture, abstractions used, rules, good practices etc.) and absolute (such as directory structure, commands to build, test etc.)

CLAUDE.md  is located at the root. You can create additional  CLAUDE.md  files in subfolders to provide additional context for e.g  /CLAUDE.md  and  /frontend/CLAUDE.md . Additional files don’t overwrite and only append to the context.

How to create

Create it manually or with claude code’s help. To do the latter, run  /init , while inside your project directory. Claude scans all files and generates  CLAUDE.md  with the required documentation.

For a new project, it helps to write a  prd.md  file listing the project requirements. Then ask claude code to update  CLAUDE.md  based on that. e.g  refer to @.claude/prd.md and update CLAUDE.md

When to use

You don’t manually use  CLAUDE.md  anywhere. It is added by default to every new conversation.

/Command

What is it

In the previous section we used our first /command i.e  /init .

/command is essentially a shortcut to prompts that are used often. Every /command is a  .md  file containing instructions written in plain English.

/commands are located at  /.claude/commands/ .

How to create

Create custom /commands by creating a  <command-name>.md  in the above mentioned location.

You can pass arguments to commands like  /command arg1 arg2  and refer to it as  $1  and  $2  in the file.

/commands are scoped allowing reuse of the same command name e.g you can have both  /.claude/commands/frontend/test.md  and  /.claude/commands/backend/test.md  . They will be invoked based on your current working directory.

When to use

Use commands when you find yourself repeating certain prompts often.

Below are some commonly used default commands

/clear  Starts a new chat with fresh context. Use it when you’re starting a new task.

/compact  Summarises the chat so far and compresses the context. Use this in long running chats to prevent exceeding the context limit and reducing token usage.

/rewind  Reverts back to a previous state of code and chat.

Hooks

What is it

Hooks are just callbacks, either bash scripts or prompts, that run automatically before/after claude code specific events. When used with scripts it allows for deterministic behaviour.

Hooks are located at  .claude/settings.json .

How to create

Create hooks by editing the  settings.json  file.

Let’s look at a simple use case — running the formatter after claude code has finished modifying code.

In the below definition,  PostToolUse  is the event,  Write  and  Edit  are the type of tools used (referred to as matchers in the docs), running  format.sh  is the thing to do.

{ 
  "description": "Automatic code formatting", 
  "hooks": { 
  "PostToolUse": [ 
  { 
  "matcher": "Write|Edit", 
  "hooks": [ 
  { 
  "type": "command", 
  "command": "${CLAUDE_PLUGIN_ROOT}/scripts/format.sh", 
  "timeout": 30 
  } 
  ] 
  } 
  ] 
  } 
 }

The list of events and their corresponding matchers are defined in the 

official docs

https://code.claude.com/docs/en/hooks

.

When to use

Use hooks when you want  always do A when event B of type C happens .

SKILL.md

What is it

Skills are a knowledge base for claude code on how to do certain things. It is a  .md  file that should always be named  SKILL.md.

Each skill is located at  /.claude/skills/<skill-name>/SKILL.md

How to create

Here

https://code.claude.com/docs/en/hooks

 is an example pdf skill from Anthropic. It’s written in natural language along with code on how to read, extract, modify pdf files using python. So whenever claude code has to deal with pdfs it will refer to this skill file and execute the code.

Below is a simpler example pdf skill for reference.

--- 
 name: pdf-processing 
 description: Extract text, fill forms, merge PDFs. Use when working with PDF files, forms, or document extraction. Requires pypdf and pdfplumber packages. 
 allowed-tools: Read, Bash(python:*) 
 --- 
 # PDF Processing 
 ## Quick start 
 Extract text: 
 ```python 
 import pdfplumber 
 with pdfplumber.open("doc.pdf") as pdf: 
  text = pdf.pages[0].extract_text() 
 ``` 
 For form filling, see [FORMS.md](FORMS.md). 
 For detailed API reference, see [REFERENCE.md](REFERENCE.md). 
 ## Requirements 
 Packages must be installed in your environment: 
 ```bash 
 pip install pypdf pdfplumber 
 ```

It is recommended to keep  SKILL.md  under 500 lines. Add any additional content in other files and reference it in the  SKILL.md . For e.g add the below line to extend the pdf skill to manipulate tables instead of bloating the original  SKILL.md .

For dealing with tables in pdfs, see [tables.md](tables.md)

When to use

Use a skill when claude code’s implicit knowledge about something is limited, wrong or doesn’t fit your project’s conventions.

Optional

MCPs and Subagents are something I’m still exploring. So I’ll just briefly introduce them.

MCPs

MCPs are essentially APIs to tools/software that allow AI models to use them. I’m not big on MCPs as I’ve never come across the need to use one. Most MCPs can instead be defined as a SKILL.md

Subagents

Subagents are new instances of claude code with a separate fresh context.

Claude code can spawn subagents on its own to delegate tasks. Often I’ve seen claude code spawn subagents when building context while the main agent is working on creating the plan.

Define and spawn subagents with the  /agents  command.
