# Google's Open Knowledge Format: Just Markdown for AI Agents
your AI agents are only as good as what they know about your systems But that knowledge the schema of a table the real meaning of a metric the runbook for an outage is scattered across cataloges wikis code comments and the heads of your senior engineers Google Cloud just proposed a fix and it is refreshingly low tech It is called the open knowledge format or OKF and it is basically a folder of markdown files that any agent can read No SDK no database no vendor lockin Here's the announcement on the Google Cloud blog OKF comes from the data cloud team written up by tech leads Sam McViti and Amir Hormati and it landed as version 0.1 The framing is deliberately humble This is an open specification not a product Google is explicitly inviting other vendors and the community to adopt it extend it and build their own implementations So what is OKF concretely Google describes it in three words just markdown just files just YAML front matter The knowledge is plain markdown so it is readable in any editor and renders on GitHub It is just files so you can ship it as a tarball host it in any git repo or mount it on any file system And a little bit of YAML front matter at the top of each file holds the structured fields you actually need to query That is the whole format There is no SDK to install and no account to create To see why this matters look at the mess it replaces In most companies the knowledge a model needs is spread across metadata catalogs with their own APIs wiks and shared drives code comments and dock strings and a few senior engineers memories So when an agent needs to answer something like how do I compute weekly active users from our event stream it has to stitch the answer together from a dozen incompatible surfaces Every agent builder solves that same context assembly problem from scratch Every catalog vendor reinvents the same data model and the knowledge stays trapped behind whatever tool created it OKF's bet is that a shared almost boringly simple file format is what finally breaks that cycle We have actually seen this movie before The web took off because HTML was a dead simple open format anyone could write and any browser could read OKF is trying to be that same kind of lowest common denominator but for the knowledge that AI agents consume Here's what a single piece of knowledge looks like in OKF Google calls it a concept and each concept is one file At the top YAML front matter carries the queryable fields and there are just six of them Type title description resource tags and a timestamp Below that is a free form markdown body Here a schema table for an orders table with a column that links off to the customer's concept That link is the magic concepts reference each other with ordinary markdown links which quietly turns your folder of files into a graph of knowledge and notice there is nothing exotic on screen A junior analyst could read this file and understand it and so can a language model with zero parsing logic in between That shared legibility where the same artifact serves the human and the machine is the quiet superpower of building on plain markdown Zoom out and a collection of these concepts is called a bundle and it is just a directory data sets tables metrics each gets a folder and a file The file path is the concepts identity So tables/orders.m MD is simply how you refer to the orders table Optional index files give you progressive disclosure A table of contents the agent reads first and optional log files keep a chronological history It looks exactly like a wiki because that is essentially what it is Three principles keep it honest First it is minimally opinionated The only field OKF actually requires is type Everything else what types exist what sections a document has is left to you The spec defines how things interoperate not what you are allowed to say Second producer and consumer are independent A human can handwrite a bundle that an agent consumes or an agent can generate one that a human browses The file is the contract and the tooling on each end is freely swappable And third it is a format not a platform It is never tied to a specific cloud database model or agent framework and it will never require a proprietary account to read or write And Google did not just publish a spec It shipped tools to make it real There is an enrichment agent that walks a BigQuery data set drafts an OKF document for every table then runs a second pass that crawls documentation to add citations schemas and join paths automatically There is a static HTML visualizer that turns any bundle into an interactive graph in a single self-contained file with no backend and no data ever leaving the page They published three readyto browse sample bundles built from public data sets And Google Cloud Zone knowledge catalog can now ingest OKF and serve it directly to agents The spec and all of the code are on GitHub That enrichment agent is worth pausing on because it points at how this is meant to scale You do not hand author thousands of files An agent drafts the bundle A human reviews and curates it like code And from then on the agents keep it current The grunt work of documentation gets handed to the machines that are actually good at it The idea did not come from nowhere OKF formalizes a pattern that AI researcher Andre Karpathi described as the LLM wiki His insight quoted right in the announcement is that language models are unusually good at exactly the chore humans hate keeping a knowledge base tidy They don't get bored They don't forget to update a cross reference and they can touch 15 files in one pass OKF is the standardized portable version of that wiki Trying it is as easy as you would hope Clone the knowledge catalog repo from GitHub and you have got the full spec the reference agent the visualizer and the three sample bundles List the samples and you will see the J4 e-commerce stack overflow and Bitcoin data sets And because every concept is just a markdown file you can cat one straight to your terminal and read it with no tooling required That is the whole pitch Knowledge you can read with the tools you already have Put it all together and OKF is striking for how little it asks of you The current version is 0.1 The format is nothing but markdown and a sprinkle of YAML Every concept needs just six front matter fields And the entire specification conformance rules and all fits on a single page In a world of sprawling proprietary cataloges the genuinely radical move here is restraint Google calls OKF lingua franca for knowledge a common tongue your context can be exchanged in It is open it is simple and the spec is on GitHub right now Subscribe to Prism Labs for more deep dives into the tools shaping AI
