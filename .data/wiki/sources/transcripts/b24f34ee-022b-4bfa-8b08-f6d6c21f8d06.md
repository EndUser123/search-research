First Bad Commit

Brief description

The model loads successfully (vision encoder detected, flash attention enabled, pipeline parallelism working) and runs at normal speed (~110 t/s), but output tokens are completely garbled. The same llama.cpp binary works perfectly with text-only Qwen2.5-7B-Instruct.

To reproduce

llama-cli -m Qwen2.5-VL-7B-Instruct-Q4_K_M.gguf

--mmproj mmproj-Qwen2.5-VL-F16.gguf

-p "What is the capital of France?"

Actual output

The

!***

(or patterned repetition like "of of of / is is is ...")

Expected output

Paris

What I've tried

Two independent GGUF sources (unsloth + lmstudio-community/ModelScope) — same result

Raw /v1/completions with manual ChatML — still garbled (ruled out template issue)

Without mmproj — same result

Different context sizes (32768, 128000) — same result

No OOM, no CUDA errors

Control test (same binary, same environment)

Text-only model works fine:

llama-cli -m qwen2.5-7b-instruct-q4_k_m.gguf -p "What is the capital of France?"

Output: "Paris" ✓

Log excerpt

n_ctx = 32768

Flash Attention: enabled

Pipeline parallelism: enabled

clip_model_loader: has vision encoder

KV cache: q4_0 (8192 MiB limit)

Chat format: peg-native # appears even with raw completions

Suspected issue

Bug in qwen2vl architecture backend — likely tokenizer or logits-to-token conversion, since:

Text-only qwen2.5 works → not a general Qwen issue

Raw completions still broken → not a template problem

Same binary, same build → qwen2vl code path is the culprit
