On May 28, 2026, alongside the release of Claude Opus 4.8, 

Dynamic Workflows

 and a new setting to invoke them called 

"ultracode"

 were added to Claude Code.

As this is a brand-new feature, many of you are likely confused, thinking, "I opened /effort and saw an unfamiliar 'ultracode' option," or "It doesn't appear in my environment." I personally got stuck on this issue where it appeared on my work PC but not on my home PC.

In this article, I will organize everything for beginners regarding:

What exactly is ultracode?

What it can do and when to use it

Steps to enable it

A checklist for when it "doesn't show up!" (based on my own experience)

I will cover all of these for beginners.

First, the conclusion: ultracode is "Full Power Mode + Automatic Team Formation"

In short, ultracode is 

Claude Code's "Full Power Mode"

.

It consists of a combination of two elements:

Runs at xhigh (the deepest level of reasoning)

Automatically uses Dynamic Workflows

The key point is that ultracode is a 

Claude Code-side setting

, not a "model setting." It doesn't mean a new ultracode option has been added to the API effort levels; rather, internally, it sends xhigh while Claude itself decides, "This task should be handled via workflows," and automatically forms a team to execute it.

Also, this setting is 

session-specific

. It resets when you start a new session, so you need to re-select it via /effort each time.

What can Dynamic Workflows do?

Dynamic Workflows can be considered the core of ultracode. When Claude receives a large task, it:

Breaks the task down into subtasks itself

Runs multiple sub-agents 

in parallel

Has another agent 

verify and refute

 the results

It is a mechanism that repeats until the answer converges.

The concept shifts from the traditional "one model, one conversation, one task at a time" to "Claude creates its own plan and manages a group of agents."

It excels at tasks such as the following:

Bug investigations and security audits across the entire codebase (e.g., authentication checks, input validation, identifying dangerous patterns).

Refactoring or migrations on the scale of hundreds of thousands of lines, pushing them through all at once while ensuring existing tests pass.

Research tasks that require investigating from multiple angles to verify facts and returning a report with citations.

Conversely, this feature is overkill for minor fixes or simple questions (the reason for which is explained later).

Prerequisites for use

To use ultracode, you must have the following in place:

1. The model must support xhigh

Since ultracode is configured to send xhigh, you must select a model that supports xhigh ( 

Opus 4.8 / Opus 4.7

). 

If you are using a model that does not support xhigh, such as Sonnet 4.6, ultracode will not appear in the /effort menu.

2. Claude Code version

Dynamic Workflows requires 

Claude Code v2.1.154 or later

. If you are using an older version, please update it.

# バージョン確認
claude --version

# アップデート（npm経由でインストールしている場合）
npm install -g @anthropic-ai/claude-code

3. Plan

Officially, it is provided for 

Max, Team, and Enterprise (if enabled by an administrator)

 plans, as well as via Claude API, Amazon Bedrock, Vertex AI, and Microsoft Foundry. It is on by default for Max and Team, and off for Enterprise until enabled by an administrator.

Note that in some cases, it can be enabled on the Pro plan via "Dynamic workflows" in /config (in my own Pro environment, ultracode appeared after I toggled it on in /config, as described below). If you cannot find it in your plan, please check /config first.

Activation steps

Once the prerequisites are met, activation is very simple.

STEP 1: Turn on Dynamic Workflows

Run /config in Claude Code and look for the 

"Dynamic workflows"

 line in the settings list. If it is set to false, please turn it on.

Dynamic workflows                          false   ← これをオンにする


copy

Use the arrow keys to select a row, and press Enter (or space) to toggle it to true.

STEP 2: Set the model to Opus 4.8

Use /model to switch the model to 

Opus 4.8

.

STEP 3: Select ultracode

When you open /effort, in addition to low / medium / high / xhigh / max, you should see 

ultracode

. Select this to complete the activation.

Checklist for when "ultracode doesn't appear!"

This is where I personally got stuck. "It appeared on my work PC, but not on my home PC"—I wondered why, even though it was the same account. The cause was 

differences in settings per machine

.

If it doesn't appear, please check in order from the top.

✅ 

Is the model set to Opus 4.8 (or Opus 4.7)?

 If you are using a model that does not support xhigh, such as Sonnet 4.6, it will not appear in the menu at all.

✅ 

Is "Dynamic workflows" in /config turned on?

 If this is false, ultracode will disappear from the menu. 

This was the cause in my case.

 Since /config is 

a setting per machine

, there was a discrepancy where it was on for the work PC and off for the home PC.

✅ 

Is the Claude Code version v2.1.154 or later?

 Check with claude --version. If it is old, update it.

✅ 

Are there any remaining disable settings?

 If the environment variable CLAUDE_CODE_DISABLE_WORKFLOWS=1 is set, or if "disableWorkflows": true is included in the configuration file (such as ~/.claude/settings.json), the feature itself will be disabled and ultracode will also disappear.

When it doesn't appear on one device despite being the same account, it is almost certainly either /config or an environment variable.

Points to note when using it

While it is a convenient feature, it also has its quirks. Here are some points to keep in mind before using it.

① Token consumption increases significantly

 Because workflows run a large number of sub-agents in parallel, token consumption is significantly higher than in a normal session. This is not a bug, but a specification. It is recommended to first get a feel for the behavior and consumption amount with smaller tasks.

② Return to high for daily tasks

 While ultracode is on, it attempts to plan a workflow for virtually every task. It is excessive for light work, so return to /effort high when going back to routine work.

③ Using auto mode is recommended

 The official recommendation is to 

turn on auto mode

 when using Dynamic Workflows. Workflows are difficult to progress if they stop every time a tool is executed, so they are compatible with auto mode (just be sure to understand what will be executed in advance).

④ Session limited

 As mentioned above, ultracode is a setting only for the current session. You need to select it again in a new session.

How to try only workflows without using ultracode

If you feel that "always-on is a bit intimidating" or "I want to try it just once," you can invoke workflows without turning on ultracode.

Include the word "workflow" in your prompt

 Example: "Audit all endpoints under src/routes/ with workflow and report any missing authentication checks." Claude Code will detect that word and execute only that task as a workflow (allowing for a one-off execution without changing the session's efficiency level).

Use /deep-research

 This is a pre-prepared workflow for research.

It is safest to start by trying these "one-off workflows" to get a feel for them before deciding whether to use ultracode regularly.

Summary

ultracode = Claude Code's "full-power mode"

 (xhigh + dynamic workflow automation)

To use it, you need 

Opus 4.8 (xhigh-compatible model) + Dynamic Workflows enabled via /config + v2.1.154 or later

If it "doesn't appear in the menu," check in this order: 

Model → /config → Version → Disable settings

Since token consumption is high, it is best to 

reserve it for heavy tasks

 and switch back to high for daily use.

As it is a newly released feature, there is still little information available, but it can be a game-changer for "heavy and large" jobs like refactoring or auditing an entire codebase. If you are curious, please try ultracode on a small task first.

※The content of this article is based on information as of May 2026. Since Dynamic Workflows are in the research preview stage, specifications and available plans may change in the future. Please check the official documentation (code.claude.com/docs) for the latest information.
