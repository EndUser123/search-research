Executive Summary

At a Glance

The MIDAS Catalog implements a comprehensive JSON-LD metadata framework that achieves 

96% FAIR compliance

 ( 

F-UJI

https://f-uji.net/

 score) while serving the infectious disease modeling research community. This architecture supports 

9 distinct resource types

, integrates 

14+ metadata standards

, and provides machine-readable structured data that enhances discoverability through Google Dataset Search and other aggregators.

96% F-UJI FAIR Score · 48 of 50 metrics

FAIR Compliance Gaps (2 of 50 Metrics)

Two 

F-UJI

https://f-uji.net/

 metrics are currently scored as non-compliant, neither of which reflects deficient metadata practices:

R1.3-01M-1 — Community-Specific Metadata Standards

F-UJI classifies Schema.org as "generic" rather than "community-specific." No formally recognized standard for infectious disease modeling data currently exists in F-UJI's reference sources (RDA Metadata Standards Catalog, FAIRsharing). MIDAS compensates with domain-specific extensions including OBO ontologies, the MIDAS Metadata Vocabulary, and Bioschemas. 

See full justification →

https://midasnetwork.us/midas-catalog-json-ld-metadata-architecture/#fair-r13-01

R1.3-02D-1 — Data Format in Metadata

MIDAS catalog records intentionally link to data landing pages rather than direct download URLs, prioritizing link persistence, user context, and alignment with standard academic repository practice. Data formats are still documented in machine-readable form via 

encodingFormat

 and 

distribution

 .

JSON-LD Architecture Components

JSON-LD Access Points

The JSON-LD metadata for each MIDAS Catalog record is available through multiple mechanisms:

Embedded in HTML

A 

<script type="application/ld+json">

 block within each catalog landing page (e.g., 

https://catalog.midasnetwork.us/collection/1990

https://catalog.midasnetwork.us/collection/1990

), making the metadata directly consumable by search engines, FAIR assessment tools, and any agent that parses the page HTML.

Static JSON-LD Files

Each catalog record has a corresponding static JSON-LD file available at a predictable URL following the pattern: 

https://catalog.midasnetwork.us/jsonld/{id}.jsonld

(e.g., 

https://catalog.midasnetwork.us/jsonld/1990.jsonld

https://catalog.midasnetwork.us/jsonld/1990.jsonld

)

These files are generated at build time and served as static assets, providing a lightweight access point for the structured metadata without requiring HTML parsing. Each catalog detail page includes a JSON-LD icon linking directly to its corresponding file.

Bulk JSON-LD File

A single file containing every catalog record as a JSON array is available at:

https://catalog.midasnetwork.us/jsonld/all.jsonld

https://catalog.midasnetwork.us/jsonld/all.jsonld

This file is regenerated during the nightly build and provides a convenient access point for consumers who need the entire catalog — for example, to build search indexes, run batch analyses, or integrate MIDAS metadata into external systems. Using this file avoids the need to fetch individual records via the sitemap.

Sitemap Discovery

The catalog's 

sitemap.xml

https://catalog.midasnetwork.us/sitemap.xml

 includes URLs for all individual JSON-LD files, the bulk 

all.jsonld

 file, and the JSON Schema. This enables automated harvesters and search engines to discover all available metadata resources.

Context Flattening & Vocabulary Namespaces

All 

@context

 definitions are consolidated at the root level, removing nested contexts for cleaner JSON-LD structure and improved parser compatibility.

JSON Schema Validation

Each JSON-LD record includes a self-reference to its defining JSON Schema, enabling consumers to programmatically validate records they harvest or process.

Schema Self-Reference

Every JSON-LD record references the schema in two ways:

1. conformsTo declaration

 — The schema appears as a 

dcterms:Standard

 entry in the 

conformsTo

 array alongside the other metadata standards:

{
  "conformsTo": [
    {
      "@type": "http://purl.org/dc/terms/Standard",
      "name": "MIDAS Catalog JSON-LD Schema",
      "description": "JSON Schema (Draft 2020-12) defining the structure of MIDAS Catalog JSON-LD metadata records",
      "url": "https://catalog.midasnetwork.us/schema/midas-catalog-jsonld.schema.json",

  ]
}


2. @context reference

 — A 

describedby

 entry in the context points directly to the schema URL, providing a lightweight discovery mechanism:

{
  "@context": {

R1.3-02D-1: Data Format in Metadata

Status: Non-Compliant (Architectural choice)

MIDAS catalog records link to 

data landing pages

 rather than direct download URLs, causing F-UJI metric FsF-R1.3-02D-1 to fail. This is an intentional architectural decision.

Why Landing Pages Over Direct Downloads

Link Persistence:

 Data providers frequently reorganize file structures. Landing pages remain stable; direct file URLs break. Our 

schema:url

 and 

dcat:landingPage

 provide reliable access.

Essential Context:

 Landing pages provide usage documentation, terms of service, citation requirements, related resources, and version information.

User Guidance:

 Multiple format options explained, data quality notes, processing recommendations, and support contact information.

Format Information Still Available

The underlying data formats ARE documented in machine-readable form:

{
  "encodingFormat": "text/csv",
  "distribution": [{
    "encodingFormat": "text/csv",
    "url": "https://landing-page-with-download-links"
  }],
  "distributionFormats": ["text/csv", "application/json"]
}


Community Alignment

Standard practice in academic data repositories (Zenodo, Dryad, Figshare). Recommended by DataCite metadata schema. Aligns with DCAT specification for data catalogs. This architectural choice reflects 

mature data stewardship

 rather than incomplete metadata.
