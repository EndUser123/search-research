# Graphify: Turn Your Codebase into a Queryable Knowledge Graph for Claude Code
graphify turns your entire codebase into a knowledge graph code docs PDFs images even videos all connected in one queryable structure it uses Tree Sitter for free local code parsing supports 28 plus languages and saves 71.5 times the tokens compared to reading raw files let's see how it works when developers need to understand an unfamiliar codebase they run into four fundamental problems first Grep has no structural awareness it finds string matches but it cannot show you how concepts relate across files and modules second there's the token cost sending raw source files to an AI assistant for every question is expensive a 52 file corpus consumes 71.5 times more tokens per query compared to a pre-built graph third cross-file relationships are invisible an import in one file a function call in another and a design rationale in a doc are all logically connected but flat file reads don't surface these connections and fourth there's no persistence every new conversation with your AI assistant starts from scratch with no structural memory of your project the token savings are dramatic in a benchmark with a 52 file corpus querying the graph uses 71.5 times fewer tokens per query compared to sending raw files to an AI assistant the key insight is that you build the graph once then query it forever and when files change you use the update flag to only reextract what's different incremental updates keep things fast getting started takes just three steps step one install the package with UV tool install graphify y note the double y on the pipi package name step two run graphify install to register it with your AI assistant you can scope it globally or use the project flag for just the current repo step three type /graphify dot from your project route to build the knowledge graph the output goes into a graphify out folder with three files graph.html for an interactive visualization you can open in any browser graph report.mmd with god nodes insights and suggested queries and graph.json JSON the full graph in networkX format for programmatic access running graphify install does several things automatically it writes a skill file so your AI assistant recognizes the /graphify command after that your assistant will automatically check the knowledge graph before answering codebased questions and rebuild it after code changes it works globally or per project and supports a wide range of platforms including Claude Code Codeex Cursor Gemini CLI GitHub Copilot and ADER among others once you've built the graph you can query it without rereading any source files use Graphy Query to trace relationships between concepts use Graphy Path to find the shortest connection between two nodes add the DFS flag for depth first traversal when tracing data flows and use graphify explain to get a deep dive into any single concept you also have useful options like budget to cap the answer length update to only reextract changed files and cluster only to reccluster without reextraction here's a real example of querying the graph in clawed code we ask why the extract function serves as a bridge between multiple subsystems the answer isn't just that it calls certain functions instead the graph reveals the architectural role extract is a two pass orchestrator that stitches together five otherwise independent subsystems it shows which communities the function bridges and how this kind of structural insight is what distinguishes a graph query from reading source code line by line graphy also generates an interactive HTML visualization you can open graph.html HTML in any browser to explore your project visually nodes are color-coded by community so you can see natural module boundaries at a glance you can click on individual nodes to inspect their connections filter the view to show only one community at a time and use the search feature to jump directly to any concept in the graph it's a great way to get an overview of the project before diving into specifics under the hood Graphify follows a six-stage pipeline where each stage is a pure function first Detect walks the directory tree and classifies files by type then Extract pulls out entities and relationships using either a parsing or LLM analysis build graph assembles everything into a single network X graph cluster runs the Leiden algorithm to group related concepts into communities analyze identifies the most important nodes and surprising connections and finally the output stage generates the HTML visualization the report and the JSON export extraction happens in three passes with different cost profiles pass one handles code files like Python TypeScript Go Rust and 23 more languages it uses Trees sitter to parse abstract syntax trees locally extracting classes functions imports and call graphs this is completely free with no API calls needed pass two handles video and audio files using faster whisper for local transcription also free the transcription prompt is seated with the top god nodes from the code graph so domain specific terms are transcribed correctly pass three dispatches docs PDFs and images to LLM sub aents in parallel batches this is the only pass that costs tokens the graph is built from two core primitives nodes and edges nodes represent entities from your project including code entities like classes and functions document concepts like topics and design decisions and rationale nodes from inline comments edges connect these nodes with typed relationships like calls imports and semantically similar to every relationship gets a confidence tag extracted means it was found directly in the source like an import statement with confidence 1.0 inferred means it's a reasonable deduction like crossfile call resolution scored between 0.55 and 0.95 and ambiguous means the relationship is uncertain and flagged for human review community detection is where things get really interesting graphy runs the Leiden algorithm to group densely connected nodes into communities based purely on connectivity not file type this means a design doc that heavily references an authentication module ends up in the same community as that module's code a paper describing an algorithm clusters with its implementation an architecture diagrams component nodes cluster with the modules they depict in other words graphify discovers natural module boundaries that cross file types and even programming languages the analysis stage identifies two key structural features god nodes are the most connected entities in the graph forming the architectural spine of your project for example the extract function might have 47 connections because it orchestrates multiple subsystems build graph might have 32 because it assembles all outputs then there are surprising connections these are cross community edges ranked by how unexpected they are for instance a video transcription module connecting to a clustering algorithm because domain terms in videos are seated from the code graph or a PDF parser connecting to an O module because a security white paper references internal authentication patterns you would never find these with GP the mechanism that makes cross-type linking work is shared node IDs both the A extractor and LLM sub aents use the same deterministic ID format parent directory file name stem and entity name all normalized to a canonical form using Unicode case folding so when a design doc references the validate function and the parser already produced a node for that same function both generate the same ID and the nodes merge automatically no manual linking required dduplication happens in three layers within a file using a scene ID set between files using NetworkX's built-in item potency and across cache hits and new extractions not every situation calls for a knowledge graph for a quick keyword lookup in a known file just use GP or your IDE search for understanding one functions implementation read the file directly but when you need to trace how module A connects to module C through B use graphify path when you're trying to understand an unfamiliar codebases architecture run Graphify and explore the report for repeated AI queries on a large project build the graph once and query cheaply forever for finding non-obvious crossfile dependencies the graph's surprising connections feature is invaluable and for a small project with fewer than 20 files just read them directly the sweet spot is when your code base is too large to hold in one context window and you need crossfile relationships graphy works with virtually any AI coding assistant it supports CLI tools like Claude Code Codeex and Gemini CLI IDE integrations like Cursor VS Code Copilot and Kilo Code and terminal tools like ADER AMP and Open Code you can also install optional extras for specific file types the PDF extra handles PDF extraction office handles Word and Excel files video GitHub and Notion GraphML for GEI and direct Neo Forj push let's be honest about the trade-offs on the advantages side you get 71.5 times token savings per query cross- file relationships in one hop it's static analysis only so it can't see runtime behavior like dynamic imports and it requires Python 3.10 or newer here are the five key takeaways one graph beats GP for structural questions trace
