Problem description & steps to reproduce

Let me say upfront that I'm not even sure if this is actually a bug or normal behavior I was not aware of. I'm currently running the MTP enabled Qwen3.6-27B-UD-Q4_K_XL on a 22GB 2080TI GPU using the CUDA backend and I can just about fit 80k context which uses 21.05GB after the model is fully loaded.

The issue I'm facing is that once I start running prompts the VRAM usage will start steadily increasing until it eventually OOMs.

To give specific numbers : VRAM usage immediately jumps from 21.05 to 21.5 when launching the first prompt, then it will slowly but surely increase as tokens are being generated, reaching 21.75 at 5k tokens and hits the OOM error at around 10k tokens.

The additional VRAM is not freed after the generation fully finishes either. It just keeps adding up for every new prompt I run.b

I thought this might be an MTP related bug since I had never noticed this before and I'm aware that MTP in general requires more VRAM so I tried the non mtp version of the same Qwen3.6-27B model and although the steady increase in VRAM usage does still happen, it does tend to go up much slower.

I thought this might be related to checkpoints but setting the number of checkpoints to 1 makes no difference whatsoever.

Thanks for any help.

Since the issue still persists and makes using any kind of speculative decoding impossible, I decided to do some more testing by switching to the vulkan backend to see if there's any difference. Unfortunately the same exact behavior is observed so whatever the issue is, it's not cuda specific.

Edit: Also tried Bartowski's Q4_K_M quant instead of unsloth's thinking it might be a quantization issue but I'm still seeing the same thing happen.

Edit 2: Further testing indicates that this issue is in some way related to kv-cache quantization. When I get rid of the --cache-type-k q8_0 and --cache-type-v q8_0 parameters (Thus having to lower my context to 45000), the initial +650mb bump in vram usage on first prompt still occurs, but after that vram does not grow significantly as tokens are generated like it did before. It only goes up by 11mb after generating 30k tokens.

So the issue I'm facing seems to perhaps stem from a combination of speculative decoding and kv-cache quantization.

param(
  [string]$Endpoint = "http://127.0.0.1:8083/v1/chat/completions",

$vramCsv  = Join-Path $outDir "vram.csv"

  -ArgumentList "--query-gpu=timestamp,memory.used,memory.free","--format=csv,noheader,nounits","-l","1" `
  -RedirectStandardOutput $vramCsv -NoNewWindow -PassThru

function Get-VramMiB {
  $line = & nvidia-smi --query-gpu=memory.used --format=csv,noheader,nounits | Select-Object -First 1
  [int]($line.Trim())
}

# Seed prompt — long-ish, ~1.5k tokens, so 30 turns covers ~45k+ tokens of context.

"turn,ctx_messages,vram_before_mib,vram_after_mib,delta_mib" | Out-File -FilePath $turnsCsv -Encoding ascii
