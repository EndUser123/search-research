3. EXECUTION AND DATA FLOW
TDD Phase Flow
DISCOVER (Phase 0)
  ├── Load /t gap data (optional)
  ├── Read target code files
  └── Capture baseline test results

RED (Phase 1)
  ├── Parse feature into N test cases
  ├── Launch N × tdd-test-writer PARALLEL
  ├── Each writes ONE failing test
  └── Confirm: All tests FAIL

GREEN (Phase 2)
  ├── Launch N × tdd-implementer PARALLEL
  ├── Each reads failing test, writes minimal code
  └── Confirm: All tests PASS

VERIFY (Phase 3)
  └── Run actual command with real data (no mocks)

REGRESSION (Phase 4)
  └── Run targeted related tests

REFACTOR (Phase 5)
  ├── Launch N × tdd-refactorer PARALLEL
  ├── Each evaluates and improves code structure
  └── Confirm: All tests STILL PASS

Phase State Machine (TDDPhase enum)

Evidence Rules (PostToolUse_tdd_state_tracker.py)
Stage 1: DISCOVER → command contains pytest|cat|grep|head|tail|ls (any exit)
Stage 2: RED → pytest with FAILED|ERROR in output, nonzero exit
Stage 3: GREEN → pytest with "passed" in output, no FAILED|ERROR, zero exit
Stage 4: VERIFY → no dry-run, zero exit
Stage 5: REGRESSION → pytest tests/ with passed, no FAILED, zero exit
Stage 6: REFACTOR → pytest with passed, zero exit
