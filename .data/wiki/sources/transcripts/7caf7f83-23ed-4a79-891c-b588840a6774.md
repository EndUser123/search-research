Suggestion description

I understand that the iOS client was removed due to difficulties in retrieving a valid 

PoToken/Visitors Data generated via commands on Termux

https://github.com/inotia00/scrape-youtube-termux

 and the challenges in maintaining it.

However, while experimenting last week [August 4] with the old RVX Patch ( 

Version 5.4.1

https://github.com/inotia00/revanced-patches/releases/download/v5.4.1/patches-5.4.1.rvp

) and patched the YT version 19.44.39 using 

RVX Manager Compose

https://t.me/AnddeaChat/41104

, I discovered that the iOS client still functions using PoTokens—specifically, GVS PoTokens generated via the integrated YTDLnis PoToken generator.

At that time, the client only required the GVS PoToken to enable video playback. The Player PoToken and visitor data were not necessary.

Screenshot on August 16:

~

My experiment was successful, and the iOS client continued to work until August 16 (Philippine Time). However, it broke again today (August 17), likely 

due to changes in YouTube's enforcement of PoToken requirements for video playback.

https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide#current-po-token-enforcement

Screenshot from the generated web client tokens on the YTDLnis app 

(I hid my generated ones; this is for demo purposes only):

I know that you are now busy. But i was wondering if you could consider bringing back the iOS client, with support for 

updated PoToken input similar to what's implemented in the YTDLnis app.

https://github.com/user-attachments/assets/422343be-6478-49e5-a721-f524187153a1

Screenshot from RVX patches 5.4.1, the last version that supports Po Token and Visitors data input:

Screenshot from YTDLnis app, it shows the input PoTokens from the iOS client, including the copied GVS and Player PoTokens:

~

I compared the two images because there are now two types of PoTokens—GVS and Player—but neither is supported in the 5.4.1 patch, since it was discontinued several months ago.

I've tested the 

latest PoToken implementation

https://github.com/user-attachments/assets/d9e541a8-31bf-40c2-a47f-78962343f562

 on the iOS client on YTDLnis app, and it's now working as expected.

App mentioned: 

YTDLnis

https://github.com/deniscerri/ytdlnis/?tab=readme-ov-file#-ytdlnis

Edit: I found an argument 

suggesting that the iOS client requires an iOS-specific PoToken generated directly from the iPhone.

https://github.com/inotia00/ReVanced_Extended/issues/2869#issuecomment-2749715035

 However, through testing, I found that the client works with valid GVS and Player PoTokens provided from the YTDLnis app (login is required to generate the potokens).

YouTube Data Scraper for Termux

https://github.com/inotia00/scrape-youtube-termux

 is deprecated. 

YouTube Data Scraper for Termux

 was inspired by 

iv-org/youtube-trusted-session-generator

https://github.com/iv-org/youtube-trusted-session-generator

.

However, since YouTube servers now require Player PoTokens and GVS PoTokens separately, 

iv-org/youtube-trusted-session-generator

https://github.com/iv-org/youtube-trusted-session-generator

 is no longer used.

(Now, a PoToken must be issued every time a video is played, and the issued PoToken must be bound to the user's SessionId)

For the same reason, 

YouTube Data Scraper for Termux

 is also no longer valid, and the generated PoTokens cannot be used anywhere.

Currently, the only known method for generating PoTokens is 

BotGuard

 , which is only available for clients such as 

WEB

 and 

MWEB

 .

Generating PoTokens through 

DroidGuard

 (Android) or 

iOSGuard

 (iOS) is currently not possible.
