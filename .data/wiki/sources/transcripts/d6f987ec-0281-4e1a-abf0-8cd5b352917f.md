Issue body actions

Problem

When using 

create_agent

 with 

ToolStrategy

 (structured output), the agent sets 

tool_choice="any"

 which 

ChatLiteLLM.bind_tools()

 maps to 

"required"

 ( 

L780-782

https://github.com/langchain-ai/langchain-litellm/blob/v0.6.3/langchain_litellm/chat_models/litellm.py#L780-L782

). This forces Claude to produce only tool calls with no text content, completely suppressing chain-of-thought reasoning.

This is the same issue that was already fixed in:

ChatAnthropic

 : 

langchain-ai/langchain#35544

https://github.com/langchain-ai/langchain/pull/35544

ChatBedrockConverse

 : 

langchain-ai/langchain-aws#927

https://github.com/langchain-ai/langchain-aws/pull/927

Original issue: 

langchain-ai/langchain#35539

https://github.com/langchain-ai/langchain/issues/35539

Expected Behavior

When the model supports thinking (e.g., Claude on Bedrock or Anthropic API), 

bind_tools

 should downgrade 

tool_choice

 from 

"required"

 to 

"auto"

 so the model can produce CoT text before the tool call. The model will still call the required tool, but can reason first.

Current Behavior

bind_tools

 unconditionally maps 

"any"

 to 

"required"

 for all providers:

if tool_choice == "any" or isinstance(tool_choice, bool):
    if tool_choice is True or tool_choice == "any":
        tool_choice = "required"


With 

tool_choice="required"

 , Claude cannot produce any text content alongside tool calls, so all reasoning is lost.

Prior Art

The sister repos fixed the same root cause with slightly different approaches:

ChatAnthropic

 ( 

PR #35544

https://github.com/langchain-ai/langchain/pull/35544

): checks 

self.thinking

 config. If thinking is enabled and 

tool_choice

 is forced ( 

"any"

 or specific tool), drops 

tool_choice

 entirely (defaults to 

"auto"

 ). Emits a warning.

ChatBedrockConverse

 ( 

PR #927

https://github.com/langchain-ai/langchain-aws/pull/927

): checks 

additional_model_request_fields

 for thinking config. If thinking is enabled and 

tool_choice

 is forced, downgrades to 

"auto"

 with a warning.

Both rely on an explicit thinking configuration flag on the model instance. 

ChatLiteLLM

 doesn't currently have a 

thinking

 config, and it supports many providers, so the fix may need a different approach (e.g., model name detection for Claude, or adding a thinking config option).

Reproduction

No API credentials needed. The bug is observable at the 

bind_tools

 level:

from langchain_litellm import ChatLiteLLM
from langchain_core.tools import tool

@tool
def get_data() -> str:
    """Returns some data."""
    return "The answer is 42."

model = ChatLiteLLM(model="bedrock/us.anthropic.claude-opus-4-6-v1", temperature=0)

# This is what create_agent + ToolStrategy does internally:
bound = model.bind_tools([get_data], tool_choice="any")

print(bound.kwargs.get("tool_choice"))
# Expected: "auto" (so Claude can reason before calling tools)
# Actual:   "required" (suppresses all chain-of-thought)


At inference time, with 

tool_choice="required"

 , every AIMessage from Claude has empty 

content

 and only 

tool_calls

 :

# Full agent trace (requires API credentials):
from langchain.agents import create_agent
from langchain.agents.structured_output import ToolStrategy
from langchain_core.messages import HumanMessage
from pydantic import BaseModel

class MyOutput(BaseModel):
    answer: str
    reasoning: str

agent = create_agent(
    model,
    tools=[get_data],
    response_format=ToolStrategy(MyOutput),
)
result = agent.invoke({"messages": [HumanMessage(content="What is the answer?")]})

for msg in result["messages"]:
    if hasattr(msg, "tool_calls") and msg.tool_calls:
        print(f"content: '{msg.content}' | tool_calls: {[tc['name'] for tc in msg.tool_calls]}")
        # Expected: content='Let me look up the data...' | tool_calls=['get_data']
        # Actual:   content='' | tool_calls=['get_data']
