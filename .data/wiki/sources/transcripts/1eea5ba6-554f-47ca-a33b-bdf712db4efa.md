# 9-Arm Skill: THIS SIMPLE & FULLY FREE SKILL-SET IS SO CRAZY!
hi welcome to another video so today I want to talk about a small GitHub repo that I think is way more interesting than it looks at first it is called nine arm skills and it is by thanon now this is not a massive AI coding framework it is not a new IDE it is not trying to replace claw code cursor codeex verdant or anything like that it is basically a focused set of clawed code skills but the interesting part is that these skills are not random prompt templates they are little pieces of engineering discipline they tell the agent how to debug properly review properly write a real postmortem and translate technical work into a managementfriendly update and honestly I think this is the kind of thing a lot of agent workflows are missing because most people try to improve AI coding by adding more capability more models more tools more context more commands but sometimes the highest leverage thing is not more capability sometimes it is better constraints so let's get right into it the repo is organized around a skills folder with buckets like engineering productivity MISK personal in progress and deprecated the shippable skills right now are debug mantra postmortem scrutinize and management talk there is also a script for linking those skills into the local claude skills directory plus claude plug-in metadata that points to the main skills so it is small but it is structured this is not just a notes folder with some markdown files thrown into it now the first skill is debug mantra and this is probably my favorite one debug mantra is basically a rule system for debugging it tells the agent to follow four steps before fixing anything first reproduce the issue second know the failing path third question the hypothesis now fourth treat every run as a breadcrumb that sounds obvious but this is exactly the obvious thing AI agents skip all the time you paste an error and the agent immediately says "I found the issue." And then it edits three files then the error changes then it edits four more files then it says the issue was actually something else and suddenly you're not debugging anymore you're just letting the agent chase symptoms debug mantra is trying to stop that it basically says do not propose a fix until you have a reliable repro do not guess until you have traced the failing path do not trust a hypothesis until you have tried to disprove it that is pretty great because the problem with many coding agents is not that they cannot write code the problem is that they are too eager to write code before they understand the failure this skill adds friction in the right place it makes the agent slower before the fix so the actual fix can be cleaner now the second skill is post-mortem this one is for writing the engineering record after a bug has actually been fixed and the important part is that it refuses to write a postmortem unless the required facts are there if there is no reliable repro stop if the root cause is still unknown stop if the fix is not identified stop if the fix is not validated stop this is super important because AI tools are very good at writing professionallook nonsense they can make a speculative root cause sound final they can turn a guess into an RCA postmortem pushes against that it wants the real root cause the mechanism the fix the validation and the reason the bug slipped through it is written for engineers so file paths function names test names and concrete validation details matter so this is not a fake executive summary it is the record future you can use when the same class of bugs shows up 6 months later the third skill is scrutinize this is a review skill but it is not just a diff checker it asks the agent to stand outside the change and ask whether the change should exist at all and I love that because a lot of AI review is very shallow it looks at the diff checks the obvious lines maybe asks for a test and then says something like "Looks good overall." But real review is not just line review real review asks "What is this change trying to do is there a simpler way does the actual code path produce the behavior of the PR claims what inputs break it are the tests testing the real path that is the value of scrutinize it adds an outsider perspective the implementation agent may already be attached to its own solution the review agent should not be so this is especially useful in agent workflows because agents are great at making their own work sound coherent they write the plan write the code then summarize the code in a way that agrees with the plan but coherent does not mean correct scrutinize is the colder second look then the fourth skill is management talk this one is not really a coding skill it takes engineer to engineer content and rewrites it for engineering leadership PMs release managers or similar audiences and that is useful because engineering work does not always end when the code is fixed sometimes you need a Jira update a slack post a standup line or a quick leadership summary without dumping function names and stack traces into the message management talk keeps the important tracking details like product names ticket ids PR numbers impact owner and next steps but strips the code level details that the audience cannot act on so it is not dumbing things down it is translating the same truth to the right channel now when you put these four skills together the shape is very clear debug properly review properly write the engineering record properly communicate the result properly that is a really nice loop around serious bug work and that is why I think this repo is worth talking about even though it is small now let's come to the verden angle nine arm skills is built for claude code so if you're
