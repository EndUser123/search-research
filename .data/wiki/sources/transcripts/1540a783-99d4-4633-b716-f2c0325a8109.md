Question: Structured Output Strategy - How does it compare to other libraries?

Context

I'm exploring Pydantic-AI for structured output handling and would like to understand how its approach compares to other libraries in the ecosystem, particularly Instructor and similar tools that leverage native structured/function calling APIs.

Current Understanding

From what I can tell, there are two main approaches to handling structured outputs:

API-Level Schema Enforcement

 (e.g., Instructor):

Leverages OpenAI's function calling API

Schema validation happens during the API call

Built-in streaming validation and automatic retry mechanisms

Potentially more efficient due to native API integration

Post-Response Validation

 (Pydantic-AI's approach):

Uses tool calling pattern with Pydantic models

Validation occurs after receiving the LLM response

Model-agnostic implementation

Integrates with broader features (DI, cost tracking)

Questions

What were the technical considerations behind choosing post-response validation over API-level schema enforcement?

Are there performance implications (e.g., token usage, retry rates) between these approaches?

As more providers implement native structured output APIs, are there plans to support both approaches?

What specific advantages does the current implementation offer for complex AI applications that might outweigh native function calling?

Additional Context

This question comes from building production systems where output reliability and cost efficiency are key concerns. Understanding the trade-offs would help in making informed architectural decisions.

I don't think your characterization is quite right.

tools calls vs. structured outputs

Using tool calls vs. "structured outputs" for the return value, see 

#582

https://github.com/pydantic/pydantic-ai/issues/582

.

Currently PydanticAI always uses tool calls to for structured responses. While this works really well in most scenarios, I do think there are cases where "structured responses" would be preferable, particularly smaller models that implement the OpenAI interface, e.g. some Ollama models. Structured responses might also be better at streaming.

But implementing this kind of structured responses is quite a lot of work.

OpenAI's "strict" model

To better enforce the return type, see 

#81 (comment)

https://github.com/pydantic/pydantic-ai/issues/81#issuecomment-2557376878

.

This is slower and more expensive, and still doesn't guarantee you get valid data back, so you still need pydantic validation on the response data.

We'll probably add both at some point, but it's not the number one priority.
