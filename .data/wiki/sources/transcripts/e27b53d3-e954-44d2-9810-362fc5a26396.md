# Google's WebMCP: Why Every Website Will Need This by 2027
watch an AI agent try to use a website it opens the page takes a screenshot and starts guessing which box is the search which button actually submits it is squinting at pixels hoping it picked right that is how almost every agent works today it cannot really see your buttons it sees a flat picture of pixels and just hopes it clicks the right one now watch the new way the website simply hands the agent the controls one clean typed call and the task is done no squinting no guessing no second screenshot this is WebMCP the web model context protocol a way for any website to speak straight to AI agents built right into the browser itself and the whole idea fits in three words: publish tools not pixels your site stops being a wall of buttons an agent has to decode and becomes a clean menu of actions it can simply call by name it is the same model context protocol behind today's AI tools but instead of a separate server your page itself becomes the server right inside the tab and it is dramatically leaner reading a page as a screenshot can burn 2,000 tokens a structured tool call costs around 50 here is why it matters by 2027 if an agent can finish the job on your site but fumbles on your rivals the agent sends every user straight to you built by Google and Microsoft together through the W3C and shipping in Chrome right now so let us take it apart start with the problem for 30 years we have built the web for human eyes color layout icons buttons you understand the instant you see them all of that meaning lives in the visuals and a person fills in the rest without even thinking about it so how do agents browse at all today mostly by brute force computer use models and automation frameworks that move a virtual mouse read the raw page structure or snap screenshots and reason over them it looks brilliant in a demo in the real world it is fragile because that whole approach is a guessing loop people call it actuation grab a screenshot find a likely pixel click it grab another screenshot and check whether anything changed the agent is reading your interface the way you would read a foreign newspaper through frosted glass and it is painfully brittle move one button rename a label ship a small redesign and the agent's carefully learned script just shatters it clicks where the button used to be hits empty space and the whole task silently fails no error no a tiny tool server running right there in the browser tab no extra backend to deploy no new API to host the page you already ship simply announces what it can do if you have heard of MCP this clicks navigator.mmodel context things like search flights add to cart or file a ticket each one declared upfront ready to be called second discover when an agent lands on the page it does not stare at pixels anymore it asks the browser one simple question what can I do here and gets back a structured list of every tool each with a plain language description of exactly what it does third invoke the agent picks the right tool and calls it with typed parameters the same way it would call any function an origin a destination a date no hunting for a button no fragile click no second screenshot just to confirm something happened fourth respond your own code runs the action and hands back structured data the model can read directly the search results a confirmation and order number the model reads it decides the next move and the loop continues cleanly until the job is finished and a tool is not some heavy new framework it is just four small things a name a description in plain English an input schema that defines the parameters and an execute function that actually does the work that is the entire contract if you have ever defined a function you already know this there are two ways to add these tools and the first is almost too easy it is called the declarative API and it works on plain HTML forms no JavaScript at all you take a form you already have on the page and you simply annotate it you add two attributes a tool name and a tool description that is genuinely it the browser reads the form turns its fields into a structured schema and offers it to agents automatically as one engineer put it if your forms are already clean you are 80% of the way there and here's a neat touch when an agent submits one of those forms your code receives a flag agent invoked that tells you a machine did it not a human you can even respond with a structured result straight back to the model one form quietly serves both a person and an agent the second way is the imperative API pure JavaScript for richer dynamic tools you call register tool hand it a schema and a function and you can build anything a live pricing lookup a multi-step booking a product filter there is even a method to swap the whole tool set as your app changes state and it is a real two-way conversation your tool can return a clean result or a clear descriptive error wrong date sold out missing field the agent reads that error understands what went wrong and corrects itself instead of blindly clicking the same broken thing again and again a few habits make tools that agents love name them with precise verbs so create event is never confused with start event creation keep schemas simple accept a plain time string do not make the model do math validate strictly in your code and return clear errors do that and the agent rarely needs a second try so why is this so much better because a tool is a contract not a guess you can redesign your entire page move every button change the whole layout overnight and
