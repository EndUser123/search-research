Claude Code Hook Templates

Production-ready hooks for Claude Code. Copy, paste, run. 

 

 

About

A comprehensive collection of production-ready hooks covering all 8 Claude Code lifecycle events. Includes safety guards, autonomous TDD workflows, PR approval gates, cost controls, and more.

How Hooks Work

Hooks are scripts that run at specific points in the Claude Code lifecycle. They receive JSON input on stdin and control behavior through exit codes.

Exit Code Behavior:

0

 - Allow the action to proceed

2

 - Block the action (stderr message is sent back to Claude as feedback)

Other - Non-blocking error (action proceeds, error is logged)

Basic Flow:

Claude triggers action
       |
       v
Hook script runs (receives JSON on stdin)
       |
       v
Exit code determines outcome
       |
       +---> 0: Action allowed
       +---> 2: Action blocked (stderr sent to Claude)
       +---> Other: Error logged, action proceeds


Lifecycle Events

Claude Code hooks can run at 8 different lifecycle events:

Event

When It Runs

Use Cases

SessionStart

When a new session begins

Load context, create branches, set up environment

UserPromptSubmit

Before processing user input

Validate prompts, inject context, log requests

PreToolUse

Before a tool executes

Block dangerous commands, protect files, audit

PostToolUse

After a tool executes

Format code, run tests, send notifications

Notification

When events occur

Desktop alerts, Slack notifications

Stop

Before session ends

Enforce quality gates, save checkpoints

SubagentStop

Before subagent completes

Validate subagent work, run tests

PreCompact

Before transcript compaction

Backup transcripts, preserve context

Writing Custom Hooks

Bash Template

#!/bin/bash
set -euo pipefail

# Read JSON input from stdin
INPUT=$(cat)

# Parse fields using jq
TOOL_NAME=$(echo "$INPUT" | jq -r '.tool_name // empty')

# Implement your logic
if [[ "$TOOL_NAME" == "dangerous" ]]; then
    echo "Blocked: This operation is not allowed" >&2
    exit 2  # Block the action
fi

exit 0  # Allow the action


Python Template

#!/usr/bin/env python3
import json
import sys

# Read JSON input from stdin
input_data = json.load(sys.stdin)

# Implement your logic
if should_block(input_data):
    print("Blocked: reason for blocking", file=sys.stderr)
    sys.exit(2)  # Block the action

sys.exit(0)  # Allow the action


Injecting Context

Hooks can inject additional context into the session by outputting JSON:

cat << EOF
{
  "hookSpecificOutput": {
    "hookEventName": "SessionStart",
    "additionalContext": "Your context here"
  }
}
EOF


Hook Input JSON

Each hook receives JSON on stdin with event-specific data:

{
  "session_id": "abc123",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": {
    "command": "npm test"
  }
}


Fields vary by event type. Common fields include:

session_id

 - Unique identifier for the session

hook_event_name

 - The lifecycle event that triggered the hook

tool_name

 - Name of the tool being used (for tool-related events)

tool_input

 - Input parameters for the tool

prompt

 - User prompt text (for UserPromptSubmit)

stop_hook_active

 - Whether stop hooks are active (for Stop events)
