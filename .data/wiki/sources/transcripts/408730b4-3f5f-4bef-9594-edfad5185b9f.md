Feature Request: Enable YouTube Transcript Download

Summary

Currently, the Obsidian Web Clipper can recognize YouTube links, but it lacks the capability to directly fetch and import transcripts. By leveraging the 

official YouTube Data API

 (using a personal API key), we can reliably download transcripts for most videos and sidestep the fragility of scraping YouTube pages.

Proposed Functionality

Personal API Key Integration

A field in the plugin settings allows users to enter their YouTube Data API key.

The clipper uses this key to make calls to the YouTube Data API for transcripts.

Transcript Download via YouTube Data API

When clipping a YouTube link (already recognized by the clipper), use the 

[captions.list](https://developers.google.com/youtube/v3/docs/captions/list)

https://developers.google.com/youtube/v3/docs/captions/list

 endpoint to find available captions for that video.

If captions are found, use 

[captions.download](https://developers.google.com/youtube/v3/docs/captions/download)

https://developers.google.com/youtube/v3/docs/captions/download

 to retrieve them (in SRT, TTML, or other available formats).

Parsing & Inserting into Obsidian

Convert the downloaded file (e.g., SRT) into plain text or Markdown.

Insert the transcript and optional metadata (video title, channel, timestamps) into the user's Obsidian vault.

Why Avoid Scraping 

ytd-transcript-segment-list-renderer

Unreliable

: Scraping front-end HTML elements (like 

.ytd-transcript-segment-list-renderer

 ) can break without notice if YouTube changes its layout or naming conventions.

Failure-Prone

: Relying on something like 

{{selectorHtml:.ytd-transcript-segment-list-renderer|first|replace:"&nbsp;":" "|join|markdown}}

 may fail outright if the DOM structure changes.

Against Policy

: Direct scraping may violate YouTube's terms of service, whereas using the YouTube Data API is fully documented and supported.

Potential Limitations

Auto-Generated vs. User-Uploaded Captions

: Auto-generated captions are often restricted and may require being the channel owner or having special permissions; otherwise, you'll get a 

403 Forbidden

 .

Quota & Rate Limits

: Each request to the YouTube Data API counts against the user's personal quota. Users must be mindful of API usage.

API Key Security

: The plugin must store this key securely to prevent unauthorized use.

Implementation Steps

Settings Page

Let the user enter and save their YouTube Data API key in the Web Clipper's settings.

API Requests

Use 

captions.list

 to get available caption IDs.

Prompt the user to select a caption track (if multiple).

Call 

captions.download

 to retrieve the SRT (or TTML) transcript.

Transcript Handling

Parse the file into human-readable text or Markdown.

Insert the transcript plus relevant metadata into a new or existing note.

Conclusion

By integrating a 

personal YouTube Data API key

 for transcript downloads, the Obsidian Web Clipper will avoid the 

unreliable

 and 

failure-prone

 approach of scraping DOM elements like 

ytd-transcript-segment-list-renderer

 . This ensures a more robust, compliant, and future-proof method of capturing YouTube transcripts directly into Obsidian.

Feature Request Update: Enhanced YouTube Transcript Extraction for Clipper

Thank you for considering the addition of a feature to extract YouTube transcripts via the Clipper. After extensive research and some testing, I identified three potential approaches, each with its strengths and challenges.

I'm putting it here in case you ever consider this and some sample code for completeness in may save others time when consider features and options.

:

1. 

YouTube Data API v3 (OAuth Required)

The 

YouTube Data API v3

 offers an official method to access YouTube captions, but there are significant limitations:

Requires OAuth 2.0:

 API keys cannot access restricted resources like auto-generated captions. OAuth authentication is mandatory.

Works Only for Owned Videos:

 OAuth only grants access to captions for videos that are uploaded by the authenticated user.

Limited Use Cases:

 This method isn't viable for public transcripts of third-party videos.

While this is the most compliant and robust solution for owned content, it does not address use cases where transcripts for publicly available videos are required.

2. 

Using Timedtext API (Fragile and Inconsistent)

An older method involves directly querying YouTube's internal 

Timedtext

 endpoint to retrieve transcripts. This method:

Fragile:

 Relies on undocumented YouTube APIs and is subject to breaking changes if YouTube updates its backend.

Success Rates Vary:

 In my tests, this method often failed or returned incomplete results, making it unreliable for consistent transcript extraction.

Given its instability and lack of official support, this approach may not be suitable for inclusion in the Clipper.

3. 

Scraping YouTube's Web Data ( ytInitialPlayerResponse )

The most flexible and broadly applicable method involves scraping the 

ytInitialPlayerResponse

 object, which is part of YouTube's web player data. This method:

Reliable:

 Successfully extracts transcripts for many public videos.

Versatile:

 Works for both user-provided and auto-generated transcripts.

Sample Implementation:

 Below is a sample JavaScript implementation adapted from [ 

Nidhin Kumar's blog

https://blog.nidhin.dev/extracting-youtube-transcripts-with-javascript

]( 

https://blog.nidhin.dev/extracting-youtube-transcripts-with-javascript

https://blog.nidhin.dev/extracting-youtube-transcripts-with-javascript

):

 * youtubeTranscriptPlayerResponse.js
 *
 * Place this file in your .obsidian/scripts/ folder.
 *
 * In your Templater template, call:
 *
 *   <%*
 *   const videoId = await tp.system.prompt("Enter the YouTube video ID or URL:");
 *   const transcript = await tp.user.youtubeTranscript(tp, videoId);
 *   tR += transcript;
 *   %>
 */

module.exports = async function youtubeTranscript(videoInput) {
  console.log("Received videoInput:", videoInput);

  // 1) Check if videoInput is valid
  if (!videoInput) {
    console.log("Error: videoInput is undefined or empty!");
    return "Error: No valid video ID provided.";
  }

  // 2) Extract the videoId from either a full URL or just an ID
  function extractVideoId(input) {
    try {
      const url = new URL(input.trim());
      const id = url.searchParams.get("v") || "";
      console.log("Extracted ID:", id);
      return id;
    } catch (err) {
      // If parsing fails, assume it's already a raw ID
      console.log("Error parsing URL, returning raw input:", input.trim());
      return input.trim();
    }
  }

  const videoId = extractVideoId(videoInput);
  if (!videoId) {
    console.log("Error: No valid video ID extracted.");
    return "Error: Invalid video ID.";
  }

  // 3) Fetch the watch page and parse out the caption tracks
  console.log("Fetching watch page to retrieve captions...");
  const captionsData = await fetchPlayerCaptions(videoId);

  if (!captionsData || captionsData.error) {
    return `Error: ${
      captionsData ? captionsData.error : "Failed to fetch captions from watch page."
    }`;
  }

  return captionsData.transcriptText;
};

/**
 * Fetch captions from the watch page's ytInitialPlayerResponse JSON.
 * We look for a suitable English track (if available), or default to the first track.
 * Then we fetch it in JSON format (&fmt=json3) and organize it into 30-second chunks.
 */
async function fetchPlayerCaptions(videoId) {
  const watchUrl = `https://www.youtube.com/watch?v=${videoId}`;

  try {
    const response = await requestUrl(watchUrl);
    if (response.status < 200 || response.status >= 300) {
      return { error: `Failed to fetch watch page: HTTP ${response.status}` };
    }
    const body = response.text;
    const YT_INITIAL_PLAYER_RESPONSE_RE =
      /ytInitialPlayerResponse\s*=\s*({.+?})\s*;\s*(?:var\s+(?:meta|head)|<\/script|\n)/;

    const match = body.match(YT_INITIAL_PLAYER_RESPONSE_RE);
    if (!match) {
      return { error: "Unable to locate ytInitialPlayerResponse in watch page HTML." };
    }

    const playerResponse = JSON.parse(match[1]);
    const tracks =
      playerResponse?.captions?.playerCaptionsTracklistRenderer?.captionTracks || [];
    if (!tracks.length) {
      return { error: "No caption tracks available for this video." };
    }

    tracks.sort((t1, t2) => {
      if (t1.languageCode === "en" && t2.languageCode !== "en") return -1;
      if (t1.languageCode !== "en" && t2.languageCode === "en") return 1;
      if (t1.kind !== "asr" && t2.kind === "asr") return -1;
      if (t1.kind === "asr" && t2.kind !== "asr") return 1;
      return 0;
    });

    const chosenTrack = tracks[0];
    if (!chosenTrack?.baseUrl) {
      return { error: "Chosen track does not have a baseUrl." };
    }

    const captionsJsonUrl = chosenTrack.baseUrl + "&fmt=json3";
    const captionsRes = await fetch(captionsJsonUrl);
    if (!captionsRes.ok) {
      return { error: `Failed to fetch track: HTTP ${captionsRes.status}` };
    }
    const transcriptJson = await captionsRes.json();

    const events = transcriptJson.events || [];
    const chunkSize = 30; // 30 seconds per chunk
    const transcriptChunks = [];

    let currentChunkStart = 0;
    let currentChunkText = "";

    // Process events into chunks
    events
      .filter((e) => e.segs) // Ensure the event has text segments
      .forEach((e) => {
        const startSeconds = e.tStartMs ? parseFloat(e.tStartMs) / 1000 : 0;
        const text = e.segs
          .map((seg) => seg.utf8)
          .join(" ")
          .replace(/[\u200B-\u200D\uFEFF]/g, ""); // Remove special chars

        // If the current event's timestamp exceeds the current chunk window
        if (startSeconds >= currentChunkStart + chunkSize) {
          // Save the current chunk
          transcriptChunks.push(
            `[${new Date(currentChunkStart * 1000).toISOString().substr(11, 8)}] ${currentChunkText.trim()}`
          );
          // Move to the next chunk
          currentChunkStart += chunkSize;
          currentChunkText = "";
        }

        // Add the current text to the current chunk
        currentChunkText += ` ${text}`;
      });

    // Add the last chunk if there's remaining text
    if (currentChunkText.trim()) {
      transcriptChunks.push(
        `[${new Date(currentChunkStart * 1000).toISOString().substr(11, 8)}] ${currentChunkText.trim()}`
      );
    }

    // Combine all chunks with double newlines for separation
    const transcriptText = transcriptChunks.join("\n\n");

    return {
      transcriptText,
      metadata: {
        title: playerResponse?.videoDetails?.title,
        author: playerResponse?.videoDetails?.author,
        duration: playerResponse?.videoDetails?.lengthSeconds,
      },
    };
  } catch (err) {
    return { error: `Exception: ${err.message}` };
  }
}



Recommendation

Based on these findings, regardless of clipper getting transcripts is not straightforward:

Default to API v3 for Owned Content:

 Use OAuth to support users who want transcripts for 

their

 uploaded videos. While limited, this method is officially supported by YouTube and ensures compliance. So does not really fly as general feature.

Provide ytInitialPlayerResponse Scraping as an Optional Feature:

 Implement scraping for public transcripts as an advanced feature with clear disclaimers about its potential fragility and terms of service implications. Works.

Avoid Timedtext API:

 Due to its unreliability and lack of documentation, not recommend against pursuing this method.

Hopefully it will save people time when pondering the options and whats pragmatic
