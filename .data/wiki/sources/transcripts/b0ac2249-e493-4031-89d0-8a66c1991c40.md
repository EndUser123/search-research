Issue body actions

"Integrate Aider ( 

https://github.com/Aider-AI/aider

https://github.com/Aider-AI/aider

) as a backend AI coding agent to handle code editing, git operations, and multi-file project management within claude-task-master workflows."

Motivation

Aider has become a critical tool for developers using LLMs to edit codebases directly in their terminal, offering unique advantages:

Codebase Awareness

: Maintains context across entire projects (unlike chat-only interfaces)

Git Integration

: Automatically tracks changes with commit messages

Multi-Model Support

: Already aligns with claude-task-master's philosophy of model flexibility

Terminal-Centric Workflow

: Complements claude-task-master's CLI/editor-agnostic approach

Current limitations without this integration:

Users must manually copy/paste code between claude-task-master and Aider

No unified interface for task management and code implementation

Duplicate configurations for model providers

Proposed Solution

High-Level Feature

: Add Aider as a configurable execution backend that handles code-related tasks (implementation, refactoring, testing) while retaining claude-task-master's core strengths in task planning and research.

Relevant Technologies

:

Aider's CLI wrapper

Shared configuration for API keys/model providers

Task context passing via temporary files or in-memory state

Workflow Integration

:

[Task Master] → (Task Planning/Research) → [Aider] → (Code Edits) → [Git] → [Project]


High-Level Workflow

Phase 1: Configuration & Basic Delegation

Add 

aider

 as a configurable agent type in 

mcp.json

Create shared API key management for overlapping providers (Anthropic, OpenAI)

Implement basic task delegation: 

task-master implement --agent=aider

Phase 2: Context-Aware Integration

Pass project file structure/metadata to Aider

Sync task descriptions and acceptance criteria as Aider chat context

Parse Aider's git output into claude-task-master's task tracking

Phase 3: Bidirectional Communication

Surface Aider's /commands (e.g., 

/test

 , 

/commit

 ) in claude-task-master UI

Forward linting/test results back to task tracking system

Key Elements

New Configuration Options

:

"agents": {
  "aider": {
    "path": "/usr/local/bin/aider",
    "model": "claude-4-opus-20250514"
  }
}


CLI Enhancements

:

New 

--agent

 flag for 

implement

 , 

fix

 , 

refactor

 commands

task-master sync-git

 command to map Aider's commits to task completion

UX Changes

:

Visual indicator when Aider is active

Toggle between raw LLM and Aider-mediated responses

Example Workflow

# User initiates a coding task
$ task-master next
→ Task 3: Implement JWT authentication middleware in src/auth.js

# Deploys task to Aider with project context
$ task-master implement 3 --agent=aider --files=src/auth.js,package.json
→ [Aider] Starting session with claude-3-opus...
→ [Aider] Added src/auth.js to chat
→ [Aider] Generated diff (saved to .aider.patch)
→ [Git] Commit 3a8bdd9: "Implement JWT middleware (Task #3)"

# Verify integration
$ task-master status 3
→ COMPLETED - Linked to commit 3a8bdd9


Implementation Considerations

Dependencies

:

Aider must be installed and in PATH

Shared model provider configurations (API keys, model versions)

Backward Compatibility

:

Existing 

implement

 command remains default (direct LLM)

New features opt-in via 

--agent

 flag

Performance

:

Subprocess spawning for Aider CLI adds ~200-500ms overhead

Recommended to use Aider's persistent chat mode ( 

--chat

 ) for multi-task sessions

Out of Scope (Future Considerations)

Real-time collaboration between Aider and other agents

Automatic conflict resolution between multiple AI agents

Custom command mappings between claude-task-master and Aider

Direct integration with Aider's voice interface
