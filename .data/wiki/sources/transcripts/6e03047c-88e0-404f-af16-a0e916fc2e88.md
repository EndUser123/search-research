AWS S3 Object Lock Batch Operations Toolkit

A comprehensive suite of shell scripts for applying AWS S3 Object Lock retention policies and legal holds to existing objects using S3 Batch Operations. This toolkit automates the process of bulk applying object protection policies across thousands of objects efficiently.

🎯 Overview

This project provides automated scripts to:

Apply object lock retention policies (GOVERNANCE/COMPLIANCE modes)

Set legal holds on S3 objects

Monitor batch operation progress in real-time

Generate comprehensive reports with failure analysis

Handle prerequisites automatically (versioning, object lock configuration)

Key Benefits:

✅ Bulk operations on thousands of objects

✅ Interactive user input validation

✅ Automatic prerequisite configuration

✅ Real-time progress monitoring

✅ Comprehensive error reporting

✅ Cross-platform compatibility (Linux/macOS)

📝 Script Descriptions

1. upload_objects.sh / upload_objects.py [OPTIONAL]

Purpose

: Upload test objects to S3 bucket for testing batch operations

Features:

Creates 1000 test objects with unique content

Progress tracking every 100 objects

Cross-platform compatibility

Both shell and Python versions available

When to use:

Testing the batch operation scripts

You have an empty bucket and need sample data

Demonstrating the functionality

Skip if:

You already have objects in your S3 bucket

Working with production data

2. setup_permissions.sh [REQUIRED]

Purpose

: Create IAM role and attach required permissions for S3 Batch Operations

What it does:

Creates 

batch-operations-role

 IAM role

Attaches trust policy for S3 Batch Operations service

Grants minimum required permissions for batch operations

Displays role ARN and permission summary

Output:

✓ IAM role setup completed successfully!
Role Name: batch-operations-role
Role ARN: arn:aws:iam::123456789012:role/batch-operations-role


3. create_batch_job_for_object_lock_mode.sh [MAIN SCRIPT]

Purpose

: Apply object lock retention policies to all objects in S3 bucket

Features:

Interactive prompts for bucket, region, mode, and retention period

Automatic bucket versioning enablement

Automatic Object Lock configuration

Support for GOVERNANCE and COMPLIANCE modes

Shows a clear disclaimer when user says COMPLIANCE mode

Reconfirms if user wants to proceed with COMPLIANCE mode

Real-time job monitoring

Comprehensive failure analysis

Detailed progress reports

User Inputs:

S3 bucket name

AWS region

Object lock mode (GOVERNANCE/COMPLIANCE)

Retention period in days

4. create_batch_job_for_legal_hold.sh [OPTIONAL]

Purpose

: Apply legal holds to all objects in S3 bucket

Features:

Similar functionality to object lock script

Applies legal hold status "ON" to all objects

Independent operation (can run without step 3)

Real-time monitoring and reporting

Note

: Legal holds prevent object deletion regardless of retention policies

🔒 Object Lock Modes

GOVERNANCE Mode

Characteristics:

Objects can be deleted by users with 

s3:BypassGovernanceRetention

 permission

Retention period can be shortened by authorized users

Suitable for most compliance requirements

Provides flexibility for authorized operations

Use Cases:

Internal compliance policies

Data retention for auditing

Temporary protection during processing

COMPLIANCE Mode

⚠ CRITICAL WARNING:

Objects 

CANNOT

 be deleted by 

ANYONE

, including root user

Retention period 

CANNOT

 be shortened

Only way to remove objects is to 

DELETE THE ENTIRE AWS ACCOUNT

Use only for strict regulatory compliance

Use Cases:

SEC regulations (financial records)

HIPAA compliance (healthcare data)

Legal discovery holds

Regulatory archival requirements

Compliance Mode Confirmation:

DISCLAIMER: In compliance mode, a protected object version can't be overwritten 
or deleted by any user, including the root user in your AWS account. When an 
object is locked in compliance mode, its retention mode can't be changed, and 
its retention period can't be shortened. The only way to delete an object under 
the compliance mode before its retention date expires is to delete the 
associated AWS account.

🛠 Troubleshooting

Installation Issues

AWS CLI not found:

# Install AWS CLI v2
curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
unzip awscliv2.zip
sudo ./aws/install


jq not found:

# Ubuntu/Debian
sudo apt-get update && sudo apt-get install jq

# macOS
brew install jq

# CentOS/RHEL
sudo yum install jq


Permission Issues

Access Denied Errors:

Verify AWS credentials: 

aws configure list

Test basic access: 

aws s3 ls

Check IAM permissions in AWS Console

Ensure user has required permissions listed in prerequisites

chmod +x *.sh

bash --version  # Should be 4.0+

High failure rate:
