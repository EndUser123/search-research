# Claude Code Dynamic Workflows Explained for Beginners
<b>This is not a normal Claude Code session.</b>

<b>What you're seeing here is Claude Code</b>

<b>spinning up a dynamic workflow,</b>

<b>which means it's written its own</b>

<b>orchestration script,</b>

<b>and it's now fanning out all of this work</b>

<b>to different agents.</b>

<b>At the moment, we've got 351 agents</b>

<b>running at the same time,</b>

<b>going through all of</b>

<b>these different items.</b>

<b>Basically, for each of these items, I've</b>

<b>asked Claude to analyze</b>

<b>the transcript of a video</b>

<b>and apply very specific rules for</b>

<b>generating new title ideas.</b>

<b>This is something that would not be</b>

<b>possible with a</b>

<b>normal Claude Code session,</b>

<b>even if you try to use subagents.</b>

<b>The Claude Code dynamic workflow is</b>

<b>Claude will write its</b>

<b>own orchestration script,</b>

<b>which will then run things to hundreds of</b>

<b>parallel subagents in a single session.</b>

<b>I do want to mention that this is not</b>

<b>just useful for coding tasks,</b>

<b>it's also useful for non-coding tasks.</b>

<b>Think about it like this.</b>

<b>You pass a prompt to Claude Code,</b>

<b>which is going to touch a lot of</b>

<b>different files or</b>

<b>actually a bunch of items.</b>

<b>Maybe you want to respond to a whole</b>

<b>bunch of emails or support tickets,</b>

<b>or in my case, audit</b>

<b>hundreds of YouTube videos.</b>

<b>For each of those items,</b>

<b>it's very much the same prompt.</b>

<b>We set the rules on how</b>

<b>Claude needs to process each item</b>

<b>and Claude will fan out hundreds of</b>

<b>agents to perform that work for you.</b>

<b>By the end of the session, the results</b>

<b>can be merged into a final</b>

<b>report or a final code base</b>

<b>or whatever that</b>

<b>final output needs to be.</b>

<b>Dynamic workflows are now generally</b>

<b>available, so all of</b>

<b>you can start using it.</b>

<b>In this video, we will have a look at</b>

<b>when you should use dynamic workflows</b>

<b>and when you should avoid it entirely.</b>

<b>So we'll go through all</b>

<b>the best practices together.</b>

<b>Well, I think the best way</b>

<b>to learn dynamic workflows</b>

<b>is to build a new workflow that you can</b>

<b>use in your own applications right now.</b>

<b>In order to start a dynamic workflow,</b>

<b>what you have to do is actually tell</b>

<b>Claude Code explicitly to use a workflow.</b>

<b>My advice would be to</b>

<b>do something like this.</b>

<b>Start your prompt with Ultra Code,</b>

<b>followed by use a</b>

<b>workflow for the following.</b>

<b>Now we can tell</b>

<b>Claude what we want to do.</b>

<b>I do not recommend using dynamic</b>

<b>workflows for very simple tasks.</b>

<b>If you know for a fact that that task can</b>

<b>be achieved in a single session,</b>

<b>by all means rather</b>

<b>implemented in a single session,</b>

<b>then using workflows unnecessarily.</b>

<b>The reason is that</b>

<b>workflows are expensive.</b>

<b>Keep in mind we're kicking off multiple</b>

<b>Claude Code sessions,</b>

<b>and each of those will have their own</b>

<b>system prompts and context,</b>

<b>and all the tool calls,</b>

<b>everything available in it.</b>

<b>So you are going to burn through a lot of</b>

<b>tokens really quickly.</b>

<b>Dynamic workflows are really great if</b>

<b>you've got a task that</b>

<b>you need to repeat at scale.</b>

<b>So there's a specific task or action that</b>

<b>you need to perform,</b>

<b>In that instance, this</b>
