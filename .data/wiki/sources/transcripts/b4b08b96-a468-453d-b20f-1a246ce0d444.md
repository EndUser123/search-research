What is an MCP?

The 

Model Context Protocol (MCP)

 was introduced in 2024, spearheaded by OpenAI and other contributors in the AI ecosystem. It was developed to provide additional information to AI Models (such as ChatGPT, Claude, etc.) by standardising how they connect to external tools, data sources, and APIs 

[1][4]

.

You can think of MCPs as being universal adapters — a way to provide industry standard large language models (LLMs) with your own information, without a need to train or develop your own model.

Example flowchart of MCP

We've reached an inflection point where the most significant gains will come not from marginally better AI models, but from solving this fundamental integration problem [3].

Why are MCPs important?

Before the MCP protocol existed, developers had to create a custom plug-ins or adapters for every use-case, and every model — this is a timely task, potentially a significant cost to maintain. With an MCP, you setup your instance once and it is shareable across any supporting models.

LLMs may not have access to your technical implementations or private business data by default. With MCPs you can expose this additional data directly to the model, without that data being used to train a model 

(privacy configurations dependant)

. In a corporate environment, especially involving confidential technical data, MCPs provide a new approach — you can now run your development agents with that missing context through additional tools, such as:

API Schemas

Database Schemas

GIT Repositories

Issue Trackers

CI/CD Pipelines

Documentation Systems

Logs

etc.

The Large Language Model (LLM) at the agent's core then 

reasons

 about the user's request, autonomously selects the appropriate tool (or sequence of tools) from its available “toolbox,” and executes it to achieve the goal [3].

Whilst you can expose tooling, just adding additional technical data context has the ability to provide a vast improvement in the outcome of development work 

[2]

.

Disclaimer: It is very important to assess ethical, legal and moral considerations before implementing MCPs — as with creating any software. This is especially vital when planning to integrate sensitive / private data.

Example Python MCP Overview

The following walks through an example scenario where we have a database schema with multiple tables and relations, and a JSON RESTful API Schema representing a desired API implementation.

The hypothesis is that providing additional business context through an MCP to an AI agent IDE (such as Cursor with 

claude-4-sonnet

 ), will enable it to generate API code implementation to a standard not possible without that context.

Example Python MCP Implementation

The project has a simple directory structure:

# Project structure example
mcp_service/
├── schemas/api_schema.json
├── schemas/db_schema.sql
└── service.py


This script acts as the main MCP server, it has two resource functions that are used to provide the schemas — these read the files and return the data alongside additional formatting.

The following MCP functions are available within FastMCP:

@mcp.tool

 used when you wish an AI agent to be able to perform an action or fetch data on demand.

@mcp.resource

 provides static, read-only context throughout a session. These are used to provide reference material that doesn't change often.

@mcp.config

 structured configuration data, used to define how an MCP server should run.

@mcp.event

 allows streaming or subscribing to real-time events, instead of just pulling data on demand.

@mcp.prompt

 a way to expose reusable prompt templates or system instructions, for example a reusable CLI command.

import json
from fastmcp import FastMCP
# Initialise MCP service
mcp = FastMCP("BlogPostMCP")
# Tools that AI agents can use
@mcp.tool
def get_api_schema() -> str:
    """Get the API schema as a JSON string for reference."""
    with open("schemas/api_schema.json", "r") as f:
        return f.read()
@mcp.tool
def get_db_schema() -> str:
    """Get the database schema as SQL for reference."""
    with open("schemas/db_schema.sql", "r") as f:
        return f.read()
# Resources for read-only access
@mcp.resource("resource://api-schema")
def api_schema():
    """Provides the API schema for reference."""
    with open("schemas/api_schema.json", "r") as f:
        content = f.read()
    
    return {
        "uri": "resource://api-schema", 
        "name": "API Schema",
        "description": "JSON schema for the API",
        "text": content
    }
@mcp.resource("resource://db-schema")
def db_schema():
    """Provides the database schema for reference."""
    with open("schemas/db_schema.sql", "r") as f:
        content = f.read()
    
    return {
        "uri": "resource://db-schema",
        "name": "Database Schema", 
        "description": "SQL schema for the database",
        "text": content
    }
if __name__ == "__main__":
    mcp.run(transport="sse", port=8000)

MCP Security Considerations

When building MCPs it is critical to carefully consider security boundaries. Exposing private business or technical data could quickly become a data leakage risk if not controlled. At minimum, MCPs should look to implement safeguards such as:

Authentication and authorisation

 — require tokens or API keys before granting access.

Role-based access control (RBAC)

 — only expose the minimum resources each role needs 

[11]

.

Sanitisation

 — avoid exposing sensitive credentials or personally identifiable information in schemas.

Audit logging

 — capture when and how the MCP was accessed for compliance purposes.

What other use-cases are there?

There are as many use-cases for MCPs as you can imagine but some current industry implementations include:

Automated security reviews

By connecting MCPs to code repositories, dependency manifests and vulnerability databases, an agent can automatically scan for CVEs, flag insecure code patterns, or even raise pull requests with recommended patches. One such paper describes an MCP developed to flag cloud compliance and governmental risks at an early stage 

[10]

.

Observability and incident response

Exposing logs, monitoring dashboards (for example Prometheus or Grafana) and runbooks through MCPs enables an agent to investigate incidents, correlate errors across services and suggest remediation steps. Early adopters in cloud operations are using this to reduce mean time to resolution. The Grafana MCP already has over 1.6k Github stars 

[9]

.

CRM and sales support

MCPs are being integrated into customer relationship management systems. For instance, Salesforce (via Agentforce) is experimenting with MCP-style connectors that allow agents to fetch customer data, generate account summaries, and trigger workflows directly 

[3]

.

Enterprise search and knowledge management

Documentation systems such as Confluence, SharePoint or Notion can be exposed as MCP resources. This allows an agent to reason across multiple sources, draft standard operating procedures, or align documentation with live codebases 

[8]

.

Continuous testing and QA

With test case libraries, mock APIs and staging environments available through MCPs, an agent can generate, run and update integration tests automatically as code evolves. Start-ups are already building AI-native QA pipelines using this approach [7].

Data engineering and analytics

Data warehouse schemas (Snowflake, BigQuery, Redshift, etc.) can be shared via MCPs. Agents can then generate safe queries, optimise ETL jobs, or even draft dashboards without requiring direct access to sensitive raw data 

[6]

.

Final Thoughts

MCPs give us a new way to connect LLMs to the tools and data they need, but there are still some things to keep in mind. Latency, data leakage, context drift, and limited client support can all introduce challenges if not understood and planned for.

As adoption grows, we'll likely see stronger security features, schema versioning, and wider ecosystem support. Just as APIs became the standard for system integration, MCPs could well become the standard layer for AI integration.

I hope this guide has been useful — feedback is welcome, either directly or in the comments. Good luck with your own MCPs!
