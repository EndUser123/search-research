# AI Coding Assistants Reviewed Each Other's Code: What They Missed
what if you took code written by one AI coding assistant and asked a competing AI to review it not a human another AI would it catch the bugs would it flag the security issues or would it wave the code through because both models were trained to think the same way we ran that experiment and what the AI coding assistants missed tells you a lot about how much you should trust them before we get into the results here is how the test worked we selected four widely used AI coding assistants and had each one generate solutions to the same set of coding tasks these were practical tasks not trick questions things like writing a REST API endpoint handling user authentication parsing file input and managing concurrent requests then we fed each tools output to the other tools for code review each reviewing tool was given the same prompt review this code for bugs security issues and edge cases flag anything that needs attention we logged every comment every warning and every piece of code that was passed with no notes at all that last category turned out to be the most interesting the first thing we noticed in round one is that AI coding assistants are generally good at catching obvious formatting issues and simple logical errors if a variable is used before it is declared or a loop condition is clearly wrong most tools flag it that part of the review works the problems start when the code looks right but behaves incorrectly under specific conditions off by one errors were missed consistently across the board this is a classic programming bug where a loop runs one iteration too many or too few when AI tools generate code they tend to produce off by one errors in array indexing and range calculations when other AI tools reviewed that code they missed those same errors at a high rate all four tools showed this pattern missing input validation was the second major blind spot one tool generated an API endpoint that accepted user submitted data and passed it directly into a database query with only minimal sanitization two of the three reviewing tools gave that code a clean pass the third tool mentioned that validation could be improved but did not flag it as a security risk in a real production environment that code would be a serious vulnerability race conditions were almost universally ignored when one tool wrote an asynchronous function that modified a shared resource without proper locking none of the reviewing tools flagged the potential for concurrent access issues this is a bug that only appears under load and it can cause data corruption or application crashes every single reviewing tool missed it so why do AI coding assistants keep missing the same things the answer has to do with how these models learn what good code looks like they are trained on enormous amounts of code from public repositories most of that code works most of the time which means subtle bugs that only appear in edge cases are under reprepresented in the training signal the models learn to recognize code that looks like working code not code that is provably correct there is also a reinforcement learning factor these tools are fine-tuned using human feedback which means a human reviewer approved many of the examples the model learned from human reviewers misra conditions and off by one errors too the model has essentially learned to replicate the same blind spots that exist in human review at scale the security findings deserve their own focus across the full test we found three categories of security issues that no AI tool flagged consistently the first was insecure direct object references where code exposed internal identifiers in API responses without authorization checks the second was improper error handling that leaked stack traces to the client the third was hard-coded fallback credentials left in configuration functions hard-coded credentials are worth pausing on one tool generated a configuration function with a comment that said something like "Replace this with your real password before deploying." A second tool reviewed that code and did not flag it as a security concern at all it noted the comment but treated it as a developer reminder rather than a risk in a codebase where that function gets committed to version control that comment becomes an active security problem there was one area where cross review actually worked well and it is worth acknowledging when it came to code style naming conventions and documentation gaps ai tools reviewing each other's code were genuinely helpful they caught inconsistent naming missing dock strings and functions that were too long to be readable if your only goal is cleaner more consistent code AI cross review adds real value but style is not safety a well- formatted function that silently corrupts data under concurrent load is still a production incident waiting to happen the tools are optimizing for the wrong signal when it comes to correctness and that gap becomes significant the more you rely on them what does this mean for developers and engineering teams using AI coding assistance right now the first implication is that AI crossreview cannot replace human review for security sensitive code paths it can supplement a human reviewer but it should not substitute for one the categories of bugs that AI tools miss are exactly the categories that create real production failures the second implication is that static analysis tools and dedicated security scanners still have a role that AI has not replaced tools like llinters type checkers and automated security scanners look for specific patterns using rules that were written explicitly they do not generalize the way language models do and that specificity is actually an advantage when you are hunting for known vulnerability classes the third implication is that your review workflow needs to account for shared failure modes if the same AI tool that wrote the code is also reviewing it or if the reviewing tool was trained on similar data with similar weaknesses you are not adding a second opinion you are running the same check twice diversity in your review process is not just about having humans in the loop it is about making sure the checks you use do not all fail in the same way a practical workflow that addresses this looks like the following use AI coding assistance for generation and first pass review because they are fast and they catch real mistakes run static analysis and security scanners as a separate automated step in your CI pipeline reserve human review for any code that touches authentication data storage external APIs or shared state that layered approach gives you the speed benefit of AI tools without trusting them beyond what the evidence supports one thing this experiment changed for us is how we think about confidence scores when an AI coding assistant says something like this code looks good or no issues found that statement carries implicit confidence but based on what we saw that confidence is not calibrated to the actual risk of the code a clean pass from an AI reviewer is evidence that the code passes the checks the model knows how to run not that the code is correct the tools tested here are genuinely useful that is the honest answer they reduce time spent on boilerplate they catch obvious mistakes and they make it easier for developers to move faster on routine work the problem is not that the tools are bad the problem is the assumption that because a tool is powered by a large language model it must also be good at the nuanced judgment calls that matter most the field is also moving fast some of these limitations are being addressed in newer model versions and with tool use features that let AI assistants call external analyzers it is worth staying current on what each tool can actually do today rather than assuming the version you used 6 months ago represents current capability to recap what we covered AI coding assistants consistently miss off by one errors input validation gaps race conditions and several classes of security vulnerability when reviewing each other's code the root cause is shared training patterns and reinforcement feedback that mirrors human blind spots the practical response is a layered review workflow that does not rely on any single type of check if this gave you a clearer picture of how to use AI coding assistance more carefully hit
