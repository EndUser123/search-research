Part 3: 

AGENTS.md

 

#

https://codex-best-practices-d67bea.pages.oit.duke.edu/best-practices/agents.html#part-3-agents-md

AGENTS.md

 gives Codex reusable instructions for a whole user account, repository, or subdirectory. Think of it as a lightweight onboarding note that Codex reads before it starts work: project norms, preferred commands, review expectations, writing style, and things it should be careful about.

Try to keep your 

AGENTS.md

 lean. Codex loads it into the session's instruction context, so unnecessary information wastes tokens/energy/water and can also confuse your results.

Remember this is natural language: current LLMs are very impressive at understanding what we ask, but there is no guarantee that guidelines inside this file will be followed. Use 

config.toml

 , rules, sandboxing, and approval settings for firmer controls.

How Codex finds 

AGENTS.md

 

#

https://codex-best-practices-d67bea.pages.oit.duke.edu/best-practices/agents.html#how-codex-finds-agents-md

Codex builds an instruction chain when a session starts. If you edit an 

AGENTS.md

 file while Codex is already running, restart Codex or start a new session so it sees the updated instructions.

Codex checks for instructions in this order:

Global instructions in your Codex home directory, usually 

~/.codex/AGENTS.md

 .

Project instructions starting at the project root, usually the Git repository root.

Nested instructions in directories between the project root and your current working directory.

Files closer to your current directory appear later in the combined instructions, so they can refine or override broader guidance. For example, 

myproject/backend/AGENTS.md

 can add backend-specific instructions on top of 

myproject/AGENTS.md

 .

Codex also supports 

AGENTS.override.md

 . If both 

AGENTS.override.md

 and 

AGENTS.md

 exist in the same directory, Codex uses the override file for that directory. This is useful for temporary or team-specific overrides, but can be confusing if you forget it exists.

What to put in 

AGENTS.md

 

#

https://codex-best-practices-d67bea.pages.oit.duke.edu/best-practices/agents.html#what-to-put-in-agents-md

Good cases:

Repository setup commands, such as how to install dependencies or start the app.

Test and validation commands Codex should run after certain changes.

Style expectations for Markdown, Python, JavaScript, slide content, or documentation.

Safety preferences, such as asking before adding dependencies, touching generated files, or changing deployment configuration.

Project-specific vocabulary, architecture notes, or directories Codex should know about.

Avoid putting these in 

AGENTS.md

 :

Long documentation that Codex only needs for rare tasks.

Secrets, keys, tokens, passwords, or private data.

Instructions that should be enforced by sandboxing, rules, or approvals.

Large generated content that will crowd out more useful context.

Personal vs project instructions

#

https://codex-best-practices-d67bea.pages.oit.duke.edu/best-practices/agents.html#personal-vs-project-instructions

Use 

~/.codex/AGENTS.md

 for preferences you want everywhere:

How you like final answers formatted.

Whether Codex should ask before committing.

General review habits, such as leading with risks and tests.

Use 

myproject/AGENTS.md

 for instructions that only make sense in one repository:

Build and test commands.

Project file structure.

Documentation tone.

Contribution workflow.

Use nested 

AGENTS.md

 files when one part of a project has special rules. For example, a 

slides/AGENTS.md

 file might remind Codex to update 

.pptx

 sources before exported PDFs, while a 

backend/AGENTS.md

 file might list API test commands.

What goes in 

AGENTS.md

 vs 

SKILL.md

 ?

#

https://codex-best-practices-d67bea.pages.oit.duke.edu/best-practices/agents.html#what-goes-in-agents-md-vs-skill-md

Instructions that should be sent to the model with EVERY conversation should likely go in AGENTS.md.

Instructions that only apply to certain specific operations should go in a SKILL.md.

This separation helps keep your context more focused.
