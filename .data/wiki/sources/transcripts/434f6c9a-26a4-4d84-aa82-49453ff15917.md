# Why AI Coding Assistants Fail in Monorepos (and How to Fix It)
you've probably noticed that most AI coding tools work great on small clean projects but when you drop them into multi-million line monor repos legacy code bases or systems spending dozens of microservices they start to fall apart traditional rag powered coding assistants rely on embedding the entire codebase and retrieving relevant chunks at query time but at enterprise scale this model breaks the embedding pipeline simply cannot keep up with hundreds of active engineers committing new code by the time you query the index it's already out of date it retrieves a function that was renamed hours ago or references a module that was deleted in the last sprint causing the AI to hallucinate based on stale data claude Code approaches this problem differently instead of relying on a pre-built centralized index it navigates the codebase just like a human software engineer would by traversing the file stem reading files and running Grep locally because it runs locally on the developer machine it works directly from the live active state of the code there are no embedding pipelines to maintain and no lag but this local autonomy comes with a trade-off it works best when the agent has enough starting context to know where to search if you ask it to find a vague pattern across a massive repo you will hit context limits before the work begins you have to feed it the right harness we often think of an AI tools capability as being defined solely by the underlying model but in real world engineering the ecosystem built around the model the harness is what determines whether it succeeds this developer harness consists of five primary layers clawed MD files hooks skills plugins and MCP servers together with LSP integrations and sub aents they form a structured scaffolding let's break down how to set them up building these layers in the right order is crucial as each layer builds on top of the ones below it the absolute foundation of this harness is the claude.md file these are local markdown files that Claude reads automatically at the beginning of every session best practice is to keep them lean and layered place a highle guide at the repo route for global conventions and smaller localized cloud MD files in specific subdirectories clode will read them editively as it navigates ensuring it only loads relevant local test and build commands next come hooks rather than just using prompts to guide hooks run scripts at key moments a start hook can fetch database schemas dynamically while a stop hook can analyze the session and automatically write updates back to your cloud.md file as your codebase grows loading every guideline into cloud.md will bloat the context window and degrade performance to solve this anthropic introduced skills these are packaged instructions for specific tasks that load only when needed skills can also be path scoped for example a specialized deployment skill for your billing system will only load when the developer is working inside the payments directory protecting the agents focus to distribute these configs use plugins a plug-in bundle skills hooks and configs into a single installable package instead of letting best practices remain tribal plugins allow you to share working setups across your entire organization to hook into your internal infrastructure you use MCP the model context protocol mcp servers act as secure gateways giving the agent read and write access to internal documentation databases and ticketing systems for code navigation the highest value integration is LSP the language server protocol by connecting Claude to your language server it can search by symbol rather than by string it can follow definitions and trace references with absolute precision finally Claude can delegate work using sub aents a sub aent is an isolated instance with its own context window you can spin up a readonly sub aent to explore and map a subsystem keeping your main agent session clean setting up the technical harness is only half the battle the companies that see the highest ROI treat AI configuration as infrastructure they designate a DRRi or directly responsible individual to manage these settings without central ownership setups become fragmented and tribal a DRRi or developer productivity team manages the plug-in marketplace enforces security controls and keeps cloudMD files up to date start with a small secure rollout define approved skills integrate AI edits into standard human code review pipelines and regularly clean up obsolete rules every 3 to 6 months as models improve deploying AI agents at scale isn't about finding a magic model it's about building a robust harness by starting with lean clot.md files setting up LSP and designating a DRRi
