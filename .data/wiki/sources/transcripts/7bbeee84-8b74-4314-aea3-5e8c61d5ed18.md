) is mostly an mcp for claude-code to be able to use, I mean you can use the commands directly with / slash commands in claude-code, but if you just install ruv-swarm and initialize it, it will setup the CLAUDE.md files and agent instructions so that claude code will know how to use the ruv-swarm commands, and then you can interact with claude code as you normally would but you should see that when claude-code is working, it is using a lot of ruv-swarm mcp tools. Sometimes even with the claude.md instructions, claude code may still not remember to use ruv-swarm, so it can be helpful to remind claude code in your prompt to use ruv-swarm.

Another thing to consider here is that I think that claude-flow, even in its current state, is very very similar to roo code. Roo worked by having a way to orchestrate multi-agent projects where the primary enhancement were the ability to orchestrate + the special agentic instructions files it provided for all the agent. With claude-flow currently, initializing a directory will load powerful claude.md settings, agent settings, other claude-code enhancements like memories and custom hooks, checkpoints, helpers, workflows and more and you dont need to use the claude-flow mcp tools to get these benefits, if the only thing you do is initialize the directory with claude-flow, and after that just use the claude-code prompt, it wont be your same old claude code, it will be substantially enhanced. And while the claude-flow mcp tool to spawn agents may not work, claude-code now has its own task tool to spawn sub-agents, so if you tell claude code to use its task tool to spawn sub-agents (either via the prompt or more ideally by updating the CLAUDE.md files), and when it does, it spawns agents with the same instruction files that would have been used had the claude-flow mcp been used to spawn the agent and so the result is I think a system that is already quite similar to roo code and a lot better than just claude code by itself.

And whether every claude-flow feature is working right or not, in any case its also really important to enhance your claude.md and .claude/agents/ instruction files and how exactly you do that matters a lot. You can put claude.md files in most directories within a repo and you can also do a lot with agent instruction files, but research it first to understand how use these optimizations properly - the main thing thats needed to add are information about your project and your project specific process requirements. Agents need to analyze your code base, multi-agent complicates this and the more multi-agent your system is the harder this is to get right as the agents you talk to will spawn sub-agents or swarms which may themselves run sub-agents and you need to make sure across these layers that every new subagent an agent spawn doesnt need to try to analyze your entire repo before they can figure out what to do, the more complex your project, the more context an agent might need to analyze to be able to add code to your project without accidentally breaking things. The simpler you can make it for your agents to learn what they need to in order to effectively work on your code base, the more effective the agents become. Instruction files can get too large and overwhelming, which is why you need to intelligently distribute instructions across layers, like for example you can put project wide claude.md files in .claude and in project root - and you can put additional prompt relative to like a code directory that has a specific type of files, you can put some instructions in a claude.md in that directory that only gets scoped into the prompt when claude is working on files in that directory. You should put hints about how to find things that different agent roles will likely need to know or find in the agent instruction files. You can add comments within code files themselves that can serve as reminders that help agents stay on track and more likely to follow processes correctly.

All the stuff that claude-flow and ruv-swarm adds to these files is really impactful and powerful, but there is no way to make a public project like that aware of the project-specific elements in your specific project, the stuff that claude-flow and ruv-swarm put into these files should be preserved as it works very well, you should only minimally enhance it with the minimal project-specific instructions that are needed, and if your project-specific instructions seem too cumbersome, you need to simplify it by doing things like for example, if you have a complicated build/serve process, simplify it with something like a makefile, script or ci/cd tool so you can give agents one command you know will work to ensure build processes and serving work right. And making sure you have a really clean modular project architecture. Also, a lot of the agent instructions created by claude-flow or ruv-swarm are optimized for html5 apps (typescript/js/html) and so if you are using a different language, you can optimize it a lot by enhancing agent instructions or claude.md files for your language - a good method is look at the CLAUDE.md and agent instruction files that are created by claude-flow, find the ones that have language-specific instructions, feed them to an llm and ask them to modify the file in a way that provides essentially the same instructions but optimized for your language and or tool stack.
