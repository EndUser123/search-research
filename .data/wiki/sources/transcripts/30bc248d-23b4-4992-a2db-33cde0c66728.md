Summary

Add skill-security-auditor as an automated check in the GitHub Actions CI pipeline. Every PR that adds or modifies a skill should be scanned for security issues.

Tasks

[-]

 

Create 

.github/workflows/skill-security-audit.yml

 

[-]  Detect which skills changed in the PR (diff-based)

 

[-]  Run 

skill_security_auditor.py --strict --json

 on each changed skill

 

[-]  Post findings as PR comment

 

[-]  Block merge on FAIL verdict To pick up a draggable item, press the space bar. While dragging, use the arrow keys to move the item. Press space again to drop the item in its new position, or press escape to cancel.

Example Workflow

name: Skill Security Audit
on: pull_request
jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Find changed skills
        id: changed
        run: |
          # Detect skill dirs with changes
      - name: Run security audit
        run: |
          for skill in ${{ steps.changed.outputs.skills }}; do
            python3 engineering/skill-security-auditor/scripts/skill_security_auditor.py "$skill" --strict
          done


Acceptance Criteria

PR check runs on every skill change

FAIL verdict blocks merge

Findings posted as PR comment for easy review

Good call on automating this as a PR gate. The "FAIL verdict blocks merge" requirement is the right default — too many repos treat security scans as advisory and then wonder why malicious contributions slip through.

A couple things that might be worth thinking about as you build this out:

The diff-based detection is important but tricky. Skills can have indirect dependencies — a change to a shared utility that multiple skills reference might not show up as a change to the skill directory itself. Might be worth scanning all skills on a scheduled basis too, not just on PR diffs.

Also, CI-time scanning only covers your own repo. The bigger threat right now is 

installation-time

 — ClawHavoc pushed 1,184 malicious skills through a permissive registry this month, and users installing from external sources have no scan step at all. 

SkillSafe

https://skillsafe.ai/

 handles this by scanning at publish time and again on the consumer side after download, with tree-hash verification to catch tampering in transit. It's a different layer than CI, but complementary.

For the auditor script itself — if it's doing 

--strict --json

 , posting structured findings as a PR comment (collapsible details with severity levels) makes the review feedback loop much tighter than just a pass/fail status check.

Hi 

@alirezarezvani

https://github.com/alirezarezvani

 — I'm the author of 

Prism Scanner

https://github.com/aidongise-cell/prism-scanner

, an open-source (Apache 2.0) security scanner for agent skills/plugins/MCP servers.

Prism already ships with a ready-to-use 

GitHub Action

 that could cover most of the tasks listed here. Here's what a minimal integration would look like:

# .github/workflows/prism-scan.yml
name: Prism Security Scan
on: pull_request

permissions:
  security-events: write
  contents: read

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: aidongise-cell/prism-scanner@main
        with:
          path: '.'
          fail-on: 'high'


What it covers from your checklist:

39+ detection rules

: AST taint tracking, malicious signatures, metadata analysis, system residue detection

A-F grading

 with structured JSON output ( 

--json

 ) — easy to post as a PR comment

fail-on threshold

 — can block merge on high/critical findings

Findings integrate with GitHub's 

Security tab

 via SARIF

This could work alongside or as a complement to 

skill-security-auditor

 . Happy to help with integration if there's interest — I can submit a PR with the workflow once we align on the approach.

For the diff-based detection point raised above: 

prism scan

 can target specific directories, so pairing it with a changed-files step would keep scan times fast on PRs, while a scheduled full scan could catch indirect dependency issues.
