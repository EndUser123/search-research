Decision

Implement a three-layer validation architecture that prevents whitelist bypass, infers optimal locations, and handles

 

multi-terminal concurrency safely.

Rationale

The core problem was that allowed_config_files whitelist was a complete bypass - if a file was whitelisted, it skipped

 

ALL validation checks. This violated the principle of "fix the source, not the symptom" because we couldn't detect when

 

whitelisted files were in the wrong location.

Three-layer architecture addresses this:

Layer 1: Type-Based Validation (type_validator.py)

Validates whitelist entries by file type (.py files shouldn't be in config whitelist)

Detects setup.py packages (has setuptools/distutils) vs modules (doesn't)

Categorizes files: config, python, doc, cache, unknown

Layer 2: Optimal Location Inference (location_optimizer.py)

Answers "where SHOULD this file live?" not just "is this allowed?"

Hook-imported Python modules → .claude/hooks/

Per-project configs → workspace root

Hidden data directories → .claude/state/session_data/

Layer 3: Whitelist Bypass Prevention

Whitelisted files STILL go through type validation

Type mismatches flagged even if whitelisted

Root cause fixes (remove from whitelist) vs symptom patches
