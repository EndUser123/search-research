Introduction

Claude Code is a CLI-based AI coding assistant provided by Anthropic. It allows you to read code, edit files, and execute commands directly from your terminal.

However, running 

claude --help

 displays 

over 50 options

. While official documentation and cheat sheets exist, they often just list "what you can do" without making it clear " 

why you should use it

" or " 

how to combine these features

."

In this article, we will organize the 

mindsets and patterns for practically mastering

 the Claude Code CLI.

Target Audience

Engineers who have started using Claude Code for work

Those who know the basic commands but want to expand their application

Those considering integrating it into CI/CD or team development workflows

Target Version

claude --version
# 2.1.74 (Latest as of March 2025)


 

Our Approach in This Article

Existing cheat sheet articles "explain every option." This article takes a different approach:

Focusing on the "Why"

 — Which options are useful for which use cases?

Focusing on "Combinations"

 — Synergistic effects between options rather than using them in isolation.

Focusing on "Pitfalls"

 — Notes not covered in the official documentation.

The 5 Basic Commands — Start Here

1. 

claude

 — Start an Interactive Session

claude
claude "Explain the structure of this project"


 

Why use it

: This is the default interactive mode. It is the most basic way to read files, edit code, and run commands.

Key Points

:

Launch without arguments → An empty session.

Launch with arguments → Automatically sends the initial prompt.

2. 

claude -p

 — Non-Interactive Mode (For Pipelines)

claude -p "List the dependencies in package.json"
cat error.log | claude -p "Explain the cause of this error concisely"


 

Why use it

: Essential for scripts, CI/CD, and pipelines. It accepts standard input, outputs results to standard output, and exits.

Important Note

:

In 

-p

 mode, the 

workspace trust dialog is skipped

.

Only use this in trusted directories.

Common Combinations

:

# Output as JSON for downstream processing
claude -p --output-format json "Analyze this" | jq '.[-1].content'

# Run safely with a budget limit
claude -p --max-budget-usd 1.00 "Summarize the test results"


 

3. 

claude -c

 — Continue Session

claude -c  # Continue the previous session
claude -c -p "Run tests for the fix I just made"


 

Why use it

: You can carry over context when working in multiple steps.

Key Points

:

Loads the 

latest session

 associated with the current directory.

Combining with 

-p

 enables "continuation + non-interactive" mode.

4. 

claude -r

 — Resume Session (Specify ID)

claude -r                              # Select with picker
claude -r "auth refactor"              # Search by keyword
claude -r abc12345-6789-def0           # Specify directly by session ID


 

Why use it

: Allows you to return to any past session. While 

-c

 is for the "latest," 

-r

 allows you to pick "any."

5. 

claude --model

 — Select Model

claude --model opus    # Highest performance (for complex reasoning)
claude --model sonnet  # Balanced (for daily development)
claude --model haiku   # Fast/low cost (for lightweight tasks)


 

Why use it

: Balance cost and quality according to task complexity.

Model Selection Guidelines

:

Model

Suitable Tasks

Cost Level

opus

Architecture design, complex refactoring, debugging

High

sonnet

Daily code generation, review, documentation

Medium

haiku

Simple questions, format conversion, summarization

Low

!

You can change models during an interactive session using the 

/model

 command. You can also instruct it by saying "Switch to opus."

Patterns by Workflow

Pattern 1: Automating Code Review in CI/CD

Challenge

: Automatically review PR diffs and output issues as structured data.

Solution

:

claude -p \
  --model sonnet \
  --max-budget-usd 2.00 \
  --output-format json \
  --no-session-persistence \
  --json-schema '{
    "type": "object",
    "properties": {
      "issues": {
        "type": "array",
        "items": {
          "type": "object",
          "properties": {
            "file": {"type": "string"},
            "line": {"type": "number"},
            "severity": {"type": "string", "enum": ["error", "warning", "info"]},
            "message": {"type": "string"}
          },
          "required": ["file", "line", "severity", "message"]
        }
      },
      "approved": {"type": "boolean"}
    },
    "required": ["issues", "approved"]
  }' \
  "Review the diff against the main branch"


 

Why this combination?

:

Option

Role

--model sonnet

Best balance for review tasks

--max-budget-usd

Prevents cost runaways

--output-format json

Allows downstream parsing

--no-session-persistence

Keeps session history out of CI environments

--json-schema

Guarantees output format (avoids parsing errors)

Pattern 2: Parallel Development (Git Worktree)

Challenge

: Want to develop multiple features in parallel, but switching branches is a hassle.

Solution

:

# Start a session in a worktree for feature-auth
claude -w feature-auth

# Use a worktree for feature-api in a separate terminal
claude -w feature-api


 

Why use it

: 

--worktree

 creates an independent working directory without affecting the original branch.

Key Points

:

Worktrees are created at 

<repo>/.claude/worktrees/<name>

 .

Automatically cleaned up after the session ends if there are no changes.

Can be combined with 

--tmux

 to launch within a tmux pane.

claude -w feature-auth --tmux


 

Pattern 3: Cross-Package Work in Monorepos

Challenge

: Need to perform changes across multiple packages at once.

Solution

:

claude \
  --add-dir ../packages/api ../packages/web ../packages/shared \
  --model opus \
  --allowed-tools "Bash(git:*) Bash(npm:*) Edit Read Write" \
  "Update the UserType in the shared package and fix references in api/web"


 

Why this combination?

:

Option

Role

--add-dir

Allows access to multiple packages

--model opus

High reasoning power for complex cross-package changes

--allowed-tools

Auto-approves git/npm operations (skips confirmation)

Pattern 4: Fully Automated Execution in Sandboxes

Challenge

: Want to finish large-scale refactoring without human intervention.

Solution

:

# Run inside a sandbox like Docker
claude -p \
  --dangerously-skip-permissions \
  --model opus \
  --max-budget-usd 10.00 \
  "Update the entire project to support TypeScript strict mode"


 

!

Use 

--dangerously-skip-permissions

 only in sandboxed environments without internet access. Never use it in production environments.

Pattern 5: Session Management Linked to PRs

Challenge

: Want to resume work related to a specific PR.

Solution

:

claude --from-pr 142
claude --from-pr "https://github.com/org/repo/pull/142"


 

Why use it

: Sessions created via 

gh pr create

 are automatically linked to the PR. You can resume them later using 

--from-pr

 .

Common Pitfalls and Solutions

1. Permission checks are annoying

Symptoms

: Asked for confirmation for every file edit or command execution.

Solution 1

: Bulk settings with 

--permission-mode

claude --permission-mode acceptEdits  # Auto-approve file edits
claude --permission-mode dontAsk      # Auto-approve all operations


 

Solution 2

: Auto-approve only specific operations with 

--allowed-tools

claude --allowed-tools "Bash(git:*) Bash(npm:*) Edit Read"


 

!

Difference between 

--permission-mode

 and 

--allowed-tools

 :

--permission-mode

 : Switches the entire mode.

--allowed-tools

 : List for auto-approving specific tools.

2. Session not found

Symptoms

: Previous session not restored with 

-c

 .

Reasons

:

Working in a different directory.

Session not saved to disk.

Solutions

:

# Search using picker
claude -r

# Search by keyword
claude -r "yesterday's implementation"


 

3. MCP server not loading

Symptoms

: Server specified with 

--mcp-config

 not available.

Reason

: Conflicts with other configuration files ( 

~/.claude.json

 or 

.mcp.json

 ).

Solution

:

# Use only specified settings (ignore others)
claude --strict-mcp-config --mcp-config ./my-servers.json


 

4. JSON output cannot be parsed

Symptoms

: JSON error despite using 

--output-format json

 .

Reason

: Debug info or warnings might be mixed into stdout.

Solution

:

# Send debug output to a file
claude -p --output-format json --debug-file ./debug.log "Process this"


 

5. Higher costs than expected

Symptoms

: High costs despite short interactions.

Solution 1

: Reconsider the model

# Use haiku for simple tasks
claude --model haiku "Summarize this file"


 

Solution 2

: Lower reasoning level with 

--effort

claude --effort low "Convert format"


 

Solution 3

: Set budget limit

claude -p --max-budget-usd 0.50 "Check lightly"


 

Leveraging New Features

--remote-control

 / 

--rc

 — Operate via browser

claude --remote-control "My Project"


 

Why use it

: Control local Claude Code sessions from Claude.ai or the Claude app.

Use cases

:

Continue home machine sessions while on the go.

Check desktop work from mobile.

--teammate-mode

 — How to display teammate agents

claude --teammate-mode in-process  # Same process
claude --teammate-mode tmux        # Separate tmux pane


 

Why use it

: Control display methods when running multiple sub-agents (teammates).

--brief

 — Inter-agent communication

claude --brief


 

Why use it

: Enables the 

SendUserMessage

 tool, allowing agents to communicate with the user.

--teleport

 — Move Web sessions locally

claude --teleport


 

Why use it

: Resume web sessions started on Claude.ai in your local terminal.

--auto

 — Automatic mode classification

claude --auto-mode


 

Why use it

: Check the current settings for automatic mode classification.

MCP Server Management

claude mcp get <name>                     # Get details
claude mcp serve                          # Start Claude Code MCP server


 

MCP Addition Example

:

# stdio server
claude mcp add my-server -- npx my-mcp-server

# HTTP server
claude mcp add --transport http sentry https://mcp.sentry.dev/mcp

# With env vars
claude mcp add -e API_KEY=xxx my-server -- npx my-mcp-server


 

Plugin Management

claude plugin list
claude plugin install <name>@marketplace
claude plugin remove <name>


 

Other
