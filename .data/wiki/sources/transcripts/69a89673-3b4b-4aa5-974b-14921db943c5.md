every time you ask a large language model a question it answers one word at a time behind the scenes that serial bottleneck burns latency power and money the deeper the model the longer you wait dspark asks a simple question what if we let the model guess ahead and only pay for the parts it gets wrong the headline is unambiguous against the standard multi-token prediction baseline DSpark fast draft model proposes the next few tokens the big target model the one you actually care about verifies them in a single parallel pass matched tokens are accepted for free rejected tokens are discarded and the target model regenerates only the parts that were wrong dspark's contribution is the hardware aware prefixuler it watches real GPU occupancy and decides on the fly how many draft tokens to send and how long the shared prefix cache should stay warm when the GPU is hungry it pushes more speculative work when the GPU is hydrated it backs off theuler is the brains the draft model
