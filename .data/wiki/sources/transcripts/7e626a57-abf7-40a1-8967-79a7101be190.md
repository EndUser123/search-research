I use Claude Code every day as a Senior Machine Learning Engineer. Most people's mental model of AI is still stuck in the ChatGPT era: you type a question, you get an answer. Claude Code is something different. It's an agent that reads, writes, and edits your actual files, runs terminal commands, and operates directly on your codebase. That makes it powerful, but power without structure creates new problems.

Writing code is the easy part now. Getting code that's actually good requires more than just prompting. Without the right habits, you end up generating “AI slop” you'll eventually rewrite anyway. I learned that the hard way. Over time, I organized what worked (and what didn't) into a simple framework for using Claude Code effectively.

The framework has two categories: 

compounding habits

 you set up once that make every future session smarter, and 

session habits

 that keep you on track in the moment. Together, they give you a repeatable system for getting more consistent and trustworthy output from Claude Code.

A best practice framework for power users

Getting Started

Go to 

code.claude.com/docs

https://code.claude.com/docs/en/overview

 and follow the install instructions. You'll need a Claude Pro, Max, Team, or Enterprise account.

Once installed, open your terminal, 

cd

 into your project folder, and type 

claude

 . That's it. You're in a session with access to everything in that directory.

The Shortcuts You Need Right Now

Shift+Tab

 cycles between three modes. 

Normal

 lets Claude use all its tools but asks you to approve risky actions (like file writes and shell command before they run. 

Auto-Accept

 lets Claude apply file edits without asking, while still prompting for shell commands, so it's faster once you trust it. 

Plan

 restricts Claude to read-only, meaning it can explore your project and propose an approach, but it can't change anything.

Once you know your modes and shortcuts, the real leverage comes from your habits.

The Power User Habits

You don't need a complex setup to get the most out of Claude Code. Boris Cherny, the creator of Claude Code, 

has said

https://x.com/bcherny/status/2007179832300581177

 his own setup is “surprisingly vanilla.” He doesn't heavily customize, because the tool is already powerful on its own. The edge comes from the habits, not from complex configs.

Compounding Habits

Set up CLAUDE.md and keep it current.

 Type 

/init

 to create a 

CLAUDE.md

 file in your project root. Claude reads this at the start of every session, so whatever's in there, Claude just knows, every time. Fill it with your tech stack, build and test commands, and any rules you want enforced. Keep it under 200 lines. If your 

CLAUDE.md

 gets too long, move rules into separate files in a 

.claude/rules/

 folder. Claude loads those the same way, and you can scope rules to only apply when certain files are being edited. See the 

rules docs

https://code.claude.com/docs/en/memory#organize-rules-with-claude/rules/

.

The key habit: every time Claude does something wrong, add a note to your 

CLAUDE.md

 so it doesn't happen again. The Claude Code team at Anthropic does this internally and calls it " 

compounding engineering

https://www.youtube.com/watch?v=IDSAMqip6ms&t=1815s

." Each correction becomes permanent context, so Claude never makes that class of error again. And don't just update 

CLAUDE.md

 when things go wrong; update it when your tech stack changes, your conventions evolve, or you learn something new about your codebase. On a team, this compounds even faster, because every rule one person adds benefits everyone else's sessions automatically.

Give Claude feedback loops.

 Tell Claude to run tests, linters, or build commands after every change. Without a feedback loop, Claude makes changes, assumes they work, and moves on. With one, it catches its own mistakes. Cherny 

has said this alone can 2–3x output quality

https://x.com/bcherny/status/2007179861115511237

. Another compounding habit: once you wire feedback loops into your 

CLAUDE.md

 , every future session gets them for free. A line like 

Always run pytest after changing Python files

 is all it takes.

Session Habits

Start complex tasks in plan mode.

 If a task touches multiple files or requires research, switch to Plan mode first. For one-liner changes like fixing a typo, skip it. Cherny 

starts most of his own sessions in Plan mode

https://www.youtube.com/watch?v=PQU9o_5rHC4&t=1623

. Push back if something's off, and once you're happy, switch to Normal or Auto-Accept and tell it to implement. This is the core session habit: ten seconds of planning saves ten minutes of undoing.

Be specific and reference files directly.

 Instead of saying “Fix the authentication bug,” try something like “Fix the off-by-one error in 

@utils.py

 around line 42 that skips the last item." A detailed prompt up front saves you multiple corrective round trips.

Protect your context window.

 Every file read, command output, and back-and-forth message eats into your context. Claude manages a lot of this for you now and will prompt you to compact or clear when things get heavy. For large tasks, be more deliberate: use 

/compact

 to summarize and free up space, or 

/clear

 to start fresh between unrelated tasks. For research-heavy work, subagents can keep the heavy lifting out of your main context (more on those in the features section below).

Keep tasks small.

 “Build me a full e-commerce site with auth, payments, and checkout” is really ten tasks in one. The bigger the task, the more likely Claude loses track of requirements or makes cascading errors. Break it up: start with “create a plan for a full e-commerce site with auth, payments, and checkout, then break it into waves.” Tackle each wave one by one, clearing your context window between them. Small tasks also produce cleaner checkpoints, so if something goes wrong, you rewind less.

For a deeper dive on all of these habits, see the 

best practices docs

https://code.claude.com/docs/en/best-practices

.

Common Pitfalls

Claude ignores your project conventions.

 It writes code that works but doesn't follow your patterns, like using 

snake_case

 when your codebase uses 

camelCase

 . This is almost always a missing 

CLAUDE.md

 rule. You may add something like 

Always use camelCase for variables and PascalCase for classes

 , and Claude follows the convention from that point on. This is compounding engineering in practice: every correction you encode makes every future session better.

A complex task spirals.

 Claude starts editing files you didn't expect, or the changes snowball. Stop it ( 

Ctrl+C

 ), rewind with 

Esc+Esc

 if needed, switch to Plan mode, and break the task into smaller pieces. Then execute each piece one at a time.

Features Worth Knowing

Claude Code has several features that unlock more advanced workflows.

**claude -p**

 

for pipe mode.

 

claude -p

 runs Claude non-interactively, so you can use it in scripts and automation. For example, you can wire it into a git pre-commit hook with 

git diff --cached | claude -p 'review these staged changes for bugs'

 to automatically review code before every commit. See the 

CLI reference

https://code.claude.com/docs/en/cli-reference

 for the full list of flags.

**--worktree**

 

for parallel sessions.

 

claude --worktree feature-auth

 creates an isolated git worktree. You can run multiple Claude sessions on different branches without any conflicts. See the 

worktree docs

https://code.claude.com/docs/en/common-workflows#run-parallel-claude-code-sessions-with-git-worktrees

.

Built-in subagents for context isolation.

 Claude Code has built-in subagents (Explore, Plan, and general-purpose) that each run in their own separate context window. Claude spawns these subagents on its own when a task calls for one. All the verbose output stays in the subagent's context, and only a summary comes back. You can also direct them yourself: “Spin up three subagents to research the authentication module, the database layer, and the API routes in parallel, then summarize what you find.” Rule of thumb: if a task touches more than about five files, consider isolating it in a subagent. See the 

subagents docs

https://code.claude.com/docs/en/sub-agents

.

Built-in skills.

 Claude Code ships with built-in skills that you invoke with 

/

 . For example, 

/simplify

 reviews your code for reuse, quality, and efficiency, then applies fixes. New skills get added regularly, so type 

/

 in a session to see what's currently available. See the 

skills docs

https://code.claude.com/docs/en/skills

.

Custom subagents and skills.

 You can build your own. The easiest way is to just ask Claude, for example “create a subagent that reviews code for security issues” or “create a skill that deploys to staging,” and it generates the file for you. For a deeper dive into Claude Code's extension system (skills, subagents, plugins), I wrote a separate piece: 

A Mental Model for Claude Code: Skills, Subagents, and Plugins

https://medium.com/gitconnected/a-mental-model-for-claude-code-skills-subagents-and-plugins-3dea9924bf05

. See the 

subagents docs

https://code.claude.com/docs/en/sub-agents#quickstart-create-your-first-subagent

 and 

skills docs

https://code.claude.com/docs/en/skills#create-your-first-skill

 if you want to build them manually.

That's It

The people getting the most out of Claude Code aren't writing magic prompts. They're investing in both categories: 

compounding habits

 ( 

CLAUDE.md

 , feedback loops) that make every session smarter than the last, and 

session habits

 (planning, specificity, context management, small scope) that keep each task on track. That's the whole framework.

And as the tools improve, those habits compound with them. Context windows are growing, models are getting better at self-correcting, and every improvement multiplies the value of a well-maintained 

CLAUDE.md

 and a disciplined session. The framework stays the same. The results keep getting better.
