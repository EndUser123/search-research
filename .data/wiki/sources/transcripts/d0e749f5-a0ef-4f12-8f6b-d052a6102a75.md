First let's talk about agent teams If you remember from my last anti-gravity video Google had already enabled the /tework preview command for all paid plans That was the same multi- aent system that used to build a whole operating system from a single prompt with 93 sub aents and over 2.6 billion total tokens Now they have officially launched it as agent teams The anti-gravity account posted that they have built a new way to ship software and that you can just run/teamwork preview to spin up a dynamic team of specialized sub agents These agents coordinate in the background to plan build and verify complex engineering tasks in parallel They also presented this at the AI engineer worlds fair So this is clearly not a side experiment anymore This is Google's main pitch for how software should get built The word to pay attention to here is dynamic Earlier the teamwork stuff felt more like a fixed pipeline Now the team is assembled dynamically based on your task So when you run the command anti-gravity looks at what you asked for and decides what kind of team it actually needs One agent handles the architecture and planning Others implement different parts in parallel Another one writes tests another reviews the code and a verification agent checks whether the result actually matches what you asked for So instead of one AI doing everything one step at a time you get something that behaves like an actual engineering team One agent is building the back end while another is doing the front end and a reviewer is checking the diffs as they come in And because the coordination happens in the background you are not sitting there babysitting six chat windows You give it the task The team organizes itself and you watch the progress from the agent manager This is pretty amazing to be honest but I'll repeat the same warning from last time This thing eats tokens for breakfast There are already people on the Google forums who started a teamwork task watched it work beautifully and then hit their individual quota right in the middle of the run And the annoying part is that there is still no mechanism to pause the task gracefully when your quota runs out It just stops and your code can be left in a half-finished state So my recommendation stays the same Use agent teams for big tasks where the parallelism is actually worth it like a full app build a large refactor or a multi-art feature Do not use it to change a button color and make sure you have enough quota a headroom before you start because there is still no proper token estimate before a run Now So if your main agent is deep into a task and you just want to ask a side question like what does this function do or why did you pick this library you can ask it without polluting the main
