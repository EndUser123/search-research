The brutal truth about running advanced AI coding tools on Windows:

 You spend more time fighting your operating system than building anything meaningful. Until now.

“The computer was born to solve problems that did not exist before.” — Bill Gates (But sometimes it creates new ones first.)

I watched it happen again last week.

Sarah, a talented full-stack developer, spent three hours trying to get Claude Code running on her Windows machine. She followed the official docs. She installed WSL2. She configured Ubuntu. She fought with file permissions. She debugged path issues.

Then her WSL instance corrupted itself.

She gave up and went back to Cursor, convinced that Claude Code “just wasn't ready for Windows.”

But here's what nobody told Sarah: 

Claude Code wasn't designed to run natively on Windows. It expects a Unix-like file system because that's where the power lives.

 Every command, every file operation, every tool interaction assumes forward slashes, bash commands, and POSIX-compliant paths.

Windows uses backslashes. Windows has different path conventions. Windows breaks Claude Code's internal tooling in subtle, infuriating ways.

The standard advice? Install WSL. Set up a full Linux environment. Deal with the complexity.

But there's a better way that takes five minutes instead of five hours.

Git Bash gives you a Unix-compatible environment that runs directly on Windows, no virtual machines, no subsystems, no complexity. It's been sitting on most developers' machines all along, quietly waiting to solve this exact problem.

The Hidden Architecture Problem (And Why Git Bash Solves It)

Claude Code's internal tools expect Unix file paths. When you run commands like 

grep

 , 

find

 , or even basic file operations, Claude Code generates Unix-style commands behind the scenes.

On Windows Command Prompt or PowerShell, these commands fail. Paths break. Tools don't exist. Error messages multiply.

Git Bash translates everything automatically. It provides Unix commands that work on Windows files. It handles path conversion transparently. It gives Claude Code exactly what it expects without forcing you into a separate Linux environment.

This isn't a workaround. It's the architecture Claude Code was designed for, running exactly where you need it.

Why This Matters Beyond Installation

Once you understand this architecture decision, everything else clicks into place.

You can run VS Code, Cursor, or Windsurf for their visual interfaces and occasional code assistance. But when you need the full power of autonomous AI coding, you drop into Git Bash and unleash Claude Code.

Many developers run them side by side.

 Your IDE on one monitor, Claude Code CLI on the other. You get the best of both worlds: visual debugging and file navigation in your IDE, autonomous multi-file refactoring and complex implementations in Claude Code.

This isn't redundancy. It's specialization. Your IDE handles what it does best. Claude Code handles what no IDE can touch: understanding context across dozens of files, making architectural decisions, and implementing complete features autonomously.

And here's the bonus most people miss: 

This exact setup becomes the foundation for running Claude Agent SDK.

 Once Claude Code works in Git Bash, you've already solved the environment challenges that stop most developers from building custom AI agents.

The Five-Minute Installation (That Actually Works)

Step 1: Install Node.js

Node.js powers Claude Code's runtime environment. You need the LTS (Long Term Support) version for stability.

Navigate to nodejs.org in your browser

Click the large green button labeled “LTS” (it will show the version number)

Download the Windows Installer (.msi file)

Run the installer and accept all default options

Restart your terminal if you have one open

Verify the installation by opening any terminal (Command Prompt works fine for this check) and typing:

node --version
npm --version


You should see version numbers appear for both commands. If you do, Node.js is installed correctly.

Micro-Why:

 Node.js provides the JavaScript runtime that Claude Code is built on. NPM (Node Package Manager) gives you the tool to install Claude Code globally on your system.

Step 2: Install Git for Windows (Your Secret Weapon)

Git for Windows includes Git Bash, the Unix-compatible terminal that makes everything work.

Navigate to git-scm.com in your browser

Click “Download for Windows”

Run the installer

Accept all default options (the defaults are specifically configured for Windows compatibility)

Complete the installation

After installation, find “Git Bash” in your Start menu and launch it. You should see a terminal window with a bash prompt that looks something like:

Micro-Why:

 Git Bash provides a complete Unix-like environment that runs directly on Windows. It includes all the standard Unix commands (grep, find, ls, etc.) that Claude Code expects, automatically translating Windows paths into Unix format and back again.

Step 3: Install Claude Code

Now comes the actual Claude Code installation. In Git Bash (not Command Prompt, not PowerShell), run this single command:

npm install -g @anthropic-ai/claude-code


The 

-g

 flag installs Claude Code globally, making it available from any directory. You'll see npm download and install the package along with its dependencies. This usually takes 30-60 seconds.

Once completed, verify the installation:

claude --version


You should see the Claude Code version number appear. If you see it, installation succeeded.

Micro-Why:

 Installing globally with npm means you can invoke 

claude

 from any project directory without reinstalling. The verification step confirms that the binary is properly linked and accessible from your PATH.

Step 4: Set Up Your First Project

Create a dedicated folder for Claude Code projects. This keeps your work organized and makes switching between projects effortless.

In Git Bash, create your project structure:

mkdir -p /c/ClaudeProjects/FirstProject
cd /c/ClaudeProjects/FirstProject


The path 

/c/

 represents your C: drive in Git Bash's Unix-style notation. The 

-p

 flag creates parent directories automatically if they don't exist.

Now launch Claude Code:

claude


Press enter or click to view image in full size

 

Micro-Why:

 Git Bash automatically translates 

/c/ClaudeProjects/FirstProject

 to 

C:\ClaudeProjects\FirstProject

 when interacting with Windows. Claude Code sees Unix paths internally but operates on your actual Windows files seamlessly.

Step 5: Authenticate Your Session

When you launch Claude Code for the first time, you have two authentication options.

Press enter or click to view image in full size

 

Option A: Browser Authentication (Recommended)

Claude Code will display a URL in the terminal

Copy the URL and paste it into your browser

You'll be redirected to claude.ai to approve the connection

Click “Allow” to grant access

Return to your terminal, Claude Code is now authenticated

Option B: API Key Authentication

Visit console.anthropic.com

Navigate to “API Keys” in the account settings

Click “Create Key”

Copy the generated key

In Git Bash, run: 

export ANTHROPIC_API_KEY=your-key-here

Launch claude again

Most developers prefer Option A because it doesn't require managing API keys or setting environment variables. The browser authentication session persists across terminal sessions.

Micro-Why:

 Authentication connects your local Claude Code installation to Anthropic's AI models. Browser auth is simpler and more secure than manually handling API keys, and it automatically refreshes tokens when needed.

Building Your First Subagent: Creating a Virtual Synthetic Employee

This is where Claude Code transcends simple coding assistance and becomes something fundamentally different. You're about to create a specialized AI agent that handles specific tasks autonomously.

Think of subagents as virtual employees with specific job descriptions. They have their own context windows, their own tool access, and their own expertise areas. When Claude Code encounters a task matching their expertise, it delegates automatically.

Let's create a “research-assistant” subagent that gathers information and creates comprehensive summaries.

Creating the Subagent Through Meta-Prompting

Instead of manually writing configuration files, we'll use Claude Code's intelligence to build the subagent. This demonstrates a powerful pattern: using AI to create AI.

In your Claude Code session, paste this prompt:

> Create a subagent called "research-assistant" that specializes in gathering information from files, analyzing content, and creating detailed summaries. This subagent should:
- Use Read, Grep, and Glob tools to search through files
- Be proactive about finding relevant information
- Create structured summaries with key findings
- Include specific examples and quotes from source material
- Operate in the project-level agents directory
Generate the complete subagent configuration and save it to the appropriate location.


Claude Code will create the subagent file structure automatically. You'll see it create 

.claude/agents/research-assistant.md

 with a complete configuration including the system prompt, tool permissions, and description.

Micro-Why:

 Meta-prompting (using Claude to create Claude configurations) leverages AI's understanding of effective prompt engineering. The subagent Claude generates will be more sophisticated than most hand-written configurations because it understands what makes agents effective.

Testing Your Research Assistant

Now let's put your new virtual employee to work. Create some sample files for it to analyze:

> Create three text files about different topics:
- artificial-intelligence.txt with information about AI history
- quantum-computing.txt with quantum computing basics  
- renewable-energy.txt with renewable energy technologies
Then use the research-assistant subagent to analyze all three files and create a comprehensive summary showing connections between these technologies.


Watch what happens. Claude Code will:

Create the three source files with relevant content

Automatically invoke your research-assistant subagent

The subagent will read all three files independently

It will analyze connections and create a structured summary

The subagent returns results to the main Claude Code thread

You didn't write any of the analysis code. You didn't manually configure the subagent's behavior beyond the initial prompt. You created a specialized AI worker that understands its job and executes autonomously.

This is your first virtual synthetic employee.

Understanding What Just Happened

The subagent operated in its own context window, separate from your main conversation with Claude Code. This means:

It didn't pollute your main thread with file-reading operations

It can be reused across multiple projects

Other developers on your team can use the same subagent

It has specific tool permissions (only Read, Grep, Glob, not Write or Edit)

You can verify the subagent exists by checking:

> Show me what's in the .claude/agents directory


You'll see 

research-assistant.md

 with the complete configuration Claude generated.

Micro-Why:

 Subagents solve the context management problem that plagues long coding sessions. Instead of one AI trying to track everything, you have specialized agents that focus on specific tasks, keep their own context, and return clean results. This architectural pattern scales to teams and complex projects.

The Power Setup: IDE + Claude Code Side by Side

Now that Claude Code is running smoothly, here's how professionals actually use it in production.

Open your project in two places simultaneously:

Launch VS Code, Cursor, or Windsurf

Open 

C:\ClaudeProjects\FirstProject

 in your IDE

Keep Git Bash with Claude Code running in a separate window

Put your IDE on one monitor, Git Bash on the other

Use each tool for what it does best:

Your IDE handles: syntax highlighting, visual debugging, quick edits, file tree navigation, and Git operations through UI.

Claude Code handles: multi-file refactoring, feature implementation, architectural decisions, test generation, and autonomous task completion.

This isn't redundancy. This is specialization.

When you need to change a variable name across 50 files while updating tests and documentation, Claude Code does it. When you need to see a visual diff or set a breakpoint, your IDE does it.

Micro-Why:

 AI coding tools excel at different tasks. No single tool wins everywhere. The developers who leverage AI most effectively understand this and build workflows that use the right tool for each job. Your IDE and Claude Code complement each other rather than compete.

What This Unlocks: The Path to Custom AI Agents

Here's the secret benefit nobody mentions in the installation guides: 

Everything you just set up is the exact environment you need for Claude Agent SDK.

The Agent SDK lets you build custom AI agents that integrate with your own tools, APIs, and workflows. These aren't just chatbots. They're autonomous systems that take actions, make decisions, and complete complex workflows.

But the Agent SDK has the same environment requirements as Claude Code: Unix-style paths, bash commands, Node.js runtime, and proper authentication.

You just installed all of that.

When you're ready to build custom agents (and you will be, once you see what subagents can do), you don't need another complicated setup process. You run:

npm install @anthropic-ai/agent-sdk


And you're building custom AI agents in the same Git Bash terminal where Claude Code already works perfectly.

Micro-Why:

 The path from using AI coding tools to building AI systems should be friction-free. By solving the environment challenges once, you've eliminated the barrier that stops most developers from exploring custom agent development.

Common Issues and Instant Fixes

“Command 'claude' not found”

Close and reopen Git Bash (the PATH needs to refresh after npm global installation)

If that doesn't work, run 

npm config get prefix

 and verify it's in your PATH

“Permission denied” errors

Run Git Bash as Administrator (right-click, “Run as administrator”)

This is usually only needed during initial setup

“Cannot find module” errors

Run 

npm cache clean --force

 and reinstall Claude Code

This clears corrupted package cache

Paths showing weird characters

You're probably in Command Prompt or PowerShell, not Git Bash

Open Git Bash specifically from the Start menu

Claude Code won't authenticate

Check that your browser didn't block the authentication popup

Try API key authentication if browser auth fails

Verify you have internet connectivity

Micro-Why:

 Most installation issues stem from using the wrong terminal or stale npm cache. Git Bash solves the terminal problem. A clean install solves the cache problem.
