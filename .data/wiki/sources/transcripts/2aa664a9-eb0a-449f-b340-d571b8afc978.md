❯ why use 5 min?  is that a magic number?

● Honest answer: yes, it's a magic number. I matched it to StopHook_skill_execution_gate.py's STALE_TIMEOUT = 300 as a

 

consistency argument, but that constant is also arbitrary — it's just "5 minutes" from whoever wrote that file.

What the actual semantic is:

The intent file is written at UserPromptSubmit (the moment the user hits Enter). It should be valid until the model makes

 

its first tool call in response to that prompt. That is measured in seconds, not minutes — it's one model round-trip.

The only reasons to be generous:

Slow model response on a long context

Heavy hook overhead adding latency before the gate fires

Neither of those exceeds ~30 seconds in practice.

What 5 minutes actually protects against is the orphan case (crash, force-kill, abandoned command) — not the normal flow.

 

For the normal flow the file is deleted event-driven (Skill() called, new slash command, non-slash prompt). The TTL is

 

purely a safety net for the abnormal path.

More principled value: 90 seconds. Generous enough to cover any realistic slow-model scenario, tight enough that a crash

 

recovery is unblocked in under 2 minutes rather than 5+.

But the even better answer is: don't hardcode it at all.
