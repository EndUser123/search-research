# MCP Is Getting Its Biggest Update Ever (No One's Ready)
on July 28th MCP ships the biggest rewrite of its 16-month life the handshake is gone the session ID is gone three of the original features are deprecated and the foundation under 110 million SDK downloads a month is about to get simpler than the day it launched you do not rip the core out of a protocol at 16 months because everything is going great so before you look at the change log here is the real question is this a protocol that earned its dominance and is now cleaning up the mess that comes with moving fast or is it a protocol that got adopted before it was ready and is now paying the bill the answer is both and the distinction matters if you are building on it start with why the rewrite exists because the reference script most people are sharing gets this part wrong the problem was not complexity the problem was a single architectural decision that made MCP nearly impossible to deploy in production original MCP was stateful every connection opened with a handshake the server minted a session ID and every request after that had to land on the exact machine holding that session in memory on your laptop harmless in a data center that one decision poisoned everything above it load balancers needed sticky sessions teams stood up red clusters just to store protocol plumbing api gateways had to crack open JSON bodies to figure out where a request should even go and serverless was off the table completely because there was no long-lived process left to do the remembering mcp was designed for a developer machine and the world tried to deploy it to infrastructure that assumes nothing persists in April MCP's co-creator stood on a conference stage and said the new transport exists because people running it in production told the team they got parts of it wrong his words near enough they were still humble enough to say they got it wrong and wanted to fix it together credit where it is due standards usually die defending their mistakes this one admitted the flaw in public what they built instead is a wire with no memory every request now carries everything the server needs to answer it protocol version client identity capabilities any instance can serve any call roundrobe and load balancing autoscaling and serverless deploys work the way they do for every other web service that is the whole change and it is the right one multi-step work survives through a trick as old as the signed cookie when a server needs to hold state across calls it hands back a sealed blob of its own state the client collects it and echoes it back on the next request whichever replica catches it picks up where the last one stopped the state made a round trip through the client and came home now the part the announcement does not say out loud the state management did not vanish it moved if your server tracked anything across calls an open transaction a live browser session a file handle that is now an explicit handle your tools mint and your storage keeps alive and the courier for that handle is a language model a non-deterministic text generator that can drop or mangle an ID for any reason it likes a handle is also a key accept one back without verifying it belongs to the caller and you have handed out a textbook authorization hole at MCP's own conference a vendor was already on stage selling a state side car to hold everything the protocol just evicted that is not a criticism of the decision stateless was the right call but the complexity did not disappear it just became your problem instead of the protocols so here is what that actually means if you build servers if your tools are pure functions a weather lookup a database read a calculation you gain everything and lose nothing deploy them serverless scale them to zero forget they exist but the moment your server holds something live a transaction mid-flight a pageionated cursor a login session you now own three jobs you mint the handle you store what it points to and you check that the caller is allowed to use it every time it comes back skip that last one and a helpful language model will happily replay another user's handle straight into your data the rewrite did not make servers simpler it made simple servers trivial and stateful servers your full responsibility now the part that actually matters more than the transport rewrite and the part the
