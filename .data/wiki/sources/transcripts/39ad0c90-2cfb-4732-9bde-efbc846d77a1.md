# Current UPS Logging Implementation
# UPS Execution Trace Logging Implementation





## Architecture


- File-based JSONL logging: `ups_execution_trace.jsonl`


- Location: `P:/.claude/hooks/logs/diagnostics/`


- Rotation: 1000 entries max, 10MB file size max, 30-day retention


- Format: One JSON object per line





## Data Flow


```


UserPromptSubmit event


↓


registry.py:run_hooks()


↓


For each hook:


1. Capture stdout/stderr (StringIO buffers)


2. Execute hook


3. Log execution trace (hook, result, stdout, stderr)


↓


After all hooks:


Log final results summary


```





## Log Entry Structure





### Per-Hook Execution Trace


```json


{


"ts": "2026-03-08T13:25:00",


"session_id": "abc123",


"terminal_id": "slug",


"hook_name": "memory_size_check",


"result": {


"is_empty": false,


"has_context": true,


"context_type": "str",


"tokens_added": 150,


"context": "actual context data"


},


"stdout_captured": "...",


"stderr_captured": "..."


}


```





### Final Results Summary


```json


{


"ts": "2026-03-08T13:25:00",


"session_id": "abc123",


"terminal_id": "slug",


"num_hooks_run": 5,


"num_results": 3,


"results_summary": [


{"is_empty": false, "has_context": true, "context_type": "str"},


{"is_empty": false, "has_context": true, "context_type": "dict"},


{"is_empty": true, "has_context": false, "context_type": null}


]


}


```





## Key Features


- **Session correlation**: session_id and terminal_id in all entries


- **Stdout/stderr capture**: StringIO buffers during hook execution


- **Result classification**: is_empty, has_context, context_type


- **Final summary**: Aggregate statistics after all hooks complete


- **Graceful degradation**: Logging failures don't break hooks


- **Unified rotation**: Integrated with existing log rotation system
