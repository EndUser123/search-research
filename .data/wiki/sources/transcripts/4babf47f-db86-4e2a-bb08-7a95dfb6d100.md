This looks to be an evolution of the problem reported in 

#13770

https://github.com/yt-dlp/yt-dlp/issues/13770

, which was fixed (at least for a while) by 

8820101

https://github.com/yt-dlp/yt-dlp/commit/8820101aa3152e5f4811541c645f8b5de231ba8c

.

YT has likely imposed a much stricter rate-limit on subtitles requests since then. They could also be increasing their fingerprinting efforts.

If you want to still be able to download the video when the subtitles download fails, then add 

-i

 ( 

--ignore-errors

 ) to your command.

Also, as always, if you are downloading multiple videos in one invocation of yt-dlp (such as a playlist or batch), then add 

-t sleep

 to your command.

Manual subtitles and original language automatic captions are not affected by this HTTP Error 429 issue.

Only subtitles/captions that have been automatically translated into another language are affected. So you may be able to get the subs you want without a problem if you are precise with your 

--sub-langs

 and 

--write-subs

 vs 

--write-auto-subs

 arguments.

But if you 

want

 translated auto subs,

there are 2 known ways of avoiding this HTTP Error 429:

Pass fresh cookies to yt-dlp from a browser session where you've very recently loaded auto-translated subs

Wait ~60 seconds after extraction and before downloading the auto subs, e.g. 

--sleep-subtitles 60

(Either of these 2 methods will work individually, you do not need to combine them)

Also, updating method 1 in the YTDLNIS android application is very easy.

I seem to have found a workaround that allows you to at least skip downloading auto-translated subtitles. To download the default auto-generated subtitles, you can seemingly just use 

[language code]-orig

 in 

--sub-langs

 . Now, for downloading manually added subs while you have the 

--write-auto-subs

 flag enabled, you run into the issue that, with e.g. the language code 

en

 on a non-english video youtube will give you auto-translated english subtitles, which causes the 429 error. For some reason though, you can just 

double the language code

 (e.g. 

en-en

 , 

de-de

 , 

es-es

 , etc.) and the issue gets fixed. This language code seems to correspond to auto-translating the english language subtitles to english, which youtube for some reason allows, and seems to just download the original subtitles unchanged. For videos with more specific subtitles, e.g. "English (Ireland)", you'll still have to use its own code (in this case 

en-IE

 ).

So as an example this is what I have in my config for downloading any english language subtitles (including auto-generated ones) while excluding auto-translated subs: 

--sub-langs "en-en,en-AU,en-CA,en-IN,en-IE,en-GB,en-US,en-orig"
