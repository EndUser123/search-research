How to Install OpenCode: Step-by-Step Setup Guide (2026)

OpenCode is the open-source AI coding agent built for the terminal. It brings the power of large language models directly into your command line, letting you write, refactor, debug, and understand code without leaving your editor or terminal workflow.

Whether you are setting up OpenCode for the first time or migrating from another AI coding tool, this guide walks you through every installation method, initial configuration, provider setup, and troubleshooting step you will need.

Prerequisites

Before installing OpenCode, confirm your system meets the following requirements.

Operating System

OpenCode runs on macOS, Linux, and Windows. For Windows users, WSL (Windows Subsystem for Linux) is strongly recommended. Native Windows support via Scoop is also available.

Runtime Requirements (depends on install method)

Install Method

Requirement

npm

Node.js 18 or higher

Homebrew

macOS or Linux with Homebrew installed

Curl script

bash, curl

Go install

Docker

Docker Engine 20+

Build from source

Go 1.22+, Git

Terminal Requirements

OpenCode provides a TUI (Terminal User Interface), so your terminal emulator must support true color and proper Unicode rendering. Most modern terminals (iTerm2, Alacritty, WezTerm, Windows Terminal, Ghostty) work out of the box. Older terminals like the default macOS Terminal.app may have rendering issues.

Check your Node.js version:

node --version


Check your Go version (if using the Go install method):

go version

Method 1: Install Script (Fastest)

The official install script is the quickest way to get OpenCode running. It detects your OS and architecture, downloads the correct binary, and places it in your PATH.

curl -fsSL https://opencode.ai/install | bash


This single command handles everything. After it completes, verify the installation:

opencode --version


This method works on macOS and Linux. It does not require Node.js or Go.

Method 2: npm Install

If you already have Node.js in your workflow, npm is the most familiar option.

npm install -g opencode-ai@latest


The package name on npm is 

opencode-ai

 , not 

opencode

 . This is a common source of confusion.

To verify:

opencode --version


If you encounter permission errors, either fix your npm global directory permissions or use npx to run it without a global install:

npx opencode-ai@latest


Method 3: Homebrew (macOS and Linux)

Homebrew users can install OpenCode from the official tap:

brew install anomalyco/tap/opencode


This installs the latest stable release and handles updates through 

brew upgrade

 .

To verify:

opencode --version


Method 4: Go Install

If you have Go 1.22+ installed, you can install directly from source via 

go install

 :

go install github.com/opencode-ai/opencode@latest


Make sure 

$GOPATH/bin

 (or 

$HOME/go/bin

 by default) is in your PATH. Add it to your shell profile if it is not already:

export PATH="$PATH:$(go env GOPATH)/bin"


Verify:

opencode --version


Method 5: Docker

Running OpenCode in Docker is useful for CI/CD pipelines or when you want an isolated environment.

docker pull ghcr.io/opencode-ai/opencode:latest


Run it with your project directory mounted:

docker run -it --rm \
  -v "$(pwd)":/workspace \
  -w /workspace \
  -e OPENAI_API_KEY="$OPENAI_API_KEY" \
  ghcr.io/opencode-ai/opencode:latest


The 

-it

 flags are essential because OpenCode uses an interactive TUI. The 

-v

 flag mounts your current project directory so OpenCode can read and modify your files.

Method 6: Build from Source

For contributors or anyone who wants the bleeding-edge version:

git clone https://github.com/opencode-ai/opencode.git
cd opencode
go build -o opencode .


Move the binary to a directory in your PATH:

sudo mv opencode /usr/local/bin/


Building from source requires Go 1.22+ and Git. This gives you access to unreleased features and lets you modify the tool for your own needs.

Method 7: Scoop (Windows)

Windows users who prefer a native experience over WSL can use Scoop:

scoop install opencode


Scoop handles PATH configuration automatically.

First Launch and Configuration

With OpenCode installed, navigate to any project directory and launch it:

cd your-project
opencode


On first launch, OpenCode opens its TUI and prompts you to connect an AI provider. You can use the interactive 

/connect

 command to add your API key:

/connect


This walks you through selecting a provider (OpenAI, Google, Anthropic, etc.) and entering your API key. Credentials are stored in 

~/.local/share/opencode/auth.json

 .

For a faster start, you can also initialize your project with:

/init


This analyzes your repository structure and creates an 

agents.md

 file with context about your codebase, helping the AI give more accurate responses from the start.

Configure AI Providers

OpenCode supports multiple AI providers. Here is how to configure each one.

OpenAI (GPT-5.4, GPT-4.1, o3)

Set the API key as an environment variable:

export OPENAI_API_KEY="sk-your-key-here"


Or add it to your shell profile ( 

~/.zshrc

 , 

~/.bashrc

 ) for persistence.

Google Gemini (Gemini 2.5 Pro, Gemini 2.5 Flash)

export GOOGLE_API_KEY="your-google-api-key"


You can obtain a Google API key from 

Google AI Studio

https://aistudio.google.com/

.

Ollama (Local Models -- Free, Private)

Ollama lets you run models locally without any API key. Install Ollama first, pull a model, then configure OpenCode:

# Install Ollama (if not already installed)
curl -fsSL https://ollama.com/install.sh | sh

# Pull a coding model
ollama pull qwen2.5-coder:32b

# OpenCode detects Ollama automatically when running on localhost:11434


No API key is needed for Ollama. OpenCode auto-detects it when running locally.

Anthropic (Claude -- Limited Access)

Anthropic has restricted Claude access in third-party tools including OpenCode. If you have an API key that still works:

export ANTHROPIC_API_KEY="sk-ant-your-key-here"


However, most users in 2026 are using OpenAI or Gemini as their primary provider with OpenCode due to these restrictions.

Essential Configuration: config.toml Walkthrough

OpenCode uses a TOML configuration file for fine-grained control. The config file lives at 

~/.config/opencode/config.toml

 (or in your project root as 

opencode.json

 for project-specific settings).

Here is a practical example of a 

config.toml

 :

# Provider configuration
[provider.openai]
apiKey = "{env:OPENAI_API_KEY}"

[provider.openai.models.gpt]
id = "gpt-5.4"

[provider.google]
apiKey = "{env:GOOGLE_API_KEY}"

[provider.google.models.gemini]
id = "gemini-2.5-pro"

# Disable providers you do not use
disabled_providers = ["anthropic"]


Key things to note:

Variable substitution

: Use 

{env:VARIABLE_NAME}

 to reference environment variables instead of hardcoding keys.

Model selection

: You can specify exactly which model to use under each provider.

Disabled providers

: Prevent OpenCode from loading providers whose credentials you do not have, avoiding startup warnings.

Base URL override

: If you use a proxy or custom endpoint, add 

baseURL = "https://your-proxy.com/v1"

 under the provider section.

For project-level configuration, create an 

opencode.json

 in your project root:

{
  "provider": "openai",
  "model": "gpt-5.4"
}


This overrides global settings for that specific project.

Verify Your Installation

Run through this checklist to confirm everything works correctly.

1. Check the version

opencode --version


You should see the version number printed. As of March 2026, the latest stable version is in the 0.x range.

2. Launch the TUI

cd any-project-directory
opencode


You should see the OpenCode terminal interface with a prompt at the bottom.

3. Test a simple prompt

In the OpenCode TUI, type a simple request:

Explain what this project does based on the file structure.


If you get a response from the AI, your provider configuration is working.

4. Test file operations

Ask OpenCode to create a small test file:

Create a file called test-opencode.txt with the text "OpenCode is working"


Check that the file was created in your project directory, then delete it.

Troubleshooting Common Issues

"command not found: opencode"

The binary is not in your PATH. Solutions depend on your install method:

npm: Run 

npm list -g opencode-ai

 to confirm installation. If installed, check that npm's global bin directory is in your PATH: 

npm config get prefix

 and add 

/bin

 to that path.

Go: Add 

$(go env GOPATH)/bin

 to your PATH.

Curl script: Re-run the install script or manually move the binary to 

/usr/local/bin/

 .

Permission errors during npm install

Do not use 

sudo npm install -g

 . Instead, fix npm's default directory:

mkdir -p ~/.npm-global
npm config set prefix '~/.npm-global'
echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
npm install -g opencode-ai@latest


"Error: Node.js version too old"

OpenCode's npm package requires Node.js 18+. Check your version:

node --version


If you are on an older version, upgrade using nvm:

nvm install 18
nvm use 18


Network errors behind a corporate firewall

If npm install hangs or fails due to network restrictions:

npm install -g opencode-ai@latest --registry https://registry.npmmirror.com


Or download the binary directly from the 

GitHub releases page

https://github.com/opencode-ai/opencode/releases

 and place it in your PATH manually.

"API key not found" or "No provider configured"

Make sure your API key environment variable is exported in the same shell session:

echo $OPENAI_API_KEY


If it prints nothing, set it again:

export OPENAI_API_KEY="sk-your-key-here"


For persistence, add the export line to your 

~/.zshrc

 or 

~/.bashrc

 and run 

source ~/.zshrc

 .

TUI rendering issues (garbled text, missing borders)

Switch to a modern terminal emulator that supports true color. Recommended options: iTerm2 (macOS), Alacritty (cross-platform), WezTerm (cross-platform), or Windows Terminal (Windows).

Go install: "go: command not found"

Go is not installed or not in your PATH. Install Go from 

go.dev/dl

https://go.dev/dl/

 and ensure it is in your PATH:

export PATH="$PATH:/usr/local/go/bin"


Updating OpenCode

Keep OpenCode current to get the latest model support and bug fixes.

npm

:

npm update -g opencode-ai


Homebrew

:

brew upgrade opencode


Curl script

: Re-run the install command:

curl -fsSL https://opencode.ai/install | bash


Go install

: Re-run with 

@latest

 :

go install github.com/opencode-ai/opencode@latest


Next Steps

Now that OpenCode is installed and configured, you are ready to start using it in your daily workflow.

Learn the commands

: Check out our 

OpenCode Tutorial 2026

https://www.nxcode.io/resources/news/opencode-tutorial-2026

 for a full walkthrough of commands, workflows, and advanced features.

Set up GitHub integration

: Install the OpenCode GitHub App to use AI-powered code review and issue responses directly in your repositories.

Explore the /init command

: Run 

/init

 in your project to generate an 

agents.md

 file that gives OpenCode deep context about your codebase architecture.

Try multiple providers

: Configure two or three providers and switch between them to find which model works best for your coding tasks.

OpenCode is one of the fastest-growing open-source AI tools in 2026 because it meets developers where they already work: the terminal. With installation taking under five minutes and configuration requiring just one API key, there is no reason not to try it today.
