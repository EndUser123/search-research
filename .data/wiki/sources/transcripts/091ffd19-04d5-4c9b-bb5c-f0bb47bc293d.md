A Practical Framework
Think of each domain as a verification layer:
LAYER 1: SYNTACTIC (does it parse?)
 
→ ruff, mypy, tsc
LAYER 2: SEMANTIC (does it work?)
 
→ pytest, integration tests
LAYER 3: STRUCTURAL (is it built right?)
 
→ Architecture checks, dependency analysis
LAYER 4: REQUIREMENTS (did we build the right thing?)
 
→ GTO, acceptance criteria mapping
LAYER 5: SECURITY (is it safe?)
 
→ Vulnerability scanners, secret detection
LAYER 6: PERFORMANCE (is it fast enough?)
 
→ Benchmarks, load tests
LAYER 7: OPERATIONAL (does it deploy/run?)
 
→ Health checks, smoke tests
What GTO partially covers: Layer 4 (Requirements) — it finds missing tests, docs, dependencies. But it doesn't verify requirements
 
are correct, just that coverage exists.
What Would Actually Move You Toward "Perfect"
Map your codebase against these 7 layers — see which layers have tooling and which don't
For each gap, decide: fix it, accept the risk, or document the gap
GTO filling its own gaps would be: GTO adding architecture conformance detection, dependency freshness checks
The user has GTO doing Layer 4. The missing layers (3, 5, 6) are where you'd see the biggest move toward completeness confidence.
