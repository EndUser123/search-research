From Interactive to Automated

In Lesson 1, you learned to create 

Skills

 that guide 

Claude

 's behavior during interactive conversations. You write instructions in 

SKILL.md

 , and 

Claude

 follows them when you chat. This works well when you're present to guide the interaction and review results.

However, many tasks need to run without your direct involvement: processing files during meetings, reviewing every 

pull request

 automatically, or analyzing thousands of 

log entries

 overnight. These scenarios require 

CLI automation

. 

CLI automation

 transforms 

Claude

 into a tool that integrates with your workflows. Instead of starting a conversation, you invoke 

Claude

 with specific parameters, feed it data through files or 

standard input

 , and capture structured 

output

 that scripts can process.

This lesson teaches you to invoke 

Claude

 from the command line with specific parameters, control accessible tools, structure output for machine parsing, and integrate everything into 

shell scripts

 . You'll build three automation scripts: one reviewing changed files in 

pull requests

 , one generating 

API documentation

, and one categorizing 

log

 errors.

When you invoke 

Claude

 in 

print mode

 , any 

Skills

 you've created remain active. If your instructions match a 

Skill

 's description, 

Claude

 automatically applies that guidance. However, you cannot use 

/skill-name

 syntax in 

print mode

 — write instructions directly and optionally use 

--append-system-prompt

 for additional context.

Print Mode: The Foundation of CLI Automation

The 

-p

 flag enables 

print mode

 — 

Claude

 's non-interactive operation. In 

print mode

 , 

Claude

 receives instructions, processes input, generates output, prints to 

stdout

 , and exits. No conversation, just: input in, output out, process ends.

Basic syntax:

Bash
Copy to clipboard
1claude -p "Explain what a for loop does"


Claude

 generates an explanation, prints it, and exits. Your terminal prompt returns immediately.

The power emerges when combining with 

shell

 features. Capture output in variables, redirect to files, or pipe to other commands. 

Print mode

 makes 

Claude

 behave like any 

Unix

 tool.

When deciding between modes: use interactive for exploration and debugging where you need follow-up questions. Use 

print mode

 for batch processing, documentation generation, or automated checks.

Controlling Tools and Context from the Command Line

The 

--tools

 flag accepts a comma-separated list of tool names 

Claude

 can access. Specify only what's needed for the task:

Bash
Copy to clipboard
1claude -p \
2  --tools "Read,Bash" \
3  "Check if the tests pass by reading the test file and running them"


Claude

 can read files ( 

Read

 ) and execute commands ( 

Bash

 ) but cannot edit anything. Available tools: 

Read

 , 

Write

 , 

Edit

 , 

Bash

 , 

Grep

 , 

Glob

 .

The 

--append-system-prompt

 flag adds instructions for this specific invocation without modifying 

Skill

 files:

Bash
Copy to clipboard
1claude -p \
2  --tools "Read,Bash" \
3  --append-system-prompt "Focus on security and bugs" \
4  "Review this file for security issues" < app.js


The 

--max-turns

 flag limits execution iterations. Setting 

--max-turns 2

 allows one response with potential tool use and a final response. Setting 

--max-turns 1

 forces a single response.

Complete example:

Bash
Copy to clipboard
1claude -p \
2  --tools "Read,Bash" \
3  --append-system-prompt "Focus on security and bugs" \
4  --max-turns 2 \
5  "Review this file for security issues" < app.js


Structured Output for Machine-Readable Results

Conversational responses return natural language, which is difficult to parse reliably in scripts. The 

--output-format json

 flag returns structured data.

When using 

--output-format json

 , the CLI wraps the response with metadata (execution time, token usage, costs). Your data lives under 

.result

 :

Bash
Copy to clipboard
1cat /var/log/app.log | \
2  grep ERROR | \
3  claude -p \
4    --output-format json \
5    --max-turns 1 \
6    "Categorize these errors by type and severity"


Output structure:

JSON
Copy to clipboard
1{
2  "type": "result",
3  "duration_ms": 5234,
4  "usage": {...},
5  "result": {
6    "categories": [
7      {
8        "type": "DatabaseConnectionError",
9        "severity": "high",
10        "count": 15
11      }
12    ]
13  }
14}


Extract data with 

jq

 using 

.result

 :

Bash
Copy to clipboard
1cat /var/log/app.log | \
2  grep ERROR | \
3  claude -p --output-format json --max-turns 1 \
4    "Categorize these errors by type and severity" | \
5  jq '.result.categories[] | select(.severity == "high")'


For precise control over output shape, use 

--json-schema

 :

Bash
Copy to clipboard
1claude -p \
2  --json-schema '{
3    "type": "object",
4    "properties": {
5      "endpoint": {"type": "string"},
6      "method": {"type": "string"},
7      "description": {"type": "string"}
8    }
9  }' \
10  "Extract API documentation" < src/api/users.ts


The schema guarantees specific fields exist with defined types. With 

--json-schema

 , data appears under 

.structured_output

 :

Bash
Copy to clipboard
1claude -p --json-schema '{...}' "Extract API docs" < src/api/users.ts | \
2  jq '.structured_output.endpoint'


Use 

--output-format json

 when you want structured output but don't need control over the exact shape — results appear in 

.result

 . Use 

--json-schema

 when integrating with existing systems or when you need guaranteed field names — results appear in 

.structured_output

 .

Shell Integration: Piping and Redirection

Input redirection

 ( 

<

 ) feeds file contents to 

Claude

 :

Bash
Copy to clipboard
1claude -p "Explain this code" < app.js


Pipes

 ( 

|

 ) connect command output to 

Claude

 's input:

Bash
Copy to clipboard
1grep ERROR /var/log/app.log | claude -p "Summarize these errors"


Chain multiple commands:

Bash
Copy to clipboard
1grep ERROR /var/log/app.log | sort | uniq | claude -p "Categorize these unique errors"


Output redirection

 ( 

>

 ) writes 

Claude

 's response to a file:

Bash
Copy to clipboard
1claude -p "Generate a README" < project-info.txt > README.md


Complete example combining all mechanisms:

Bash
Copy to clipboard
1find src/ -name "*.js" | \
2  xargs cat | \
3  claude -p "List all exported functions" | \
4  sort > exports.txt


Reviewing Pull Request Changes

Create 

scripts/review-changes.sh

 :

Bash
Copy to clipboard
1#!/bin/bash
2# Review all changed files in PR
3
4git diff --cached --name-only | while read file; do
5  echo "Reviewing: $file"
6  
7  claude -p \
8    --tools "Read,Bash" \
9    --append-system-prompt "Focus on security and bugs" \
10    --output-format json \
11    --max-turns 2 \
12    "Review this file for security issues" < "$file" | \
13  jq '.result'
14done


The script lists staged files, feeds each to 

Claude

 for security review, and extracts structured results.

Generating API Documentation

Create 

scripts/document-apis.sh

 :

Bash
Copy to clipboard
1#!/bin/bash
2# Generate API docs for all endpoints
3
4find src/api -name "*.ts" | while read file; do
5  output="${file%.ts}.md"
6  
7  claude -p \
8    --json-schema '{
9      "type": "object",
10      "properties": {
11        "endpoint": {"type": "string"},
12        "method": {"type": "string"},
13        "description": {"type": "string"}
14      }
15    }' \
16    "Extract API documentation" < "$file" | \
17  jq -r '.structured_output | "# \(.endpoint)\n\n**Method:** \(.method)\n\n\(.description)"' > "$output"
18done


The script finds all API files, extracts documentation using a schema, and formats as Markdown.

Analyzing Log Files

Create 

scripts/analyze-logs.sh

 :

Bash
Copy to clipboard
1#!/bin/bash
2# Analyze logs for errors
3
4cat /var/log/app.log | \
5  grep ERROR | \
6  claude -p \
7    --output-format json \
8    --max-turns 1 \
9    "Categorize these errors by type and severity" | \
10  jq '.result'


Filters log errors, categorizes them, and outputs structured results.

Understanding JQ for Output Processing

The dot notation 

.result

 or 

.structured_output

 accesses fields in 

JSON

 objects depending on which flag you used. Square brackets 

[]

 iterate over arrays, so 

.result.categories[]

 processes each category element.

The 

jq

 pipe operator chains operations. The expression 

.result.categories[] | select(.severity == "high")

 gets all categories, then keeps only high-severity ones.

For most automation, you'll extract fields using 

.result.field_name

 with 

--output-format json

 or 

.structured_output.field_name

 with 

--json-schema

 .

Summary

You've learned to invoke 

Claude

 from the command line using 

print mode

 ( 

-p

 ), restrict operations with 

--tools

 , add context with 

--append-system-prompt

 , and limit iterations with 

--max-turns

 . For output, use 

--output-format json

 for structured data in 

.result

 or 

--json-schema

 for precise shapes in 

.structured_output

 . 

Shell

 mechanisms like 

input redirection

 , 

pipes

 , and 

output redirection

 connect 

Claude

 with other commands.

You have a complete toolkit: 

Skills

 defining reusable behaviors, 

Plugins

 packaging them for sharing, and 

CLI automation

 integrating everything into workflows. 

Skills

 work automatically in both interactive mode and automation.
