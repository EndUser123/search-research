I'm Katagiri from the AI Business Division/Western Japan Development Team.

As April approaches and more people are likely to start using Claude Code,

I've organized what I consider to be "settings and features to understand from the start."

About this article

[Target audience]

People who have installed Claude Code but haven't configured it specifically

People who want to review Claude Code's basic features

!

The information in this article is based on Claude Code v2.1.84 (as of April 2026).

Please check the 

Claude Code official documentation

https://code.claude.com/docs/ja/overview

 for the latest information.

Current status check

Run the following command to verify Claude Code is working properly.

claude doctor


After execution, you'll want to confirm these 2 items:

claude doctor execution results (partial excerpt)

└ Currently running: native (2.1.84) ← check if running native version
└ Auto-update channel: stable ← (version setting for auto-updates)


!

Installing via npm is currently "not recommended" by official sources.

For more details, please check 

here

https://code.claude.com/docs/ja/setup#%E9%9D%9E%E6%8E%A8%E5%A5%A8%E3%81%AE-npm-%E3%82%A4%E3%83%B3%E3%82%B9%E3%83%88%E3%83%BC%E3%83%AB

.

Introduction - Claude Code general settings ( 

settings.json

 )

Before creating 

CLAUDE.md

 , let's first check 

settings.json

 , which contains Claude Code's settings.

This file defines model specifications, environment variables, and 

Hooks

 that will be discussed later.

settings.json

 location

~/.claude/settings.json

 common across all projects

.claude/settings.json

 per project (create as needed)

Example 

settings.json

Below is what I set up initially.

settings.json

{
  "autoUpdatesChannel": "stable",
  "language": "japanese",
  "cleanupPeriodDays": 14,
  "showTurnDuration": true,
  "spinnerTipsEnabled": false,
  "model": "sonnet",
  "env": {
    "DISABLE_NON_ESSENTIAL_MODEL_CALLS": "1"
  }
}


Explanation of settings

autoUpdatesChannel ("stable")

: Update resource channel

language ("japanese")

: Fix responses to Japanese.

cleanupPeriodDays (14)

: Automatically delete old session history after 14 days.

showTurnDuration (true)

: Display time taken for each response.

spinnerTipsEnabled (false)

: Turn off tips display during loading (personal preference).

DISABLE_NON_ESSENTIAL_MODEL_CALLS ("1")

: Stop unnecessary API calls in the background.

Auto-update (About update resource channels)

This option lets you configure whether Claude Code installs the latest version or the stable version when updating.

"latest"

: Receive the 

latest version

 as soon as it's released (default)

"stable"

: Use a version from 

about 1 week ago

, skipping releases with major regressions

Quoted from the 

official documentation

https://code.claude.com/docs/ja/setup#%E3%83%AA%E3%83%AA%E3%83%BC%E3%82%B9%E3%83%81%E3%83%A3%E3%83%8D%E3%83%AB%E3%82%92%E6%A7%8B%E6%88%90

!

For the Native version, updates happen automatically in the background.

If installed via Homebrew, etc., you'll need to run update commands separately. 

Reference

https://code.claude.com/docs/ja/quickstart#%E3%82%B9%E3%83%86%E3%83%83%E3%83%97-1%EF%BC%9Aclaude-code-%E3%82%92%E3%82%A4%E3%83%B3%E3%82%B9%E3%83%88%E3%83%BC%E3%83%AB%E3%81%99%E3%82%8B

After setting, run 

claude doctor

 to confirm the changes have been applied.

How to change the IDE that opens for editing

If you use multiple editors, the system might not automatically launch your preferred editor.

In that case, you can modify the 

env

 in 

settings.json

 to change it.

Here's an example for opening files in 

VSCode

:

settings.json

{
  "env": {
    "EDITOR": "code --wait",
    "VISUAL": "code --wait"
  }
}


For opening in Cursor

settings.json

{
  "env": {
    "EDITOR": "cursor --wait",
    "VISUAL": "cursor --wait"
  }
}


For opening in Vim

settings.json

{
  "env": {
    "EDITOR": "vim",
    "VISUAL": "vim"
  }
}


Creating instructions for Claude Code ( 

CLAUDE.md

 )

CLAUDE.md

 is an instruction document that's automatically loaded at the start of each session.

The goal is to create a state where "you don't have to explain the same thing every time."

CLAUDE.md

 location

~/.claude/CLAUDE.md

 ← "Personal rules" common across all projects

./CLAUDE.md

 (project root) ← Instructions specific to that project

Principles to know before writing 

CLAUDE.md

The longer your 

CLAUDE.md

 , the more tokens are consumed each time, and overall inference accuracy may decrease.

+ What to write: Your work style, things you don't want done, rules used across projects  

- What not to write: Code style, things controlled by settings.json, overly long background explanations


Example 

CLAUDE.md

First, create rules common to all projects.

CLAUDE.md

# Basic Policy
- Always present a work plan and get confirmation before making changes
- Make changes gradually in small steps rather than large batches
- Stop and ask questions when something is unclear

# What Not to Do
- Don't modify files that weren't specified
- Don't read or modify `.env` files
- Don't skip tests without permission

# Context Management
- Suggest `/clear` after completing tasks
- Suggest `/compact` for long sessions


Creating 

CLAUDE.md

 for specific projects during work

Project-specific 

CLAUDE.md

 can be automatically created using 

/init

 within a Claude session.

Since it's auto-generated, be sure to review it after creation.

You can also manually create it in the project directory.

Examples to add per project

Add team-specific rules that weren't automatically detected

Delete unnecessary lines (shorter is better!)

Four Methods to Reduce Token Consumption

The context window counts 

[conversations with Claude Code, loaded files, execution results, CLAUDE.md content]

 etc.

As this amount increases, accuracy decreases and token consumption (cost) increases.

Check the current session context window status

Use the 

/context

 command to check current usage.

At startup, 

about 15k tokens

 are consumed.

Of those, about 14.5k (System prompt + System tools) are 

fixed costs that cannot be changed

.

From here, you can only adjust 

[Memory files (CLAUDE.md) + Skills]

.

Four commands for saving tokens

/clear

 ← Initialize the context window

When to use:

When switching to a different task

When one task is completed

When the conversation starts to go off track

/compact

 ← Summarize the context window to create space

When to use:

When you want to continue the same task, but the context exceeds 70%.

It's even more useful when used with instructions, like 

/compact Make sure to keep the modified files and current TODOs

 .

/context

 ← Check current usage

When to use:

When response accuracy seems poor

When speed decreases

@

 ← Narrow down the loaded content by specifying files

Using 

@filename

 or 

@directory

 lets you include files in your prompt.

By providing only the parts related to the current task instead of the entire project, you can minimize context window growth.

+ Bad example: `@project-a/` Find bugs in the entire project  

- Optimal example: `@src/auth.ts Add error handling to the loginUser function as it's currently missing`


Understanding Two Key Features

I'll briefly summarize two representative features of Claude Code: 

[Skills & Hooks]

.

Execution (invocation) timing

Skills

:

Explicit execution ( 

/skill-name

 )

Automatically executed by Claude Code as needed

Hooks

:

Automatically executed based on Claude Code's processes

1. Skills

By placing SKILL.md in the 

.claude/skills/

 directory, you can package workflows.

!

Slash commands are now functionally integrated into "Skills". 

Reference

https://code.claude.com/docs/ja/skills

SKILL.md

---
name: memo-management
description: Used when handling memos, minutes, and note files. Applied when summarizing, organizing, and extracting actions.
---

## How to handle memo files
- Read only, do not modify or overwrite content


2. Hooks

This powerful feature automatically runs shell commands at specific times when Claude Code performs certain actions (before/after tool execution, at session end, etc.).

Add a 

hooks block

 to 

settings.json

 to define them.

Recently, it's become possible to use if filters to hook only specific commands and block their execution.

[

Claude Code Hooks の if フィルタで特定コマンドだけをフックする | DevelopersIO

 dev.classmethod.jp](https://dev.classmethod.jp/articles/claude-code-hooks-if-condition-guardrails/)

Here's a simple example that sends a notification when work is completed.

settings.json

{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Work completed\" with title \"Claude Code\"'"
          }
        ]
      }
    ]
  }
}


How to choose between 

CLAUDE.md

 and 

Skills

CLAUDE.md

 loads " 

all content

" at the start of each session, always consuming tokens. 

Skills

 only loads the " 

description

" at startup, loading the full content only when needed.

Using 

Skills

 allows you to use tokens more efficiently.
