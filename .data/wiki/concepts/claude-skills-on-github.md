# Claude Skills on GitHub

## Decision context

**Definition:** A recurring pattern across the corpus in which modular, folder-based skills for Claude Code are distributed through public GitHub repositories, installed into the user's skills directory, and consumed by Claude Code's progressive-disclosure loader. Each skill lives in its own folder, is configured by a SKILL.md file with YAML frontmatter (name, description), and is referenced by a Claude Code plugin marketplace.

## Operational details

- Skill distribution shape: a single GitHub repo containing one folder per skill; the folder always includes SKILL.md and optionally CHANGELOG.md, scripts/, assets/, references/, and a .env.example.
- Installation surface: Claude Code plugin marketplace (`claude plugin marketplace add <owner>/<repo>` then `claude plugin install <skill>@<marketplace>`), `npx skills add <owner>/<repo> --skill <name>`, or manual `cp -r <skill> ~/.claude/skills/`.
- Authoring contract: SKILL.md requires YAML frontmatter fields `name` (kebab-case, matches parent directory) and `description` (third-person, keywords for matching, ~1024 char cap).
- Authoring rules: body under 500 lines, progressive disclosure (top-level metadata ~100 tokens, body <5000 tokens when active, references loaded on demand), no absolute paths, scoped tools only, never embed secrets.
- Discovery and load behavior: Claude Code reads SKILL.md metadata at discovery and the full body only when the skill activates; skill activation reliability without intervention is roughly 20%, rising to roughly 84% when a UserPromptSubmit lifecycle hook enforces an EVALUATE→ACTIVATE→IMPLEMENT sequence.
- Cross-assistant path mapping: Claude Code `.claude/skills/`, Codex `.agents/skills/`, Cursor `.cursor/skills/`, Gemini CLI `.gemini/skills/`, GitHub Copilot `.github/skills/` (or `~/.copilot/skills/`), OpenCode `.opencode/skills/`, Windsurf `.codeium/windsurf/skills/`, Antigravity `.gemini/antigravity/skills/`.
- Security posture: skills are curated, not audited; recommended external checks include Snyk Skill Security Scanner (`snyk/agent-scan`) and Agent Trust Hub. Skills are typically MIT-licensed as curated lists; underlying skill code retains its own license.
- Cross-cutting GitHub-adjacent plumbing present in skills: a `KAIROS_GITHUB_WEBHOOKS` flag with a partially wired command slot and missing `SubscribePRTool.js`; utilities `ghAuthStatus.ts` and `githubRepoPathMapping.ts` exist; a dedicated `github-app` install slash command exists with a multi-step wizard (ApiKeyStep, OAuthFlowStep, InstallAppStep, etc.) and constants at `src/constants/github-app.ts`.
- GitHub authentication is documented in two forms: an OAuth GitHub App installation flow implemented as a slash command wizard, and GitHub-gist publication via the `gh` CLI (`gh auth status` / `gh auth login`) with a `GITHUB_GIST_TOKEN` fallback carrying gist scope.
- Claude Code HTTPS exposure: the Anthropic API is reached via HTTPS POST with `model`, `messages`, `max_tokens`, optional `system`, `temperature`, `stream`; streaming uses Server-Sent Events; tool use blocks (`tool_use`, `tool_result`) maintain a multi-turn message history. Rate-limit handling relies on exponential backoff with jitter, honoring `Retry-After` on HTTP 429.
