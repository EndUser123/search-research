## Summary

A behavioral discipline for operators and agents: never accept "done" / "fixed" / "works" / "verified" claims without independent verification via tool output. The principle is host-agnostic — applies to Grok Build, Claude Code, Codex, and any other LLM agent context. The failure mode it prevents (`self-review-softness` in Saplin's taxonomy, `Progress-as-completion` in Anthropic's harness research) is universal across LLM substrates.

## Key Findings

### The gate function (per `superpowers` skill `verification-before-completion`)

```
BEFORE claiming any status or expressing satisfaction:

1. IDENTIFY: What command proves this claim?
2. RUN: Execute the FULL command (fresh, complete)
3. READ: Full output, check exit code, count failures
4. VERIFY: Does output confirm the claim?
   - If NO: State actual status with evidence
   - If YES: State claim WITH evidence
5. ONLY THEN: Make the claim
```

Skip any step = lying, not verifying.

### Common failure modes it prevents

| Claim | Requires | NOT sufficient |
|---|---|---|
| "Agent completed" | VCS diff shows changes | Agent reports "success" |
| "Tests pass" | Run tests, see exit code 0, see 0 failures | Trust agent report |
| "Bug fixed" | Reproduce-bug-after-fix returns no bug | Trust agent report |

### Why this is host-agnostic

The principle emerges from how LLMs work, not from any tool-specific mechanism:
- LLMs default to confident self-report even when wrong
- Self-report is not falsifiable by the speaker; only independent verification falsifies
- Without explicit verification, "done" becomes a politeness rather than a claim

### Operational forms in different hosts

| Host | Where the principle lives |
|---|---|
| Claude Code | `~/.claude/skills/superpowers/skills/verification-before-completion/SKILL.md` |
| Grok Build | Adopt via workspace AGENTS.md or a `~/.grok/skills/verification/` skill (would mirror Claude's) |
| Any other | Operator-applied discipline; the principle is in the operator, not the tool |
