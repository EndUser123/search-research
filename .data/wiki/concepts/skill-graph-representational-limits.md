# Skill graph representational limits

## Finding

The auto-generated skill dependency graph (`P:/.data/wiki/concepts/skill-graph.md`, built by `build_skill_graph.py`) was designed for **blast-radius analysis** and **delegation tracing**. It represents four things per skill:

| Field | Meaning |
|-------|---------|
| `delegates_to` | Skills this one explicitly calls |
| `consumes_provider` | MCP/CLI tools it uses |
| `provides` | Capability names it offers |
| `domain` | A single flat category label (13 domains) |

The graph **cannot** represent six dimensions that matter for skill placement and workflow design:

1. **Workflow position / temporal ordering** — can't show `/why → /aar → /prevent → /go → /check` as a pipeline. Edges are undirected delegation, not ordered phases.
2. **Trigger conditions** — can't show *when* a skill fires (on "how do we prevent?", on "remember that").
3. **Composition vs delegation** — can't distinguish "I call this skill and let it run" from "I select a phase and embed it in my flow."
4. **Modes/sub-modes** — can't show `/aar --prevent` vs `/aar --measure` as different invocations.
5. **Authority targets** — can't show that a skill routes to AGENTS.md vs SKILL.md vs wiki vs task vs handoff.
6. **Problem-type mapping** — domains are too coarse. Both `/prevent` and `/directive` would land in `self-improvement`, indistinguishable from `/aar` and `/debrief`.

## Decision

**Path B (now):** Use the graph as-is. Put richer metadata (triggers, workflow position, composition, authority targets) in capability contract stubs at `P:/.data/wiki/capabilities/`.

**Path A (later):** Enhance the graph schema when the semantic composition graph pilot (A2b phase) is operational. Forcing the schema change now would duplicate that work.

## Capability contract template for richer placement

```markdown
---
title: "prevention-design"
node_type: capability
created: 2026-07-30
domain: self-improvement
---

# prevention-design

**Inputs:** verified root cause, prevention goal, evidence
**Outputs:** selected control mechanism, authority target, acceptance test
**Workflow position:** after root-cause-analysis, before implementation
**Triggers:** "how do we prevent this", "stop this happening again"
**Composes:** root-cause-analysis, opportunity-landscape
**Authority targets:** skill, hook, rule, config, wiki
```

## Falsifier

If a future session cannot determine when to use a skill or where it fits in a workflow from the capability contracts alone, the Path B approach has failed and the graph schema must be enhanced.
