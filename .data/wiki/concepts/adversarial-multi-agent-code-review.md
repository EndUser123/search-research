# Adversarial Multi-Agent Code Review

## Decision context

**Definition:** Adversarial Multi-Agent Code Review is an architectural pattern in AI-assisted software engineering that employs multiple specialized agents in competing or complementary roles to verify and validate code, addressing the limitation where a single AI system evaluating its own output lacks the adversarial perspective necessary for rigorous quality assurance.

## Operational details

- The pattern emerged in response to the 'self-review monoculture' problem, where the same mental models that produce a logic error are often the ones tasked with identifying it, leading to performative agreement without genuine verification.
- Multi-agent architectures leverage compartmentalization to create effectively infinite context windows, with specialized agents synthesizing findings into concise signals for a supervisor.
- A typical implementation uses a Builder Agent to produce code and a distinct Critic Agent to review the output against the specification, implementing consensus verification.
- Parallel agent configurations allow multiple reviewers to examine code simultaneously, enabling code review at the speed AI can produce code changes.
- The transition from monolithic LLM architectures to modular multi-agent systems represents a paradigm shift driven by limitations including context window degradation, conversational sycophancy, and the 'lost in the middle' retrieval phenomenon.
- Adversarial frameworks prioritize structured conflict, multi-model debate, and parallelized scrutiny over single-pass generation approaches.
