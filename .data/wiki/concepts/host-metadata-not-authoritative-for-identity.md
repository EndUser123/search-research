# Host metadata is not authoritative for session/worktree identity

## Finding

On Grok Build (Windows 11):

- **`summary.json` is model-writable.** The model can `Set-Content` overwrite it (probed 2026-07-24, restored). Therefore `git_root_dir`, `head_commit`, and `head_branch` in `summary.json` cannot serve as identity authority.
- **Payload `cwd` is not always `git show-toplevel`.** Subagent worktree sessions record `cwd` as the subagent copy path, but `git rev-parse --show-toplevel` returns the main repo root (`P:/`). Using `cwd` as worktree root would produce incorrect identity.
- **`workspaceRoot` in payload** matches `cwd` in observed sessions but may differ in general (unverified for edge cases).

## What IS authoritative

A single combined `git rev-parse --show-toplevel --git-common-dir --absolute-git-dir` call (51ms warm, was 165ms with 3 separate calls). This is the only source where the model cannot influence the output.

## Optimization

Combined the 3 subprocess calls into 1 — 69% latency reduction with identical identity values.

## Falsifier

If Grok Build adds a session-identity field to the payload that is provably non-model-writable and includes worktree-level identity, this concept should be superseded.
