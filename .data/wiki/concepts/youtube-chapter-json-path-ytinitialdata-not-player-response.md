# YouTube Chapter JSON Path — ytInitialData Not ytInitialPlayerResponse

## The Finding

YouTube stores native chapter data (both creator-uploaded and auto-generated) in **`ytInitialData.engagementPanels`**, NOT in `ytInitialPlayerResponse`. The player response has zero chapter/marker fields.

This was discovered during Gate 2 of the YouTube Workspace Sidebar Extension build (2026-08-11). The Gate 1 handoff assumed chapters would be in `ytInitialPlayerResponse.macroMarkersListRenderer` — this is wrong.

## The Correct Path

```
ytInitialData
  .engagementPanels[]
  .engagementPanelSectionListRenderer
  .content
  .macroMarkersListRenderer
  .contents[]
  .macroMarkersListItemRenderer
```

## Chapter Item Shape

Each chapter item contains:
- `title.simpleText` — chapter title
- `timeDescription.simpleText` — display timestamp (e.g., "6:02")
- `onTap.watchEndpoint.startTimeSeconds` — pre-parsed seek target (integer)
- `onTap.watchEndpoint.videoId` — video ID
- `thumbnail.thumbnails[]` — chapter thumbnail images

## Why This Matters

The `steipete/summarize` extension (MIT, 6.5k stars) has zero chapter handling because its `youtube-page-transcript.ts` only reads from the player response. Any YouTube extension that needs chapter data must read from `ytInitialData`, not `ytInitialPlayerResponse`.

## Description Regex Fallback

For videos without native chapters, the description-timestamp regex `(\d{1,2}:\d{2}(?::\d{2})?)\s+(.+)` extracts chapters from `videoDetails.shortDescription`. YouTube auto-generates native chapters FROM description timestamps, so the regex and native path usually converge for description-derived chapters.
