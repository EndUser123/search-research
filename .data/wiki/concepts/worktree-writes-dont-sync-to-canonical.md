# Worktree writes don't sync to canonical

## The failure pattern

A wiki concept page (`grok-pretooluse-deny-contract-verified.md`) was written
during a worktree subagent session on 2026-07-19. The write landed at the
worktree's local path:

```
~/.grok/worktrees/repo/subagent-019f7cbb-.../.data/wiki/concepts/grok-pretooluse-deny-contract-verified.md
```

Multiple subsequent artifacts (the exec-gate plugin README, the wiki log at
`P:/.data/wiki/log.md:4256`, an enhancement plan) cited the canonical path:

```
P:/.data/wiki/concepts/grok-pretooluse-deny-contract-verified.md
```

The canonical path was empty for three days. The citations dangled. When a
session tried to read the page, it was "not found" — despite the verification
work having been done and logged.

## Why it happens

Git worktrees create isolated working copies. Each worktree has its own
filesystem view. A write to `.data/wiki/concepts/X.md` inside the worktree
does NOT appear at `P:/.data/wiki/concepts/X.md` in the parent workspace until
the worktree is merged back.

The subagent session that wrote the page was operating inside its worktree's
context. The path `.data/wiki/concepts/X.md` resolved to the worktree-local
copy, not the canonical workspace path. No merge happened — the worktree was
eventually cleaned up or abandoned, leaving the file stranded.

## How to detect it

When a file is "not found" at the canonical path but was cited by an artifact
that claims it exists:

1. Search the worktree copies:
   ```
   Get-ChildItem -Recurse ~/.grok/worktrees -Filter "<filename>"
   ```
2. Check the wiki log (`P:/.data/wiki/log.md`) for ingest entries that claim
   the page was written. If the log says "ingested" but the file is missing
   from canonical, it was likely written in a worktree.

## The fix

**For worktree sessions writing durable artifacts:** write via absolute paths
that resolve to the parent workspace, not the worktree-local copy. For wiki
concepts, this means:

```python
# WRONG (resolves to worktree-local copy):
Path(".data/wiki/concepts/X.md")

# RIGHT (resolves to canonical workspace):
Path("P:/.data/wiki/concepts/X.md")
```

**For recovering stranded files:** copy from the worktree to canonical:

```powershell
Copy-Item "~/.grok/worktrees/repo/subagent-<id>/.data/wiki/concepts/X.md" `
          "P:/.data/wiki/concepts/X.md"
```

## Structural prevention (future)

A SessionEnd hook could scan for writes to `*/.data/wiki/concepts/*.md` from
worktree-scoped sessions and warn if those files don't exist at the canonical
`P:/.data/wiki/concepts/` path. This is a candidate for the exec-gate
enhancement plan's PR 5 scope.
