## Summary

`/verify` is a **bundled skill shipped with Claude Code itself** (≥ v2.1.145), per the official Commands reference and the Skills page. It runs and verifies your app as the third phase of Claude Code's three-phase loop (gather → act → verify). It is invoked as a *slash command* the user types (`/verify`), not via the `Skill(skill="verify")` tool surface — which is why `Skill(verify)` returns `disable-model-invocation`.

This corrects an earlier hypothesis in this repo that `/check`'s Phase 1 could call `verify` as a Skill. That spec was wrong: the right Phase 1 instructs the operator to run `/verify` and treats its outcome as the gate signal.

## Key Findings

- **Bundled, not marketplace:** "[Claude Code] includes bundled `code-review` and `verify` skills." Listed on the [Commands reference](https://code.claude.com/docs/en/commands) and [Skills page](https://code.claude.com/docs/en/skills) as a bundled skill.
- **Slash-command invoked:** Purpose per the docs is "Run and verify your app." Bundled with `/run`; `/run-skill-generator` teaches both how to build/launch/drive an app.
- **Version requirement:** `v2.1.145` or later.
- **Invocation surface:** Slash command (`/verify`), not Skill-tool callable. `Skill(skill="verify")` returns `disable-model-invocation`. This is documented convention, not a bug.
- **Override risk:** "Naming a custom command after one [bundled command/skill] overrides the built-in" ([Slash Commands in the SDK](https://code.claude.com/docs/en/agent-sdk/slash-commands)). A marketplace plugin named `verify` would shadow the bundled one — *do not* create one. Earlier hypothesis (Path A in 2026-07-19 design session) was retracted on this finding.
- **Dispatch fact:** 24 marketplace SKILL.md files in this monorepo mention `disable-model-invocation` (improve, prompt_refiner, bf, review-pr, uci, sqd, retro, top-problems, pre-mortem, adv-review, av, usm, …). Two patterns appear: (a) consumers that *intend* to `Skill(verify)` — these were the unlucky authors who hit the same dead-end `/check` did; (b) declarations of "this skill will be invoked by other tools" referencing a never-existing target. Treat (a) as a known anti-pattern; (b) as documentation drift to be normalized when next touched.
- **Three-phase loop name origin:** The "verify results" phase of Claude Code's gather→act→**verify** loop ([How Claude Code Works](https://code.claude.com/docs/en/how-claude-code-works)) is what the bundled skill is named after.

## How to apply

- **When authoring a skill that wants verification:** do not `Skill(skill="verify")`. Either (i) instruct the operator to run `/verify` and consume the outcome, or (ii) implement a project-local pytest harness under `tests/` and gate on that. Don't shadow the bundled command.
- **When `/check` exits BLOCKED at Phase 1:** root cause is the `Skill(verify)` call. Fix is in `/check`'s Phase 1 spec, not a marketplace skill. See memory entry for the patch surface.
- **When auditing marketplace SKILL.md files:** `disable-model-invocation` near `verify` references is *almost always* a copy-paste of a convention that never worked. Worth flagging when reviewing new skill bodies.
- **When checking Claude Code version compatibility:** `/verify` as a slash command requires CC ≥ v2.1.145. Below that threshold, neither the slash command nor the bundled Skill exist — the spec text is a hard version gate.
