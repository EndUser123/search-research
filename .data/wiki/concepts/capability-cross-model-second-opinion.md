# cross-model-second-opinion: design notes

## The contract

`P:/.data/wiki/capabilities/cross-model-second-opinion.md`

## Why this node exists

Three skills (agy, codex, mmx) each implement cross-model second opinion
with different dispatch shapes, different model families, and different
output formats. The capability defines the contract (prompt in, run
record out); each skill provides its own implementation.

## Providers (3)

| Skill | Model family | Dispatch shape | File access | Write capable |
|-------|-------------|----------------|-------------|---------------|
| `/agy` | Gemini | Local agent CLI | Yes | Yes |
| `/codex` | OpenAI/GPT | Local agent CLI + sandbox | Yes | Yes |
| `/mmx` | MiniMax | HTTP API (chat-only) | No | No |

## Glue (how each provider customizes)

The capability defines WHAT (prompt in, labeled outcome out). Each skill
defines HOW:

| Skill | Conductor | Outcome labels | Unique capability |
|-------|-----------|---------------|-----------------|
| `/agy` | Assignment adequacy (5 dims) | INVOCATION_FAILED through CONFIDENCE_GAIN | File-based code review, repo maps |
| `/codex` | Assignment adequacy (5 dims) | Same 7-label precedence | Sandbox write-capable tasks |
| `/mmx` | Assignment adequacy (5 dims) | Same 7-label precedence | MiniMax web search index |

All three share the same outcome-label precedence (INVOCATION_FAILED >
UNRELIABLE > MATERIAL_DELTA > USEFUL_DISAGREEMENT > CONFIDENCE_GAIN >
DUPLICATES_BASELINE > LOW_SIGNAL). This was deliberately unified per
ADR-009 so consumers can compare results across providers.
