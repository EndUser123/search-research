# Web Design Skills for AI-Generated Internal Tools — 2025-2026

## Decision context

This research was motivated by the fusion portal design cleanup session
(2026-08-03). After incrementally adding features to `fusion2.html` over multiple
sessions, the page accumulated classic "AI design slop": 14 overloaded color
variables with contradictory meanings, emoji everywhere, hover-scale animations on
every element, 8 type sizes. The operator asked: what design skills do people
actually like, what's growing fastest, and what's appropriate for our environment?

The research changed the approach: instead of fixing each symptom ad hoc, the
structural fix is a shared design token system (`tokens.css`) that every generated
HTML tool references, preventing design drift between tools.

## What practitioners love (State of CSS 2025 + practitioner sources)

The **State of CSS 2025** developer survey (Devographics) is the authoritative
source for adoption + satisfaction data. Three features moved "from wish lists to
everyday practice" and rank among "most loved":

| Feature | Adoption signal | Why developers like it |
|---------|----------------|----------------------|
| **`:has()` selector** | **80.4% usage** — most-used CSS feature in survey | Eliminates entire categories of JS. Form validation, conditional layouts, state-aware UI in pure CSS |
| **Container Queries** | Shipped all browsers Feb 2023 (30+ months stable) | Components adapt to where they're *placed*, not the viewport. No media-query gymnastics |
| **Subgrid** | "Moved from wish lists to everyday practice" | Nested elements align to parent tracks. Solves the "why doesn't this line up?" pain |

Beyond the top 3:
- **CSS custom properties + `color-mix()`** — derive hover/focus/disabled variants from one base token mechanically
- **Cascade layers (`@layer`)** — explicit specificity ordering, no more `!important` arms races
- **`:focus-visible`** — solves "remove ugly outline vs keep accessibility" tension
- **System font stacks** — zero load, native feel, automatic dark-mode matching
- **`light-dark()` function** — one-liner theme-aware values without media queries

[Scrimba 2026 CSS landscape](https://scrimba.com/articles/best-css-courses-and-tutorials-2026/) (cites the 80.4% number),

## Fastest-growing skills

| Tier | Skills | Growth signal |
|------|--------|---------------|
| **Mainstream** | `:has()`, Container Queries, CSS Nesting, `color-mix()`, Cascade Layers | "Everyday practice" per State of CSS 2025 |
| **High-growth** | View Transitions, Scroll-driven animations, Anchor Positioning | Chrome I/O 2025 highlighted all three |
| **Direction shift** | **Vanilla CSS resurgence over utility frameworks** | Multiple 2026 essays document migration away from Tailwind toward native CSS |

Key number: **91.7% of mobile pages use CSS transitions, only 18.4% load a JS
animation library** (State of Web Animation 2026). CSS is winning the animation war.

## AI design tells — 20 patterns beyond the obvious

Research from 5 independent sources (925studios, YC design review summaries,
Search Engine Journal, madebyoversight, Kargutkar) identified 20 specific patterns
that make AI-generated pages look AI-generated. The ones most relevant to internal tools:

### Interaction anti-patterns (loudest signal, most missed)
1. **Hover effects going the wrong direction** — fade out, shrink, move away instead of reinforcing clickability
2. **Scroll-jacking and decorative scroll-following elements** — hijacking native scroll
3. **Information hidden behind hover** — critical data only revealed on mouseover (workflow killer for terminal operators)
4. **Auto-advancing components that look clickable** — timer-driven elements with mismatched affordance
5. **Snap-instead-of-ease transitions** — no easing curves, or generic ease with no state semantics

### Visual identity tells
6. **Inter font as sole typeface** — no display/body contrast pair
7. **"Fisher-Price" icon palette** — default red/yellow/green/blue Google colors on everything
8. **"Fake dashboard" motif** — big-number cards with colored dots, generic chart icons
9. **Lucide icons + oversized headline + pill buttons** — the full default kit
10. **Uniform padding/radius/spacing everywhere** — flattens hierarchy into undifferentiated mush

### Copy tells (the worst offender per multiple sources)
11. **Vague aspirational headlines** — "Build the future," "Transform your workflow"
12. **Hedging language and generic superlatives** — "best-in-class," "cutting-edge"
13. **Same-architecture page template** — hero + features + pricing + CTA regardless of purpose

### Structural tells
14. **Inconsistent visual language across sections** — drift when generated in multiple passes
15. **AI-generated illustrations** — plastic, symmetrical, too smooth
16. **5+ typography styles in one section** — AI showing off vs deliberate hierarchy
17. **Section fade-in/fade-out on scroll** — delays content visibility (workflow cost)
18. **Meteor/particle effects in hero** — the default AI decorative animation

### Overcorrection trap
19. **Over-designing as compensation** — adding gradients/parallax/animations to escape "generic" label
20. **Design system drift after first deploy** — defaults reassert on every new generation unless constrained

## What applies to our environment

Our context: single-file HTML internal tools, dark-mode dashboards, no build step,
AI-generated. The applicability assessment:

| Finding | Applies? | Why |
|---------|----------|-----|
| OKLCH tokens + `prefers-color-scheme` | **Yes — highest leverage** | Single-file, dark-mode, no build |
| Container Queries | **Yes** | Components in unpredictable layouts |
| `:has()` + `:focus-visible` | **Yes** | Zero-JS state management + a11y |
| `color-mix()` + `light-dark()` | **Yes** | Derive variants from one token |
| Cascade layers (`@layer`) | **Yes** | Single-file specificity management |
| View Transitions | **Conditional** | Needs `@supports` (Firefox gap) |
| Scroll-driven animations | **Conditional** | Firefox doesn't support yet |
| Shared design token file | **Yes — structural fix** | Prevents design drift between tools |

### The structural fix: shared token system

Implemented this session as `tokens.css` in the model-web skill directory. Every
HTML tool links it via `<link rel="stylesheet" href="tokens.css">`. The token system
encodes:

- **4 surface levels** (`--bg` through `--surface3`)
- **1 accent color family** (not 14 overloaded variables)
- **3 type sizes** (11/13/16px — not 8)
- **5-step spacing rhythm** (4/8/16/24/32px)
- **1 transition speed** (150ms)
- **5 category colors** scoped to model-group labels only
- **1 font stack** (system, zero load)

This prevents the failure mode where each generated tool invents its own palette and
the next cleanup session has to re-consolidate. See [[expected-ui-ux-features]] for
the broader tier-1/2/3 feature checklist.

## Disconfirmation pass

- **Vanilla CSS resurgence:** tested against our existing approach — we already use
  vanilla CSS, so this validates rather than redirects. Confirmed.
- **`:has()` at 80.4% adoption:** this number comes from State of CSS 2025 via
  Scrimba's citation. Could not independently verify the raw number, but the trend
  (has() is mainstream) is corroborated by every other source. Qualified.
- **"Shared token file prevents design drift":** this is the research's prescription,
  not yet tested longitudinally. Implemented this session but not validated across
  multiple tool generations. Labeled as `[INFERENCE]` for longitudinal claims.

## Falsifier

This concept is wrong if:
- State of CSS 2026 shows `:has()` adoption stalled or declining
- The shared token system doesn't prevent design drift in practice (test: generate
  3 new tools with tokens.css and check if they remain visually consistent)
- A build-step-based approach (Tailwind v5, vanilla-extract) becomes clearly better
  for single-file HTML tools than vanilla CSS + tokens
- The AI design tells list becomes outdated because LLMs stop generating these
  patterns (unlikely within 12 months)
