# Textual app lifecycle: settings persistence and the X-button trap

## Decision context

The Keep-Smaller-Copy TUI lost saved paths when the user closed the app
via the Windows terminal X button. Settings were saved in `action_quit`
(Ctrl+Q) and `on_unmount`, but `on_unmount` fires **after** the widget
tree is dismantled — `query_one("#from-path", Input)` returns nothing,
the try/except swallows the error, and settings are silently lost.

## The problem

Three exit paths, only one saved settings:

| Exit path | `action_quit` runs? | `on_unmount` runs? | Settings saved? |
|-----------|---------------------|---------------------|-----------------|
| Ctrl+Q | ✅ | ✅ (but widgets may be gone) | ✅ (via action_quit) |
| Esc (reset, not quit) | ❌ | ❌ | ❌ |
| Terminal X button | ❌ | ✅ (but widgets gone) | ❌ (query_one fails) |

The user has no way to know their settings weren't saved. On next launch,
paths are empty or stale.

## The fix: save on Input.Changed

```python
@on(Input.Changed, "#from-path")
@on(Input.Changed, "#to-path")
@on(Input.Changed, "#min-size")
def _on_path_changed(self, event: Input.Changed) -> None:
    self._save_current_settings()
```

Settings save on every keystroke/paste. By the time any exit path fires,
`settings.json` already has the latest values. Exit-time saving becomes
a belt-and-suspenders backup, not the primary mechanism.

**Cost:** one `json.dump` per keystroke. For a small settings dict (5
keys), this is <1ms — imperceptible. For larger configs, debounce with a
timer.

## Related finding: pasted Windows paths include quotes

When a user copies a path from Windows Explorer's address bar, it comes
with surrounding quotes: `"C:\Users\brsth\Videos"`. The app passes the
raw string to `os.path.isdir()`, which fails because the quotes are part
of the path string.

**Fix:** Strip quotes from every path read:

```python
path = self.query_one("#from-path", Input).value.strip().strip('"').strip("'")
```

Apply this at every site that reads path inputs (scan, browse, open, counts).

## Falsifier

If Textual adds a lifecycle hook that fires **before** widget teardown
(e.g., `on_request_close`), the Input.Changed approach becomes redundant.
Until then, it's the only reliable cross-exit-path persistence mechanism.
