# Check the data on disk before deferring: calibration data may already exist

## The pattern

The agent encounters a task that requires calibration, benchmark data, or prior measurements. The agent's default response: "We need to calibrate first; defer this task."

**But the operator may have already run the calibration.** On a mature host with months of accumulated data, trial results, benchmark runs, and evaluation outputs exist on disk — in `docs/operations/`, `.data/`, `.artifacts/`, or package-specific dirs.

## The fix

Before deferring any task with the reason "needs data/calibration/benchmark":

1. **Search the filesystem** for the specific data type
2. **Check `docs/operations/`** for trial data (the yt-is migration plan showed this pattern: trial data existed but wasn't indexed)
3. **Check `README.md`** — the cold-start entry point should link to operations docs
4. If the data exists → use it; don't defer
5. If the data doesn't exist → defer with a note about where it should be stored when generated

## Evidence

- **R12 L1** (session fa595529): The agent deferred a calibration task. The operator pointed out the calibration data was already on disk. The deferral was unnecessary.
