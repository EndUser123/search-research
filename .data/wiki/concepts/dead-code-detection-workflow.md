# Dead code detection workflow: vulture for Python LLM agent pipelines

## The tool

**Vulture** (`pip install vulture`) finds unused code in Python programs.
It uses static analysis to identify unreachable functions, classes,
variables, and imports.

```bash
# Quick check on a specific module
vulture ~/.grok/skills/aar/__lib/ --min-confidence 60

# Full skills directory
vulture ~/.grok/skills/ --min-confidence 60

# Output format: file:line: <message> (<confidence>%)
```

## Why it matters

The red-team review of the AAR efficiency plan (session 019f8507) found
that `all_aggregates()` in `aggregators.py` is dead code — defined,
unit-tested, but never imported or called by `full_preprocessor.py`.
This is exactly the class of bug vulture catches.

Dead code in LLM agent pipelines is particularly dangerous because:
1. It looks maintained (tests pass) but isn't wired to anything
2. The implementer of TASK-02b would have added another aggregator
   alongside dead code, not knowing the wiring step was missing
3. The dead code pattern (defined + tested + unused) is invisible
   to both `/check` and `/review` — they check behavior, not wiring

## False positive management

Vulture's false positives come from dynamic dispatch (reflection,
`__import__`, plugin auto-discovery). Mitigation:

```bash
# Whitelist dynamic dispatch points
vulture ~/.grok/skills/ --min-confidence 60 --exclude "*/__pycache__/*"
# Or use a whitelist file:
echo "import_module" > .vulture_whitelist.txt
vulture --define-whitelist .vulture_whitelist.txt
```
