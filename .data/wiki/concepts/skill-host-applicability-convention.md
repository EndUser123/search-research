# Skill host applicability convention

## Rule

SKILL.md frontmatter must include:

```yaml
host: grok   # one of: grok | claude | both
```

- `host: grok` — written for Grok Build, may not work under Claude Code
- `host: claude` — written for Claude Code, may not work under Grok Build
- `host: both` — written and tested under both, transfers cleanly

A missing `host:` field is pre-convention. Don't infer host from path — cross-bridged installs make that unsafe.

## Audit (2026-07-18)

884 SKILL.md files scanned. Zero currently declare a `host:` field. The convention applies prospectively to new and edited files.

## Falsifier

Wrong if cross-host skill portability is never a problem (skills just work everywhere). Test: run a `host: claude` skill on Grok Build and check for failures.
