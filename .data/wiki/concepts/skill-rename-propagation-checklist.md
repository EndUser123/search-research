## Summary

Renaming a skill that's referenced in global config (`CLAUDE.md`), plugin constitutions, and consumer skills is a 10-step propagation. The rename of `source-authority-discovery` → `preflight` (2026-07-20) is the reference case.

## The 10-step checklist

1. **Primary skill directory** — `git mv` at `P:\.agents\skills\<old>\` → `<new>\`. Never copy+delete (loses git history).
2. **Plugin mirror** — if the skill has a mirror in a marketplace plugin (e.g., `cc-skills-sdlc/skills/<old>/`), `git mv` inside the submodule's own git repo.
3. **SKILL.md frontmatter** — update `name:` field in both copies.
4. **SKILL.md body** — update title, script paths in examples, and any self-references.
5. **Workspace constitution** — update `P:\.claude\CLAUDE.md` (the skill name appears in the mandatory-invocation section).
6. **Plugin constitution** — update the plugin's `CLAUDE.md` if it references the skill.
7. **Consumer skills** — grep for the old name across `~/.grok/skills/`, `P:/.agents/skills/`, and any plugin skills. Update each consumer's references.
8. **Consumer scripts** — check for hardcoded paths in `.ps1`, `.py`, `.sh` scripts that invoke the skill's scripts.
9. **Contract tests** — update test assertions that check for the old name/path. Rename test functions to match. Run the tests to verify.
10. **ADR references** — update any ADR that cites the skill by name. Add a rename note: "(Formerly `<old>`; renamed YYYY-MM-DD per ADR-NNN.)"

## What NOT to update

- **Historical artifacts** — audit JSONs (`.artifacts/source-discovery-*.json`), session state JSONs, and dated investigation docs contain paths that describe what was there at audit time. Editing them rewrites history. Leave them as-is.
- **Chat history / session transcripts** — these are immutable records.

## Stale git index.lock

If `git mv` fails with `Unable to create '.git/index.lock': File exists`, check:
- Lock age (`Get-Item .git/index.lock`). If >1h old and no git process is running, it's stale.
- No git processes (`Get-Process git`). If none, safe to remove.
- Remove via `[System.IO.File]::Delete()` (single file, non-recursive — avoids permission-policy blocks on `Remove-Item -Force -Recurse`).

## Verification

After the rename:
- Run contract tests that assert the skill name and paths.
- Run the skill's own script (`python <new-path>/scripts/<script>.py --help`) to confirm it's invokable.
- Grep live-source roots for the old name. Remaining hits should all be rename-notes ("(formerly `<old>`)"), not active references.
