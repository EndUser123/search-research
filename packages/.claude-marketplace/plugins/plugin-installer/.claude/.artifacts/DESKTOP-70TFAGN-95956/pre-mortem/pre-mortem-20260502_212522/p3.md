## Intent Summary

The `user_prompt_submit_hook.py` hook validates explicit `/skill-name` invocations via the `slash_command_observability.extract_command_name()` pipeline, resolves skill metadata via `get_skill_config()`, and calls `ExecutionRuntime.create_run()` to produce `execution-state.json` — the run state that PreToolUse reads to enforce tool blocking. The goal is to close the execution contract loop: create-run → tool-use → artifact → stop.

## Hidden Assumptions & Fragile Dependencies

2.1. [MEDIUM] **`_NON_SKILL_COMMANDS` allowlist not synced with `BUILTIN_SLASH_COMMANDS`** — The allowlist at `user_prompt_submit_hook.py:99-102` is a manually maintained frozenset. If Claude Code adds new built-in commands, they bypass the UserPromptSubmit path (good) but the allowlist could become incomplete. A new built-in that IS a skill name would cause false run creation. The coupling between these two sources is unverified. (source: p2_meta_critique, blind-spot #1)

2.2. [MEDIUM] **`terminal_id` may contain Windows-invalid filename characters** — `detect_terminal_id()` can return IDs containing `:` (e.g., `DESKTOP-70TFAGN:95956`). Used as a path component in `execution-state.json` path construction. On Windows, `:` is illegal in filenames. The Path() constructor accepts it but the actual filesystem operation may fail. (source: adversarial-io-validation, IO-005)

2.3. [LOW] **Exception handling catches KeyboardInterrupt and SystemExit** — `handle_user_prompt_submit()` at line 163 catches `Exception` which includes `KeyboardInterrupt` and `SystemExit`. These should propagate rather than be swallowed — they indicate the user cancelled or the process should terminate. Fail-open should cover runtime errors (missing files, bad config), not program-level interrupts. (source: p2_meta_critique, blind-spot #3)

## Concrete Recommendations

5.1. [HIGH] **Fix regex to support namespaced invocations** — In `slash_command_observability.py`, add a second pattern or extend `SLASH_COMMAND_RE` to `^/([a-z0-9_-]+):([a-z0-9_-]+)(?:\s+(.*))?$`. Extract both namespace and skill name. Update `extract_command_name()` to return the full qualified name or just the skill part depending on resolution intent. (source: p2_meta_critique)

5.2. [MEDIUM] **Sanitize terminal_id before path construction** — Filter Windows-invalid chars from `terminal_id` before using as a path component. At minimum, replace `:` with `-`. Add a `ValueError` if the sanitized result is empty. (source: adversarial-io-validation, IO-005)

5.3. [MEDIUM] **Use os.path.expandvars for env var substitution** — At `plugin-audit-and-fix.py:167`, replace `Path(str(script_path).replace(f"${var}", replacement))` with `Path(os.path.expandvars(str(script_path)))`. This handles all env vars and avoids substring collisions. (source: adversarial-compliance, COMP-004)

5.4. [LOW] **Narrow exception handling to exclude interrupts** — Change `except Exception` to `except (OSError, RuntimeError, ValueError, KeyError)` or catch `Exception` but re-raise `KeyboardInterrupt`/`SystemExit`. (source: p2_meta_critique, blind-spot #3)
