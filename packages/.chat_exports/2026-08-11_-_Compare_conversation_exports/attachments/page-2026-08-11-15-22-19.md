## 1\. AnythingLLM — strongest overall match

[Mintplex-Labs/anything-llm on GitHub](https://github.com/Mintplex-Labs/anything-llm?utm_source=chatgpt.com)

This one surprised me by how close it has become.

AnythingLLM now has **dynamic model routing, local/cloud LLM support, document ingestion/RAG, source citations, web-browsing agents, custom agents, MCP, intelligent tool selection, filesystem access, scheduled agents and memory**. It supports Ollama, llama.cpp-compatible models, LM Studio and generic OpenAI-compatible endpoints. [![](https://www.google.com/s2/favicons?domain=https://github.com&sz=128)GitHub+1](https://github.com/Mintplex-Labs/anything-llm/blob/master/README.md?utm_source=chatgpt.com)

Functionally:

```
Truth Engine                    AnythingLLM

Companion                 →     Workspace/chat agent
Extractor                 →     Document pipeline/RAG
Researcher                →     Web-browsing agent
local model               →     Ollama/LM Studio/OpenAI-compatible
research handoff          →     Agent tool invocation
private documents         →     Local document store
memory                    →     Workspace/agent memory
```

And critically, its recent versions added **automatic tool use and intelligent skill selection**. The model can decide when it needs a tool rather than requiring the user to explicitly switch into researcher mode. [![](https://www.google.com/s2/favicons?domain=https://github.com&sz=128)GitHub](https://github.com/Mintplex-Labs/anything-llm/releases?utm_source=chatgpt.com)

For a usable application today, this is probably **#1 to investigate**.

# The research side gets even more interesting

There are projects substantially more sophisticated than the Truth Engine's apparent "Researcher" concept.

## 4\. GPT Researcher

[GPT Researcher on GitHub](https://github.com/assafelovic/gpt-researcher?utm_source=chatgpt.com)

This is probably the most directly reusable **evidence acquisition service** I found.

Its architecture is approximately:

```
Question
   ↓
Planner
   ↓
Research questions
   ↓
┌────────┬────────┬────────┐
│research│research│research│
│ agent  │ agent  │ agent  │
└───┬────┴───┬────┴───┬────┘
    ↓        ↓        ↓
 sources   sources   sources
       \     |     /
        aggregation
             ↓
       cited report
```

It can research **both the web and local documents**, tracks sources, performs parallel research, maintains context and produces cited reports. It also exposes its research capability through MCP. [![](https://www.google.com/s2/favicons?domain=https://github.com&sz=128)GitHub](https://github.com/assafelovic/gpt-researcher?utm_source=chatgpt.com)

That's more compelling to me than simply giving a conversational model a web-search tool.

## 5\. LangChain Local Deep Researcher

[Local Deep Researcher on GitHub](https://github.com/langchain-ai/local-deep-researcher?utm_source=chatgpt.com)

This one is particularly worth examining because it is relatively conceptually clean.

It runs with **local models through Ollama or LM Studio** and performs an iterative loop:

```
question
   ↓
generate search query
   ↓
search web
   ↓
summarize evidence
   ↓
reflect:
"What don't I know yet?"
   ↓
generate next search
   ↓
search again
   ↓
...
   ↓
answer + sources
```

That's an important improvement over:

> LLM searches Google once → reads three snippets → declares victory.

The explicit **knowledge-gap reflection loop** is exactly the sort of mechanism I'd want in an evidence acquisition layer. [![](https://www.google.com/s2/favicons?domain=https://github.com&sz=128)GitHub](https://github.com/langchain-ai/local-deep-researcher?utm_source=chatgpt.com)

# What I would _not_ do

I wouldn't build:

```
Truth Engine Clone
 ├ companion.py
 ├ extractor.py
 ├ researcher.py
 └ router.py
```

from scratch.

There is too much mature implementation available already.

Instead, I'd separate **product shell** from **epistemic machinery**.

A promising architecture would be:

```
                    USER
                      │
                      ▼
             ┌─────────────────┐
             │ Assistant / UI  │
             │ AnythingLLM or  │
             │ Open WebUI/Khoj │
             └────────┬────────┘
                      │
                 task/router
                      │
       ┌──────────────┼──────────────┐
       ▼              ▼              ▼
 LOCAL REASONING   PRIVATE DATA    RESEARCH
       │              │              │
 local model      RAG/extractor     │
                                     ▼
                              GPT Researcher
                                   or
                              Open Deep Research
                                     │
                                     ▼
                              SOURCE EVIDENCE
                                     │
                                     ▼
                             assistant context
                                     │
                                     ▼
                             reason / challenge
                                     │
                                     ▼
                                  answer
```

And then add the part I think **Truth Engine itself doesn't sufficiently solve**:

```
Evidence
   ↓
claim extraction
   ↓
┌─────────────────────────────┐
│ What supports this claim?   │
│ What contradicts it?        │
│ Is the source authoritative?│
│ Is it current?              │
│ Fact vs inference?          │
└──────────────┬──────────────┘
               ↓
         adversarial review
               ↓
       confidence / unknowns
               ↓
             answer
```

That last layer is important.

**RAG is not truth. Web search is not truth. Citations are not truth. Multiple agents agreeing is not truth.**

They're evidence-acquisition mechanisms. The system still needs to determine whether the evidence actually entails the claim.

### My shortlist for our purposes

I'd investigate **four**, rather than dozens:

1.  **AnythingLLM** — steal/integrate its local assistant, model routing, documents, tools and general UX.
    
2.  **GPT Researcher** — study/reuse its evidence-acquisition and source-tracking architecture.
    
3.  **Open Deep Research** — study its supervisor/researcher separation, reflection and evaluation methodology.
    
4.  **Local Deep Researcher** — steal the very simple **search → evidence → identify knowledge gap → search again** loop.
    

LlamaIndex/Haystack become relevant only if we conclude those products don't expose enough control; they're excellent construction kits, but I'd rather **reuse an existing engine than construct another framework around frameworks**. [![](https://www.google.com/s2/favicons?domain=https://github.com&sz=128)GitHub+1](https://github.com/run-llama/llama_index?utm_source=chatgpt.com)

The especially interesting next step would be to compare these repos against the mechanisms already in your agentic system and produce a **capability matrix: `already have / repo does better / integrate / steal pattern / unnecessary`**. I suspect there are several places where an existing repo could eliminate custom machinery rather than adding more of it.
