## Cross-Agent Contradictions
1. Target misidentification conflict — adversarial-compliance (COMP-002) and adversarial-io-validation (IO-001) both reported that a UserPromptSubmit hook and ExecutionRuntime class "do not exist" in the plugin-installer plugin. Both are FALSE POSITIVES — the hook and runtime ARE implemented in the separate skill-guard plugin at `P:/packages/.claude-marketplace/plugins/skill-guard/`. The specialists reviewed the wrong plugin scope entirely.

## Severity Calibration Issues
1. SEC-002 (plugin names not sanitized) rated MEDIUM by adversarial-security but IO-005 (terminal_id invalid chars) rated LOW — both are equivalent path injection/safety risks for filename construction. SEC-002 is more exploitable (arbitrary plugin names from iterdir) while IO-005 requires a specific terminal_id format. Calibration is roughly correct but SEC-002 could credibly be rated HIGH.
2. COMP-004 (naive string replace for env var expansion) rated MEDIUM by adversarial-compliance — this is more precisely a LOW given the constrained context (env vars are known keys from a fixed dict, not user input). The "substring corruption" scenario requires a very specific path pattern.

## Missed Blind Spots
1. `_NON_SKILL_COMMANDS` allowlist is hardcoded and not synced with `BUILTIN_SLASH_COMMANDS` from slash_command_observability.py. If Claude Code adds a new built-in command, the allowlist could become stale. No specialist flagged this coupling.
2. `extract_command_name()` uses `SLASH_COMMAND_RE` which matches `^/([a-z0-9_-]+)` — does NOT match namespaced skills like `/plugin-installer:audit`. The regex requires only lowercase alphanumerics, dashes, underscores. The `:` in `plugin-installer:audit` would cause the entire match to fail, meaning namespaced skill invocations would NOT create runs. No specialist flagged this.
3. The `fail-open` exception handling in `handle_user_prompt_submit()` swallows ALL exceptions including KeyboardInterrupt and SystemExit. No specialist flagged that these should perhaps be re-raised rather than caught.

## Precision Failures
1. COMP-001 (hooks.json at root) — The adversarial-compliance specialist reported hooks.json at the plugin root instead of `hooks/hooks.json`. This is a FALSE POSITIVE for plugin-installer. The plugin has a proper `hooks/hooks.json` at line 118 of plugin-audit-and-fix.py. The specialist apparently misidentified the file location.
2. IO-001 and IO-002 (ExecutionRuntime.create_run() missing, execution-state.json dir not created) — Both reported as blockers in the plugin-installer scope. These are FALSE POSITIVES. ExecutionRuntime IS in skill-guard, and ArtifactsExecutionStore DOES call `mkdir(parents=True, exist_ok=True)`. The specialists were reviewing the wrong plugin.
3. COMP-004 (path substitution bug) — described as corrupting paths "containing the env var name as substring" but the actual code replaces `${VAR}` with the full value. For a var named `CLAUDE_PLUGIN_ROOT` and a path like `P:/packages/plugin-installer/scripts/plugin.py`, no substring match occurs. The real risk is if someone had a path segment literally containing `${CLAUDE_PLUGIN_ROOT}` as a directory name — a highly unlikely edge case.

## Improvements to the Phase 1 Findings
1. The misidentification of the target plugin (plugin-installer vs skill-guard) should have been caught in the triage phase. A proper scope check would have identified that the hook in question lives in the skill-guard plugin, not plugin-installer. This is a systemic P1 failure — the orchestrator must verify the target plugin before dispatching specialists.
2. The most critical actual finding — that `extract_command_name()` does NOT match namespaced skill invocations like `/plugin-installer:audit` — was not caught by any specialist. This is the highest-value bug in the actual hook code and would prevent runs from being created for the most common skill invocation format.
3. The Phase 1 consolidation correctly flagged false positives but should have been more explicit: "COMP-002 and IO-001 are FALSE POSITIVES — the target is skill-guard, not plugin-installer." This should have elevated the remaining real findings to higher visibility.
