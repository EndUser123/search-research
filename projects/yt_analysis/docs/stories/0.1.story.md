# Story 0.1: Establish Core Project Repository & Structure

## Status: Done

## Story

- As a YTAP developer
- I want a standardized monorepo initialized with the defined backend (`src/backend_engine/`) and frontend (`src/frontend_ui/`) directory structures, including basic configuration files (`package.json`, `pyproject.toml`/`requirements.txt`, `.env.example`)
- so that all subsequent development has a consistent and organized foundation.

## Acceptance Criteria (ACs)

1.  A new Git repository named `ytap-monorepo` is initialized on a version control platform (e.g., GitHub).
2.  The repository can be successfully cloned to a local development environment.
3.  The root directory `ytap-monorepo/` is present.
4.  The core project directory structure as defined in `docs/project-structure.md` is created within the repository. This MUST include at least:
    * `docs/`
    * `scripts/`
    * `src/`
        * `src/backend_engine/`
        * `src/frontend_ui/`
    * `tests/`
        * `tests/backend/`
        * `tests/frontend/`
5.  A basic `package.json` file is created and committed at `src/frontend_ui/package.json`, ready for a React/TypeScript project.
6.  A basic Python project configuration file is created and committed for the backend within `src/backend_engine/`, suitable for Python 3.11+.
7.  A root `.gitignore` file is created and committed, configured with common ignore patterns for Node.js, Python, and common OS-generated files.
8.  A root `.env.example` file is created and committed, listing placeholder environment variables as detailed in `docs/environment-vars.md`.
9.  (Optional) Separate `.env.example` files may be created and committed within `src/backend_engine/` and `src/frontend_ui/` if more specific variable organization is preferred over a single root file.
10. All these initial project structure elements and configuration files are committed to the main branch of the Git repository with a descriptive initial commit message.

## Dev Technical Guidance

* **Repository Naming:** Use `ytap-monorepo` or an equivalent agreed-upon name.
* **Target Directory Structure:** Strictly adhere to the structure outlined in `docs/project-structure.md`.
* **Frontend `package.json`:** This should be a minimal file. Specific dependencies for React, TypeScript, etc., will be added in later stories.
* **Backend Python Configuration:**
    * Use `requirements.txt` for now as per simplicity for MVP. The tech stack specifies Python 3.11+.
    * For more advanced dependency management options like Poetry/PDM, refer to the architect's notes in the PRD's Epic 0 review.
* **`.gitignore` Content:** Ensure it is comprehensive for Node.js, Python, and common OS files.
* **`.env.example` Content:** This file should list all environment variables needed by the application, with placeholder or example values. Refer to `docs/environment-vars.md` for context.
* **Version Control:** Use Git for all version control. Initial commit should be to the main branch.
