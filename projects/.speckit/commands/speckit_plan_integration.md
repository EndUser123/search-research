# speckit.plan Integration Guide

## System Integration Overview

speckit.plan is designed to integrate seamlessly with the broader speckit workflow ecosystem and CSF NIP infrastructure. This guide covers all integration points and workflows.

## Speckit Workflow Integration

### Core Workflow Sequence
```
1. /speckit.specify → Feature specification generation
2. /speckit.clarify → Requirements clarification (optional)
3. /speckit.research → Component discovery (automatic)
4. /speckit.plan → Implementation planning
5. /speckit.tasks → Task breakdown
6. /speckit.analyze → Artifact validation (optional)
```

### Prerequisites Integration

#### Required Artifacts
- **spec.md**: Generated by `/speckit.specify`
- **clarification_summary.md**: Generated by `/speckit.clarify` (optional)
- **TSK-### ID**: Assigned by speckit registry system
- **Feature Directory**: Created under `.speckit/specs/TSK-###-plan-name/`

#### Artifact Validation
```bash
# Verify specification exists
ls -la .speckit/specs/TSK-###-plan-name/spec.md

# Check clarification summary if available
ls -la .speckit/specs/TSK-###-plan-name/clarification_summary.md

# Validate TSK ID assignment
cat .speckit/registry/tsk_registry.json | jq '.[] | select(.tsk_id == "TSK-###")'
```

### Research Integration

#### Automatic Research Invocation
speckit.plan automatically invokes research when:
- Component existence validation fails
- No existing patterns found in knowledge base
- Technology stack detection is incomplete
- Evidence requirements are not met

#### Manual Research Integration
```bash
# Pre-planning research
/speckit.research "existing authentication patterns"
/speckit.plan "research:existing_solutions, evidence:required"

# Research-informed planning
/speckit.research "microservices patterns in current codebase"
/speckit.plan "template:feature-development, research_informed:true"
```

### Task Generation Integration

#### Plan-to-Task Transition
```bash
# Generate plan
/speckit.plan "tech:python, database:postgresql"

# Generate tasks from plan
/speckit.tasks "use_plan:true, validation:comprehensive"
```

#### Task Breakdown Integration
- Plan architecture decisions inform task structure
- Technology choices affect task dependencies
- Validation gates become task acceptance criteria
- Resource requirements inform task assignment

## Troubleshooting Integration

### Common Integration Issues

**❌ TSK-010 Component Not Responding**
```bash
# Check component status
python .speckit/scripts/check_component_status.py --component template_engine

# Restart component if needed
python .speckit/scripts/restart_component.py --component knowledge_integration
```

**❌ Knowledge System Connection Failed**
```bash
# Test knowledge system connectivity
python scripts/knowledge_interface.py test-connection

# Validate knowledge system configuration
python scripts/knowledge_interface.py validate-config
```

**❌ Component Validation Blocking Planning**
```bash
# Investigate component validation issues
python src/modules/orchestration/discovery_engine.py investigate --project TSK-XXX

# Override validation block if appropriate
python src/modules/orchestration/validation_override.py --project TSK-XXX --reason "documented_risk_acceptance"
```

### Recovery Procedures
1. **Component Recovery**: Restart failed components and validate connectivity
2. **Data Recovery**: Restore from backups if data corruption detected
3. **Configuration Recovery**: Revert to last known good configuration
4. **Workflow Recovery**: Resume planning from last valid checkpoint
