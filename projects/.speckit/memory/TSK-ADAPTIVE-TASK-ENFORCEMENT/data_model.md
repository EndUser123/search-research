# Adaptive Task Management Enforcement Data Model

## Overview

This document defines the data models, entities, relationships, and integrity rules for the Adaptive Task Management Enforcement system. The data model supports intelligent enforcement, user pattern learning, and adaptive optimization while maintaining CWO12 constitutional compliance.

## Core Entities

### EnforcementContext

**Description**: Represents the context analysis for determining task enforcement requirements.

```python
class EnforcementContext:
    context_id: str                    # Unique identifier
    session_id: str                     # Claude Code session identifier
    tool_name: str                      # Tool being used (Write, Edit, Bash, etc.)
    tool_input: dict                    # Tool input parameters
    operation_risk_level: int           # Risk level (0-4)
    conversation_context: dict          # Conversation history and context
    user_pattern_match: float           # Pattern matching confidence (0.0-1.0)
    recommended_enforcement_level: int  # Recommended enforcement (0-4)
    minimum_enforcement_level: int      # Minimum required enforcement
    timestamp: datetime                 # Context analysis timestamp
    processing_time_ms: int             # Analysis processing time
```

**Attributes**:
- `context_id`: UUID-based unique identifier
- `operation_risk_level`: Assessed risk of operation without task context
- `user_pattern_match`: Confidence that user follows established patterns
- `recommended_enforcement_level`: Intelligent recommendation based on context
- `minimum_enforcement_level`: Hard minimum based on operation type

**Relationships**:
- One-to-many with EnforcementDecision
- Many-to-one with UserPattern
- One-to-one with ToolOperation

### EnforcementDecision

**Description**: Represents the final enforcement decision and user response.

```python
class EnforcementDecision:
    decision_id: str                    # Unique identifier
    context_id: str                     # Reference to EnforcementContext
    enforcement_level_applied: int      # Actual enforcement level applied
    user_action: str                    # User response (complied, overridden, etc.)
    active_tsk_id: str                  # Active TSK at time of decision
    override_reason: str                # Reason for override (if applicable)
    user_satisfaction: float            # User satisfaction score (0.0-1.0)
    workflow_impact: float              # Measured impact on workflow (0.0-1.0)
    timestamp: datetime                 # Decision timestamp
    learning_signals: dict              # Signals for pattern learning
```

**User Actions**:
- `COMPLIED`: User followed enforcement requirement
- `OVERRIDDEN`: User manually overrode enforcement
- `POSTPONED`: User postponed action to set task context
- `IGNORED`: User ignored warning and continued
- `ACCEPTED_SUGGESTION`: User accepted task creation suggestion

**Relationships**:
- Many-to-one with EnforcementContext
- One-to-many with LearningSignal

### UserPattern

**Description**: Represents learned user work patterns and preferences.

```python
class UserPattern:
    pattern_id: str                     # Unique identifier
    pattern_type: str                   # Type of pattern (work habits, preferences, etc.)
    pattern_data: dict                  # Pattern data and characteristics
    confidence_score: float             # Confidence in pattern accuracy (0.0-1.0)
    frequency_weight: float             # How often pattern occurs (0.0-1.0)
    effectiveness_score: float          # Pattern effectiveness measure (0.0-1.0)
    created_at: datetime                # Pattern discovery timestamp
    last_updated: datetime              # Last pattern update
    usage_count: int                    # Number of times pattern applied
    success_rate: float                 # Success rate when pattern applied
```

**Pattern Types**:
- `WORK_HABITS`: When and how user works
- `TASK_PREFERENCES`: User task creation and management preferences
- `ENFORCEMENT_TOLERANCE`: User tolerance for enforcement levels
- `WORKFLOW_PATTERNS`: Typical workflow sequences and patterns
- `CONTEXT_PREFERENCES`: Preferred context requirements by operation type

**Relationships**:
- One-to-many with EnforcementContext
- One-to-many with PatternApplication

### SmartTaskSuggestion

**Description**: Represents intelligent task suggestions generated by the system.

```python
class SmartTaskSuggestion:
    suggestion_id: str                  # Unique identifier
    context_id: str                     # Reference to EnforcementContext
    suggested_tsk_name: str             # Proposed task name
    suggested_tsk_description: str      # Proposed task description
    estimated_effort_hours: float       # Estimated effort in hours
    confidence_score: float             # Confidence in suggestion quality (0.0-1.0)
    similar_completed_tasks: list       # Similar tasks user has completed
    suggestion_reasoning: str           # Reason for suggestion
    user_action: str                    # User response (accepted, rejected, modified)
    user_feedback: str                  # Optional user feedback
    timestamp: datetime                 # Suggestion timestamp
    expires_at: datetime                # Suggestion expiration time
```

**User Actions**:
- `ACCEPTED`: User accepted suggestion as-is
- `MODIFIED`: User modified suggestion before accepting
- `REJECTED`: User rejected suggestion
- `POSTPONED`: User postponed decision

**Relationships**:
- Many-to-one with EnforcementContext
- One-to-many with TaskCreation

### TaskCreation

**Description**: Represents tasks created as a result of smart suggestions or enforcement actions.

```python
class TaskCreation:
    creation_id: str                    # Unique identifier
    suggestion_id: str                  # Reference to SmartTaskSuggestion (if applicable)
    enforcement_decision_id: str       # Reference to EnforcementDecision (if applicable)
    created_tsk_id: str                 # ID of created TSK
    creation_method: str                # How task was created (suggestion, enforcement, manual)
    time_to_creation_seconds: int      # Time from suggestion to creation
    user_satisfaction: float            # Satisfaction with creation process
    task_completion_outcome: str        # Eventual task outcome (completed, abandoned, etc.)
    timestamp: datetime                 # Creation timestamp
```

**Creation Methods**:
- `SMART_SUGGESTION`: Created from smart suggestion
- `ENFORCEMENT_REQUIRED`: Created due to enforcement requirement
- `USER_INITIATED`: User created after enforcement warning
- `MANUAL`: User created independently

**Relationships**:
- Many-to-one with SmartTaskSuggestion
- Many-to-one with EnforcementDecision
- One-to-one with TaskMaster TSK entry

```python
class PerformanceMetrics:
```

### LearningSignal

**Description**: Individual learning signals used for pattern improvement.

```python
class LearningSignal:
    signal_id: str                      # Unique identifier
    enforcement_decision_id: str        # Reference to EnforcementDecision
    signal_type: str                    # Type of learning signal
    signal_data: dict                   # Signal data and parameters
```

**Signal Types**:
- `USER_OVERRIDE`: User overrode enforcement
- `PATTERN_VIOLATION`: User violated expected pattern
- `SATISFACTION_FEEDBACK`: User provided satisfaction feedback
- `WORKFLOW_EFFICIENCY`: Measured workflow efficiency
- `CONTEXT_CORRELATION`: Context-pattern correlation

### PatternApplication

**Description**: Records of when patterns were applied and their outcomes.

```python
class PatternApplication:
    application_id: str                 # Unique identifier
    pattern_id: str                     # Reference to UserPattern

    application_confidence: float       # Confidence in pattern application
    user_response: str                  # User response to application
    outcome_effectiveness: float        # Measured effectiveness (0.0-1.0)

```

## Data Integrity Rules

### Primary Keys
- All entities must have unique identifiers
- Use UUID format for system-generated IDs
- Maintain referential integrity across relationships

### Foreign Key Constraints
- `EnforcementContext.context_id` referenced by EnforcementDecision, SmartTaskSuggestion
- `EnforcementDecision.decision_id` referenced by LearningSignal, TaskCreation
- `SmartTaskSuggestion.suggestion_id` referenced by TaskCreation
- `UserPattern.pattern_id` referenced by PatternApplication
- All foreign keys must be valid references

### Data Validation Rules

#### EnforcementContext
- `context_id` must be unique and non-null
- `operation_risk_level` must be between 0 and 4
- `user_pattern_match` must be between 0.0 and 1.0
- `recommended_enforcement_level` must be between 0 and 4
- `processing_time_ms` must be non-negative

#### EnforcementDecision
- `decision_id` must be unique and non-null
- `context_id` must reference valid EnforcementContext
- `enforcement_level_applied` must be between 0 and 4
- `user_satisfaction` must be between 0.0 and 1.0
- `workflow_impact` must be between 0.0 and 1.0

#### UserPattern
- `pattern_id` must be unique and non-null
- `confidence_score` must be between 0.0 and 1.0
- `frequency_weight` must be between 0.0 and 1.0
- `effectiveness_score` must be between 0.0 and 1.0
- `success_rate` must be between 0.0 and 1.0

#### SmartTaskSuggestion
- `suggestion_id` must be unique and non-null
- `context_id` must reference valid EnforcementContext
- `confidence_score` must be between 0.0 and 1.0
- `estimated_effort_hours` must be positive

### Business Rules

#### Enforcement Level Logic
- Level 0 (No Enforcement): Help, research, analysis operations
- Level 1 (Guidance Only): Low-risk operations, read-only activities
- Level 2 (Warning + Log): Medium-risk operations, existing file modifications
- Level 3 (Soft Block): High-risk operations, new project creation
- Level 4 (Hard Block): Critical operations requiring definite task context

#### Pattern Learning
- Patterns must have minimum confidence score of 0.7 to be applied
- Patterns with effectiveness < 0.6 are deprecated automatically
- User overrides reduce pattern confidence by 0.1
- Successful applications increase pattern confidence by 0.05

#### Performance Requirements
- Context analysis must complete within 50ms
- Enforcement decisions must complete within 100ms
- Pattern learning must not impact enforcement response time
- System overhead must remain under 100ms total

#### Data Privacy
- All learning data stored locally with user control
- Pattern data retention period configurable by user
- Analytics aggregation preserves individual privacy
- User can delete all learning data on request

## Relationship Diagrams

### Core Relationship Structure
```
EnforcementContext (1) -----> (N) EnforcementDecision
EnforcementContext (1) -----> (N) SmartTaskSuggestion
EnforcementContext (N) -----> (1) UserPattern
EnforcementDecision (1) -----> (N) LearningSignal
EnforcementDecision (1) -----> (1) TaskCreation
SmartTaskSuggestion (1) -----> (1) TaskCreation
UserPattern (1) -----> (N) PatternApplication
PatternApplication (N) -----> (1) EnforcementContext
```

### Data Flow
```
Tool Operation Request → Context Analysis → EnforcementContext
EnforcementContext → Pattern Matching → UserPattern
EnforcementContext + UserPattern → EnforcementDecision → User Response
User Response + Context → LearningSignal → Pattern Learning
Pattern Learning → UserPattern Updates → Future Enforcement Improvement
```
