# Feature Contracts

## Channel Progress Display
- **File:** rich_parallel_progress.py
- **PRD Reference:** FR-3 | AC.3.1, AC.3.2, AC.3.3, AC.3.4, AC.3.5
- **Required Class:** `ChannelProgress` (line 72)
- **Required Field:** `channel_name: str` (line 75)
- **Purpose:** Display human-readable channel names in progress bars
- **Regression Risk:** HIGH - User-facing progress display
- **Contract:**
  - AC.3.1: Progress MUST show human-readable channel_name from Channels table
  - AC.3.2: If channel_name unavailable, fall back to @handle format (e.g., @3blue1brown)
  - AC.3.3: If handle unavailable, fall back to channel/ID... format (e.g., channel/UCX...)
  - AC.3.4: MUST NOT display raw truncated IDs (e.g., UCXKeNggiHUHpdkIfUj7...)
  - AC.3.5: Progress display MUST query database for channel_name before rendering

**Regression Signature:**
- Truncated channel IDs like "UCXKeNggi..." appearing in progress output
- This indicates channel_name lookup was skipped or failed silently

**Data Flow:**
1. Resolve channel → get channel_id
2. Query Channels table for channel_name
3. Store in ChannelProgress.channel_name
4. Rich renders channel_name in progress bar

**Removal:** Requires explicit user override

## Batch Progress Counter
- **File:** batch_downloader.py
- **PRD Reference:** FR-3 | AC.3.1, AC.3.2, AC.3.3, AC.3.4, AC.3.5
- **Required Variables:**
  - `completed_count` (line 419) - ALL channels processed (success + failure + no-videos)
  - `successful_downloads` (line 420) - ONLY channels with actual video downloads
- **Purpose:** Track batch processing progress for multi-channel downloads
- **Regression Risk:** HIGH - UI progress display depends on this
- **Tests:** `tests/integration/test_batch_progress.py::test_progress_shows_all_channels`
- **Contract:**
  - Progress display MUST use `completed_count` for [X/N] format
  - Summary stats MAY use `successful_downloads` for "Total videos: X"
  - Counter semantics MUST NOT be swapped
  - `completed_count` increments for: success, failure, no-videos, quota-exceeded
  - `successful_downloads` increments ONLY when videos > 0

**Regression Signature:**
- `[0/N]` for all channels indicates `completed_count` not incrementing
- Check: Is counter incrementing in all code paths (try/except/finally)?

**Removal:** Requires explicit user override
