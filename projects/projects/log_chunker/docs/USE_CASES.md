# Log Chunker: Operational Use Cases

This document outlines the two primary operational workflows for using the `log_chunker` tool. Both are valid and serve different needs, but they have different implications for automation, learning, and system integration.

---

## Use Case A: AI-Orchestrated Workflow

This is the system-native, fully integrated workflow. It leverages the complete 4-system architecture (`UPI`, `PACT`, `MEMORY`, `BMAD`) for an automated, intelligent, and self-improving process.

### Actors
- **Human:** The *Director*. Initiates the task with a high-level goal.
- **AI Orchestrator:** The *Executor and Analyst*. Manages the entire workflow from planning to learning.

### Workflow Steps

1.  **Trigger (Human):** The user provides a high-level command in the chat interface.
    > **Example:** "Use `log_chunker` to analyze `rovodev.log` for critical errors and performance bottlenecks."

2.  **Intelligent Planning (AI):** The AI Orchestrator uses its direct access to the file system and the 4-system architecture to prepare for execution.
    - **Gathers Project Intelligence (Fulfilling the `_UPI` Role):** The AI directly inspects the project's files (`README.md`, `plugins/`, `config.py`) using its native tools to understand the tool's capabilities, plugins, and configuration options.
    - **Consults `_MEMORY`** to find historical data on similar tasks (e.g., "What were the most effective plugins for analyzing logs of this type?").
    - **Consults `_PACT`** to create an optimal execution plan (e.g., selecting the right plugins, setting the ideal chunk size based on historical performance).

    *\*Note on the `_UPI` Role: For a local CLI agent, the "Project Intelligence" step is performed directly. The `_UPI` system itself is designed to provide this same context to remote LLMs that lack file system access.*

3.  **Execution (AI):** The AI runs the `log_chunker.py` script with the optimized parameters determined in the planning phase.

4.  **Outcome Capture (AI):** Upon completion, the AI automatically gathers a structured summary of the run.
This includes:
    - Performance metrics (time taken, etc.).
    - The exact configuration used.
    - A summary of the analysis results (errors found, etc.).

5.  **Memory Integration (AI):** The AI takes the structured outcome from the previous step and creates a new, permanent entry in the `_MEMORY` system. **This is the automated learning step.**

6.  **HOD Synthesis (AI):** The AI analyzes the raw output from the script and the structured outcome to generate a human-readable **Handover Document (HOD)**. This document summarizes the key findings, problems identified, and any recommended next steps or outstanding tasks.

7.  **Reporting (AI):** The AI presents the synthesized HOD to the user in the chat.

### Key Outcomes
- The task is executed with optimized parameters based on historical data.
- A new, structured "experience" is automatically saved to the `_MEMORY` system, improving the system for all future tasks.
- A human-friendly HOD is generated and presented to the user.

---

## Use Case B: Human-Driven Workflow with AI Analysis

This workflow prioritizes direct, hands-on control. The user runs the script manually and then uses an AI as a powerful analysis assistant after the fact. To achieve parity with Use Case A, it includes a crucial final step to manually integrate the learnings back into the system.

### Actors
- **Human:** The *Executor and Director*. Runs the script and directs the analysis.
- **AI Analyst:** The *Analysis Assistant*. Responds to specific prompts to analyze results and facilitate learning.

### Workflow Steps

1.  **Execution (Human):** The user runs the `log_chunker.py` script directly from their terminal with parameters they choose.
    > **Example:** `python c:\_Python\_Projects\log_chunker\log_chunker.py c:\_Python\_Projects\.dev\.rovodev\rovodev.log`

2.  **Initial Review (Human):** The user examines the raw output files generated by the script (e.g., in the `chunks/` or `reports/` directories). **Note:** When running `log_chunker.py` in a compatible terminal, the paths to the generated report files will be displayed as clickable links for quick access.

3.  **Trigger (Human):** The user crafts a specific prompt for the AI Analyst. This prompt, often a **PACT-HOD prompt**, includes the raw output or a summary of it.
    > **Example:** "Please act as a Senior DevOps engineer. Analyze the attached log analysis report. Identify the top 3 most critical issues, suggest the root cause for each, and define the immediate next steps for the team. Present this as a Handover Document."

4.  **HOD Synthesis (AI):** The AI Analyst processes the prompt and the provided data, generating the requested HOD.

5.  **Memory Integration (Human with AI Assistance):** **This is the critical step to enable system learning.**
    - The user, now armed with the HOD, tells the AI Analyst: "Let's create a memory entry for this run."
    - The AI assists the user in creating a structured YAML or JSON object that summarizes the run's outcome (mirroring the data from Use Case A's "Outcome Capture" step).
    - The user saves this structured object as a new file in the `_MEMORY` system (e.g., `_MEMORY/entries/log_chunker/manual_run_20250716_1500.yaml`).

### Key Outcomes
- The user has full, direct control over the script's execution.
- A human-friendly HOD is generated based on a specific, directed prompt.
- A new, structured "experience" is manually saved to the `_MEMORY` system, allowing the system to learn from the manual run.

---

### Comparison and Recommendations

| Feature | Use Case A (AI-Orchestrated) | Use Case B (Human-Driven) |
| :--- | :--- | :--- |
| **Control** | Indirect (Goal-oriented) | Direct (Parameter-level) |
| **Learning** | **Automatic & Proactive** (improves future runs) | **Manual & Reactive** (records past runs) |
| **Optimization** | High (uses historical data to set parameters) | Low (relies on human judgment for parameters) |
| **Effort** | Low (single command) | High (multiple manual steps) |
| **Consistency** | High (process is standardized) | Low (depends on human consistency) |

- **Use Case A** is recommended for most tasks. It ensures that every run contributes to the system's intelligence, leading to a powerful compounding effect of continuous improvement.
- **Use Case B** is best for experimentation, debugging the script itself, or when you need to exert precise, non-standard control over the execution parameters for a one-off task. When using this workflow, completing the final **Memory Integration** step is crucial to the long-term health of the ecosystem.
