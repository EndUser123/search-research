# Story 0.4: Initialize Core Testing Frameworks with Placeholder Tests

## Status: Done

## Story

- As a YTAP developer
- I want Pytest (for the backend) and Jest with React Testing Library (for the frontend) installed and configured, each with a minimal sample passing test
- so that a foundational structure for automated testing is established and validated early in the project lifecycle, and the CI pipeline can execute these tests.

## Acceptance Criteria (ACs)

1.  Pytest is added as a development dependency and correctly configured for the Python backend (`src/backend_engine/`).
2.  A sample (placeholder) passing Pytest test file (e.g., `tests/backend/test_initial.py`) is created and committed, containing at least one simple assertion (e.g., `assert True`).
3.  Jest and React Testing Library (RTL) are added as development dependencies and correctly configured for the React/TypeScript frontend (`src/frontend_ui/`), including any necessary Jest setup files (e.g., `jest.config.js`, `jest.setup.js`).
4.  A sample (placeholder) passing Jest/RTL component test file (e.g., located at `src/frontend_ui/src/components/ui/ExampleComponent.test.tsx` or as per the co-location strategy defined in the YTAP Frontend Architecture Document) is created and committed, testing a very simple component or asserting a basic render.
5.  The frontend's `package.json` includes a script command (e.g., `test`) that executes all Jest tests. If coverage reporting is configured (e.g., via Jest's `--coverage` flag), the script command **MUST** enable it.
6.  The backend project includes an accessible command (e.g., via `pyproject.toml` task runners or `Makefile`) to execute all Pytest tests. If coverage reporting is configured (e.g., via `pytest --cov`), the command **MUST** enable it.
7.  The CI workflow defined in Story 0.3 is updated to include dedicated steps/jobs to:
    * Execute all frontend tests (e.g., `npm test`). The CI job MUST fail if any frontend tests fail.
    * Execute all backend tests (e.g., `pytest`). The CI job MUST fail if any backend tests fail.

## Dev Technical Guidance

* **Tool Selection:** Adhere to the testing frameworks specified in `docs/tech-stack.md`: Pytest for backend; Jest and React Testing Library for frontend.
* **Test File Locations:**
    * Backend: `tests/backend/`.
    * Frontend: Co-located with components as per the YTAP Frontend Architecture Document (`docs/front-end-project-structure.md` and `docs/front-end-testing-strategy.md`).
* **Sample Tests:** Keep them extremely simple for this story, just to verify the test runners are working and integrated into CI.
* **Jest Configuration (`jest.config.js`):**
    * Ensure `testEnvironment: 'jsdom'` for React components.
    * Use `ts-jest` preset for TypeScript.
    * Configure `moduleNameMapper` for aliases if used (e.g., `@/*`).
    * Set up `collectCoverageFrom` to specify source files for coverage reports if coverage is being configured as part of this story.
* **CI Integration:** Ensure the test execution steps in the GitHub Actions workflow correctly report success/failure and cause the overall CI run to fail if any tests fail.
