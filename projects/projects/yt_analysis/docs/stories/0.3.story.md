# Story 0.3: Integrate Linting, Formatting, and Basic CI Workflow

## Status: Done

## Story

- As a YTAP developer
- I want automated linting (Ruff for Python, ESLint for TypeScript) and formatting (Prettier for frontend) configured with project-standard rules, along with a basic Continuous Integration (CI) pipeline using GitHub Actions that runs these checks on every push/pull request
- so that code quality, style consistency, and early issue detection are maintained from the project's inception.

## Acceptance Criteria (ACs)

1.  Ruff is configured for the Python backend (`src/backend_engine/`) with a sensible default ruleset and a corresponding configuration file (e.g., in `pyproject.toml` or `ruff.toml`) is committed.
2.  ESLint (with necessary plugins for TypeScript, React, and Accessibility) and Prettier are configured for the TypeScript frontend (`src/frontend_ui/`) with sensible default rulesets, and their configuration files (e.g., `.eslintrc.js`, `.prettierrc.js`, `.prettierignore`) are committed.
3.  The frontend's `package.json` includes script commands (e.g., `lint`, `lint:fix`, `format`, `format:check`) to execute ESLint and Prettier.
4.  The backend project includes accessible commands or script configurations (e.g., in `pyproject.toml` for task runners like `poe`, or a `Makefile`) to execute Ruff for linting (including auto-fix) and formatting.
5.  A GitHub Actions workflow file (e.g., located in `.github/workflows/ci.yml`) is created and configured to trigger automatically on pushes to the main development branch and on all pull requests targeting it.
6.  The CI workflow successfully executes the following steps in isolated jobs or sequential steps:
    * Checks out the repository code.
    * Sets up the Node.js environment (version as per ARD) including dependency caching (e.g., for npm/yarn packages).
    * Installs frontend dependencies.
    * Runs frontend linting and formatting checks (e.g., `npm run lint:check`, `npm run format:check`). The CI job MUST fail if these checks do not pass.
    * Sets up the Python environment (version as per ARD) including dependency caching (e.g., for pip packages).
    * Installs backend dependencies.
    * Runs backend linting and formatting checks (e.g., `ruff check .`, `ruff format --check .`). The CI job MUST fail if these checks do not pass.
7.  The status of the CI workflow (pass/fail for each check) is clearly reported on pull requests within the Git hosting platform interface.

## Dev Technical Guidance

* **Tool Selection:** Adhere to the tools specified in `docs/tech-stack.md`: Ruff for Python, ESLint & Prettier for frontend, GitHub Actions for CI.
* **Configuration Files:**
    * **Ruff:** Typically configured in `pyproject.toml` or a dedicated `ruff.toml`. Start with `ruff --select ALL` and then gradually deselect rules if too noisy, or start with a recommended base like `ruff --select E F W I --fix`.
    * **ESLint:** Use recommended configs like `eslint:recommended`, `plugin:@typescript-eslint/recommended`, `plugin:react/recommended`, `plugin:react-hooks/recommended`, `plugin:jsx-a11y/recommended`.
    * **Prettier:** Use default settings or establish a minimal shared `.prettierrc.js`.
* **GitHub Actions Workflow (AC6):**
    * Use official actions like `actions/checkout@v3`, `actions/setup-node@v3`, `actions/setup-python@v3`.
    * Implement dependency caching using `actions/cache` or built-in features of `setup-node`/`setup-python` to significantly improve CI run times.
    * Run linting/formatting checks with flags that cause a non-zero exit code on failure (e.g., `prettier --check`, `eslint` by default, `ruff check`).
* **Local Execution:** Ensure all linting and formatting commands defined in `package.json` or backend scripts work correctly locally before integrating into CI.
